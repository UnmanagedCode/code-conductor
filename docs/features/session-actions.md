# Features: session actions and spawn options

## Session actions and recovery

- **Session summary** — `⋮` menu's `📝 Summarize` opens a modal dialog that generates and displays an AI-written summary of the session via a one-shot `-p --output-format=json` call using the **Fast capability tier**'s bound model/backend, launched through that backend's template — the same `resolveBackendLaunch()` seam `project_bash`'s shell-env bundle uses (see `src/summarize.ts` and [models.md](../models.md)).
  Four options: **Title** (a single line in the form `{Project}: <title>`, the title part ≤60 chars, naming the session's *current end goal* — not a recap of what happened, the objective the most recent turns are working toward; the project prefix is the instruction's own output format, not string concatenation).
  The project name comes primarily from the **conversation itself** — the projects it spawns workers into, the paths/repos it discusses — because a conductor session's own checkout is the hidden `.conduct` project, never the project it's actually orchestrating; the checkout-derived project name (worktree-aware, so a worktree checkout still resolves to its root project) is passed in only as a labelled hint the model may use when the conversation is ambiguous, and is dropped entirely rather than passed through when it would resolve to `.conduct`.
  If no project can be identified from either source, the model omits the prefix and outputs a bare title.
  **Short** (~40 content words, plain prose gist), **Medium** (~150 words, scannable recap with bullets/tables), **Long** (~400 words, thorough with `##` headings and structured tables).
  All four are generated, cached, and rendered identically (same markdown pipeline, same stale badge, same `↺ Regenerate`); the default tier on open is still **Medium**.
  Title adds one extra affordance: an **✏️ Use as session title** button (shown only when Title is selected and has a cached value) that PUTs the generated text through the same `/api/sessions/:sid/title` path as **Rename** below, sharing its client-side apply logic.
  The dialog also shows the **cost of the last generation** (`Cost: $0.00xx`, from the POST response's `costUsd`, itself the CLI's `total_cost_usd` — `null`/hidden for a non-Claude backend, same policy as the cost dashboard) — this is **ephemeral**: it clears on open and on every tier switch, is never persisted, and is absent from the GET response.
  Summaries are rendered as full markdown (headings, tables, code) through the same `Markdown` component as assistant messages.
  A **stale indicator** (`⚠ Session has grown since this summary`) appears when the session has received more turns since the last generation; regeneration is always user-initiated.
  Stored as the session-level `summaries` map on the session's record in `<store>/sessions.json` — `{ short?, medium?, long?, title? }`, each a `{ summary, generatedAt, messageCount }` record (the key IS the tier; cost is never stored).
  The route's id may be the public id or any segment of the session; both reach the one record.
  Removed with the record when the session's last transcript is deleted, or by the boot cleanup once no transcript is left in its lineage (**Startup session cleanup** below).
  The record is keyed by the public id, which is stable across `--resume`, renewal, typed `/clear` and prune, so summaries simply persist.
  - **Ask a question** — below the summary, an **Ask about this session** field and **Ask** button (Enter submits; disabled while the draft is blank or a question is pending) send `POST /api/sessions/:sid/ask` and show the markdown answer, with its `Cost:` when the backend reports one, in a scrollable list under the field. **Nothing is stored**: the list and the draft live in the dialog's React state only and are gone on close or reopen, and the server writes no record. Closing the dialog aborts a pending question and the server kills its call. Each question is sent alone — there is no conversation memory, earlier pairs are only shown. Questions run on the Fast tier, like the summaries. The session text is the CLI's system prompt and the question is last, so a question after another question, or after a summary, on an unchanged session reads the prompt cache; a new text turn, a rebinding of the Fast tier, the cache TTL or a very short session misses (the response's `usage` carries the cache counters). Summaries and titles run with that replaced system prompt and no tools (`src/sessionOneShot.ts`, [components/store.md](../components/store.md#srcsessiononeshotts)).
- **Rename session** — `⋮` menu's `✏️ Rename` opens a prompt to set a custom human-readable label (≤100 chars, empty clears) that overrides the first-prompt preview in the sidebar and prepends an italic chip to the active header. Stored as the session-level `title` on the session's record in `<store>/sessions.json`, keyed by the **public** id; naming any segment of the session renames the session, and every transcript row of the session shows it. A session can also name itself via the `set_session_title` MCP tool, and a conductor can name a worker at spawn with `spawn_instance`'s `title`; both write through the same `applySessionTitle` (`src/sessionTitles.ts`). Removed only with the record: when the session's last transcript is deleted (Settings → Archived), or by the boot cleanup once no transcript is left in its lineage (**Startup session cleanup** below); survives a normal session's exit, since that archives rather than deletes. Survives rewind, `--resume`, renewal, a typed `/clear` and prune — none of them touch the record's facts; a fork of a titled session starts titled `fork: <source title>` (`forkTitle`, `src/sessionTitles.ts`), capped like any title; a fork of an untitled session starts untitled.
- **Change model** — the `⋮` menu's **Change model** submenu opens a capability-tier picker (Fast / Balanced / Powerful / Frontier) using the same catalog/source of truth as the spawn dialog (`Settings → Models`).
  Selecting a tier sends only the **tier name** over WS — the server resolves that row's **current** `{backend, model}` binding, so a stale client cache can never pin an old model.
  A Claude session landing on a Claude model switches **live** via a `control_request` (`subtype:set_model`) — no restart, no history loss.
  **The tier's default effort is not applied** to a live switch — it changes the model alone; move the level with the sibling **Change effort** item below.
  A switch posts a `Model changed: <from> → <to>` notice in the transcript and blanks the ctx chip to `ctx —` (see the combined chip bullet below) — **re-selecting the tier the session is already on does neither**.
  The server decides that on the canonical model ids, so a tier whose model carries a catalog launch tag is still recognised as a non-change even though the server resolves the bare version id.
  The picker marks the entry the running session is on with a check (display-only, from the client's cache of the `/api/settings/models` payload: tier bindings for tier entries, `backendModels` for registered-model entries).
  The session records no tier, so when a listed registered model and a tier both resolve to the running model only the registered entry is checked; a tier is checked only when no registered entry for its model is listed, which is always the case on Claude, since it lists no registered models.
  Tiers are **grouped by backend** (a backend label heading each group, the session's own backend first); only enabled tiers are listed.
  After the tiers, on **every** session, each non-Claude backend in registry order lists **every model registered on it**, including one a listed tier there also binds (both entries are offered because they differ: the tier sends `{tier}`, so a restart applies the tier's effort; the model sends `{model, backend}` and keeps the session's current effort) — its custom models plus, for Ollama, the curated cloud models (labelled from the registry; a click sends `{model, backend}` instead of `{tier}`).
  The check needs the running backend as well as the running model id, so the same id registered on two backends is checked once.
  When no entry offers anything besides the model the session already runs, the picker says `No other model is available. Add one in Settings → Models.` **Between turns only, on every backend:** mid-turn the menu item is greyed with the tooltip `Model can only be changed between turns` (the same check as Change effort and Prune, `isBetweenTurns`), an already-open picker greys its entries in place, and the server refuses a switch `409` too.
  Each entry's state comes from `modelEntryState` (`web/src/features/session/SessionHeader.tsx`):
  - **Claude session, Claude tier** — the live switch above, between turns (mid-turn: disabled, tooltip `Model can only be changed between turns`).
  - **Every other entry** — a non-Claude session's tiers and registered models, and any entry on another backend from any session — a **restart**, marked `↻`, with the footnote `↻ restarts the session · the conversation is kept`, tooltip `Restarts the session on this model. The conversation is kept.` (same backend) or `Restarts the session on <Backend>. The conversation is kept.` (another backend). cc kills the CLI and resumes the same session on the target backend's launch template and model — **applying the tier's Settings-row effort** for a tier, **keeping the session's current effort** for a registered model. Across providers cc does no transcript compatibility check; the target CLI resumes the conversation as it is. Disabled with the tooltip `Switching restarts the session. Wait for the running turn to finish.` while a turn, a background subagent or another switch is running (the server refuses those too, plus running background bash jobs). A refusal shows as a `Change model failed` toast naming the cause; an open picker re-enables its entries when the session goes idle. The `↻` sits on the entry's line, after its label.
  - **During a restart** the header status chip reads `Restarting · switching model <from> → <to>` — `<from> on <fromBackend> → <to> on <toBackend>` when the switch crosses backends — (amber, spinning `↻`) over the transient exited/spawning states; Send is disabled for the whole switch (a prompt is refused, nothing is queued), Resume is hidden, Change model / Change effort are disabled, and the usage popover keeps naming `<from>` — with no `· N context` clause, since the window shown would already be `<to>`'s — until the switch is confirmed (the relaunch staying up for a grace window). It ends with `Model changed: <from> → <to> (session restarted)` in the transcript (each model followed by ` on <backend id>` across backends, as on the two lines below).
  - **A failed restart** (the relaunch dies inside the grace window, or never comes up idle) leaves the session resumed on `<from>`, writes `Switch to <to> failed — still on <from>` into the transcript (warn-styled, the cause as its tooltip), and shows a red `Switch to <to> failed` (`… <to> on <toBackend> failed` across backends) header chip with the cause as its tooltip until the next turn starts.
  - **Terminate during a restart** is a stop, not a failure: the session stays stopped on `<from>` (Resume brings it back there), the transcript reads `Switch to <to> cancelled — session stopped` (neutral styling, no tooltip), and no failure chip is shown.
  - All three transcript lines survive reloads, respawns, restarts and scroll-back — mechanism in [models.md](../models.md) and [protocol/ws-events.md](../protocol/ws-events.md).
  - **Below `md`** (`WIDE_QUERY`, `web/src/lib/useMediaQuery.ts`) the picker opens in place inside the `⋮` menu instead of beside it, because no side placement fits a phone: the **Change model** row becomes a `‹` back row (`aria-expanded="true"`) over the picker, the menu's other items are hidden, and tapping the back row restores them. The back row stays enabled even when the item is disabled. From `md` up the picker floats beside the menu, capped to the viewport height and scrolling. The behaviour belongs to the shared wrapper `web/src/components/ui/dropdown-menu.tsx`, so every submenu gets it.
- **Change effort** — the `⋮` menu's **Change effort** submenu (directly below Change model) opens a picker over the level catalog (`EFFORT_LEVELS`, `src/effortLevels.ts`, ordered low → high; the client renders the `efforts` key of `/api/settings/models`, never a literal). Picking a level repoints the **live** session — no restart. There is no `set_effort` control_request, so the server sends `/effort <level>` on the session's stdin and the CLI runs it as a **local slash command**: no model turn, zero tokens, a `$0.00` turn footer. The exchange therefore **shows in the transcript** as a user bubble plus the CLI's own `Set effort level to …` confirmation — deliberately, since the CLI persists that line in the session jsonl and rewind/fork indices count it. **Idle-only**, like 🪒 Prune: mid-turn the item is greyed (`Effort can only be changed between turns`) and the server refuses it `409` — mid-turn the CLI would fold the line into the running turn's input instead of running it. The picker marks the current level with a check. **Never a restart, on any backend** — unlike every Change model entry but Claude→Claude — since nothing here repoints an endpoint or a launch command. The new level is what every later relaunch that reuses the live value comes back at — per-path table in [models.md](../models.md#default-effort). Its picker drills in place below `md` like Change model.
- **Rewind & fork** — every user message bubble has `↶` (rewind in place, same `sessionId`) and `⑂` (fork to a new `sessionId`) on hover. Both atomically rewrite the jsonl and preserve the dropped prompt in the composer (a slash-command bubble — `/clear`, `/effort high` — prefills the command as typed). Bubbles anchor on the **server-stamped `userIndex`** riding on each outer `user_echo` (the absolute Nth-pure-user-prompt ordinal) — never a client-side bubble count, which would drift once the capped ring / tail-only snapshot starts the view mid-history. An echo without a stamp (rare orphan, or an archive bubble after a renew whose offset can't be measured) renders without the buttons. Both also send the bubble's text and **refuse with an error, changing nothing**, when the clicked prompt can't be located exactly — a text mismatch, or a renewed session whose current transcript can't yet be lined up with the live bubbles. The CLI's local-command caveat line renders no bubble. A fork of a **persistent** session is itself persistent — the new `sessionId` is marked at spawn — and a fork of a **normal** session is normal and archived on its own exit; the source is untouched and keeps its kind. A fork also inherits its source's title with the fork prefix (see **Rename session**).
  - **Rewind is idle-only:** `↶` is disabled during a running turn and the server 409s it.
  - **Fork works mid-turn:** `⑂` stays enabled on every current-segment bubble during a running turn, including the prompt that opened it and a steer; the source keeps running and nothing of the open turn is copied. A prompt whose line hasn't reached the transcript yet is waited for briefly while the turn runs (`FORK_PERSIST_WAIT_MS`, `src/instances.ts`; once the turn has ended, at once), then refused with a named reason (`PROMPT_NOT_PERSISTED` — a steer is written only when the turn picks it up; one still queued when the turn ends can be refused for a moment after it, and a retry works). A rotation or restart of the source during that wait refuses `FORK_SOURCE_CHANGED`. Neither refusal writes anything; the error shows the server's message.
  - Each button's enabled state comes from the instance's status through `userActionsForStatus` (`web/src/conversation/model.ts`).
  - **Fork the whole session:** `⋮` → **Fork session…** (grouped with **Prune context…** between separators, directly after it) forks the entire current transcript — the last prompt and its answer included — into a new session after a "Fork this session?" confirm, then selects it. The original is left intact.
    - Idle-only: disabled mid-turn with a between-turns title, and the server 409s it (mid-turn, fork from a bubble's `⑂`). Disabled with no `sessionId`.
    - Enabled while a plan or question awaits; the fork's transcript carries the same pending ask.
    - Nothing is prefilled in the new composer. Otherwise it lands like a bubble fork: same project/worktree, mode, effort, thinking, backend + model + context window, `persistent`, and the `fork: <title>` title.
    - Live sessions only, like every `⋮` session item.
  - Rewinding **to the first user message** is special-cased: the prefix holds no conversation (only the CLI's leading records — `queue-operation`, `ai-title`, a renewed segment's `mode`), so the orchestrator deletes the jsonl entirely and respawns with `--session-id <sid>` (not `--resume`, which the CLI rejects on a file with no conversation).
  - A rewind whose relaunch fails is reported by the `rewind failed: …` alert (the transcript is already rewound); a normal session is then archived, a persistent one left stopped and resumable.
  - **At a renewal divider:** the `── Context renewed ──` divider carries its own `↶` **Undo this renewal** and `⑂` **Fork from before this renewal** (not in a sub-agent panel; enabled by the same `userActionsForStatus` rule — undo idle-only, fork idle or mid-turn).
    - **Undo** is offered only on the divider directly above the current context (a newer renewal or prune moves it); the server refuses an older one (`RENEWAL_NOT_LATEST`). An undo that fails before it lands leaves the earlier context's transcript exactly as it was and brings the current context back. After a destructive confirm the session goes back to the conversation before the renewal request, as if the renewal had failed: same `sessionId`, the earlier context live again (un-archived, persistent exactly when the session is), and the next prompt continues from there.
    - **Fork** works on every renewal divider: a new session starts from the conversation before that renewal's request; the original is untouched. The fork holds that one context, so its scroll-back stops there.
    - **The cut:** before the prompt that opened the turn in which the session called `renew_session` on itself (`renewalCut`, `src/renewalBoundary.ts`) — a declined earlier request and its answer survive; a steer in that turn or a prompt sent while the renewal was deferred goes with it. A conductor's `renew_session` aimed at a worker does not count. A renewal issued without such a call in the transcript (from `run_code`) cuts before the last turn opener. A **typed `/clear`** (no handoff summary anywhere in the new context, even after a prompt that landed before it) has no cut: the earlier context comes back whole.
    - **Discarded:** everything after the renewal — every later context's transcript and sub-agent dirs are deleted. Nothing outside the transcript is reverted: file edits, commits, messages to other sessions, and a `rotation_complete` already delivered to the conductor stand.
    - Nothing is prefilled in either composer (the dropped prompt is the renewal request).
    - A refusal toasts the server's message (`Undo renewal failed` / `Fork failed`) and changes nothing — e.g. the earlier context's transcript was deleted (`PRE_RENEWAL_GONE`).

- **Prune** — `⋮` menu's `🪒 Prune` shrinks a session's context **deterministically and at zero token cost**: no LLM pass, no `/compact`. It rewrites a *copy* of the jsonl under a fresh **backing** id, replacing fat block content with size stubs, archives the original (still resumable), and respawns the **same instance** against the pruned file. The session's public `sessionId` does not move, so every reference to it stays valid. The session comes back **idle** — unlike `renew_session`, nothing is seeded as a first turn. Idle-only (the button is disabled mid-turn; the endpoint 409s). It sits with **Fork session…** in its own `⋮` group (see **Rewind & fork**).
  - **Controls.** A slider over turn boundaries (`cutTurnIndex`, the same pure-user-prompt index space rewind/fork anchor on, so the cut can never land between a `tool_use` and its `tool_result`); its range is `0…turnCount`, so a full prune (newest turn included) is reachable, but the slider starts at `defaultCut` (`web/src/features/dialogs/pruneMath.ts`): about 90% of the turns, never the newest — shedding the newest turn is a deliberate drag to the far right. Plus two tickboxes: **prune all thinking blocks** (global, independent of the slider — thinking staleness is categorical, not temporal) and **minimal tool inputs** (squeeze any string value over 80 chars to a size marker; the default truncate mode keeps the first 500 chars, so a value under ~519 chars shrinks not at all — minimal always saves at least as much). A session with one turn is prunable (only `turnCount === 0` is refused).
  - **What it does in the pruned region.** Tool outputs → `[pruned: 12.4 KB]`. Tool input string values → truncated or squeezed; **path keys (`file_path`/`notebook_path`) and the input's key set are never altered** (see components/sessions.md → Prune for why this is load-bearing). Thinking text → `[pruned: thinking]`, signature retained, exempt on an assistant entry holding an unresolved `tool_use`. **Encrypted thinking** (empty `thinking` text + a `signature` — how Opus 5.x, Sonnet 5 and Fable models store it) is never rewritten: there is no text to remove, though it is in context. `text` blocks are never touched. An image block — inside a tool output, or pasted into a user message — is replaced by a stub naming its media type and, when its header can be read, its dimensions and decoded size, e.g. `[pruned: image/png 1280×800 (48.2 KB)]`. An unreadable base64 image's stub names the decoded size alone (`[pruned: image/png (20 B)]`), and a non-base64 image's stub names its source kind (`[pruned: image (url)]`, `(file)`, `(no source)`); a tool output mixing text and images names both (`[pruned: 1.2 KB; image/png 1280×800 (48.2 KB)]`). A pasted image's saving counts under **Tool outputs**. Images in kept turns are untouched. A stub that would be *larger* than what it replaces **by the estimate** is skipped, so pruning never inflates the estimated context. That includes an icon-sized image, whose stub costs more than the image. An image whose size can't be read is costed at the per-image cap (see Savings estimate), so it is always stubbed, even when its real cost is tiny.
  - **Exempt tools** (`isPruneExemptTool`, sessionPrune.ts) — a `tool_use` **and the `tool_result` answering it** are copied verbatim in every mode, at any cut, for: **`AskUserQuestion`** (the question card is rebuilt from `input.questions` on replay and the server pairs the following user echo with the card by matching the question text, and the picks are parsed back from that echo's option labels — squeezing either strands the human with an unreadable question and no answer on the card) and **core conductor MCP calls**, i.e. `mcp__code-conductor__<tool>` (the orchestration record: what was spawned, approved, merged, filed). Exempt by *namespace*, so a core tool added later is exempt by default. Three things stay prunable: **`mcp__code-conductor__project_read`**, **`mcp__code-conductor__project_bash`** and **`mcp__code-conductor__system_bash`** (bulk file/command output — exactly what Prune exists to shed; a hardcoded denylist, not user-configurable), **plugin-namespaced** tools (`mcp__code-conductor__<plugin>__<tool>` — `code-kanban__*`, `code-hub__*`, and any third-party id such as `acme-tools__*`; what discriminates them is the *further* `__` after the prefix, not the first-party `code-*` naming habit, so matching the prefix alone is not enough), and any foreign MCP server. An *orphaned* `tool_result` (no `tool_use` in context ⇒ no name) stays prunable. Thinking on an assistant entry that carries an exempt `tool_use` is unaffected — it follows the normal thinking rules.
  - **Never deletes an entry or a block** — only block content is replaced. That is what keeps the `parentUuid` chain and the `tool_use`/`tool_result` pairing invariant intact with no relinking.
  - **Read-before-edit re-arms.** A pruned Read/Write result drops the CLI's cached file-state entry, so the model must re-Read before editing that file. At a full cut (`cutTurnIndex === turnCount`, or `prune_session({keepLatestTurns: 0})`) that includes a file the worker read moments ago, so it owes a re-Read before its very next edit. Deliberate: the guard exists to guarantee current file content is in context, and pruning is what removes it. Costs one refused Edit per file, self-corrected by a Read.
  - **Sidechains are untouched** and stay readable — sub-agent transcripts are copied to the new `sessionId` alongside the jsonl.
  - **Fails safe.** A throw partway through (the cut is out of range, the copy fails) respawns the instance against the ORIGINAL, unpruned session rather than leaving it with a dead subprocess — the original jsonl is intact by construction. A prompt arriving while a prune or rewind is in flight is refused with 409 rather than racing the transform, for the whole kill→respawn. A fork never refuses prompts: it copies from one complete-line read of the transcript, and a prompt's lines land after the forked-at prompt's, so they cannot reach the copy.
  - **Savings estimate** is computed over **in-context entries only**: sidechain entries, the disk-only `toolUseResult` sidecar, and everything before the session's **last compaction** (`compact_boundary`) are excluded (counting them would report a saving while the model's real context barely moves). Each block kind has its own measured chars-per-token ratio (`TOKEN_CHARS`, sessionPrune.ts — tool output is denser than prose), and encrypted thinking is sized from its signature length. An **image** block in a prunable user or assistant line is costed by Anthropic's patch rule — `⌈w/28⌉×⌈h/28⌉` after the high-res-tier downscale, capped at `IMAGE_MAX_TOKENS` (`src/imageCost.ts`) — from the dimensions in its own header, never by a `TOKEN_CHARS` ratio; an image whose size can't be read is costed at that cap, never at its base64 length. An image carried inside an `attachment` line (e.g. a `queued_command` prompt) is never stubbed and not estimated. Every estimated figure is then scaled by a **per-session calibration factor** measured from the session's own recorded API usage (`usageCalibration`, see components/sessions.md → `src/sessionPrune.ts`); stretches of the session holding images are left out of that measurement, and an image's saving is **never scaled** by it — its cost is real already. The known bias is a slight over-report of the API-measured drop, larger on a non-Claude backend. The dialog's hint says **Calibrated against this session's real token usage** or, with too little usage history (factor 1), **Uncalibrated estimate**.
    - **Percentage** is of the **ctx chip's current reading** (`contextTokens`, the same prompt-size sum the chip shows). When the instance holds no reading — right after a prune, after a model switch, on a fresh session — the dialog shows **no percentage**, only that the reading returns after the session's next turn.
    - **Rows**: thinking / tool inputs / tool outputs / estimated total, recomputed client-side from one analysis call. **Thinking** reads `n/a — stored encrypted (~N in context, kept)` when it would save nothing but the session holds encrypted thinking. **Kept — orchestration calls (exempt)** appears only when the selected prefix holds exempt-tool payload (it explains a near-zero tool figure on orchestration-heavy turns); exempt tools contribute zero savings.
    - The preview and the transform share one code path and one factor, and a test asserts they agree exactly for every slider/tickbox combination.
  - **Known degradations.** A pruned `Write`'s `input.content` becomes the harness's cached content for that path, so a later on-disk change diffs against the stub in the watched-file attachment. Pruned `Edit` `old_string`/`new_string` shorten the tool-diff rendering (truncate mode keeps the first 500 chars). An image-only user line (a terminal-CLI paste with no text) becomes a text line once its image is stubbed, so in the pruned session it counts as a turn of its own and renders as a user bubble rather than folding into the preceding turn. The ctx chip reads `ctx —` until the first live turn — the jsonl's newest `usage` still reports the pre-prune size, and a known-wrong number is worse than none.
  - **Also reachable from a conductor** — `prune_session` ([MCP interface](mcp.md#mcp-interface)), which spells the cut relatively (`keepLatestTurns`) rather than as this dialog's absolute `cutTurnIndex`.
- **Remote worker refusals you can see (FUSE-union chroot).** Spawning a worker on a non-local project mounts a union filesystem and chroots the CLI into it. Four things surface to the user:
  - **`FUSE_UNAVAILABLE`** — a `501` on the spawn naming the FIRST missing dependency and the package that supplies it (`/dev/fuse`; passwordless `sudo -n`, which is cc's **whole** sudoers requirement — nothing rides through sudo, so a plain `NOPASSWD:` rule with no `SETENV:` tag launches a worker; one of `unshare`/`stat`/`rm`/`mount`/`umount`/`nsenter`/`chroot`/`setpriv`/`fusermount3`; `fusectl` in `/proc/filesystems`; `gcc`; or libfuse3 headers). Refused **before** anything is created: no run directory, no mount, no daemon. cc never installs anything.
  - **A file-tool refusal naming its class.** `Read`/`Write`/`Edit`/`NotebookEdit` on a remote-backed worker are decided from the session's tier table (never by probing the filesystem), and a path the union does not serve to that session is DENIED with a sentence rather than left to answer `-ENOENT` — a model that reads a refusal as file-not-found concludes the file is absent instead of using the channel that works. Four classes, four wordings, and which one a worker gets is the whole information:
    - **excluded** — the system advertises a prefix as excluded from file mirroring. Names the prefix, and points at **Bash**, which execs on the system under no such restriction (`cat` / `sed -i` / `>`).
    - **outside the mirror root** — the path is outside the boundary the system advertises. Names the root, and points at Bash.
    - **a bind mount** (`/proc`, `/sys`, `/dev`) — those are the **orchestrator's own**, bind-mounted in so the CLI works, so a file tool there would answer about the orchestrator's kernel. Points at Bash, which answers the same question about the right one.
    - **host-pinned** (and the session's own hidden scaffolding) — the path is pinned to the **orchestrator's** machine so the local CLI can run. Points at Bash and, uniquely, names **which machine Bash answers from**: the same path exists on both, so a shell on the system returns the system's own file there — the right answer for a question about the system, and explicitly not the orchestrator's copy that was refused. Without that qualifier "use Bash" would send the worker to a real file it would mistake for cc's.

    Every one of them states outright that this is cc refusing to carry the file and **not** the file being absent.
  - **Two MORE refusals, about a specific file rather than about a prefix.** These are per-path and STATEFUL — a path acquires one only by failing during this session — and they are asked only after the four above have already ALLOWED the path, so the count of tier wordings stays four. Both keep the same discipline (cc named as the actor, the act named as a refusal, the file named, an explicit *not the file being absent*, and Bash named with the machine it answers from):
    - **diverged** — an earlier write to that exact file was written locally but could **not** be landed on the system, so this session's copy and the system's have parted. Names the recorded cause, refuses every file tool **except `Read`** — the local copy is intact and still readable, and that is the recovery channel the sentence points at — and tells the worker to inspect the system's own copy with `cat` and land the change with `sed -i` or a `>` redirect **on that machine**. Sticky for the session's life, with one exception: if a later write to that same file **does** land on the system, the divergence is over and the refusal stops — that is the only thing that clears it. It also arrives **as a note on the tool result** when the failure lands after the tool already returned success, which is the only way a post-return failure reaches the worker in band.
    - **over cap** — the file is larger than the system protocol carries per file (`MAX_FILE_BYTES`, 32 MiB). Names the **size and the cap**, refuses `Read` as well (cc never materialised it, so there is nothing to serve), and names the channel that works: a **range** read through Bash — `sed -n`, `head`, `tail` — on the system. Refused before a byte moves.
  - **What a worker can still read on the orchestrator, and one accepted leak.** A short declared list stays reachable to file tools because Bash — which execs on the system — cannot see it at all, so denying it would make it unreachable through every channel at once: this project's **attachments** dir, this session's **own** tmp dir, **cc's built-in plugin root and each enabled plugin's root** (their skills instruct the model to read files under them), **its own remote's `<configDir>/plans`**, where plan mode's `Write` lands, and **`~/.claude/plans`**, where a plan file forwarded from another session lives. Everything else under its own config dir is denied — including its own `projects/` — and so is **every other remote's config directory**, which holds those remotes' transcripts and settings. Everything else under `~/.claude` is denied too, including `~/.claude/projects` — every local session's transcripts. **The accepted residual:** `~/.claude/plans` accumulates other sessions' plan files and cannot be narrowed to "its own" ahead of the write, because the CLI chooses the filename. It is allowed anyway — denying it breaks plan mode outright for every remote-backed worker — and it belongs beside the standing limit that **a chroot is not a security boundary**.
  - **A path nobody pinned is ABSENT to the CLI inside the chroot, not quietly the orchestrator's** — at the default mirror root, which is the project's own path. The union serves the system's tree at the project's own path, the orchestrator's own files at a declared set of pinned prefixes, and **nothing at all** anywhere else — so the CLI reaching an unpinned path gets `-ENOENT` rather than the orchestrator's copy. That is deliberate: one path answering from whichever machine happened to have it is the confusion this whole arrangement removes. **Bash is the channel** — it execs on the system and reaches the system's whole filesystem. Anything the CLI itself genuinely needs is pinned; if something is missing, the session's `events.log` in its run directory names the exact path, and the store-wide `systems/fuse/events.log` keeps it after the session is gone — with the array in `tierTable.ts` to add it to.
  - **The sandbox is the CLI's, not every process in the chroot's.** The shells, hooks and helper subprocesses the CLI spawns — and, before the CLI exists at all, the launch chain that starts it: the chroot'd shell, the privilege-dropper, and the backend launch command a non-Claude backend puts in front of the CLI — are separate processes that were never going to be served the system's files, so **the union subtracts nothing from the orchestrator's own filesystem for them**: wherever the orchestrator has something, they get it — its real contents, its real mode, its real write surface — and they get it at **every** mirror root, not just the default one. That is what lets a shell load its libraries and `rg` run without cc having to pin every tool on the machine. The **system's tree stays closed to them** for reads and writes alike: the remote tier is simply absent from their view of the table, so no such process can name it. The only thing added for them is entry to the CLI's own working directory — each component made traversable, by the orchestrator's own directory where it has one and by an empty traverse-only node where it does not — so a spawn can `cd` there and start at all, and so can the launch chain itself. **A backend launcher's own files are the orchestrator's**, therefore: it reads its configuration and writes its state on the machine it was installed on, and anything it hands the CLI through a file has to sit somewhere both see the same bytes — `$HOME`, the projects root, or another host-pinned prefix. Two consequences worth stating: such a process reaches whatever its uid could already write on the orchestrator at any path cc did not pin (every one is logged by path), and cc's own run directory — which holds the mirror and the control socket — stays hidden from it, because that is the one place the system's bytes live on this machine.
  - **ONLY THE FIRST OF THOSE IS THE DEFAULT MIRROR ROOT'S; THE SECOND HOLDS AT EVERY ROOT.** Where a provider advertises a mirror root **above** the project, the wider slice is remote-tier — so for **the CLI** there is no "nobody pinned it" tier left at all, and the first bullet reads differently: it is served the **system's** answer at an unpinned path rather than `-ENOENT`. For **everything else in the chroot nothing changes**, and that is deliberate: the remote tier is struck from their view whatever its extent, so a wider advertised root cannot take away a single byte of the orchestrator's filesystem from a shell or a helper. A helper that needs a host library cc did not pin still gets it, and the session's `events.log` still records the path — as a `served`/`unmarked-host-served` row, which carries **no pin suggestion**: `pinSuggestionFor` fills those columns only for the marked CLI's own `deny`/`unpinned-fail-closed` rows, because a path that was served needs no repair. The row is still the instrument — it names the path, and the pin list is derived from it by hand. Nothing about the **system's tree** differs between the configurations either: it is closed to every process but the CLI in both. *(Both halves are load-bearing: a wide root that did NOT strike the remote tier from their view would take the orchestrator's filesystem away from helpers, and under one where the mirror root is a strict ancestor of the project path it would also make the working directory unenterable, so every `Bash` call in the session would fail with no output.)*
  - **The wedged-mount report** — where teardown cannot finish, the session's event stream carries a `system`/`stderr` line naming the terminal state, the surviving mountpoints, the daemon pid and the connection minor; the same line goes to the orchestrator log, and the on-disk record is kept so the next boot re-reports it. A wedge is never silent — and a session whose worker, daemon or mount-namespace anchor is still alive **is** a wedge, so cc never discards the record that names a process it left running.
- **Crash recovery** — subprocess death → `crashed`; Resume respawns with `--resume <sid>`, preserving the in-memory event ring + conversation.
- **Session anchor** — `#session=<sid>` URL hash; on reload, auto-resumes by locating the jsonl on disk (worktree-aware) via `GET /api/sessions/:sid/locate`. `--resume` spawn costs zero API tokens until the next prompt. Stale anchors are silently cleared. An anchor naming an **archived** session, or one whose worktree the project no longer has, opens it read-only (the **Ended pane** entry) and keeps the anchor, so a reload opens it the same way. A live session the anchor names always opens, whatever order the instance list and the server's `instances` hints answer in. A session the user picks while the anchor is still being looked up or resumed stands, with its own anchor, and a notification clicked meanwhile opens its own session. Between two of the user's own actions the newest wins, whichever finishes last: a session picked while a notification click, a sidebar resume, a spawn, Conduct or a fork is still opening its session stands; of two notification clicks the later one opens its session; and an earlier action still opens its session when the later one finds nothing to open. Back/forward is not such an action: a notification click still opening its session lands over a Back made meanwhile. Opening a worker from its conductor's workers panel adds a history entry, so Back returns to the conductor and Forward to the worker again; every other selection, a notification click included, replaces the anchor and adds none. Closing the open session (its ×, archiving it, deleting its project) clears an anchor naming it without adding a history entry, so a reload resumes nothing, and once the first instance list has landed, Back or Forward onto an entry naming a session that is no longer listed clears that anchor too.
- **Ended pane** — when the session you are watching loses its instance (a conductor's `kill_instance`, a normal worker exiting), the pane stays in place, read-only: the transcript keeps its position and scroll-back (paging the killed instance's frozen pager by instance id until the server forgets it — then scroll-back simply ends), the composer is disabled with your draft kept, and a banner above it (`EndedBanner`, `data-session-ended`) says the session ended or crashed. Its **Resume** button (un-archive, then resume, as Settings → Archived's Restore) shows only while the session's project lists its worktree, so it disappears once `delete_worktree` lands. The header's Resume, Sync and ⋮ items that address the instance are hidden. Its plan and question cards are read-only. Image attachments load by session (`GET /api/sessions/:sid/attachments/:filename`); one whose file is gone (a deleted worktree's attachments are deleted with it) shows an "attachment unavailable" placeholder. An ended conductor session (`.conduct`) always offers Resume. Archiving the session it shows closes it. Selecting another session or closing it with the UI's own Stop/archive leaves no ended pane. A session opened from Settings → Archived or an anchor shows the same pane, paging `GET /api/sessions/:sid/lineage-events`. State: `appStore.ended` (`web/src/state/app.ts`), set by the instance-list landing in `web/src/app/controller.ts` and by `openEndedSession`.
- **Pristine conductor** — a conductor `🎼 Conduct` starts is **pristine** until its first prompt. The tab that started it shows it and nothing lists it: no Conductors-lens row, needs-you strip entry or conductor-filter option, no row in any other tab, and it is absent from `GET /api/instances` and MCP `list_sessions` / `describe_session`. Its first prompt, from any sender (the composer, a card answer, MCP `send_prompt`), makes it an ordinary conductor. State and rules: [components/store.md](../components/store.md#srcpristinets) → `src/pristine.ts`.
  - **Leaving it** — selecting another session, opening a full-page view, or starting another conductor over it. With a blank composer (whitespace only counts as blank) it is **discarded**: its CLI is stopped and its session record removed, so it reaches neither **Inactive** nor Settings → Archived. With text it is **listed** under that text, one line and capped like any title (`MAX_TITLE_LEN`, `src/sessionTitleText.ts`), and the text stays as its composer draft. A manual rename wins over that title; the first prompt drops it, and the row falls back to the first prompt as for any untitled session.
  - **Reload or closed tab** — with no tab showing it, it waits `PRISTINE_REAP_GRACE_MS` (`src/pristine.ts`), so a reload reopens it from its `#session=` anchor. When the window ends, the draft the composer last synced (debounced like the local draft save) decides, as a leave does. A tab opening its URL shows it too, and it lives while any tab shows it.
  - **A second visit** to one listed under its draft is the same as the first: clearing the composer and leaving **discards it completely, though it was listed**; editing the draft and leaving retitles it; leaving it unchanged keeps the title. It stays listed throughout.
  - **Stopping it** (header Terminate, a crash) also discards it: nothing is archived.
  - **Changing its model** — a Change model that restarts the CLI (every pair but Claude→Claude) keeps it open as the same session, still pristine (and still unlisted when it was hidden), now on the new model. A reconnect during the switch shows its current state once the socket is back. A switch that ends with it stopped discards it like any stop.
  - **Known limitation:** a restart does not carry a pristine conductor, listed or not. It has no transcript to resume, so it and its draft title are gone after the restart.
- **Startup session cleanup** — at every boot, before any session is spawned, cc drops each session record (title, mode, summaries and every other fact on it) none of whose Claude session ids — current, renewed/pruned-away or tombstoned — has a transcript left on this machine (`~/.claude/projects/*/` or any per-remote config dir under `<store>/claude-config/`). Such a session already lists nowhere and cannot be resumed. The store's pre-image is written to `<store>/sessions.json.startup.bak` first, on every boot that finds a store file (none is written when `sessions.json` is absent), overwriting the previous one. Sessions named in `pending-resume.json` or `running-sessions.json` (and their listed workers), sessions with a pending resume notice (and its workers), and records newer than `CLEANUP_GRACE_MS` (`src/sessionCleanup.ts`) are kept, and nothing is removed when the transcript scan fails, finds no transcript at all, or would remove every record in the store (a wrong `HOME` / `CLAUDE_CONFIG_DIR` scans as empty, and the pass warns instead of wiping). Transcripts, worktrees and the cost/playbook logs are not touched. Internals: [components/store.md](../components/store.md#srcsessioncleanupts) → `src/sessionCleanup.ts`.

## Spawn options
- **Mode** — `plan` (read-only, propose then `ExitPlanMode`) or `code` (full power, CLI's `bypassPermissions`). CLI's `default` / `acceptEdits` are not exposed: in `stream-json --print` (no SDK `canUseTool` callback) they auto-deny tool calls and the only recovery is forcing the model to regenerate the entire tool input.
- **Effort** — `low` / `medium` / `high` / `xhigh` / `max` (`EFFORT_LEVELS`, `src/effortLevels.ts`). **A separate axis from the tier/model binding** — how hard it reasons, not which model. The dialog's Effort select opens on `Default (<level>)`, which sends no `effort` and lets the server resolve the selected **tier's** default (set per row in Settings → Models; the Conduct button resolves the **Conductor role's** instead). Picking a level overrides it for that one spawn. A **resume** names no tier/role, so a sidebar/anchor resume falls back to `DEFAULT_EFFORT` (`high`), while a respawn or a post-restart resume keeps the level the session was already running at. Precedence + per-path table: [models.md](../models.md#default-effort). A running session's level can be moved without a restart — see **Change effort** above.
- **Thinking** — `adaptive` (default) / `enabled` / `disabled`.
- **Model** — pick a capability tier (Fast / Balanced / Powerful / Frontier; a tier hidden if disabled in Settings → Models). There is no empty option — the dialog renders one card per tier and pre-selects the **default spawn tier** (Settings → Models); the dialog POSTs only the tier name — no `model`/`backend` — and the server resolves it against that row's **current** binding. Each tier binds to a **backend + model**; the backend is a row in the user-managed **backend registry** (`claude` runs the CLI directly, any other row wraps it via a command template — Settings → Backends). A tier on a non-Claude backend resolves straight to its model id (no version choice) and its declared native context window drives both the context-usage bar and the cc-managed `CLAUDE_CODE_AUTO_COMPACT_WINDOW` + `CLAUDE_CODE_MAX_CONTEXT_TOKENS` at spawn. Every model — Claude or not — has exactly one native window, so there is no window picker. MCP `spawn_instance` also accepts a **role** name — built-in, user-custom, or plugin-owned (`<plugin-id>/<slug>`) — a legacy family alias (`opus`/`sonnet`/`haiku`/`fable`, → that family's default version), or a full Claude model id; **omitting `model` on a fresh spawn resolves the default spawn tier's binding** — this tool has no `tier`/`role` argument, so that is always the row it lands on, whereas `POST /api/instances` applies the same never-the-account-default rule but prefers a named `role`, then a named `tier` ([models.md](../models.md#same-row)). A resume with no `model` recovers the model **and backend** it last ran. Full contract — registry, custom models, tier/role binding + dead-binding revert, context-window policy: [models.md](../models.md).
- **Persistent session** — a session is **normal** unless it is persistent. A normal session archives on exit (jsonl kept and stays resumable, sibling `subagents/` dir deleted), drops itself from the sidebar's Sessions list on exit/crash (no ghost row to clean up by hand — it surfaces under Archived instead), and skips `last-prompt`/`permission-mode` metadata appends during the run. A **persistent** session stays listed when it ends, stopped and resumable, and writes that metadata. The header shows no badge for either (the sidebar row's warm normal styling, the Persistent group and `↑` do); a live normal row carries the `↑` `Make persistent` button in both sidebar lenses (in the Conductors lens: live normal conductor rows and live normal worker rows). The New Session dialog's **Persistent session** box is unticked for a fresh spawn and ticked for a spawn into an existing worktree (the worktree row's ⋮ → **New session in this worktree**); the spawn sends `persistent: true` only when it is ticked and omits `persistent` otherwise. Archiving and restoring keep a session's kind, so a restored session resumes as what it was. Resuming a session cc has no record of (a `claude` session run by hand outside cc) brings it up as a normal session; `↑` makes it persistent.
- **Debug mode** — mirrors raw CLI traffic (`claude-stdin.jsonl`, `claude-stdout.jsonl`, `claude-stderr.log`, `meta.json`) to `<store>/projects/<p>/[worktrees/<wt>/]debug/<instance-id>/`. Append-mode, survives session end. The header shows no badge for it: while the session is alive the ⋮ item reads `🐛 capturing` (disabled; the capture directory is in its tooltip), and a crashed or exited session shows nothing. Spawn calls that omit `debug` fall back to the persisted **debug-by-default** setting (Settings → Models → Debug capture fieldset, `spawn.debugByDefault` in `settings.json`); an explicit `debug` on the spawn call always wins. The New Session dialog's checkbox is pre-checked from this default when it opens, and always sends its literal checked state (never omitted) so unchecking it reliably opts a single session out even when the default is on.

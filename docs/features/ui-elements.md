# Features: UI elements

## UI elements
- **Text fields on touch screens** — on `(pointer: coarse)` every `Input`, `Textarea`, the composer and the sidebar filter are 16px (`TOUCH_FIELD_TEXT` in `web/src/lib/textEntry.ts`), so iOS does not zoom the page on focus; a caller's smaller size class cannot override it and it beats the `md:` size on a wide touch screen. The prose fields (composer, plan feedback, the question card's answer/note box, **Ask about this session**, rename title) render through `ProseInput` / `ProseTextarea` (`web/src/components/ui/prose-field.tsx`): each has a visually hidden associated `<label>` ("Message", "Plan feedback", "Answer", "Question about this session", "Session title") as its sole accessible name, no `name` attribute, and `PROSE_FIELD_PROPS` (`autocomplete=off`, autocorrect on, sentence capitalization, spellcheck on). `autocomplete=off` alone does not stop Safari's contact AutoFill; the associated label is the defence, and only a device check confirms the "AutoFill Contact" bar is gone. Path, id, name, search, sign-in and convention-editor fields do not. While a soft keyboard covers part of the page the app shell takes the visible height and moves with Safari's keyboard pan (`web/src/app/viewport.ts`), so the session header and the composer stay on screen above the keyboard.
- **Modal focus** — every dialog and the phone navigation drawer opens from app state, not a Radix Trigger, so focus handling is the app's own (`web/src/lib/modalFocus.ts`). Closing any of them returns focus to the control it was opened from: a menu item stands for its menu's trigger (⋮ `Session actions`, `Project actions`), and a control inside the phone drawer that the opening closed stands for the drawer's `Open sidebar`. Focus is not moved when something else already took it (a selection focusing the prompt bar). `Dialog` and `Sheet` in `web/src/components/ui/` apply this to every modal. Opened by mouse, tap or keyboard, a modal has focus inside from the moment it opens: on the control its markup auto-focuses (a confirm, its confirm button), else its first control. The ⋮ menu's Summarize, Statistics and Prune dialogs and the drawer open with focus on the dialog itself, no control preselected (`focusContent`). On a touch device (`(hover: none)`, `TOUCH_QUERY` in `web/src/lib/textEntry.ts`) a modal whose opening target is a text field opens on the dialog itself instead, so no soft keyboard pops; a tap on the field or Tab reaches it. Tab and Shift+Tab stay inside an open modal, including while the menu or drawer the opening closed is still leaving.
- **Dialog loading** — the dialogs' code is a separate chunk (`web/src/features/dialogs/LazyDialogsHost.tsx`) requested as the page boots. A dialog opened before it lands opens once it lands, with the same focus handling, and closing it returns focus to the control it was opened from. If the chunk cannot load, opening any dialog shows an error toast asking for a page reload and the dialog stays closed.
- **Task panel** — strip above composer mirroring `TaskCreate`/`TaskUpdate`. Groups into batches: while at least one task is pending/in-progress, the whole batch (including its ✓s) stays. Panel hides only when *all* batches are fully completed; a new task post-batch drops the historical ✓s and starts fresh. The CLI offers the task tools by default only on its own older model list, so on newer models the panel stays empty unless **Settings → Models → Task tools** is on.
- **Turn indicator** — a thin row between the task panel and the composer (`TurnIndicator` in `web/src/features/session/SessionPanels.tsx`). While the active instance is in `turn` status it shows a pulsing `Working…` (`Stopping at the next safe point…`, also pulsing, once an interrupt is asked) with the **Interrupt** / **Interrupt now** buttons; under `prefers-reduced-motion` it stays visible but stops animating (`web/src/features/session/turnFooter.test.tsx`, `web/e2e/reduced-motion.shared.ts`). Once idle, the same row shows a live `Last response Xm ago` label (`Instance.lastResponseAt`, stamped on `turn_end` and surfaced via `summary()`; formatted with `formatAgo()` from `web/src/lib/time.ts`, re-rendered every 15s) — hidden entirely for a session that hasn't completed a turn yet, rather than showing a "never" label. The combined ctx + rate-limit chip sits in the composer (`UsageChip` in `web/src/features/session/UsageChip.tsx`).
- **Combined context-usage + rate-limit chip** — `ctx N% · 245k/1M` pinned at the footer right (the turn-indicator footer).
  `N%` = latest `message_start`'s `input_tokens + cache_read_input_tokens + cache_creation_input_tokens` over the model's context window.
  Updates **live mid-turn** (each agent-loop step fires a `message_start`).
  Colour-graded green/amber/red at 50%/80%.
  Survives a re-subscribe whose snapshot tail carries no `message_start` — the normal case for a turn whose final text block is longer than the tail (a backend answering in one long unbroken block), where the tail's quiescent snap cuts past every one of them: the reading is seeded from the snapshot's `lastContextUsage` field instead, so a reload mid-session shows the real figure rather than `ctx —`.
  Populated on a **resumed** session too, before it takes any live turn: jsonl replay emits no `message_start` of its own, so `loadHistory` replays the newest assistant line's own `usage` as one synthetic `message_start` (see [protocol/ws-events.md](../protocol/ws-events.md)) — any resume-bearing spawn (see [components/instances.md](../components/instances.md#srcinstancests)) shows its real fill immediately rather than `ctx —` until the next turn.
  The same chip carries the **rate-limit** half — live bucket / utilization / reset-time, with an OVERAGE badge when `isUsingOverage` — and tapping opens the usage popover (session totals: turns, duration, cost, uncached input, output, cache reads + hit ratio, cache creation — once any summed turn carried a cache estimate (see **Cost dashboard**), the uncached-input and cache-reads rows read `≈ … (est.)`; plus account rate-limit windows — each with its reset, the 5-hour one as a time of day and the 7-day ones (Fable included) with weekday, date and time (`formatResetTime` / `formatResetDateTime` in `shared/usage.ts`) — plus a **7-day Fable** line sourced from the `/api/usage` response's `limits` array — rendered only when an entry with `scope.model.display_name === 'Fable'` is present, so subscriptions without Fable access show nothing).
  The denominator is the instance summary's **`contextWindowTokens`** — resolved server-side once from `{backend, exact model}` (see [models.md](../models.md)) and rendered verbatim.
  The client derives nothing: the API reports a dated snapshot id in `message_start` (not the catalog id, and without any `[1m]` build tag the session launched with) and a substitution model's id is an opaque registry key, so any client-side table would be guessing.
  A backend whose gateway reports an all-zero usage block on **every** `message_start` never renders a false `ctx 0% · 0/200k` — zero is not a measurement, so the parser drops the block.
  It instead falls back to that message's **`message_delta.usage`**, which on such a backend carries the real per-call prompt size, and the chip updates once per agent-loop step — at the **end** of each step rather than its start, since `message_delta` closes the call that `message_start` opens (both paths in [protocol/ws-events.md](../protocol/ws-events.md)).
  So a fresh session reads `ctx —` for the duration of its first call, and each later **mid-call** reading is one call behind.
  A backend that reports the real numbers only on the final `result` and in the jsonl — nothing usable on either live frame — still reads **`ctx —`**, and on a **resumed** session holds the last jsonl-measured size instead.
  That held reading is **frozen**, by design: no live frame from such a backend is a measurement, and the reading is only re-seeded when the session is relaunched against its jsonl (any resume-bearing spawn — see [components/instances.md](../components/instances.md#srcinstancests)), so the figure does not advance as context grows.
  A fresh (never-resumed) session on *that* backend reads `ctx —` for its whole life.
  A `message_delta`-fed session that is *resumed* shows its real fill before its first live turn: the CLI persists each call's real usage on its assistant lines (`tests/fixtures/nonclaude-openrouter.transcript.jsonl`), so the replay seed carries it.
  A **mid-session model switch** — the CLI switching interactively, or the ⋮ **Change model** picker — drops the reading to **`ctx —`** until the next usage-bearing frame, rather than re-rendering the outgoing model's used-token count against the incoming model's window (a full Haiku 4.5 session at `ctx 95% · 190k/200k` would otherwise re-read `ctx 19% · 190k/1.0M` on a 1M model).
  Same rule as Prune's *Known degradations* above: a known-wrong number is worse than none.
  No blank is rendered when the switching frame itself carries a measurement — that frame re-latches in the same step.
  Unlike the server's `contextTokens` (summary, turn footer, MCP), the chip **keeps** its reading across a compaction and a `/clear` rotation until the next `message_start` re-measures (a tab that reloads in that window rebuilds from its snapshot tail's last `message_start`, or reads `ctx —` when the tail holds none — the snapshot's `lastContextUsage` field is cleared with the server reading).
  When capacity is unknown the chip reads **`ctx —`** (a live model switch to an unrecognised model keeps the previous known capacity instead — see [models.md](../models.md) → context window; a session that *starts* on an unknown model still reads unknown) rather than a fabricated percentage, and its tooltip names the measured used-token count with the capacity marked unknown (`Context: 250,000 tokens used (capacity unknown)`) instead of a `used/capacity` pair.
  The popover's **Cost** row shows `—` instead of a dollar figure for a session on a non-Claude backend (`inst.backend !== 'claude'`) — same reason as the costs dashboard: the CLI's `total_cost_usd` is Anthropic list pricing, meaningless against another provider's model.
- **Cost dashboard** — a full-page view at `#costs`, opened from **Costs** in the sidebar `≡` menu (`CostsView` in `web/src/features/views/CostsView.tsx`, in the shared `ViewShell`) breaking down spend from the append-only per-turn cost log (`<store>/costs.jsonl`, written by `src/costTracking.ts` on every `turn_end`).
  Shows total spend + turn count, an expandable **By project** table (per-project cost/turns/**sessions**/**cache misses**/**LLM time**/**walltime**, drill-down to per-model tokens: input / output / cache-create / cache-read / turns / **sessions** / **cache misses** / **LLM time** / **walltime**), a **By model** table (same columns), and a **Daily spend** bar trend.
  A **Cost | Tokens** switch above the top section (a `Tabs` segmented control held in `CostsView`: not persisted, survives Refresh) swaps the stat tiles and chart; the tables never change.
  Tokens mode shows **Total tokens / Input / Output / Cache input** tiles (cache input = cache read + cache create, the read/create split in its sub-line) summed over the days with token data (Total tokens' sub-line reads `across N days with token data`; with no such day every tile reads `—` and the Total tokens / Cache input sub-lines are omitted; the page subtitle becomes `Token use by project, model and day`), and a **Daily tokens** stacked bar chart (Cache input, Input, Output bottom→top, summed across all models and projects, with a legend and a per-series tooltip with a Total row).
  A day with no token data (`tokens_known: false`) renders no bar and `—`, never 0; a day with `tokens_estimated` marks its Input and Cache input `≈` in the tooltip, the column's accessible name and the screen-reader table, as the tiles do.
  Counts from 1B up format as `N.NB`.
  The **Cache misses** column on each table is a plain count of that model's/project's rows with the persisted `cache_miss` flag `=== true`; the **Sessions** column is the count of distinct `sessionId`s among that model's/project's rows (rows with no `sessionId` aren't counted); **LLM time** / **walltime** sum the persisted per-turn `duration_api_ms` / `duration_ms` (pure inference time vs. total turn walltime; formatted via `formatDuration`, legacy rows contribute 0). turns on a non-Claude backend omit `cost_usd` entirely — the CLI's `total_cost_usd` is Anthropic list pricing, meaningless against another provider's model — so those rows contribute $0 to every cost aggregate (the cost fix is going-forward only, so non-Claude rows written before it may still carry a bogus nonzero cost).
  Token columns sum each turn's `result.usage`, on every backend.
  A turn whose `result` carried no `usage` omits the four **token** fields (`message_start` is a non-summable context snapshot, so persisting 0 would be fabricated data), and a non-Claude row whose four token fields are all 0 (a proxy reporting all-zero usage) is read as carrying none; a model/project with only such rows is marked `tokens_known: false` and its **input / output / cache-create / cache-read** columns render `—` (not 0), duration/turns/sessions still tracking normally, while a mixed model/project keeps the real totals of its other rows.
  **Estimated cache reads:** a non-Claude backend whose calls report no cache read counts every call's whole context as input.
  For such a turn the server re-splits the reported input into uncached input + an estimated cache read (`src/cacheEstimate.ts`; the two still sum to the reported input), and the row carries `cache_estimated: true`.
  A model/project with any such row is `tokens_estimated: true`, and its **Input** and **Cache read** cells render `≈` with an "estimated" tooltip and accessible name.
  Cache creation is never estimated, and rows written before the estimate existed are not back-estimated.
  Backed by `GET /api/costs/summary`; shows a "no cost data recorded yet" empty state until the first turn lands.
- **Session statistics panel** — the in-session **⋮** overflow menu's **Statistics** item opens a dialog (`StatsDialog` in `web/src/features/dialogs/SessionDialogs.tsx`) showing the active session's **cost / LLM time / turn walltime**, in two columns: **This session** (its rows alone) and **Incl. N workers** (rolled up over the conductor→worker `parentSessionId` tree, recursive, cycle-guarded). The rolled column only appears when the session spawned workers; otherwise a "No worker sessions were spawned from this session." note shows. Gated to live sessions with a `sessionId` (hidden/disabled like Rename). Backed by `GET /api/costs/session/:sessionId`. Distinct from the usage chip (a live context/rate gauge) — this is post-hoc spend/timing. The dialog also carries the **Show mid-turn statistics** box that reveals the active session's per-call usage lines (see **Per-call usage line**).
  - **Cache-miss detection** is **cross-turn**, so it catches *partial* (minority) evictions the old stateless rule missed.
    Captured live in `src/instances.ts`, it compares this turn's **first**-request `cache_read` (`read_N`, pre-tool-call) against the **previous** turn's **last**-request full prefix (`P = cache_read + cache_creation`, the fully-accumulated cacheable prefix — cache_read accumulates across a turn's tool-call iterations, so the first request is used for read_N and the last for P).
    A miss is flagged when `read_N < P − tolerance` (`tolerance = max(1024, 1% of P)`): this turn served less of the prefix than was demonstrably cached last turn ⇒ an eviction, full or partial.
    A warm continuation reads exactly `P` (drop 0) and is never flagged.
    **Turn 1** (no prior `P`) and the turn after a **compaction / model switch / rewind** fall back to the old stateless `creation > read` rule, which still flags a genuinely cold prefix (cold start, expiry, resume, cold rewind).
    **Guards:** compaction (the `compaction` event), model switch (`_trackModel`), and rewind/respawn (`_wipeForResume`) legitimately shrink the prefix, so each sets a `_prefixBaselineInvalid` flag consumed on the next turn's first request — the cross-turn rule is skipped there and `P` is re-established fresh, preventing false positives.
    **Known limitation:** a miss on a request *after* the first (e.g. a turn outliving the ~1h cache TTL) isn't caught — detection is first-request-only.
    The verdict + evidence persist on each row (`cache_miss`, `first_req_cache_read`, `first_req_cache_creation`, and `first_req_evicted` = the `P − read_N` estimate on the cross-turn path), and the dashboard's **Cache misses** column counts the flag.
    On every detected miss an informational in-session notice appears in that session's conversation (a `SystemBlock`, same surface as the overage/rate-limit notice, no action): the cross-turn path shows `♻ ~<evicted> tokens evicted (<read> served of <P> cached).`, the fallback path `♻ <creation> tokens written to cache, <read> served.`.
    Rows written before this feature are backfilled once by migration 0014 using the legacy session-relative token-spike heuristic (`cache_creation_tokens >= max(50000, 4× session median)`), so historical rows are heuristic while new rows are decisive.
- **Composer** — Enter sends, Shift+Enter newlines. With whisper installed, **Alt+Enter** (Option+Return on macOS) dictates instead of sending (see **Voice dictation**); without whisper it sends, as Enter does. Placeholder reflects state ("Agent is working · type to steer the running turn", "The session is not running · resume it to continue", etc.). Messages typed during a running turn steer it live — not queued — and carry `MID_TURN_NOTE` (`src/instances.ts`), telling the model the message was composed while it kept working; on a model that cannot take a mid-turn injection the message arrives as a fresh turn after a block-edge stop, carrying `POST_STOP_STEER_NOTE` instead, which adds that the turn was cut off ([protocol/subprocess.md](../protocol/subprocess.md#subprocess-protocol)'s `user` row). Attachments via `+` button, paste, or drag-and-drop (per-file cap `MAX_ATTACHMENT_BYTES` in `web/src/features/composer/Composer.tsx`). Saved to `<store>/projects/<p>/[worktrees/<wt>/]attachments/<timestamp>-<name>` and referenced via `` Attached file: `<abs-path>` `` text blocks — no inline base64, Claude `Read`s on demand. Project/worktree dirs stay clean (no `.gitignore` needed). User-bubble thumbnails: live echoes paint from in-memory base64, replays fetch via `GET /api/instances/:id/attachments/<filename>`.
  - **Worker identity.** A conducted worker whose owner is known (its direct spawner when that is a live section lead, otherwise the root conductor in `rootSessionId`) draws the composer's border and focus ring in the owner's `conductorColor` (`data-owner=<owner sessionId>`) and words the placeholder `Message <worker> · worker of <label>…` (mid-turn: `Agent is working · type to steer <worker> (worker of <label>)`). `<label>` is `ownerLabel` (`shared/conductors.ts`), so an owner that is not a conductor reads by its own title. A conducted worker with no known owner reads `Message <worker> · conducted worker…`, uncoloured. Top-level conductors and hand-spawned sessions are unchanged; a section lead reads as its lead's worker. A conducted worker's owner is its direct spawner (`callerInstanceId`) when that is a live section lead, otherwise the root conductor (`rootSessionId`). Logic: `workerOwnerOf` in `web/src/features/session/workerOwner.ts` and `composerPlaceholder` in `web/src/features/composer/Composer.tsx`.
  - **First-send check.** The first send from a worker's own composer (owned workers only) shows a bar directly above the message box instead of sending, naming the worker's owner, with two options: **Send to worker** (acks, then sends) and **Send to conductor** (sends the text and attachments to the owner, clears the box and this worker's draft, then opens the owner; no ack). It covers every path through the composer's submit: the Send button, Enter, a key-hold release on Send, queue mode and steering a running turn. It does not cover plan-approval and question-card answers (they send their own `prompt` frame) or the plugin bridge's `sendPrompt`. While it is open Enter in the box does nothing, editing keeps it open, Escape (in the box, or on one of its buttons, which returns focus to the box) dismisses it with the text kept; opening it puts focus in the box (from the Send button too), and switching session drops it. **Send to conductor** goes through `sendPrompt` like typing in the owner's composer: an idle or mid-turn owner (`promptSendable`) takes it, a steer in the mid-turn case; with no live owner instance, a spawning or model-switching owner, or one stopped for overage, the option is disabled and states why (`ownerSendBlock`), and the text stays in the box. The ack is per browser: `localStorage` key `code-conductor:worker-send-ack`, a JSON array of worker sessionIds, most recent last, capped at `ACK_CAP` (`web/src/features/composer/workerSendAck.ts`), no expiry; without storage it is held in memory for the page. An owner of unknown identity gets no check.
  - **Per-session drafts** — each session keeps its own composer text, keyed by `sessionId` (so it survives resume / crash / renew) and stored under `code-conductor:draft:<sessionId>` in `localStorage`: it survives a reload and a switch away and back. The stored draft is text plus the dictated-text flag, so a restored dictated draft still sends with its `<transcribed>` tag. Pending attachments are per session **in memory only**: a switch hides them and switching back restores them with their previews, a reload drops them, and a send ships and clears only the showing session's list; stopped and archived sessions keep theirs until reload; leaving the session view (Settings or another full-page view) and coming back keeps every list, a spawning instance's included; attachments added while no session is showing (an instance still spawning) are discarded, previews released, when a session is selected. A dictation started in one session is appended to that session's draft (with its `<transcribed>` flag) even when the user has switched away before it finishes; the one mic still shows its recording / transcribing state in whichever session is showing. Saved ~`DRAFT_SAVE_DEBOUNCE_MS` after typing stops and immediately on switch-away, `pagehide`, and tab hidden; cleared the instant a prompt is sent. Leaving the session view (Settings or another full-page view) also writes a pending draft at once. Restoring a draft never focuses the box by itself (a user-initiated selection focuses it separately: see Prompt focus on select under Sessions & instances). Drafts older than `DRAFT_MAX_AGE_MS` (or malformed) are pruned once at page load — age is the only prune signal, since an archived session can be resumed. If `localStorage` is unavailable or full, drafts still stay per session in memory until reload. Logic: `web/src/features/composer/drafts.ts`, wired in `Composer.tsx` beside it.
- **Voice dictation** — hidden entirely (no mic, no Settings → Voice group, no 🔊) on a platform without the `voice` capability; likewise Settings → Systems and the New/Adopt **System** pickers without `remoteSystems` ([components/platform.md](../components/platform.md#srcplatform) → `src/platform/`). When the host's capabilities cannot be read (`GET /api/health` fails), Settings loads every group — a route the host lacks answers with its refusal — and the next open retries. No separate mic button; dictation is folded into the **Send** button (WhatsApp-style). Two modes, both reuse the same `MediaRecorder` → `POST /api/transcribe` pipeline:
  - **Empty composer** (whisper installed): Send button becomes a mic (neutral styling). Tap to start recording (red pulse); tap again to stop and transcribe. Transcribed text is inserted at the caret.
  - **Non-empty composer** (whisper installed): **Hold the Send button ~500 ms** to enter recording mode (red pulse).
    The recording **keeps running after the release** until a tap on the button stops and transcribes it, and a pointer hold keeps the focus in the box throughout (a key hold leaves it on Send); the result is **appended** to existing text with a space separator.
    A short tap still sends normally.
    The button's tooltip names the hold gesture while dictation is available.
    A press the browser cancels before the hold completes (`pointercancel`) records nothing and sends nothing; a cancel after the recording started leaves it running.
    The hold has two keyboard paths.
    **Key hold:** holding Space or Enter on the focused Send button for the same threshold starts the recording, which keeps running after the release like the pointer-started one; a shorter press sends once, on the release.
    The page prevents the click the browser fires on Enter's keydown and its auto-repeats and on Space's keyup (measured in Chromium only, desktop and Pixel 7 emulation), so neither the repeats nor the release send or stop it.
    Before the threshold, Escape on the button cancels the pending hold, whichever press (key or pointer) started it, and the focus leaving the button cancels a key hold; nothing is recorded, and the cancelled press's release and click send nothing.
    After the threshold, both leave the recording running.
    While recording, a Space or Enter press on the button stops and transcribes it, as a tap does.
    At most one hold is pending: a press, key or pointer, that starts a hold while another is pending supersedes it, and the superseded press's release neither sends nor cancels the newer hold.
    An auto-repeat never presses the button again in any mode.
    **Shortcut:** **Alt+Enter** (Option+Return on macOS) in the message box, announced with `aria-keyshortcuts` on the box while it is enabled and in the Send and Dictate tooltips, starts a recording whether or not the box has text, stops and transcribes a running one, does nothing while transcribing, ignores its auto-repeats, and leaves the focus in the box; it serves screen-reader users, whose reader turns Space or Enter into one click.
    A recording keeps running when the user leaves the session view (Settings or another full-page view) and comes back, where the button still shows it; its transcript lands in the session it was spoken to, in the box when that session shows and otherwise in its draft.
    A transcript with no words changes nothing.

  While the transcription POST is in flight the button shows a spinning icon and is disabled, with the accessible name **Transcribing** (not Send); then the resulting text is inserted/appended (space-joined so back-to-back words don't run together). A transcription the server refuses (e.g. a 503 when whisper is missing) or a recorder that fails to start shows an error toast with the reason, leaves the typed text as it was, releases the microphone and leaves dictation usable. Dictated text stays plain in the composer; when you **send** a message that included any dictation, it's prepended with a `<transcribed>` tag so the receiving instance knows it contains speech-to-text that may have transcription errors. When whisper isn't installed, an empty composer shows a disabled Send, holding the Send button is a no-op, Space and Enter on it send at once (Enter on its keydown, Space on its release), and Alt+Enter in the box sends, as Enter does. Recording uses Pointer Events (`pointerdown`/`up`/`cancel`) with explicit pointer capture so releases register reliably on touch. Runs whisper.cpp **locally on the server** — no network, no API key, no telemetry. The mic affordance only appears once whisper is installed (`GET /api/transcribe/status` gates it; the Settings page can flip it at runtime). Recording uses the browser's `MediaRecorder` (webm/opus); the server converts via ffmpeg → 16 kHz mono WAV before calling `whisper-cli`.

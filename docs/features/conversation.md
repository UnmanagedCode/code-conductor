# Features: the live conversation

## Live conversation
- **Tail-first load + scroll-up history** — subscribing renders the ring tail (around `ORCH_SNAPSHOT_TAIL` events, default in `src/instances.ts` — quiescent-aligned: whole blocks, resolved tools; the quiescent snap can land the served count either shorter or longer than that count, and a backstop serves the nearest quiescent cut rather than an empty tail).
  A resumed, respawned, rewound or pruned session opens the same way once its history is replayed, never event by event, and scrolls back the same way.
  When older history exists, a tappable `Earlier messages` sentinel sits above the oldest content and scrolling near the top auto-fetches the previous page (`GET /api/instances/:id/lineage-events` at the page size `web/src/conversation/lazyHistory.ts` requests, clamped by `clampLimit` in `src/eventArchive.ts`; flipping the sentinel to `Loading earlier messages…`).
  A tail that already holds the ring's whole content asks once silently whether earlier contexts exist, so no sentinel flashes for a session that has none.
  If the rendered tail is shorter than the scroll viewport, the controller **auto-fills**: it keeps paging earlier chunks in (same path) until a scrollbar exists or history is exhausted, so the sentinel is never the only thing on screen — it stops on the no-more-history terminal case, on a fetch error (no hot-loop; sentinel stays tappable), and while the container has no layout (background tab).
  Pages splice in above with the viewport preserved; a turn split across page seams **merges back into one assistant bubble** (the batch's trailing open bubble concatenates into the chunk below), and sub-agent (Task) groups always travel whole with their nested panel — live children of a not-yet-loaded Task head are parked and adopted into the panel once its page loads.
  Events evicted from the in-memory ring are reconstructed from the session jsonl.
  Caveats: the task panel and usage chip rebuild from the tail only, and a single turn longer than the ring cap pages back with a gap (never duplicated content) ONLY when the archive replay can't correlate the ring head's own content back into the evicted history (no `(kind, msgId, blockIdx)`/`toolUseId` match) — a completed turn's content is otherwise stitched exactly, no gap.
  When a gap is marked, it renders as an `Earlier messages unavailable` divider at the exact seam; only whole blocks are ever missing, and a genuinely interrupted tool shows the `incomplete` status icon rather than a stuck spinner.
  **Earlier contexts:** scroll-up continues past the start of the current context into every earlier one of the session (each renew — `renew_session` or a typed `/clear` — and each prune started one), down to the first, each separated by a `── context renewed ──` divider — live across a renew too, with no gap for the pre-renew messages the ring evicted.
  A **pruned original is never shown**: its pruned copy (which holds the same turns with tool output stubbed) stands in for it, so nothing appears twice.
  A context whose transcript was **deleted** (Settings → Archived → Delete) or has gone missing shows one `earlier messages unavailable` divider in its place and scrolling carries on into the contexts before it.
  Bubbles from an earlier context carry **no ↶ rewind / ⑂ fork** — those act on the current context's transcript only; a renew strips them from every earlier bubble on screen the moment it happens.
  The dividers carry their own controls instead (see **Rewind & fork** → At a renewal divider).
- **Text** — streams as text-node deltas; on `text_end` re-renders through `web/src/components/Markdown.tsx` (react-markdown + remark-gfm): full CommonMark + GFM — headings, nested lists, block quotes, fenced and indented code blocks inside list items and quotes, tables, **bold**, *italic*, `~~strike~~`, task lists, links, autolinked bare `http(s)://…`, `www.…` and email addresses, `![alt](src)` images; ordered lists keep their start number — `3.` renders as 3, not 1.
  Every code block, at any depth, carries a **Copy** button that copies exactly its code.
  CommonMark consequences to expect: a line indented 4 spaces is a code block; a line of text directly above `---` is a heading, not a paragraph and a rule; an HTML block (a line opening with a block-level tag such as `<details>`) shows as its literal source up to the next blank line, markdown inside it included; a single `~` stays literal (`singleTilde: false` — agents write it for "about"); a footnote reference `[^1]` renders as literal text (cc owns `#…` links), while its definitions render as a trailing notes list.
  A document longer than `MAX_SIZE` characters, or nested deeper than `MAX_NESTING` lists and quotes (`web/src/components/markdown/guard.ts`; markers inside code blocks count too), shows as its raw source without being parsed, and any render failure falls back to the raw source too.
  Link schemes restricted to `http(s)/relative/fragment/mailto`; a link to cc — `http://cc.internal/#<view>` (or cc's own page URL) — naming a cc view (`#plugin/…`, `#settings…`, `#costs`) opens in the same tab with one history entry, its `href` rewritten to the bare hash (a plugin link while the dock shows beside the session opens in the dock instead: **Plugin dock** → **Links**; rules: [plugin-ui.md](../plugin-ui.md) → Deep links); a `cc.internal` link naming no view (or with a path, search or userinfo) renders as literal text — `[label](href)`, or the bare URL for an autolink — and other links open in a new tab; image `src` to `http(s)/file://`/absolute path; no `innerHTML`; raw HTML in source rendered as literal text.
  **`raw`/`md` + `copy`** — each assistant bubble carries one hover-revealed pair (the same shared controls as user messages, `web/src/conversation/items.tsx`), appearing with the bubble's first text block or plan.
  The turn-end line (`TurnEndView`) holds its status icon, label and figures on one row starting at the bubble's left edge, and sits close under the bubble.
  The pair sits at the right end of the turn-end line when that line directly follows the bubble (`controlsCarrier`) — a usage (`rate_limit_event`), `cache_miss` or background-task notification landing at the turn's end renders below the turn-end line (`TURN_TAIL_NOTICES`, `web/src/conversation/model.ts`), so it never separates the line from the bubble; other notes between them (an interrupt, an overage stop, a permission denial) stay above the line — and on its own right-aligned row under the bubble otherwise: mid-stream, a bubble split off earlier in the turn, a turn interrupted or never ended, sub-agent bubbles.
  Hovering the bubble or the turn-end line reveals it, as does focus, and it always shows where nothing hovers.
  `copy` yields the markdown source of the bubble's text blocks in stream order, joined by a blank line, then the body of the plan card that closes the bubble; thinking, tool calls and results, question cards and sub-agent output are excluded, and a sub-agent's own assistant bubbles carry their own pair covering only their own text.
  `raw` flips every text block of the bubble between rendered and source together (monospace), and text that streams in later follows the bubble's view.
  The controls are live mid-stream: `copy` yields what has streamed so far.
  Every copy button (`web/src/components/CopyButton.tsx`) announces its outcome, copied or failed, to assistive technology through a polite live region beside it, and keeps its own name.
  A bubble split across lazy-history pages behaves as one.
- **User messages** — rendered through the same `Markdown` component as assistant text (same safety guarantees: no raw HTML is ever rendered — tag-like text such as `<pasted_content>` and HTML blocks show literally).
  Single newlines are kept as line breaks.
  Every user-authored item (prompt, answer, plan decision, wake/skill/renew/forward folds, queued ghost, sticky pin) spans the transcript column's content box, as the AskUserQuestion and plan cards do, at every session width and on phone; inside a sub-agent panel it spans the panel's content box.
  Its text is left-aligned.
  A soft tint and an accent strip on the right edge mark the side; no outline.
  Attachments start at the bubble's text; the hover controls end at its right edge, like every transcript item's helper icons (`ActionRow` in `web/src/conversation/items.tsx`).
  Owner: `USER_BUBBLE` in `web/src/conversation/items.tsx`; pins: `web/src/conversation/userBubbleWidth.test.tsx`, `web/src/conversation/actionRowAlignment.test.tsx`, `web/e2e/user-bubble-width.spec.ts`, `web/e2e/user-bubble-width-nested.spec.ts`.
  Markdown headings render as headings, in a prompt and inside every folded bubble body.
  Hovering a bubble reveals the `raw`/`md` toggle + `copy` controls shared with assistant bubbles (see Text): the toggle switches between the rendered view and the literal source (monospace), and `copy` always copies the exact source text regardless of which view is showing (after the `<transcribed>` marker strip).
  Wake-callback, skill-load, renew-seed and forwarded-output bubbles' expanded bodies (see below) get the same rendered body, `raw`/`md` toggle and `copy`, built lazily on first expand.
  **Known limitation:** a forwarded message truncated mid-way inside an open code fence renders its tail (including the truncation marker) inside that code block — confined to that message's section of the forwarded-output bubble, so the other messages, the END marker and the conductor's instruction are unaffected; use `raw` to read it as plain text.
- **Following the transcript** — while the reader is at the bottom, the transcript follows new output; once they move up it stays where they are, whatever arrives.
  - **Stopping:** any upward movement stops following, however small; a drop in position from content shrinking or the viewport growing back does not.
  - **Resuming:** only at the very bottom (within `AT_BOTTOM_PX`) or through **Jump to latest**, which shows once the reader is more than `NEAR_BOTTOM_PX` from the bottom (both in `web/src/conversation/ConversationView.tsx`). Coming back down near the bottom without reaching it does not resume.
  - **A finger on the transcript:** nothing moves it while a touch that started on it is down. When the last finger lifts, it catches up to the bottom once if output arrived meanwhile and the reader is still following; a lift with nothing held back moves nothing.
  - **Replaced or left:** a transcript replaced in place starts at the bottom again: another session selected, a rewind, a reconnect's snapshot. Leaving a full-page view such as Settings puts the reader back on the prompt they were reading if they had scrolled up, or at the bottom (including what arrived meanwhile) if they were there.
  - **Older pages:** an older page spliced in above leaves what the reader is looking at where it was on screen; it is the one position adjustment made whatever the reader is doing.
  - Tests: `web/src/conversation/transcriptScroll.test.tsx`, and `dragWhileStreamingFlow` in `web/e2e/conversation-scroll.shared.ts`.
- **What the reader opened** — every fold the reader opened or closed and every `raw`/`md` choice they made in the transcript stays as they set it through later output and through a full-page view such as Settings: action groups, tool calls with their arguments, result and full output, sub-agent turns, thinking, folded bubbles (skill, wake, renew, forward, compaction), background-task notifications, and each message's `raw`/`md` view. A plan card's feedback and a question card's tab, picks, "Other" text and notes are kept per session, in memory, through a transcript replaced in place: a reconnect's snapshot, a respawn's or resume's history reload, re-selecting the session, and another session selected and coming back. A question's input is dropped once it is answered. A plan's feedback is dropped when its decision is sent, so a decided plan that reopens shows none; a decision whose send fails keeps it, except when a rebuild landed while that send was in flight. A page reload starts them empty; a rewind that removes a card removes its input with it.
- **Sticky prompt header** — on demand, the prompt that started the turn in view stays pinned at the top of the transcript, so the ask is never scrolled out of sight.
  - **Reveal / hide:** hidden by default.
    - **Reveal:** Down in the composer with the caret at the very end of the text (or in an empty box), or a vertical swipe down on the session top bar (`SessionHeader` in `web/src/features/session/SessionHeader.tsx`) or on the pin.
    - **Hide:** Up in the composer with the caret at the very start (or in an empty box), or a swipe up on the top bar or the pin.
    - The keys act only with no modifier, no selection and no IME composition, and are never consumed: at those caret positions the browser's own Down/Up does nothing.
    - A swipe commits once per gesture past `SWIPE_MIN_PX` (`web/src/conversation/stickyPrompt.ts`) of mostly-vertical travel; a horizontal-dominant move, a second finger or a touch starting in the overflow menu does nothing. The transcript itself is never a swipe zone, so its scrolling is unchanged. The top bar and the pin declare `touch-action: pan-x pinch-zoom`, so a swipe there starts no pull-to-refresh while pinch zoom still works. The zone is the whole top bar — in the phone layout the one-row bar, buttons included; a tap on a button is not a swipe and still clicks. Not limited to the mobile layout breakpoint: touch tablets and hardware keyboards on phones get both.
    - Hidden again on every session switch; not kept across reloads. A rewind (same session) keeps it revealed.
  - **Autoload:** revealed with no eligible prompt above the viewport, the pin pages older history into the transcript (viewport kept in place) until one pins, or until history ends, a page fails, the pin is hidden, the session switches or a full-page view opens (closing the view resumes it). Meanwhile the pin shows a status line in its place (texts: the `STATUS_*` constants in `web/src/conversation/stickyPrompt.ts`). A status line is announced as a status, not a button: it takes no Tab focus and has no jump tooltip; both come back once a prompt pins and the pin is a button again.
    - **loading** — a page is loading, or the session's snapshot has not arrived yet;
    - **no earlier prompt** — history is exhausted;
    - **failed, with a retry hint** — a page failed or made no progress. Scrolling does not retry it; revealing again (Down / swipe down) does.
  - **Behaviour:** the last eligible prompt whose top has scrolled above the viewport pins. Its left and right edges line up with the prompt bubble it repeats, at every session width. It shows the prompt's text only (no role row, no rewind/fork/raw/copy controls), clamped to five lines with a fade over the last line and a half when it is longer. A drop shadow (with a faint light line under the bottom edge) sets it apart from the transcript scrolling beneath; it adds no height. The next eligible prompt pushes it off, scrolling back above a prompt leaves the previous one pinned, and clicking the pin (or Enter/Space on it) scrolls the full original bubble to the top of the transcript. After the jump the previous prompt is the one held; it is fully pushed off by the bubble now at the top, so it is hidden (and not focusable) until the transcript scrolls again. Revealed with no earlier prompt, the status line (see Autoload) takes its place. Hidden together with the transcript in Settings, review, commits, costs and plugin views, and back as soon as the view closes.
  - **What pins:** only prompts a person typed into cc. In a worker session (a conducted one) the conductor's prompts pin too. There is no author field on any event, so `shared/promptOrigin.ts` decides from the text's shape and the event flags, stamped as `data-prompt-origin` (`typed` / `template` / `synthetic`) on each user bubble; `template` prompts pin only in a worker session.
  - **Never pins (`synthetic`):** sub-agent echoes, skill loads, compaction summaries and other CLI-injected lines, wake / heartbeat / interrupted stubs, renew request and seed, restart notices, overage preambles, the rebase brief, plan decisions with no feedback, slash commands (a first token that is a single `/word`, e.g. `/review the diff` or bare `/compact`, or a `<command-name>` wrapper), a forward frame with no instruction, an AskUserQuestion answer the server paired with its card and stamped (it renders as its own answer bubble, with no prompt text to pin), and attachment-only prompts.
  - **Pins only in a worker session (`template`):** a plan decision carrying feedback, answer-shaped text the server did not pair with a card, and a forward frame's instruction (the pin shows the instruction only).
  - **Stated degradations:** (1) a conductor's `send_prompt` brief into a non-worker session pins — it is byte-identical to a composer prompt; (2) a human's plan decision, or answer-shaped text, in a non-worker session does not pin; (3) a human prompt whose first token is a single `/word` — including a bare path like `/tmp` or `/etc is read-only` — does not pin, while a multi-segment path such as `/etc/hosts` does; (4) a human prompt that happens to start with a template's opening pins only in a worker session; (5) an overage resume carrying queued messages pins with its preamble as the first lines.
  - **Owner modules:** `shared/promptOrigin.ts` (eligibility), `web/src/conversation/stickyPrompt.ts` (`createStickyPrompt`: pin geometry, reveal state, autoload and status; `trackSwipes`: the swipes), the composer's key handler in `web/src/features/composer/Composer.tsx` (the keys), `web/src/conversation/lazyHistory.ts` (`loadUntil`, the paging); layout in [components/web.md](../components/web.md#web).
- **Transcript layout** — assistant turns have no avatar at any width. The assistant body (action cards, controls), the user bubbles and the turn footer's status icon share the transcript column's left edge and width on every viewport; assistant prose and notes are inset on both sides by the user bubble's horizontal padding, so they start at the user's text (code blocks, tables and the read-aloud row move with their block); bordered boxes (action cards, dividers, plan and question cards) keep the column edge; the footer carries the controls at its right end and wraps its figures to their left; the side padding is narrower below Tailwind's `md` breakpoint (the same one as the sidebar drawer and the phone top bar). Each root assistant bubble is a group named "Code Conductor" for screen readers; sub-agent bubbles are not. An assistant bubble directly after another (an unprompted turn replayed from the transcript, which has no turn-end row) gets a hairline top border. Owners: `AssistantBubble`, `TEXT_INSET_X`, `TURN_SEAM` in `web/src/conversation/items.tsx`, `TRANSCRIPT_PAD_X` in `web/src/conversation/ConversationView.tsx`. The DOM it rests on is `web/src/conversation/assistantLayout.test.tsx`; the geometry is `web/e2e/transcript-layout.shared.ts`.
- **Renewal reseed** — the first user turn of a session a `renew_session` rotated renders as a collapsed `♻️ Context renewed — handoff summary` bubble (a fold, like the wake-callback bubble). Expanding it shows the handoff summary split into one labelled section per heading the summary template asks for, falling back to a single "Handoff summary" section when the summary doesn't match it, then the conductor's follow-up directive (targeted-renewal form only) and the mechanical state block as literal monospace text (never markdown, so a `worktree=…` line can't mangle into emphasis). Same `raw`/`md` toggle and `copy` of the exact seed text as the wake and skill bubbles (see User messages, above); recognised live and on reload/history paging alike, since detection reads the seed's own fixed wording rather than a wire marker. The CLI's `/clear` command line at the head of a renewed transcript renders no bubble on reload, history paging, resume or fork whenever the reseed directly follows it, since the live clear shows none either; a typed `/clear` (no reseed) keeps its raw command bubble under the "Context renewed" divider.
- **Forwarded worker output** — a turn delivered by `send_prompt({forward})` renders as a collapsed `📨 Forwarded worker output · N messages` bubble (a fold, like the renewal bubble). Expanding it shows one markdown section per forwarded message, labelled `Message i/n` (`Forwarded output` when there is one). The conductor's instruction renders below the fold as an ordinary user message. Each part has its own `raw`/`md` toggle and `copy`: the fold's copies the forwarded payload exactly, the role row's copies the instruction exactly (see User messages, above). Recognised live and on reload/history paging alike, since detection reads the frame's own fixed wording (`shared/forwardFrame.ts`) rather than a wire marker; a frame with no END marker, or with text before its header, renders as a plain user message. **Known limitations:** the bubble names no source worker — the frame deliberately carries no source handle (see [protocol/mcp-results.md → `send_prompt({forward})`](../protocol/mcp-results.md#mcp-tool-results-and-refusals)); an instruction that itself contains the END-marker line as its own paragraph splits there, so its head shows inside the fold — nothing is lost.
- **AskUserQuestion answer** — an answer to a question card, sent from the card or by `answer_question`, renders as a dedicated `❓ Answered · N questions` bubble in the card's colours (`❓ Answered` for one question). It shows one row per question: the header and question text, the chosen option chips (one per label for a multi-select), the custom text, or `skipped`, and any note. It is identical live, on reload and in lazy-loaded pages, and keeps the rewind/fork affordances. It is recognised by the server-side pairing with the question card, never by the text alone: a typed prompt that merely looks like an answer stays a plain bubble when no question is pending. While a card is pending, a typed prompt in that card's canonical answer format is treated as its answer. An answer pairs only with a question in the same transcript segment, so a card left unanswered across `/clear` or a renew is answered as a plain bubble. Text that does not round-trip through the formatter — an answer in an older format, or one with a steer coalesced onto it — is shown raw inside the bubble, and its card locks with no option highlighted. Answers to sub-agent questions stay plain bubbles.
- **Text-to-speech (read aloud)** — the inverse of voice dictation: finalized assistant text blocks get a trailing `🔊` button (tap to hear it), and a global **auto-speak** toggle reads each reply as it lands. Local server-side Piper — no network, no API key. Synthesis is **streamed per sentence**: `POST /api/tts` returns a sequence of `[4-byte LE length][WAV]` frames (one per sentence) flushed as Piper yields them; the client (`web/src/features/voice/tts.ts`) decodes each with the Web Audio API and schedules them back-to-back, so the first sentence starts playing (~0.3s) while the rest synthesize. The 🔊 button appears once Piper is installed (`GET /api/tts/status` gates it; Settings → Voice → Speech installs/flips it at runtime). Auto-speak only fires after the user has interacted at least once (browsers block audio without a prior gesture); a 🔊 tap always works. Sub-agent text isn't auto-spoken. Every finished text block has a read-aloud control of its own that reads only that block. Where it sits: inline after the block's last word, on its last line, adding no line, on every viewport; a block ending in a heading, code block, table or rule keeps it on a row of its own under that element. It is muted until its block is hovered or it is focused, and at full strength while speaking and on touch screens (`web/src/conversation/speakPlacement.test.tsx`, `web/e2e/speaker-last-line.spec.ts`); the block being read, by a tap or by auto-speak, is the one whose control offers to stop. A block still streaming and a sub-agent's text have none.
- **Thinking** — collapsible block; redacted thinking renders as a non-expandable `thinking (redacted)` line (no disclosure caret). Opus 4.7 emits only a `signature_delta`; Opus 4.8 streams empty `thinking_delta`s (`""`) — the parser drops the empties so both collapse to the same redacted line. When the CLI streamed a token estimate for the block, the line reads `thinking (redacted, ~N tokens)` and keeps the count when you switch sessions or refresh; it falls back to the bare label after an action that reloads the session (resume, restart, and the rest — [docs/protocol/ws-events.md](../protocol/ws-events.md) → `thinking_tokens` lists them), since the estimate is never persisted. Blocks with visible thinking text finalize to `thinking (N chars)` instead.
- **Narration** — a progress note Claude sends as a thinking block with text **straight after a redacted one** (observed on `claude-opus-5-5`) is shown in the message flow, outside the action group, without opening anything: muted italic text under a small `note` marker (`NarrationBlock`, `data-narration`, in `web/src/conversation/items.tsx`). Raw while streaming, markdown once finished (the bubble's raw toggle applies). It is left out of **Copy message** and never read aloud. The server decides it by block order alone (rule: [protocol/ws-events.md](../protocol/ws-events.md) → `thinking_delta`), so it shows the same live and after a reload. **Limitations:** detection relies on Claude's current block ordering — a note without a redacted block before it shows as ordinary thinking; a sub-agent's notes are not classified and show as thinking in its nested panel. Prune still counts and stubs a narration block as thinking.
- **Tool use** — collapsed by default with smart one-line summary (`🔧 Bash · ls -la · done`). Edit/Write/NotebookEdit render as syntax-coloured unified diffs (green/red gutters, ±counts, sticky file-path); Write shows a numbered preview. Shell tools (Bash, the Windows CLI's `PowerShell`, cc's `project_bash` / `system_bash`; owner: `SHELL_TOOLS` in `web/src/conversation/format.ts`) render the command in an open box with a Copy button, and the summary shows the call's `description`, falling back to the command. cc's `run_code` renders its script syntax-coloured (`tokenizeJs`, `web/src/conversation/jsTokens.ts`) in the same box with a **Copy script** button and lists its other arguments beneath; its summary shows the call's `description`, falling back to the code. Other tools: raw-JSON input in its own collapsed `↪ tool_input` block. **MCP tool names** render as a chip plus a sentence-case label instead of the wire name: cc's own tools get a `cc` chip, a plugin tool gets a chip of its plugin id minus a leading `code-` (`mcp__code-conductor__code-kanban__move_card` → `[kanban] Move card`), any other server gets a chip of its server name (a leading `claude_ai_` dropped, `_` → space); each of the three kinds has its own chip colour (`ToolName` in `web/src/conversation/tools.tsx`). The raw name is the hover title; built-in tool names, the args line and the body are unchanged. A name that fits no MCP shape shows verbatim. Parse owner: `shared/toolName.ts`.
- **Action groups** — a contiguous run of non-prose blocks (tool calls, tool results, thinking) between two assistant text or narration blocks is wrapped in one collapsible (`ActionGroup` in `web/src/conversation/tools.tsx`) headed by a tally: `7 actions · Bash ×3, kanban: Move card ×2, thinking, Edit · 1 error` — count, distinct labels (an MCP tool as plain `chip: Label`) in first-appearance order (at most four, then `+N more`), and a trailing error clause counting every tool result in the group that came back as an error (including an orphan result whose `tool_use` is not in view) — except a `yielded` result, the deliberate deny of AskUserQuestion / ExitPlanMode / EnterPlanMode, which is not counted: it renders as `↪ handed to user` and its tool's status reads `handed to user`.
  The run still accumulating during a live turn stays **expanded** so it can be watched, and folds the moment the run ends: prose or narration, a user action, the turn's end, an interrupt, or the process exiting (`system/exit`, which every subprocess death emits, or `system/crashed`).
  Historical pages arrive folded.
  **Toggling a group by hand sticks** — a group the user opened or closed is never auto-collapsed again.
  A sub-agent's own machinery groups the same way inside its nested panel (its failures are tallied by its own header, not the outer one), and a run-ender folds those nested groups too — a sub-agent gets no turn end of its own.
  A backgrounded sub-agent (its `task_started` says `is_backgrounded`) is the exception: its run outlives the outer turn, so outer run-enders leave its groups open until its task ends (its `task_notification`, any status).
  Each run is tracked by its `task_id` (the tool use's id when absent), so a resumed Agent whose run gets a new `task_id` stays open the same way.
  A process exit or crash folds them, because a background task dies with its process.
  A run whose `task_started` is not in view (a snapshot tail that starts after it) folds at outer run-enders.
  Each turn gets its own assistant bubble and its own turn-end row directly under it, including the unprompted turn the CLI runs when a background task's notification arrives (no user bubble precedes it).
  A reload after a cc restart, or a scroll-back into replayed history, splits the same way: replay marks where each such turn starts (`turn_boundary`, see [protocol/ws-events.md](../protocol/ws-events.md)).
  A run cut in half by a lazy-history page seam merges back into one group with one header — unless a run boundary the live view honours (a turn-end line, an interrupt note) sits between the halves, in which case they stay two.
- **Hook context** — text a hook added to the model's context (`hookSpecificOutput.additionalContext`) is shown verbatim as a collapsed `Hook context · <hook event>` fold, live and after a reload, restart or scroll-back. Only context-adding results show: allow / `{}` answers, denials, rewritten inputs, cancelled or empty hooks and every other hook frame stay hidden.
  - **Placement:** a `UserPromptSubmit` hook's context (e.g. a memory plugin's recall) sits under the prompt it was added to; a `PreToolUse` / `PostToolUse` hook's context sits inside its tool card, after the result, and the card's header shows a hook marker (accessible name "Hook added context") so a closed card still shows it has some. While the target is not rendered the context shows as its own row (naming the tool), and moves into the card once the card appears.
  - **Body:** built on first expand, with the usual `raw`/`md` toggle and `copy`. Its open state outlives remounts, like the other folds. It is not a run-ender: an open action group stays open.
  - **Sources:** cc's own hooks (the conductor read nudge, tool-result nudges, redirect notes) and any user or plugin hook. Wire detail: [protocol/ws-events.md](../protocol/ws-events.md) → `hook_context`.
  - **Known limitations:** a `PreToolUse` / `PostToolUse` context from a hook that is **not cc's own** appears only after a reload — the CLI's live hook frames carry no tool call id, so it cannot be tied to its call live. Two prompts queued mid-turn can show the first one's recall under the second until a reload.
- **Context compaction** — one collapsible compaction bubble per compaction, identical live and after a reload. The header names the trigger and token counts (`Context compacted · manual · 27,152 → 2,952 tokens`; the trigger and counts are left out when the CLI did not report them) and the CLI's injected summary is folded beneath it, collapsed, expanding into markdown built on first expand with the same `raw`/`md` toggle and `copy` as the renew bubble. Live, a `Compacting context…` header appears first and is completed in place by the boundary; a compaction that fails, or whose turn or process ends first, reads `Compaction failed: <error>` / `Compaction did not complete` (live-only — nothing is persisted). The CLI's post-compaction re-`init` and the paired `Model changed` note are not shown. The bubble has no rewind/fork controls and ends the assistant segment and its action group, so work after a mid-turn auto-compaction continues in a new assistant bubble below it. An auto-compaction has no `/compact` bubble and no command output. The segment closes when the bubble first appears (`Compacting context…`), before the outcome is known, so a failed compaction splits the turn the same way. A typed `/compact` keeps its own user bubble exactly as it renders today (raw `<command-name>` wrapper on reload; the compaction bubble sits below it in both orders); its `<local-command-stdout>Compacted </local-command-stdout>` line is absorbed into the bubble, only while no other content has arrived since. Lazy history: a page split between the boundary and the summary shows a header-only bubble and a summary-only bubble (headed `Context compacted`, with no trigger or counts).
- **Background-task notifications** — when a task the model ran in the background (a background Bash, a Monitor, or a background Agent) completes or fails, the transcript shows one dim system line: the task's name, its status and, for a command or monitor, its exit code (`bg ok · completed · exit 0`). A failed task's line is amber. Expanding the line shows the task's summary (an Agent's result text) and its output-file path. A background Agent whose card already shows its report (the last text in the card's sub-agent transcript is the notification's summary) gets the headline alone, with nothing to expand. Otherwise the line keeps its fold, the only place the text shows: the card is not loaded, the agent's transcript is unavailable, or its last text differs, which is the usual case for a failed Agent, whose summary is the failure sentence rather than a result. Each notification shows exactly once, live and after a reload, restart or scroll-back (it is rebuilt from the session transcript). By design there is no line for a foreground call, nor for a stopped task — one the model stopped with TaskStop (its call is already in the transcript), or one cut short because the session itself ended. Wire detail: [protocol/ws-events.md](../protocol/ws-events.md) → `system`/`task_notification`.
- **Skill loading** — a `Skill` tool call's SKILL.md content, which the CLI injects back as a plain (large) user message, renders as a dedicated collapsed `📘 Loading skill: <name>` bubble instead of a giant plain-text bubble; expanding it renders the content as markdown, built on first expand, with the `raw`/`md` toggle and a `copy` of the exact injected text (see User messages, above). Works live and on session reload for top-level `Skill` calls; a `Skill` invoked inside a sub-agent `Task` folds on session reload only — no live content injection was observed to follow a sub-agent turn (n=1, in a capture since deleted; see `docs/protocol/ws-events.md`), so there is nothing to fold until the session is replayed from its jsonl. Server-side correlation with the originating `Skill` tool_use (not just the CLI's injected-message flag, which it also reuses for unrelated compaction/hook text) — see `docs/protocol/ws-events.md`.
- **Tool result** — truncated at 4 KB with "show full".
  A text block that parses strictly as a JSON object or array (each block of an MCP result is tried on its own; scalars and malformed text stay plain) renders as an indented, syntax-coloured, foldable tree instead of a `<pre>`; mixed results keep block order (a tree, then the plain text, which still truncates).
  A block over `JSON_TREE_MAX_CHARS` falls back to the plain truncated text.
  A small tree starts fully open; a larger one opens only shallow, narrow containers (`defaultOpen`).
  Click a container's header line (unless text is selected) or its chevron button (`aria-expanded`) to fold it; a folded container shows `{…}` / `[…]` and its key or item count; containers nested past `MAX_TREE_DEPTH` show as one raw source line.
  **Copy JSON** copies the block's exact source whatever is folded.
  The values are the tool's own text (no number rounding, key order and duplicate keys kept) and render as plain text, never HTML.
  Folds live on the result node (`reader.folds`) like the other toggles.
  The **Arguments** of any call rendered by the generic fallback (a tool with no specialised view, or one whose specialised renderer's guard fails, e.g. a shell call with a non-string `command`) render as the same tree inside the `data-tool-args` details, with the same default-open policy; its folds live on the tool node (`reader.argsFolds`, keyed by container id) apart from the result's. Arguments still streaming (`partialJson` only), unstringifiable, or over `JSON_TREE_MAX_CHARS` stay a plain `<pre>`.
  Owners: `web/src/conversation/jsonTree.ts` (parser), `JsonTreeView.tsx`.
  `image` content blocks (e.g. `Read` on a `.png`/`.jpg`) render as inline `<img>` thumbnails alongside the text — base64 sources become `data:` URLs, `url` sources only pass through for `http(s)`/`file://`, `image/svg+xml` is refused (XSS).
  Auto-expanded when an image is present.
  Tap any conversation image to open it full-size in an in-page overlay (`ImageZoom` in `web/src/conversation/ImageZoom.tsx`) — works for `data:`/`file://` sources that Chrome on Android refuses to open as a top-level navigation.
  Opens fit-to-screen; tap the image to toggle 1:1 full native resolution, tap again to fit.
  The 1:1 view is centred when it fits; when it overflows it opens with the tapped spot under the pointer (`zoomScroll.ts`) and scrolls inside the viewer, only on an axis that overflows.
  The zoom cursor shows only over the image; tap anywhere outside the image (the backdrop or the area beside it) or press Esc to close.
- **Sub-agent drill-down** — `Agent` tool calls nest a mini-conversation (its summary marks it as a sub-agent) inside the parent tool block, routed by `parentToolUseId`. The block exposes **four independently collapsible surfaces** (`web/src/conversation/tools.tsx`): the balloon (`data-tool-trigger`), `tool_args` (`data-tool-args`), the sub-agent's turn transcript (`data-sub-trigger`) and `tool_result` (`data-tool-result`). The balloon is **collapsed by default** — it does not pop open when the sub-agent's first event arrives — while the turn transcript is open by default, so expanding the balloon shows the transcript. Every one of the four **survives later streamed sub-agent events**: once toggled by hand a surface keeps that state for the rest of the session. Each surface's state also survives closing and reopening the balloon and a full-page view such as Settings; it is per-block and **not persisted across a page reload** (the conversation is rebuilt from the snapshot).
- **Plan mode card** — green-bordered card "Plan ready for approval".
  Body comes from `input.plan`, or — when the model wrote the plan to `~/.claude/plans/*.md` first and called `ExitPlanMode` with empty input — the most-recent such file, whose path the card shows as a `saved to …` line.
  That line survives a reload/respawn, and a cc restart between writing the plan and calling `ExitPlanMode`: jsonl replay re-derives the path from the `Write` in the current transcript segment and seeds the live tracker with it (`src/planFile.ts`), so the card shows the full plan.
  A segment rotation (`/clear`, renew) or a prune that drops the `Write` between the write and a restart is outside that recovery, and the card then renders empty.
  **Approve** sends `"I approve the plan. Please proceed with the implementation."` (+ feedback if provided) and flips the instance to `code` (`bypassPermissions`).
  **Reject** keeps plan mode active and sends `"I'd like to revise the plan. Refinement notes:\n<feedback>"`.
  The feedback stays in the card, locked, once a decision is sent.
  A decision that can't reach the CLI re-opens the card, editable, with its feedback, to send again.
  **📋 Auto-approve plans** toggle sits inline immediately left of the Plan/Code mode switch and is only visible while the instance is in `plan` mode (one-click, mid-turn friendly); per-instance, server-side state (mirrored down through `snapshot`/`status` WS frames so every tab agrees), cleared on server restart.
  When on, the orchestrator fires the same setMode+approval-prompt the moment a `plan_request` lands — works regardless of whether any tab is subscribed / focused / minimized.
  Green-tinted background when on, outlined when off.
  The card's body scrolls inside the card past the cap (see **Bounded bubble bodies**).
  The card's body is included in the `copy` of the assistant bubble it closes.
  **Known limitation:** a plan card with no assistant bubble before it (for example, the first event of a lazy-history page) is in no bubble's copy.
- **Bounded bubble bodies** — the plan card's body (the `Saved to …` line and the plan) and the body of every bubble rendered through `FoldedBody` (`web/src/conversation/items.tsx`) scroll inside the bubble once they pass `BUBBLE_BODY_MAX_HEIGHT` (`web/src/conversation/BubbleBody.tsx`); shorter bodies render as they would unbounded. The plan card's header, status, feedback box and Approve / Reject, and a fold's trigger and `raw`/`md` + Copy toolbar, stay outside the scrolling region. Overscroll is left at the default, so a wheel or swipe at either end of the region carries on scrolling the transcript, and an inner scroll never moves the transcript's follow-the-bottom state. Left unbounded on purpose: the action group (its diff, result and argument panes are already bounded, and a bounded group would nest scrollers); the sub-agent conversation and thinking body (they grow live and would need their own follow-the-bottom logic); the question card (its size is capped by the AskUserQuestion schema and most of it is controls); task notifications and completions (one line each); and user and assistant text.
- **AskUserQuestion card** — blue card; multi-question tab strip across the top: a button group named `Questions`, the showing question's button pressed. Same input field flips role: **Or write your own answer…** before any option picked (overrides), **Add a note (optional)** after a pick. Typed text persists across pick/unpick. Plain **Enter** in that field moves to the next unanswered question (after the showing one, wrapping; the field keeps focus); once every question is answered, Enter sends, exactly like **Send all answers** / **Send answer**. Shift/Ctrl/Alt/Meta+Enter, IME composition and a held (auto-repeat) Enter do nothing. **Send all answers** enables once every question is answered and sends immediately — mid-turn included, exactly like a composer send (the `can_use_tool` deny doesn't reliably leave the instance idle, so mid-turn is the normal case, not an edge). If the send can't reach the CLI (socket reconnecting, instance killed, session mid-rewind) the card re-opens with `couldn't send — <reason>` instead of sitting on `sending…`; there is no retry or queueing. Once answered from any surface (this tab, another tab, the conductor's `answer_question`, a typed prompt in the answer format), live or after a reload or lazy load, the card shows the chosen option(s) with its controls disabled; the server's pairing stamp decides which card an answer belongs to, so an answer-shaped prompt with no stamp (for example across `/clear`) leaves the card open. The card's text field shows the note on a pick, or the whole custom answer, disabled; on a multi-question card the tabs stay clickable and show each pane's answer, while Send and the status line stay locked. The status line reads `answered` once the server's stamp locks the card, including a card this tab submitted (`sending…` until its echo arrives). Plan-mode Approve/Reject cards behave identically.
- **System notes** — kept: `init`, `stderr`, `exit`, `permission_denied`, `spawn_error`, `crashed`, `history_load_error`, non-allowed `rate_limit_event`. Filtered: per-turn `status:"requesting"`, `rate_limit_event:"allowed"`, hook lifecycle pings, task progress. Non-allowed `rate_limit_event` renders as a parsed one-liner (e.g. `⚠ Usage 75% of 5-hour limit · resets 6:40pm`, `⛔ 7-day limit reached · resets Sat 5:00pm · overage unavailable (out of credits)`), not raw JSON. Adjacent `rate_limit_event` lines that render identically show once, because the CLI re-reports usage on every API call; any item between them, or any difference in the rendered line, keeps them separate. When a turn ends, any `rate_limit_event`, `cache_miss` and background-task notification lines that are the last rows at that moment render below the turn footer, and the turn's own notes render above it. A notification that arrived mid-turn counts as such a last row when only more of the same bubble's content followed it: that content joins the bubble above, so the notification still ends up below the footer.
- **Per-call usage line** — after each top-level API call's blocks, a dim one-liner (`CallUsageLine` in `web/src/conversation/tools.tsx`) from the live `call_usage` event: `+3.2k → ctx 84k · out 460 (73 thinking)` — growth over the previous call, this call's prompt, its output and the thinking part of it. The turn footer prefixes its `ctx` with these lines' sum. `ctx 84k · out 460 (73 thinking)` when there is no baseline (a session's first call — a rewind to the first user message starts a fresh one — or the first after a compaction, `/clear`, model switch or prune; any other rewind, and a respawn, re-seed the reading from the transcript, so their next call has one); no `(… thinking)` when it is 0 or unknown; just `out 460` when the prompt is unknown. Growth can be negative and keeps its sign. Tooltip: growth is the previous call's output plus everything appended since — not per-tool attribution. It lands inside the bubble's open action group (after the call's last tool) or in the bubble body after a closing text block; it is not an action, so the group's `N actions` tally ignores it, and the next call's tools continue the same group. **Live only**: it survives a re-subscribe (ring-retained), but disk-archive pages and replayed history show none. A tail or a lazy page can start between a call's last block and its `call_usage`; the line is then held until the page holding the call's message loads, and shows there once. **Opt-in per session**: hidden by default, shown while the active session's **Show mid-turn statistics** box (in its ⋮ menu, and in ⋮ → **Statistics**) is ticked — including lines already on screen when it is ticked. The tick is keyed by `sessionId` (a respawn or resume keeps it), is not persisted (a reload resets every session to off) and follows the active session on a switch; debug mode has no effect on it. The turn-end segment and the Agent-row total are not gated.
- **Agent-row subagent total** — a foreground `Agent` tool row's summary gains ` · subagent 124k ctx · 11 tool uses` (`data-agent-usage`, `web/src/conversation/tools.tsx`) once its result lands: the subagent's own context when it finished (its last call's prompt + output), a separate window, not part of this session's figures. Live only, like the per-call line, but shown in every session; a **backgrounded** Agent (`run_in_background`) shows no total, since its result carries none. The Agent card shows the total on every viewport, phone included.
- **Turn footer** — duration, cost, context in use, tokens: `✓ turn ended · (end_turn) · 1200ms · $0.0123 · +3.2k → ctx 84k / 1.0M (8%) · in=10 out=252`. The `ctx` segment is the server's `turn_end.contextTokens` against the `contextWindowTokens` stamped beside it (the latest top-level API call's prompt, so it reads one reply short; formatted by `formatTokens`/`formatPct`, `shared/usage.ts`): `ctx 84k` when the window is unknown, no segment when the reading is null (a turn after a compaction, `/clear`, model switch or prune that made no measuring call — a `/compact` turn's own line has none). The `+…`/`-…` prefix is the turn's growth (`turn_end.contextGrowthTokens`): the sum of the turn's per-call growths, in the per-call line's form, and shown in every session like the `ctx` figure it prefixes. Each figure is rounded on its own, so the formatted per-call figures need not add up visually to the turn's. No prefix for a turn whose first call had no baseline (the per-call line's rule above), a turn with a clear mid-turn, the first turn after a crash-recovery respawn of a process that died with a call already open in the turn, a turn with no measuring call, or whenever the turn's figures disagree — e.g. a call cut off before its final usage frame (a ⏹ force interrupt mid-stream) that moved the reading. Live and ring only — the turn-end line is absent from disk-archive pages altogether. `in=`/`out=` is the CLI's per-turn sum, unchanged.

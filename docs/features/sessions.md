# Features: sessions and the sidebar

## Sessions & instances
- **Unified view** — Sessions list per project (and per worktree) shows live + historical. Header: `Sessions (N) · K live · last <ago>`; at the main checkout it is the toggle of the project's Sessions group, at a worktree a summary line under the worktree's caret. Click to focus live instance, or resume stopped one (`POST /api/instances` with `--resume <sid>`). Synthetic `(new session)` row for spawned-but-no-jsonl-yet instances. Rows group as normal, then Persistent, then Conducted. With one visible group there is no label and the summary names it: `Persistent sessions (N) · …` / `Conducted sessions (N) · …` (a normal-only place keeps `Sessions (N) · …`). With two or more, the normal rows come first, unlabelled, then a `Persistent · n` and a `Conducted · n` label, each followed by a hairline, above their rows. `n` counts the group's visible rows; which groups are visible is judged on the rows the conductor filter shows, while `N` stays the place's whole count under a filter. The project row's count-pill tooltip always reads `Sessions (N) · …`. A summary too long for its row wraps between its facts (`<Noun> (N)`, `K live`, `last <ago>`), never inside one, so no fact is clipped.
- **Prompt focus on select** — a user-initiated selection focuses the prompt bar (`#composer-input`): a click on a session row, a needs-you entry, a conductor row or a sub-agent panel worker; Spawn and 🎼 Conduct; a resume the user asked for (including Settings → Archived restore); Fork; a click on an OS notification (including its resume of a reaped session). Never focused: the page-load `#session=` / stashed-anchor restore and its auto-resume, and browser back/forward (`popstate`). Also skipped when the prompt bar is disabled (a crashed or exited session), on a touch-primary device (`(hover: none)`, so the on-screen keyboard does not cover the conversation just opened), while a modal dialog or the image overlay is open, and when focus is already in another text field. Callers pass `{ userGesture: true }` to `selectInstance`; the default is off. Logic: `focusPromptAfterSelect` in `web/src/features/session/promptFocus.ts`.
- **Row open target and actions** — a session row (`SessionRow` in `web/src/features/sidebar/rows.tsx`) and a conductor row (`ConductorBlock` in `web/src/features/sidebar/ConductorsList.tsx`) open through their own button (`[data-row-open]`: the dot, the label, the ago label and the unread pill), which Enter and Space activate; a click anywhere on the row opens it too. That button's accessible name is `label, status`, then `, <playbook · stage>` and `, N unread` when the row has them, comma-separated because a status can itself contain ` — ` (`idle — waiting on a worker`) (`rowName` in `web/src/features/sidebar/rows.tsx`; the status is the dot's tooltip text); the ago label is not part of it, so the name holds steady as time passes, and the tooltip (the session id, …) is its description. The caret (`Show workers`), `↑` and `×` are buttons beside that button, never inside it, so Enter or Space on one runs that action and never opens the session.
- **Conducted sessions** — a session spawned via the MCP `spawn_instance` tool (orchestrator-driven) rather than the browser/HTTP path is marked **conducted** (a worker an orchestrator conducts; the orchestrator itself is the `.conduct` session). Orthogonal to persistence (normal or persistent): the conducted marker is **durable** — the `conducted` fact on the session's record in `<store>/sessions.json`, keyed by the public id and written **at spawn** together with `parent` (the spawning conductor's public id; `conducted` is re-asserted on each turn-end) — every session, conducted or not, also records its `project` and `worktree` at spawn — so it survives exit, restart, `/clear`, and `--resume` (a UI-resumed conducted session re-acquires the marker from the store). Set **only** in the MCP `spawn_instance` handler — plain UI spawns stay non-conducted. Grouping precedence: a conducted session renders in the Conducted group; a conducted **and** normal session renders in the Conducted group but keeps the warm normal-row label colour; a persistent-but-not-conducted session sits in the Persistent group. Pure conducted rows get a cool label tint (`SessionRow` in `web/src/features/sidebar/rows.tsx`). It's a grouping, never a filter — conducted sessions stay fully visible in `list_sessions`, the HTTP session APIs, and the sidebar. The marker goes with the session's record only when its last transcript is deleted (Settings → Archived) or when the boot cleanup finds no transcript left in its lineage (**Startup session cleanup** in [session-actions.md](session-actions.md#session-actions-and-recovery)); it survives the exit archive and the boot pending-archive sweep, staying meaningful on the archived row.
- **Live owner + awaiting-user** — every live row reports `rootSessionId` (the conductor at the root of a live worker's spawn chain) and `parentSessionId` (its immediate spawner) (null for a hand-spawned session and for anything not live; never on a disk row), and every live and disk row reports `awaitingUser` (`question` / `plan`) + `awaitingUserSource` (`tool` / `text`) while the session's last ask has had no real user message since. Derived from the session's own transcript, so it holds across a restart or resume; never set on a conducted worker. Exposed on `GET /api/instances`, `GET /api/projects/:name/sessions`, `list_sessions` and `describe_session`. Detail: [architecture.md](../architecture.md) → "Ownership and awaitingUser". The sidebar draws `rootSessionId` as the conductor colour and a live `awaitingUser` as the needs-you strip and the waiting-on-you ring (see **Sidebar lenses**).
- **Sidebar lenses** — two views of the sidebar tree, switched by the **Conductors / Projects** toggle under `🎼 Conduct` (`setLens` in `web/src/app/ui.ts`). Per-browser choice in `localStorage` (`code-conductor:sidebar-lens`, `conductors` \| `projects`); a fresh profile, a garbage value or unavailable storage opens **Conductors**. Switching keeps each lens's scroll offset (`lensScrollOf` / `setLensScroll` in `web/src/features/sidebar/state.ts`) and open groups (`sidebarStore`, same file). Between the header row and the footer, the sidebar's fixed chrome, top to bottom, is `🎼 Conduct` (full width) → the needs-you strip → the toggle, with the project `≡` menu beside it → the Projects-only filter row (the text filter and the compact scope trigger); the list below it is the only part that scrolls (`[data-sidebar-body]` in `AppSidebar`). The list keeps a minimum height, so on a short sidebar the strip shrinks first. The phone drawer follows the same rule.
  - **Conductors** (`web/src/features/sidebar/ConductorsList.tsx`) — one block per top-level conductor — a `.conduct` session that is not conducted (`isTopLevelConductor` in `shared/conductors.ts`) — live ones first, newest activity first.
    A **section lead** (a conducted `.conduct` session) has no top-level block.
    While live it is a **conductor block nested in its lead's tree**, before the lead's project groups (most recently active first): its own colour bar, caret (collapsed by default, its expansion kept like any conductor's), status dot, title (in the conducted-row colour), its `playbook · stage` line, ago label, unread pill and, while normal, the `↑`; no chips and no `×`.
    Its caret expands the same project → main-checkout workers → worktree → workers tree, built from its own direct workers.
    The lead's tree has no `.conduct` project row.
    A worker counts as the section lead's while the section lead is live and spawned it (`liveDirectOwnerOf` in `shared/conductors.ts`); otherwise it sits under its project in the lead's tree.
    Once the section lead is not live it is in no sidebar list.
    A row shows the status dot (same semantics as a session row, awaiting-wake included), the title — the session's own title, else its first prompt (80 chars), else the sessionId prefix — the ago label, an unread pill, and, on an **Inactive** row only, the session row's hover-revealed `×` (`Archive session (keeps history)`, same confirm).
    That `×` archives the session to Settings → Archived through `POST /api/projects/.conduct/sessions/:sid/archive` (retried with `?force=1` on 409), or through `DELETE /api/instances/:id` for an exited conductor with no transcript listed yet.
    A **live** conductor row has no `×`: it closes from its needs-you strip entry (see **Close**).
    Closing never stops the conductor's workers.
    A **live normal** conductor row ends in the always-visible `↑` (`Make persistent`), with the confirm `Make this conductor persistent? … It will move to Inactive instead of being archived when it stops.` and `POST /api/instances/:id/persist`; a conductor made persistent keeps its row without the `↑` and on exit lands in **Inactive** instead of Archived.
    Under it, one chip per project where it has had a worker **spawned**, directly or by one of its workers (a project it only prompted gets none): a **live** chip (solid, brighter) where it has a live direct worker now (a live section lead's workers are the section lead's, so a lead's `.conduct` chip is live while it has a live section lead, and a project only its section lead works in shows on the lead as idle once spawn history records it), an **idle** chip (dashed, dimmed) where it has only had a worker spawned before (`GET /api/conductors/projects`) — so a persistent or inactive conductor keeps showing where it has worked.
    Live chips come first by name, then idle chips by their newest spawn or renew/prune rotation first (by name on a tie); a project with a live worker is only ever a live chip.
    An idle chip for a project that is no longer registered is dropped (re-registering the name brings it back).
    Both kinds are display-only: a plain label, no click action, no tooltip, not focusable.
    On a top-level block, `no live workers` shows whenever the chip list is empty (a nested section-lead block has no chip row): no live worker and no *registered* recorded project.
    Clicking the row opens the conductor (a non-live one resumes in `.conduct`); the caret expands a tree of its chip projects, in chip order: a live project is its project row → workers in the main checkout → each worktree holding one (sorted by name) → its workers, newest first; an idle project is its project row followed by its surviving recorded worktrees, or the row alone when none survive.
    Every chip project, live or idle, lists each worktree a past worker of this conductor ran in (the worker's recorded `worktree`) that still exists — is in the project's worktree list — sorted by name among its live worktrees, as a dimmed worktree row (`≡`, its ⋮ and the ahead/behind pill, no session rows); a worktree with a live worker of this conductor renders as a live one, once, and one whose only live worker belongs to another conductor renders dimmed.
    A deleted worktree drops out on the next project refresh.
    Matching is by name, so a worktree re-created under the same name shows with its current branch.
    Worker rows show `playbook · stage` verbatim on a second line when bound — once when the stage is named as its playbook (`stageText`).
    Project and worktree rows carry the same ⋮ menus as the Projects lens, Delete… and Remove worktree… included, under the rules in **Project row menu** and **Worktree row menu**; a remote project's system pill opens its target dialog; worker rows have no close `×`.
    A **live normal** worker row ends in the always-visible `↑` (`Make persistent`) — same confirm and `POST /api/instances/:id/persist` as the Projects lens; a worker made persistent stays in the tree without the `↑`.
    Conductors that are not live sit in a collapsed **Inactive (n)** group at the bottom, newest activity first: every **non-archived, non-conducted** `.conduct` session on disk with no live instance (`GET /api/projects/.conduct/sessions`), plus any non-conducted `.conduct` instance that is exited or crashed.
    An archived conductor is in no Conductors group — including a normal one, which is what `🎼 Conduct` spawns and which is archived on exit unless it was made persistent with `↑`; it is found in Settings → Archived.
    The group keeps the user's open or closed choice for the life of the page, including while it is gone because every conductor is live.
    A conductor that still has a listed instance is placed by that instance, since an instance does not report its session's archived state.
    Nothing when there are none: `no conductors yet — tap 🎼 Conduct`.
    A pristine conductor has no row until its first prompt, or until leaving it with a draft lists it (see **Pristine conductor**).
  - **Projects** (`web/src/features/sidebar/ProjectsList.tsx`) — the project tree (workspaces, projects, worktrees, sessions), plus a filter row: the **text filter** input and the **conductor filter** trigger (labelled **All**, **Hand** or the chosen conductor's label, cut to fit, the full label in its `title`; the scope menu opens below the filter row and spans its full width; an item too long to fit is cut with an ellipsis, its full label in its `title`). The filter offers **All sessions**, **Hand-spawned only**, and one entry per conductor with a chip (live conductors, then inactive conductors), then each live owner that is not a conductor — a hand-spawned session that spawned workers. A selected owner lists only its chip projects plus the projects of the live sessions it is the root (`rootSessionId`) of, a live section lead's workers included (`filterProjects` in `web/src/features/sidebar/derive.ts`), and the workspaces holding one; where it has live sessions it lists only the worktrees and Sessions groups that hold one, force-opens the Worktrees groups without recording that as the user's expansion (clearing restores it), and shows only its session rows. **Hand-spawned only** lists only the projects, workspaces, worktrees and main-checkout Sessions groups holding a hand-spawned session — a non-archived, non-conducted one on disk (the place's `handCount`) or a live non-conducted instance — so a project with no sessions, or only conducted ones, is hidden; it drops conducted rows and the Conducted group, and force-opens nothing. Summary counts stay unfiltered. An idle project (spawn history, nothing live) shows as its project row alone. A selected owner that is no longer offered (no live session and no registered idle chip) falls back to All. A selection the filter hides switches it — see **Reveal on select**. A root with spawn history that is not a conductor is not offered.
    - **Text filter** (`FilterBar.tsx`; matching in `textFilter.ts`, state in `textFilterState.ts`, session loading in `sessionSearch.ts`) — the query is split into case-insensitive tokens; every token must appear somewhere along a node's path, ANDed with the conductor scope (a row the scope hides never matches). A workspace's path is its name, a project's adds the project name, a worktree's adds its name and branch, a session's adds its label. "Other projects" is not searched.
      - **What shows:** a workspace-name hit shows its scope-visible projects whole, in the user's own open state (not forced open); a project-name hit shows the project whole and opens its workspace; a worktree hit (name or branch) shows it whole and opens the Worktrees group; a session hit keeps only the matching rows and opens the workspace, the Worktrees group and the Sessions group above it. Counts follow the filter (`(N)` on a band, `Worktrees (N)`, the Sessions summary count only what is listed); the scope's own counts stay unfiltered. Matches are highlighted in workspace, project, worktree and session labels (`<mark data-match>`); accessible names are unchanged.
      - **Open state:** groups the filter opens use a separate in-memory collapsed list (`textFilterStore`), so collapsing one is transient and clearing the query restores the user's own state exactly. Only an explicit toggle of a group the filter did not open, or a selection's reveal, writes the user's state. The query is never persisted.
      - **Empty state** `No matches for '<query>'` with **Clear filter**; the field's ✕ clears too. **`/`** focuses the field from anywhere that is not text entry or under an open dialog or menu (switching to the Projects tab first); **Esc** in the field clears and blurs it, and in the phone drawer does not close the drawer (a second Esc does).
      - **Session lists** load lazily, so while the query is non-empty `sessionSearch.ts` fetches the lists the scope can show: debounced (`SESSION_SEARCH_DEBOUNCE_MS`), at most `SESSION_SEARCH_CONCURRENCY` requests outstanding at once (a request still running from an earlier search session keeps its slot after the query is cleared, until it settles or `SESSION_SEARCH_TIMEOUT_MS` passes, after which the loader stops counting it and treats the place as attempted; the request itself is never cancelled, so a late answer still fills the list; a place whose load is still in progress, released or not, is never requested a second time until it settles), each place at most once per search session, refetching a place only when its summary fingerprint (count and last activity) changes or a place-specific `sessionsStale` names it. A fingerprint change while a place's load is in flight discards that load's rows and refetches the place. Changing the conductor scope during a search re-plans for the new scope and drops queued loads it cannot show. **All** fetches places with sessions; **Hand** only places with hand sessions; a conductor scope fetches nothing (disk rows carry no owner), so it matches live rows only. Archived rows are never requested. `Searching sessions…` shows while loads are pending; a failed list degrades to the place's live rows and is not retried until its fingerprint changes.
  - **Conductor colour** — `conductorColor(sessionId)` (`shared/conductorColor.ts`): a hash of the sessionId onto one of `HUE_SLOTS` evenly spaced hues at a fixed saturation and lightness. Drawn as one device, a left bar in that colour: on each conductor block, a nested section-lead block included (faded for an inactive one; its hover fill and selected outline never cover it) and its strip entries, on the filter row while a conductor is selected, and in the Projects lens from **live** direct ownership only — the live section lead that spawned a worker, else `rootSessionId` (`liveDirectOwnerOf`), for both the worktree row and the session row; the conductor filter scopes by the root (`rootSessionId`): a worktree whose live conducted sessions all share one conductor carries the bar on its worktree row and none on its session rows; a worktree with several conductors stays plain and each live conducted row carries its own; a conducted row in a project's main checkout always carries its own. Hand-spawned and non-live sessions carry none. Every coloured row names its conductor in the tooltip (`conductor: <label>`). The same colour marks a conducted worker's header owner chip and composer border (see **Composer** and **Title block**); the neutral `Conducted worker` chip of an unknown owner carries none.
  - **Needs-you strip** (`Strip` in `web/src/features/sidebar/Strip.tsx`, grouping in `shared/needsYou.ts`) — one boxed strip above the toggle, the same in both lenses (the conductor filter does not narrow it), fixed above the toggle: it does not scroll with the list.
    Its height is capped (on `Strip`'s root) and it scrolls within itself past the cap.
    Groups in order **Waiting on you (n)** → **Running (n)** → **Finished (n)**, each only when non-empty; the Finished head reads **Finished (n · k new)** while k of its entries are unread (see **Unread indicator**); with every group empty the strip is not rendered and takes no space.
    Built from **live** instances only (never a disk row, so never an archived session).
    Each session lands in one group, read from the status its dot renders (`displayStatus ?? status`): `awaitingUser` set → Waiting, whatever the run state; else `idle` with no pending wake and no running background job (`waitingOnJob`) → Finished; else (`turn`, `running`, `spawning`, idle on a worker or on a job) → Running.
    Eligible: every live top-level conductor (a non-conducted `.conduct` instance) and every live hand-spawned session (not conducted, not `.conduct`); conducted workers, section leads included, are never listed.
    Within a group: conductors first (newest activity first), then hand-spawned sessions (newest `lastResponseAt ?? createdAt` first).
    An entry is the status dot plus the label (title → first prompt → sessionId prefix, never italic), followed by the compact auto-resume badge while the session has a resume armed: `⏸ <time>`, or `N · ⏸ <time>` while N messages are queued; its tooltip leads with the header chip's full wording, and the label keeps a 2em floor, below which the badge truncates with an ellipsis; conductor entries carry the conductor colour bar.
    The state is not rendered as text — it is in the `title` (`<label>\n<reason>`) and `aria-label` (`<label> — <reason>`, plus ` — resumes at <time>[ · N queued]` while a resume is armed), the reason being `<ask> · <run>` in Waiting (ask: `question`, `plan approval`, `asked in text`; run: `idle`, `on a worker`, `on a job`, `running`, else the raw status), `working` / `on a worker` / `on a job` in Running (a pending wake wins over a job), `turn ended` in Finished (`turn ended · unread` on an unread entry).
    An **unread Finished entry** (`data-unread`) has a blue ring around its status dot (`unreadRing` on `Dot` in `web/src/features/sidebar/rows.tsx`) and a semibold title (weight marks unread only; selection never sets it): the waiting-on-you ring's geometry in blue, never amber, so it never reads as Waiting.
    A Finished dot is always plain idle, so the ring sits on the grey fill; Waiting and Running entries never show unread.
    Clicking an entry opens the live session (and closes the phone drawer).
    Every entry, conductor or hand-spawned, also ends in the session row's `×`: hover-revealed, always visible on touch and on keyboard focus, a sibling of the entry button, so clicking it never opens the session, but drawn inside the entry's box at its right edge; the box (hover fill, selected outline, owner bar) spans the full row.
    Its action follows the close rule (see **Close**).
    An entry follows its session across a crash and resume: its click opens, and its `×` closes, the session's current instance.
  - **Waiting-on-you ring** (`data-needs-you` on `Dot` in `web/src/features/sidebar/rows.tsx`) — an amber ring around the status dot while a **live** session has `awaitingUser`; the fill keeps the run state (amber for plain idle, blue on a worker, green in a turn with the pulse dropped). Tooltip `waiting on you (<ask>) · <run>`. Drawn on strip entries, conductor rows and the session header; session rows and Conductors worker rows are never ringed, and neither is an inactive conductor.
  - **Selected session** — selection is marked by a fill and a ring, distinct from unread, on session rows, conductor rows and strip entries alike (`data-active` is set on exactly the selected row). Unread is the pill and a semibold label, so a selected, unread row keeps both marks: selection never reads as unread, and unread never hides selection. On a session row or strip entry, which draw their own owner bar, the ring never replaces the bar; a conductor row starts past its block's bar, so neither its ring nor its hover fill touches it. Hover stays fill-only.
  - **A first prompt the server or the CLI wrote** is shown by name in a label (and in the MCP `list_sessions` / `describe_session` rows), never by its raw marker, frame or tag text: a wake-callback stub reads `Wake: <its summary>`, a `send_prompt({forward})` frame by the first non-empty line of the conductor's instruction (`Forwarded worker output` when that is empty), a `renew_session` seed `Context renewed`; so does the head a renewed session's file opens with (the CLI's `<local-command-caveat>` record, or its `/clear` command line), and any other `<command-name>` line reads as the bare command (`/compact`). A title still wins, and a person's prompt is shown as is. A transcript whose first record does not end within `FIRST_RECORD_CAP` (`src/projects.ts`) reads from disk as having no first prompt. It covers the label, tooltip and accessible name of conductor rows, needs-you entries and session rows (both lenses; through `shared/conductors.ts` and `sessionLabel`), the conductor filter's options, an attention notification's body, the session view's Workers panel (`web/src/features/session/SessionPanels.tsx`), **Settings → Archived** (`web/src/features/settings/ArchivedSection.tsx`) and the `displayLabel` every `GET /api/instances` row carries for plugins. One rule: `readablePrompt` / `promptPreview` / `sessionLabel` in `shared/promptPreview.ts`.
  - **Reveal on select** — every selection (a sidebar row, a strip entry, the sub-agent panel, `#session=` / back, a notification click, a spawn / resume / fork follow) reveals the session in **both** lenses, once per selection (`web/src/features/sidebar/reveal.ts`); a group the user collapses afterwards stays collapsed until the next selection, and a click on the selected row or its strip entry is a selection. Selecting a section lead expands its lead conductor's tree; selecting a section lead's worker also expands the section lead's block. The reveal records the same expand state a click on each group does (a workspace's persists in `localStorage`). The sidebar drawer keeps its scroll offset across closing and re-opening, and re-opens onto the selected row. A reveal never switches or clears the Projects tab's **text filter**: a selection while filtering still records its expand state (which survives clearing the query), and a selected row the query excludes stays hidden.
    - **Conductors** — a worker opens the bubble of the conductor at the root of its spawn chain (a worker spawned by an ordinary worker lists flat under it; a live section lead's worker sits in the section lead's nested block, which also opens), plus the *Inactive* group when that conductor is not live. A selected conductor opens no bubble, its own included; when it is not live, only *Inactive* opens. A session with no conductor row (hand-spawned, or dead with no owner) opens nothing.
    - **Projects** — opens the session's workspace, its project's Worktrees group, and its Sessions group (re-opening one the user collapsed, which lazy-loads). A conductor has no Projects row, so selecting one changes nothing there.
    - **Filter** — a conductor filter that hides the row is switched: to the session's owning conductor, or **Hand-spawned only** for a hand-spawned session, or **All sessions** for a conducted session with no owner reported (a dead one). A filter that already lists the row stays.
- **Unread indicator** — one server-side fact per session, so it is the same on every device and survives a page reload and an orchestrator restart: the session record's `turnEndSeq` (every real turn end, whoever started the turn — you, a conductor's `send_prompt`, a wake callback, the boot resume notify) and `viewedSeq` (the last turn end you saw). Unread ⇔ `turnEndSeq > viewedSeq`.
  - **Where it shows** — a numeric blue pill (`UnreadPill` in `web/src/features/sidebar/rows.tsx`, `turnEndSeq − viewedSeq`) on Projects session rows and Conductors rows, live or not, with the row's label in semibold (weight marks unread only; selection never sets it); and on **Finished** strip entries as a blue ring on the status dot + semibold title, counted in the Finished head (see **Needs-you strip**).
  - **What counts as viewed** — at the moment of the check: the session is the open pane, the browser tab is visible, no full-page view (Settings, Costs, Commits, Review, a plugin) owns the hash, and none is still open. The phone drawer over the pane does not count as hidden. Checked on every selection (after it closes the open view), every instances refresh (so a turn that ends while you watch is read at once), when the tab becomes visible, and just after every full-page view exit — ⚙ or Escape out of Settings, a view's back button or Escape, the app switcher's Conductor entry, or a hash change (`startViewedMarker` in `web/src/app/viewedMarker.ts`, which re-checks on every route change; `POST /api/sessions/:sid/viewed`). An exit straight into another view (Settings → **Costs** in the sidebar `≡` menu) or one that leaves another view open (the Conductor entry with Settings showing) marks nothing; the session is marked when the last view closes. Marking one device viewed clears it on every device.
  - **What never counts** — anything a conductor or worker does over MCP (`get_recent_messages`, `get_transcript`, `describe_session`, `send_prompt` forwards): there is no MCP route to the marker.
  - A record with no turn marks reads 0/0, so a new session is read until its first turn ends. Page load removes the `code-conductor:unread` `localStorage` key.
- **Close (the `×` action)** — the `×` is **one step down** from where its session is; `closeActionOf` (`shared/closeAction.ts`) is the one mapping, read by the sidebar for the tooltip and by `closeSession` (`web/src/app/sessionActions.ts`) for the route. It is on every needs-you strip entry, every Projects-pane session row, and every **Inactive** conductor row.

  | Session state | Action | Request | Confirm |
  |---|---|---|---|
  | live, persistent, idle | **stop** | `DELETE /api/instances/:id` | none |
  | live, persistent, busy (`turn`, `running`, `spawning`) | **stop** | same | `Stop session … It is still working — the running work is killed. The transcript is kept and it stays resumable.` |
  | live normal | **archive** | as below | always |
  | not live (disk row, exited, crashed) | **archive** | as below | always |

  - **Stop** keeps the transcript: the session leaves the live list and reappears as an **Inactive** conductor or a resumable session row. An open stopped session is deselected. A persistent session that never wrote a transcript (spawned, never prompted) has nothing to resume, so it leaves no row.
  - **Archive** (never deletes): single confirm, `POST …/sessions/:sid/archive`; on 409 the client auto-retries with `?force=1` (stops the live instance) without a second prompt. A session with no persisted transcript yet (a live normal one is always so while alive) goes through `DELETE /api/instances/:id` instead, and a normal session archives itself on exit. Archived sessions keep their jsonl (still resumable) + title + conducted markers and **disappear from the sidebar entirely** — they're managed only from **⚙ Settings → Archived**. Sessions are never deleted from the sidebar.
  - **Tooltip and `aria-label`** name the action, re-patched every render: `Stop session` or `Archive session (keeps history)`.
  - The `↑` beside it on a live normal row reads `Make persistent` (tooltip, `aria-label`, confirms and failure alert) and calls `POST /api/instances/:id/persist`. The non-conductor confirm reads `Keep this session in <project>? … It will stay listed in Sessions instead of being archived when it stops.`
- **Archived page (Settings → Archived)** — lists every archived session grouped by owning project (`GET /api/archived`), plus every session of a **deleted worktree** (archived or not), whose worktree tag reads "(worktree removed)". Each project group is a collapsible **collapsed by default**; expanding reveals its archived sessions (title/first-prompt/sid + worktree tag + last-active). Per session: **Open** (shows it read-only in the session view, paging its transcript from disk — the **Ended pane** entry), **Restore** (not offered for a deleted worktree's session, which cannot resume; `POST …/restore` un-archives it, then resumes/spawns it and navigates straight to it, closing Settings — restoring alone doesn't create a live instance, so the client drives `resumeSession` itself) and **Delete** (confirm → `DELETE …/sessions/:sid`, the single permanent jsonl-removal path; cannot be undone). The `.conduct` (orchestrator) project's group is always pinned first and rendered as **Conductor** instead of its raw folder name — sorting/labeling happens client-side (`orderGroups` and `ArchivedSection` in `web/src/features/settings/ArchivedSection.tsx`).

# Environment variables

The registry is `ENV_VARS` in `src/env.ts`. `tests/env-registry.test.mjs` fails when code in the `PRODUCTION` scope of `scripts/env-reads.mjs` reads a name `ENV_VARS` lacks (`bin/` launchers are outside that scope), or when this table's names and `ENV_VARS`'s keys differ. Measure with `node scripts/env-reads.mjs --docs docs/environment.md`.

| Var | Effect |
|---|---|
| `PROJECTS_ROOT` | Projects root (default: parent dir of this repo, resolved from `import.meta.url`). |
| `CC_PROJECTS_ROOT` | Set by cc in **every** worker's spawn env (local and remote-backed alike, same host value) to `path.resolve(projectsRoot())`, in `Instance`'s spawn in `src/instances.ts`. Assigned after the backend's env pairs, so neither a backend pair nor a host value overrides it. Not given to the session one-shot (`src/sessionOneShot.ts`) or the shell-env probe (`src/claudeShellEnv.ts`). A remote worker's redirected Bash runs on the remote without cc's env, so it never sees the variable there. Read by `harness/pluginDir.mjs` (`resolvePluginDir`), which appends `.plugins/<name>`; unset, that resolver derives the root from `git rev-parse --path-format=absolute --git-common-dir`. |
| `CC_SESSION_ID` | Set by cc in **every** session's spawn env to the session's public `sessionId`, in `Instance`'s spawn in `src/instances.ts`; stripped by `cliEnvBase` and the plugin supervisor. Contract: [protocol/subprocess.md → Session identity env](protocol/subprocess.md#subprocess-protocol). |
| `CC_SESSION_KIND` | Set by cc in **every** session's spawn env to `sessionKindOf(inst)` (`conductor` \| `worker`, `src/conduct.ts`). Contract: [protocol/subprocess.md → Session identity env](protocol/subprocess.md#subprocess-protocol). |
| `CONDUCTOR_URL` | cc's base URL `http://127.0.0.1:<port>`: set for a plugin backend by the registry (`src/plugins/registry.ts`), and in every session's spawn env from `InstanceManager.conductorUrl()` (unset with no port). Contract: [protocol/subprocess.md → Session identity env](protocol/subprocess.md#subprocess-protocol). |
| `CLAUDE_CONFIG_DIR` | The CLI's own config directory on this machine (default `~/.claude`). Read through `claudeConfigDir()` by every cc reader of CLI state — settings, credentials, plans, transcripts, readiness — because the CLI honours it and a reader that spelled `~/.claude` would be looking where the CLI is not writing. cc also OVERRIDES it in a remote-backed worker's spawn env, pointing it at that remote's own config dir; a local spawn is given no value at all, because setting it even to its own default relocates the CLI's global config from `~/.claude.json` to `<configDir>/.claude.json`. |
| `CLAUDE_SECURESTORAGE_CONFIG_DIR` | Set by cc in a remote-backed worker's spawn env only, so credentials come from the real config dir without being linked into the per-remote one. `''` (empty) when the host's config dir is the default — it resolves to `~/.claude` AND keeps the unsuffixed secure-storage service name, which is keyed on the variable's presence rather than its value; otherwise the explicit path. |
| `CLAUDE_PROJECTS_ROOT` | Root the orchestrator reads LOCAL session jsonl from (default: `<claudeConfigDir()>/projects`). Outranks the derivation; honoured by the fake CLIs in tests. A remote-backed place ignores it — its root comes from `transcriptRoot()`. |
| `HOST` / `PORT` | Bind address / port (default `127.0.0.1` / `8787`). |
| `CC_BASE_PATH` | URL path prefix cc is hosted under behind a reverse proxy, e.g. `/apps/cc-2` (unset = root). Parsed by `parseBasePath` (`src/basePath.ts`) inside `createServer`: must start with `/`, one trailing `/` is dropped, empty/`.`/`..` segments and any character outside RFC 3986 `pchar` (`?`, `#`, `%`) are refused, so an invalid value fails boot with exit 1. Passed on by `entryStartOptions` → `start` → `createServer`; a restart inherits it through `process.env`. Contract: [protocol/rest-settings.md → Base path and reverse proxies](protocol/rest-settings.md#base-path-and-reverse-proxies). |
| `CC_SKIP_WEB_BUILD` | `=1` skips the web build — at boot and before a restart: `server.ts`'s entry block calls `start(entryStartOptions(process.env))`, whose `buildWeb` is false only for exactly `1`, so `/` serves whatever `web/dist` already holds (or the building page) and `runRestart` stages nothing. `tests/run.mjs` sets it, so the `node server.ts` children the suite spawns never build `web/dist` concurrently. |
| `CC_SKIP_DEPS_SYNC` | `=1` skips the dependency check and install before a restart (`syncDeps` from `entryStartOptions`, false only for exactly `1`). `tests/run.mjs` sets it, so a test that restarts a `node server.ts` child never installs into the shared `node_modules`, whatever `package.json` its branch carries. |
| `CC_RESTART_SUPERVISOR` | Internal: set by `docker/supervise.mjs` on the server it launches (the supervisor's pid); read and deleted at boot by `takeRestartSupervisor` (`src/restartSupervisor.ts`), so it never reaches a CLI, plugin or project command. |
| `CC_ROOT_LOCK_HANDOVER_WAIT_MS` | How long a restarting server waits for its replacement to adopt the projects-root lock before it exits anyway (`ROOT_LOCK_HANDOVER_WAIT_MS`, `src/rootLock.ts`; default 120 000, sized for Termux's throttled module load). See [The projects-root lock](components/headless.md#the-projects-root-lock). |
| `CC_NPM_INSTALL_CMD` | The shell command `ensureDependencies` (`src/relaunchPrep.ts`) runs to install, for a restart and for self-update (default `npm install`, never `npm ci`: no lock is tracked). A test seam. |
| `CC_CONVENTIONS_DIR` | Replaces the shipped `conventions/` tree for all three convention scopes: fragments, cores and the conductor footer are read from `$CC_CONVENTIONS_DIR/<scope>/` (`conventionsDir`, `src/conventionsDir.ts`), per call. A test seam — the convention-skill suites point it at a temp copy (`tests/conventionsTree.mjs`) with skill parts appended, so no fixture ships in `conventions/`. |
| `CC_DEV_SERVER` | The server `npm run dev:web` proxies `/api`, `/ws` and `/plugins` to (default `http://127.0.0.1:8787`; `web/vite.config.ts`). |
| `CC_ISOLATED_ROOT` | Root of `npm run start:isolated`'s sandbox: `<root>/projects` is its `PROJECTS_ROOT`, `<root>/claude-config` its `CLAUDE_CONFIG_DIR` (default `${TMPDIR:-/tmp}/cc-isolated`; `scripts/run-isolated.sh`, which also requires `PORT`). |
| `INSTALL_ROOT` | Install root for whisper/piper (default: the central store `<store>`; honours `PROJECTS_ROOT`). |
| `CC_LOCAL_SYSTEM_PROVIDER` | Replaces the in-process `local` System with a `ProviderSystem` speaking the wire protocol to this command (a JSON array of argv, or a bare executable path). The seam the systems gate runs the whole suite over — see Testing. |
| `CC_CONFORMANCE_PROVIDER` | Points `tests/systems-protocol-conformance.test.mjs` at a third-party provider (a JSON array of argv). Test-only; the suite appends each `CAPABILITY_CONFIGS` entry's `flags` (`tests/referenceProviderHarness.mjs` owns the list), and its `remotes`/`remoteDescriptors` fixtures launch providers of their own with `--remote`/`--mirror`/`--exclude` — the full launch surface is `docs/systems-protocol.md` §10. |
| `CC_CONFORMANCE_REMOTE_ID` | Binds every conformance fixture handle to that target, so a provider serving only NAMED targets is exercised at all (unbound, §8 makes it refuse the core battery `ENOREMOTE`). The argv must declare the same id with `--remote`, or cc refuses the binding client-side on `remotes:false`. To that suite what `CC_LOCAL_SYSTEM_REMOTE_ID` is to `npm test`. Unset for every in-repo run, including the gate; a fixture that is ABOUT the unbound case passes `{ remoteId: null }`, which beats it. |
| `RUN_CLI_CONTRACT` | `=1` runs `tests/systems-cli-*.real.test.mjs` against the installed `claude`. Everything Systems' redirection rests on is undocumented CLI behaviour; running this is what makes an upgrade that changes it fail loudly instead of silently corrupting edits — but neither `npm test` nor `gate:systems` runs it, deliberately, so that protection arrives when someone invokes it and not before. |
| `RUN_FUSE_LIFECYCLE` | `=1` runs `tests/fuse-*.real.test.mjs` (the files over the shared harness `tests/fuseGateCase.mjs`): real `sudo`, real `unshare`, real FUSE, a fake `claude`. Needs `/dev/fuse`, `sudo -n`, `fusectl`, `gcc`, libfuse3 headers. **Run it with `TEST_CONCURRENCY=1`** — the files starve each other at the default concurrency; see [`src/systems/fuse/`](components/fuse.md#srcsystemsfuse). |
| `RUN_DOCKER_SYSTEM` | `=1` runs `tests/systems-docker-boundary.real.test.mjs`: the reference provider INSIDE a container over `docker exec -i`, so a wrong-machine bug cannot look like success. `CC_DOCKER` (default `docker`) and `CC_DOCKER_IMAGE` (default `node:24-slim`) tune it. **Doubly opt-in since the union became mandatory**: the host must also be able to mount it, because a worker there runs at the project's path INSIDE the container, which does not exist on the host. |
| `CC_TEST_SLOTS` | How many leased test suites may run at once on the box (integer 1–1024, default `DEFAULT_SLOTS`; anything else throws). See "Box-wide test slots" under Testing. |
| `CC_TEST_SLOT_PORT` | First loopback TCP port of the slot range (integer ≥ 1, default `SLOT_PORT_BASE` in `tests/testSlot.mjs`; slot *i* is `base + i`, and `base + slots - 1` must not pass 65535, else it throws). Moves the slots, e.g. for a test of the semaphore itself. |
| `CC_TEST_SLOT_HELD` | Set by a lease holder to its pid in the env of everything it spawns; a child that sees it takes no slot. Never set by hand. |
| `CLAUDE_BIN` | `claude` CLI binary. **Unset, empty or whitespace-only all mean the stock `claude`** — `docker/compose.yaml` ships `CLAUDE_BIN: ${CLAUDE_BIN:-}`, which renders as `""`. Tests default to an in-process fake (no subprocess — see Testing); `realProcess:true` tests inject `tests/fake-claude.mjs`. |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW` | Compact-window override seeded onto the `.conduct` orchestrator session (overridable per-session in Settings). |
| `TCC_LEGACY_BASELINE` | Legacy shell-installer baseline path override, read only by `migrations/0009-seed-legacy-shell-installer-baseline.mjs` (test injection). |
| `ORCH_DISABLE_MCP_AUTOREGISTER` | `=1` omits the `--mcp-config` auto-registration at spawn. |
| `CONDUCTOR_MCP_URL` | Set **by** cc, never read, for a plugin backend only: the anonymous `/mcp` URL. A worker has none (it calls through `run_code`), and an inherited value is removed. [mcp-applications.md → Env vars](mcp-applications.md#env-vars). |
| `ORCH_EVENT_RING_CAP` / `ORCH_SNAPSHOT_TAIL` | Event-ring cap (`ORCH_EVENT_RING_CAP`) / WS subscribe tail (`ORCH_SNAPSHOT_TAIL`) — defaults in `src/instances.ts`. |
| `ORCH_SUBSCRIBE_TIMEOUT_MS` | Idle-wake HEARTBEAT interval — how often an owned session that is mid-turn or holding its owner's wake pings its owner with the "did NOT finish" stub — **and** the ceiling `set_idle_timeout`/`idleTimeoutSeconds` will accept, so those can only shorten it. Those two MCP params take **whole seconds** and are capped at `DEFAULT_SUBSCRIBE_TIMEOUT_SECONDS` (`Math.floor(DEFAULT_SUBSCRIBE_TIMEOUT_MS / 1000)` — the floor is what preserves "can only shorten"); the constant itself and every layer below the handler stay ms. One number, both roles (`DEFAULT_SUBSCRIBE_TIMEOUT_MS`, `src/idleSubscriptions.ts`; default 30 min). |
| `ORCH_OVERAGE_RESUME_BUFFER_MS` | Overage auto-resume post-reset buffer (also the test seam). |
| `ORCH_OVERAGE_RESUME_SWEEP_MS` | Overage auto-resume wall-clock sweep cadence (default 30 s, fallback in `src/overageResume.ts`; test seam to fire the sweep fast). |
| `ORCH_OVERAGE_RECHECK_MS` | Recheck cadence for a parked (still-over / can't-confirm) auto-resume (default per `ORCH_OVERAGE_RECHECK_MS`; independent of accountUsage.ts's usage-cache cadence — most ticks just re-read the cache; test seam). |
| `ORCH_USAGE_POLL_MS` | Server-side usage-poll cadence for the overage trip (default 180000 ms, fallback `DEFAULT_POLL_MS` in `src/usageOverageMonitor.ts`). |
| `ORCH_DISABLE_POST_WORKTREE_HOOK` | `=1` disables the post-worktree-create hook entirely (result: `{ ran:false, skipped:'disabled' }`). |
| `ORCH_POST_WORKTREE_TIMEOUT_MS` | Timeout for the post-worktree-create hook (default 120000 ms, fallback in `src/worktrees.ts`). Non-fatal on timeout. |
| `ORCH_DISABLE_POST_WORKTREE_MERGE_HOOK` | `=1` disables the post-worktree-merge hook (result: `{ ran:false, skipped:'disabled' }`). Each hook has its own kill switch and timeout, and neither pair touches the other hook. |
| `ORCH_POST_WORKTREE_MERGE_TIMEOUT_MS` | Timeout for the post-worktree-merge hook's own run, not its wait in the per-project queue (default `WORKTREE_HOOK_TIMEOUT_MS`, `src/worktrees.ts`). Non-fatal on timeout. A merge waits for the hook inside Node's default `http.Server` `requestTimeout` (300 s — `server.ts` sets no override), and `/mcp` is on the same `http.Server` as the REST routes: a value past it drops the response to a REST merge and to MCP `merge_worktree` alike, while the merge has still landed. Documented, not clamped. |
| `ORCH_SHELL_COMMAND_TIMEOUT_MS` | Ceiling on one redirected command in a session on a system (default 605000 ms, `DEFAULT_COMMAND_TIMEOUT_MS` in `src/systems/providerShell.ts`, derived as the built-in Bash tool's documented 600000 ms max plus 5000 ms of slack, so that for any tool timeout **up to that documented max** the caller's own timer expires first and cc's never decides the outcome). It is enforced by the PROVIDER, as the `exec` frame's own `timeoutMs` — **except when the provider reports nothing**, where what fires is cc's own abandon timer in `src/systems/providerSystem.ts` at `timeoutMs + EXEC_TIMEOUT_SLACK_MS` (at this default, 610 000 ms; measured at 610 083 ms), and the failure carries `ExecResult.abandonedAfterMs` so the message names the wait actually served rather than the provider's deadline. **It does exactly one job — the longest a command may run**: there is no long-lived shell whose wedge it also bounds and no queue whose waits it also bounds, so the value is simply correct for that one job rather than a compromise between three. A caller's tool `timeout` cannot move it and no longer reaches cc at all. **A tool timeout ABOVE the documented max is unmeasured** — the rig could not make the model emit one — and if the CLI honours such a value it outruns this ceiling, so cc would kill a command the CLI is still waiting on; raising this var is what restores the ordering, and it is the answer rather than a placeholder because the CLI's true maximum is not cheaply measurable. Also raise it for legitimately longer background work — a local background Bash has no deadline at all. `local` runs no redirected command and so has no such ceiling. |
| `ORCH_OP_TIMEOUT_MS` | Ceiling on a **provider** operation the caller did not bound itself — every `runGit` call (a timeout there is a `GIT_TIMED_OUT` system refusal, 504), every derivation in `docs/systems-protocol.md` §7, the settings-refusal reads on the create path (`src/systems/bashRules.ts`), `readFile`/`writeFile`/`describeRemote`, and a terminal's OPEN — never its life (default 60000 ms, `DEFAULT_OP_TIMEOUT_MS` in `src/systems/providerSystem.ts`). Raise it for a slow transport, a cold cache, or a tree large enough to push a checkout or an `rm -rf` past the bound; `local` has no such ceiling. Also the seam that makes a registry-built handle's bound testable without waiting it out. |
| `WHISPER_CLI` / `WHISPER_MODEL` / `WHISPER_MODEL_NAME` / `FFMPEG_BIN` | whisper binary / model path / install model name / ffmpeg path. |
| `PIPER_PYTHON` / `PIPER_VENV` / `PIPER_VOICE` / `PIPER_VOICE_NAME` / `PIPER_SYNTH_SCRIPT` | Piper venv python / venv dir / voice path / install voice name / synth script. |
| `ANTHROPIC_API_KEY` | Credential fallback when `~/.claude/.credentials.json` is absent. |
| `RUN_REAL_CLAUDE` | `=1` runs the opt-in real-claude smoke test. |
| `RUN_REAL_NPM` | `=1` runs the C3 fresh-resolution row of `tests/windows-installer-contract.test.mjs`: `npm install --package-lock-only --ignore-scripts` of a copy of `package.json` against the registry (needs network). |
| `RUN_WIN_SMOKE` | `=1` runs `tests/win-smoke.real.test.mjs` on a Windows host against a real signed-in `claude` and Git for Windows. Run it directly with `node --test`, not through `npm test`. See [the gated real-dependency suites](testing-systems.md). |
| `PATH` / `Path` / `ProgramFiles` / `SystemRoot` / `LOCALAPPDATA` / `LD_LIBRARY_PATH` / `SHELL` | Host OS variables cc reads but does not own (kind `platform` in `ENV_VARS`): the executable search path, the Windows directories the Git for Windows bash search uses, the library path whisper.cpp is prepended to, the login shell the terminal starts. Readers: `src/platform/win32.ts`, `src/systems/fuse/tierTable.ts`, `src/systems/fuse/wrap.ts`, `src/transcribe.ts`, `src/systems/ptyHost.ts`. |
| `CC_RUN_URL` / `CC_RUN_TOKEN` / `CC_RUN_MEMBERS` | Internal: set by `run_code` for the runtime child (`RUN_URL_ENV`, `RUN_TOKEN_ENV`, `RUN_MEMBERS_ENV` in `src/codeMode/runtimeApi.ts`) and read back by `src/codeMode/runtime.ts`. Contract: [code-mode.md](code-mode.md). |
| `CC_SERVER_BOOT_SHA` / `CC_SERVER_BOOT_UNKNOWN` | Internal: the commit the running server booted from, or why it is unknown, handed to merge hooks that land in the server's own checkout (`bootCommitFromEnv` in `src/webPostMerge.ts`). See [components/web.md](components/web.md). |
| `CC_ROOT_LOCK_HANDOVER` | Internal: set by a restarting server for its replacement (`ROOT_LOCK_HANDOVER_ENV` in `src/rootLock.ts`), read and deleted at boot. See [components/headless.md](components/headless.md#the-projects-root-lock). |
| `WHISPER_INSTALL_SCRIPT` / `PIPER_INSTALL_SCRIPT` | Override the installer script for whisper / Piper (`scriptEnvVar` in `src/whisperInstall.ts` / `src/ttsInstall.ts`, read by `src/installRunner.ts`). |
| `CC_FUSE_SOURCE_OVERRIDE_ROOT` | Selects the source root the FUSE union draws from instead of the session's own (`src/instances.ts`). |
| `CC_FUSE_TRACE` | `=1` turns on the FUSE plan trace (`resolveTraceEnabled` in `src/systems/fuse/plan.ts`). |
| `CC_FUSE_EVENTS_MAX_BYTES` | Byte size past which the store-wide FUSE event log (`fuseEventStore()`) is rotated to `events.log.1` before the next harvest appends (`fuseEventStoreMaxBytes()` in `src/systems/fuse/plan.ts`; default `FUSE_EVENT_STORE_MAX_BYTES`, 8 MiB). Read per harvest. A value that is not a positive whole number falls back to the default. The rows are still stored, and that teardown's notes name the variable. Contract: [protocol/fuse-event-log.md](protocol/fuse-event-log.md). |
| `CC_LOCAL_SYSTEM_REMOTE_ID` | Target the `CC_LOCAL_SYSTEM_PROVIDER` provider is bound to (`LOCAL_REMOTE_ENV` in `src/systems/registry.ts`). |
| `CLAUDE_CODE_GIT_BASH_PATH` | Git for Windows bash path, searched before the default roots (`src/platform/win32.ts`). |
| `CLAUDE_SHELL_ENV_TIMEOUT_MS` | Timeout for capturing the user shell environment (default in `src/claudeShellEnv.ts`). |
| `ORCH_DISABLE_STDIO_PERMISSIONS` | Kill switch for the stdio permission path in `src/instances.ts`. |
| `ORCH_IDLE_DRAIN_SETTLE_MS` | Settle window before an idle subscription drains (`IDLE_DRAIN_SETTLE_MS` in `src/idleSubscriptions.ts`). |
| `ORCH_RENEW_CLEAR_TIMEOUT_MS` | Timeout for the clear step of a session renew (`src/sessionRenew.ts`). |
| `ORCH_SOFT_INTERRUPT_DEADLINE_MS` | Deadline for a soft interrupt before it escalates (`softInterruptDeadlineMs` in `src/instances/overageRouting.ts`). |
| `ORCH_STORE_LOCK_RETRY_MAX` / `ORCH_STORE_LOCK_RETRY_BASE_MS` | Retry count and base delay for the store lock (`src/storeLock.ts`). |
| `SELF_UPDATE_REPO_ROOT` | The checkout self-update works on (default in `src/selfUpdate.ts`). |

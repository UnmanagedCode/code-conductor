## Stack
- Node 24+ (native type-stripped TypeScript for `src/*.ts`, `node:test`, top-level await, `crypto.randomUUID`).
- `express` (REST + static) + `ws` (WebSocket).
- Vanilla HTML/CSS/JS in `public/`, no build step.
- `happy-dom` (dev-only) for DOM-backed rendering tests.
- No DB — projects in `<projectsRoot>/`, sessions in `~/.claude/projects/<encoded-cwd>/*.jsonl` (the jsonl root is overridable via `CLAUDE_PROJECTS_ROOT`).

## Component layout
- **server.ts** — Express + ws boot, mounts `/api` → `/mcp` → `/plugins` (reverse proxy) → static, binds `127.0.0.1:8787`. The WebSocketServer is `noServer: true` with a manual `server.on('upgrade')` dispatcher: `/ws` → wsHub, `/plugins/<id>/…` → plugin proxy raw-socket pipe, anything else destroyed. (With `noServer` the ws lib never attaches to the http server, so the old EADDRINUSE error-forwarding guard around `listenWithRetry` is gone — `tests/eaddrinuse-retry.test.mjs` covers the retry path.) Creates the plugin host and, after listen, feeds it the bound port + fires its adopt-on-boot init. Sets `process.title = 'code-conductor'` on entry so `pkill -f code-conductor` targets it precisely and `pkill -f server.ts` misses it. Launched via `conductor.sh` (`npm start`).
- **src/instances.ts** — Instance class, InstanceManager, capped event ring (`EventLog`: drop-oldest at `ORCH_EVENT_RING_CAP` (default in this module); `_seq` stamped at push and never renumbered; `trimmedBefore` = first retained `_seq`; trim snaps the surviving head to an outer `user_echo` turn boundary, falling back to the nearest **quiescent point** (`firstQuiescentAtOrAfter`, parser.ts) when no echo is in reach so the gap-case head still opens on whole blocks — plain cut only for a giant non-quiescent span; `snapshotTail()` serves the trailing window around `ORCH_SNAPSHOT_TAIL` (default in this module) events for WS subscribe, quiescent-snapped via `snapStartToQuiescent` — the snap moves the start EITHER way (forward, past an open block or a headless run, when the raw cut lands mid-block; back, to an earlier quiescent point, when the forward search finds nothing before the ring's end), so the served tail can be shorter OR longer than the cap and no inequality holds in general — backstopped by `lastQuiescentAtOrBefore` (parser.ts) when the forward snap would push past the ring's own end (the tail's only remaining content was sub-agent children with no reachable head), serving from the nearest quiescent cut rather than returning an empty tail; **retention is storage-only, decoupled from the live feed** — `push()` declines to retain the CLI's per-token floods (see the `thinking_tokens` entry in [protocol.md](protocol.md) for which models were observed emitting that one; prose streams one `text_delta` per token on every backend) so a single long turn can't overflow the ring and strand the archive mid-turn: `system/thinking_tokens` (a live-only last-value-wins counter, never persisted) is dropped from the ring entirely, and consecutive `thinking_delta` **or** `text_delta` of one `(msgId, blockIdx)` block fold into ONE slot — the same one-delta-per-block shape disk replay produces (`src/transcript.ts`), so ring + jsonl-archive reconstruct identically. The two kinds never fold into each other (`tail.kind === v.kind`), and `msgId` is per-message so a sub-agent block can never fold into an outer one; async sub-agents interleave their deltas with the outer turn's, breaking adjacency, so folding does not apply inside background-task regions. The replay-path `message_start` (`replayed: true`, emitted by `loadHistory` to seed the ctx readout — see [protocol.md](protocol.md)) is declined too: it is synthetic, so it must not become history, and keeping it off the ring also keeps it from ever becoming the ring head (`message_start` is quiescent, so a trim could snap there and its non-`user_echo` head would read as mid-turn and mark a spurious `history_gap`). It also never advances `ring.nextSeq`, which `idleSubscriptions.ts` arms on as its "activity since arm" marker — defense-in-depth rather than a live hazard, since the event fires once inside `loadHistory` before any turn and so cannot land inside an arm→fire window. A declined event gets no `_seq`, so `_emitUi` still emits it seq-less and the LIVE per-token stream is untouched; the first delta of a block anchors the slot with its `_seq` so a later forward page dedups via the client's `seenSeq`. In-place `tail.text +=` is **append-only** — the slot is never shrunk, replaced, or renumbered — so a consumer holding a shallow snapshot across an `await` (`ringSnapshot` → `pageInstanceEvents`, `snapshotTail` → `wsHub`) can only observe a longer extension of the same `_seq`, never a torn or duplicated one. That, not synchronous serialization, is what makes it safe: `wsHub` subscribes the socket **before** calling `snapshotTail()` and awaits `reconstructActiveTasks` before sending, but the client clears before replaying a snapshot (`public/wsRouter.js`) so live frames emitted inside that window are discarded in favour of the grown slot, and on the paging path the client's `_seq` dedup drops an already-applied slot outright. The current counter isn't lost for a client joining mid-stream: `_emitUi` also keeps the latest count as O(1) `_liveThinkingTokens` state (set per `thinking_tokens`, cleared on `thinking_start`/`thinking_end`/`turn_end` so a finished block shows none), exposed via `inst.liveThinkingTokens` and re-attached by the WS subscribe path as a trailing seq-less `system/thinking_tokens` on the snapshot — so a fresh subscriber sees the coalesced partial thinking text (from the ring slot) AND the current count with no flicker. A block that has already CLOSED gets nothing re-attached, so a redacted one — which replays no text at all — would rebuild as a bare `thinking (redacted)`; `_emitUi` therefore stamps the final estimate onto the retained `thinking_redacted` slot as `estimatedTokens` before pushing it. Ring-resident only — the `thinking_tokens` entry in [protocol.md](protocol.md) enumerates the jsonl-backed rebuild paths that lose it), absolute `userIndex` stamping on outer user_echoes (the rewind/fork anchor — immune to trimming), control_request round-trip, mode validation. The **context-size** reading rides the same O(1)-state-on-the-snapshot pattern as `_liveThinkingTokens`, for the same "the ring is not a reliable carrier" reason: `_emitUi` latches every `message_start.usage` as `_lastContextUsage` (exposed via `inst.lastContextUsage`, sent as the snapshot's `lastContextUsage` **field** — not an appended event, which would also reach `conversation.apply`). Only `message_start` feeds the client's `UsageTracker`, and a turn whose final text block outruns the tail leaves the quiescent snap no cut except past the whole block, so every `message_start` lands below the window and a re-subscribe would otherwise rebuild an empty tracker (`ctx —` — the symptom on a backend that answers in one long block). Two deliberate differences from the thinking counter: it is **not** cleared at `turn_end` (the reading stays valid between turns, which is exactly when a reload would lose it), and its only reset is `_wipeForResume` (rewind/respawn) — a fork or a resume-after-restart needs none, since each builds a new Instance whose constructor starts it `null`, and a fork must leave the parent's value alone because that session continues. **Resume idempotency:** `create()` is a thin synchronous wrapper over `_doCreate()` that guards duplicate resumes of one sessionId — an already-live session (`i.proc`) throws 409 `already attached`, and a still-in-flight resume (tracked in `this._resuming`, keyed on the session's PUBLIC id when it is already in memory, so two callers naming one session by different forms still coalesce rather than racing two subprocesses onto one transcript) is **coalesced** (the second concurrent caller gets the same restored instance, one subprocess). The checks run in the wrapper's synchronous prefix (before any `await`), closing the window `_doCreate` opens between the guard and `spawn()` attaching `.proc`; the map entry is released when the create settles (success OR failure). This makes the restart anchor auto-resume racing the manifest restore — and manual stop+resume — safe regardless of caller.
- **src/idleSubscriptions.ts** — `IdleSubscriptionHub`, the idle-subscription graph extracted from `InstanceManager` as a composed collaborator. Owns the `targetInstanceId → Map<callerInstanceId,{timerId}>` map — **keyed by the stable instanceId** (the event stream carries it, and it survives an in-place `/clear`, so keying by instanceId needs no migration). sessionId lives only at the boundary: `subscribe`/`unsubscribe` translate the MCP-supplied sessionIds to instanceIds on entry (via `liveForSession`), `deliver` translates the target instanceId back to its current sessionId for the wake stub, and the test-only `snapshot()` projects instanceIds back to sessionIds. Subscriptions are purged on `remove()` and never persisted, so there is nothing to "survive a restart." One-shot consume-on-fire by whichever of **four trigger paths** lands first — `turn_end`, the **idle task-drain settle** (`ORCH_IDLE_DRAIN_SETTLE_MS` — see the wake state machine below), **rotation completion** (`_onRotationComplete`, for a rotation that comes up idle with no turn at all — i.e. a prune; a renewal declares `comesUpIdle:false` and is delivered by its reseed turn's `turn_end`), or the **always-armed** `timeoutMs` watchdog (explicit finite value, else `DEFAULT_SUBSCRIBE_TIMEOUT_MS` via `ORCH_SUBSCRIBE_TIMEOUT_MS`; `.unref()`'d) — plus the wake-stub text. `onEvent` receives every instance event: `_onTurnEnd` **defers** delivery while the target's `activeAgentTaskCount > 0`, `taskNotificationPending`, or `rotationPending` (keeping the subscription + watchdog armed), so a wake fires only once the worker's turn ends with no live background subagents and no context rotation in flight; `_onTaskEvent` covers the drain-at-idle-with-no-re-invocation case; a subagent that never finishes is caught by the watchdog. The rotation defer reads `Instance._rotation` (opened at `arm()` / at the top of `pruneSession`, closed by `endRotation`) rather than any controller state, so it holds regardless of listener registration order — the hub's listener is registered *before* the renew controller's, which is why a wake used to be spent on the **armed** `turn_end`, a turn early. Cross-instance lookups + `subscription_changed` emission route back through the manager. `InstanceManager` delegates the `subscribeIdle`/`unsubscribeIdle`/`isIdleCaller`/`idleSubscriptionsOf`/… surface and exposes the live `_idleSubscribers` getter. `subscriptionsOf(callerInstanceId)` (the inverse of `snapshot()`, caller-indexed) backs the `renew_session` mechanical state block (see `src/sessionRenew.ts`). `noteRenewalDeclined(targetInstanceId, requestedBy)` records a one-sentence note in `_pendingDeclines`, keyed target→**caller** and only when that caller is actually waiting (`_isWaitingOn`: still subscribed, or subscribed at the turn_end being dispatched — `_justConsumed` now carries the caller set for exactly this). `_takeDecline` read-and-deletes one pair's note, and every path that ends a single caller's wait calls it — delivery before its first `await`, the dead-caller drop in `deliver()`, `unsubscribe`, and `purge`'s **caller-end** loop; `purge`'s **target end** drops that target's whole inner map in one `_pendingDeclines.delete` instead. Either way a note reaches the conductor that asked, exactly once, and can never linger onto an unrelated wake. `deliver()` picks one of three stubs (`_plainStub`/`_buildFoldedStub`): a real `turn_end` to an already-idle caller **folds** the worker's recent output inline (reusing `buildRecentMessages` from `mcp/handlers.ts` + `flattenPayload` from `mcp/content.ts`, tagged with the `public/wakeCallback.js` marker for the collapsible UI bubble); the timeout-watchdog and live mid-turn steering paths keep the plain pointer stub (a mid-turn wake is injected live into the caller's running turn). No import cycle — nothing in `handlers.ts`'s import graph reaches back to `instances.ts`.
- **src/overageResume.ts** — `OverageResumeController`, the overage auto-resume timer machine extracted from `InstanceManager` as a composed collaborator. Owns the `instanceId → fireAtMs` (wall-clock epoch-ms **deadline**) map (**keyed by the stable instanceId**, so a due-tick resolves the Instance by a direct `byId.get(id)` rather than a scan) and `AUTO_RESUME_TEXT` (re-exported from `instances.ts` for back-compat); the per-Instance overage flags (`autoResumeAt`/`autoStoppedForOverage`/`_overageHandled`/`_overageResetsAt`) stay on the Instance. Firing is driven by a **single shared wall-clock sweep interval** (`ORCH_OVERAGE_RESUME_SWEEP_MS`, `unref()`'d — started on first arm, stopped when the map empties), **not** one `setTimeout` per session: each tick re-reads `Date.now()` and fires every deadline that is now due, so a deadline that lapsed while the process was suspended (Android Doze / Termux backgrounding freezes the libuv monotonic clock a `setTimeout` rides) fires on the first tick after wake. `resetsAt`-based scheduling, deadlines in-memory but persisted in the resume manifest (survive a graceful restart), never kills/respawns. **Usage-verified fire:** a due deadline does NOT resume on our clock alone — the tick does ONE coalesced `fetchUsage()` (`getAccountUsage`, injectable seam; its usage-cache cadence + backoff absorb the pressure — one fetch shared across all sessions due that cycle, guarded by `_ticking`) and only resumes when `usageOverThreshold(usage) === false` (five-hour util `< 100` and under any enabled threshold — the SAME evaluator the poll trip uses). Still-over → `_reschedule` to `max(resetsAt, now + ORCH_OVERAGE_RECHECK_MS)` (also pushes the manager's global `_overageResetsAt` forward so the lockout gate's future-resetsAt rail stays satisfied while parked), naturally polling at each recheck until the account clears — which is what kills the boundary re-trip (no resume turn is ever sent while still throttled). Can't-confirm (null/backoff/malformed) reschedules too, up to `FAIL_OPEN_AFTER` consecutive failures, then fails open and resumes so a persistently-down usage API can't park a session forever. `arm()` no longer dead-ends on a missing/past `resetsAt` — it schedules the first check at `now + recheck`; **`auto_resume_skipped`** now fires ONLY for the genuine "process gone" case in `run()`. `armRestored` (restart) re-inserts its persisted deadline as-is (keyed by the freshly-created Instance's new instanceId — the manifest persists the deadline by sessionId, and restore re-arms off the live restored `inst` after `create()`) and inherits the same usage-verified fire. `InstanceManager` delegates the `_armAutoResume`/`_cancelAutoResume`/… surface (also called from the temp-session exit branch so a disposed temp session never leaves an orphan deadline) and exposes the live `_autoResumeTimers` getter. **Message queueing:** while a session is auto-stopped-and-armed, a non-internal `Instance.prompt()` is intercepted **before** `emit('user_prompt')` and pushed onto `inst._overageQueue` (`{text, attachments, ts}`) with an `overage_message_queued` UI event — it does NOT resume or cancel. `run()` flushes on fire: it snapshot-empties the queue, calls `cancel(sid)` FIRST (clears `autoStoppedForOverage`/`autoResumeAt` so the follow-on non-internal resume send isn't re-queued — `cancel` is idempotent so the send's own `user_prompt→cancel` is a no-op), emits an `auto_resume` system line, then sends ONE combined `prompt()` (`buildCombinedResumeText` = `AUTO_RESUME_TEXT` + numbered list, with all queued attachments concatenated). `cancel()` also clears `_overageQueue` (kill/remove/temp-exit/shutdown cleanup). `summary()` exposes `queuedCount` (rides every status emit → header/sidebar badges append `· N queued`). `fireNow()` is the sweep-internal + test seam and is also the primitive `InstanceManager.reevaluateOverageResumes()` drives (one `fireNow` per parked instanceId, snapshotting `timers.keys()` first since `fireNow` synchronously deletes its own entry) — called after a Settings → Account Apply that raises/disables the threshold, so a session parked under the OLD bar resolves against the new one immediately instead of waiting out its deadline. There is still **no** early-resume UI/button — this is a settings-save side effect, not a user-facing control.
- **src/usageWindowDomains.ts** — the backend-scoped **usage-window domain** seam that decides whether an instance is subject to the overage flow at all. A usage/rate-limit window is a provider concept: `usageDomainOfBackend(backend)` maps the identity `claude` backend to `'anthropic'` and every other registry backend to a domain named after itself, and `MONITORED_DOMAINS` (today just `{'anthropic'}`) names the domains with an active monitor. `InstanceManager` composes three helpers on top: `agentTreeBackends(inst)` (cycle-safe walk of `inst` + its conducted-worker descendants by `callerInstanceId` → `Set` of backend ids; in-process Agent-tool subagents share the parent CLI's launch-fixed backend so they add nothing), `usageWindowDomainsOf(inst)`, and `_inUsageWindowFlow(inst)` (true iff the tree touches a monitored domain). A tree with no Claude agent → e.g. `{ollama}` → exempt; a tree with any Claude agent (incl. a non-Claude conductor with Claude workers) → in-flow. Shipping a monitor for another backend's window later = add its domain to `MONITORED_DOMAINS`; no exemption logic changes.
- **src/usageOverageMonitor.ts** — `UsageOverageMonitor`, the server-side usage poller composed by `InstanceManager` as a second, equal-footing overage-trip source alongside the stream `rate_limit_event`. On an `ORCH_USAGE_POLL_MS` interval (`unref()`'d), `_tick()` is heavily gated (skip if `_overageActive`, threshold disabled, `getOnOverageAction()==='none'`, or nothing mid-turn — so it doesn't fetch needlessly), then calls `getAccountUsage()` (injectable as `fetchUsage` for tests; a throw or null is swallowed → no false-trip) and, when the **five-hour** window's `utilization` (a 0–100 percent) `>= overageThresholdPct`, calls `manager._handleOverageTrip(null, { resetsAt })` — the *same* seam the stream trip lands in. It writes no parallel stop logic and injects no prompts (routing's `internal:true` prompts are inherited), so dedup (`_overageActive`), conductor/conducted/plain routing, and resume all behave identically regardless of source. `start()`/`stop()` are idempotent; the server starts it after `listen()`, and both `shutdown()` and `shutdownForResumeSync()` stop it. The point: the stream event only reports near Anthropic's own ~90% mark, so a *low* threshold (e.g. 25%) is invisible to it — only the poll catches it. `parseResetEpochSecs` is exported from `instances.ts` and reused here to turn the bucket's ISO `resets_at` into epoch seconds. `forceTick()` is a thin public passthrough to `_tick()` — the same gates apply — used by the Settings → Account Apply handler (`src/routes.ts`) so a *lower* threshold that's already crossed trips a mid-turn session immediately instead of waiting up to `ORCH_USAGE_POLL_MS` for the next scheduled tick.
- **src/sessionLineage.ts** — the sidecar store that makes a session's identity permanent. `<store>/session-lineage.json`: `publicId → { current: <backingId>, segments: [{ id, reason, at }, …] }`, with the **backing → public reverse index built in memory at load and never persisted** (a second on-disk copy is a divergence surface). A session's **public id** is minted once from the first 8 hex chars of its first CLI `session_id` (`mintPublicId`, extending to `xxxxxxxx-xxxx` on collision, then to the full id with a `console.warn`); derive-check-extend-**and-write** is one operation under `withLock`, or two concurrent spawns mint the same id. The **collision universe is every key in BOTH indexes**, so a fresh public id can never shadow another session's segment. Follows `src/tempSessions.ts` verbatim otherwise: bulk load, atomic tmp+rename, `withLock` around every mutation, a module-level `serialize` chain, `loadStrict` inside mutations (so a failed read aborts rather than clobbering), missing file = empty with ENOENT the only legitimate empty base case.

  **BASE CASE, not a legacy branch:** absent row ⇒ public id == backing id. Every resolver returns its input unchanged for an unknown id, so pre-existing sessions work with **no migration and no backfill**, and nothing anywhere asks "is this a legacy id?". `migrations/` is untouched by this store.

  `reason: 'initial' | 'renew' | 'prune'` is load-bearing, not polish. Every segment's file survives on disk in both mechanisms, so segments are uniform for *identity* — but not for *content*: a `renew` segment is **disjoint** from its predecessor (full history is their concatenation) while a `prune` segment is a filtered **copy** that **overlaps** it (`src/sessionPrune.ts` writes a new file and leaves the original untouched) and must never be concatenated. `reason` alone carries that — do **not** add a second boolean that can disagree with it.

  API: `loadLineage` · `mintPublicId` (only caller: `Instance.launch()` on a fresh spawn) · `recordRotation(publicId, backingId, reason)` (appends + advances `current`; **creates the row lazily** for a previously row-less session by promoting its public id to an `initial` segment; idempotent on a retry) · `revertRotation` (drops the trailing segment iff it is the one named, and **deletes the row entirely** when that restores the base case — only caller: `pruneSession`'s rollback) · `resolveBacking` (public → `current`; a known **segment → itself**, deliberately, so clicking an archived row opens *that* transcript rather than silently redirecting to the newest) · `publicIdFor` · `segmentsFor` · `dropSegment`.

  **Read tolerance, not writes on reads.** A row can outlive the files it names (Claude prunes its own `~/.claude/projects` after ~30 days). `findSessionLocation` therefore resolves, probes, and on a miss walks the row's segments **newest-first**, returning the first that exists — read-only, because a write inside a hot read path races concurrent readers. The two places that *do* prune are the ones that know a file is gone for good: `deleteSessionForCwd` (the only jsonl-deleting path in the repo) and `Instance.loadHistory`'s ENOENT branch, both via `dropSegment`.

  **The path chokepoint.** `sessionFilePath(absCwd, backingId)` / `subAgentDirPath(absCwd, backingId)` in `src/projects.ts` are the only constructors of a transcript path, and both call `assertBackingId` — which THROWS when handed something shaped like a minted public id. It is an assertion, not a branch: nothing resolves differently by id length. `isMintedPublicId` (same regex, one source) lets a route that has already resolved and *still* sees that shape decline cleanly as an unknown session (null / false / 404) instead of turning a clean miss into a 500. `tests/session-lineage-chokepoint.test.mjs` fails the build on any other `.jsonl` path literal, with a small named exempt list and a vacuity guard.
- **src/sessionRenew.ts** — `SessionRenewController`, the managed session-renewal machine composed by `InstanceManager` (the `renew_session` MCP tool). Owns a `instanceId → {state:'requested'|'armed'|'clearing', opts, oldSid, timerId}` map. **Keyed by instanceId, not sessionId**, because renewal's whole job is to rotate the caller's sessionId out from under it — only the stable `byId` key survives. `arm(instanceId, {summary, followUp?})` (idempotent; re-arm refreshes opts, always carrying `followUp` forward) registers a pending renewal, and CONSUMES a `requested` entry for that instance if one is pending — folding its `followUp` in. `request(instanceId, {followUp, requestedBy})` registers the conductor-side ask (`requestedBy` is the asking conductor's sessionId, so the decline can be reported to IT and no other watcher) (see the `renew_session` targeted form in [protocol.md](protocol.md)); it overwrites another request but never a live `armed`/`clearing` renewal, and deliberately opens NO rotation window, so a decline rides the worker's ordinary `turn_end`. `dropRequest` un-registers one whose prompt never went out. `onEvent` acts on `turn_end` for a pending instance: `requested` → the entry is deleted and `manager.noteRenewalDeclined(id, requestedBy)` is called SYNCHRONOUSLY in that dispatch (the decline; the ordering that makes it reach the already-queued wake is documented on `noteRenewalDeclined` in `idleSubscriptions.ts`); `armed` → the caller's next `turn_end` drives `Instance.clearContext()` (a server-managed `/clear`, see protocol.md) and remembers the pre-clear sessionId → `clearing`; `clearing` → the first `turn_end` where `inst.backingSessionId` has rotated off the pre-clear id (i.e. `/clear`'s own turn_end, after its `system/init`) builds the mechanical state block (`buildStateBlock(manager, id)` — **at this point, not at arm time**, so it reflects current state) and injects `buildRenewSeed({...opts, stateBlock})` as the cleared session's first user turn (`prompt(..., {internal:true})`). The public `inst.sessionId` is pinned throughout — only the backing id moves.

  **The reseed waits on durability.** `system/init` corrects in-memory truth in its own tick and kicks the `recordRotation` write onto the instance's serialised `_lineageWrite` chain immediately — the earliest possible point, since the CLI has ALREADY written the new transcript by the time we see that line, making durable-before-first-use physically impossible. `_onClearingTurnEnd` then **awaits `inst.flushLineage()` before the reseed** (`flushLineage` rethrows the first failure since the last flush; the error is remembered rather than swallowed so a failed write cannot wedge later rotations). On rejection it emits a `system`/`renew_error` UI event naming the orphan risk and **still reseeds** — the clear already happened irreversibly and the summary is the only thing that can save the session. Failure-visible, not abort. The reseed's own failure gets the same event, replacing a `.catch(() => {})` that silently lost a cleared-context-with-no-summary. **Consequence for readers: "rotated" no longer implies "seeded"** — the reseed is dispatched one or more ticks after the rotation.

  **The rotation window.** `arm()` calls `inst.beginRotation('renew')` — mid-turn, when the tool is called, well before that turn ends — and every exit path closes it via `_clear(id, {ok})` → `inst.endRotation({ok, comesUpIdle: !ok})`. The window lives on the `Instance` (not in either controller) so `IdleSubscriptionHub`'s defer works regardless of listener registration order; `comesUpIdle` is `false` only on the success path, where a reseed turn follows by construction. Every abandonment — dead proc at either `turn_end`, a `clearContext` throw, the rotate watchdog, `purge()` — declares `comesUpIdle: true`, because no turn is coming at all and the completion event is then the only wake point a waiting conductor will ever get. Unlike the instanceId-keyed side structures, the **transcript-keyed** durable markers (`temp`/`conducted`/title/mode/backend) DO need carrying — they are looked up by FILENAME (`listSessionsForCwdWithCounts`), so the carry is a backing→backing move and reads `backingSessionId` at both ends: `clearing` calls `inst.carryMarkersAcrossRenewal(oldSid)` (fire-and-forget, best-effort) which marks the rotated id **first** (`markTemp`/`markConducted`/`setTitle` per the flags the instance carries — closing the window before the reseed `turn_end`'s incidental `_writeSessionMetadata` re-write, and carrying the title, which no `turn_end` path writes) then retires the abandoned old id **last** (`unmarkTemp` + `markArchived`, mirroring `_archiveTempSession` — conducted/title stay meaningful on the archived row); new-id-first ordering means a crash mid-way can't strand the new id unmarked while the old id is archived. No side-structure migration is needed — the idle-subscription graph and overage timers are keyed by the stable instanceId, which `/clear` preserves. A `turn_end` that has NOT rotated (a mid-turn-queued user turn the CLI ran before `/clear` took effect) is ignored, so an intervening turn can't reseed into the wrong session. The `armed` state **defers** the clear while the caller has an overage-queued turn (`_overageQueue.length`), live subagents (`activeAgentTaskCount`), or an owed re-invocation (`taskNotificationPending`) — so queued/background work is never stranded by the rotation (mirrors the idle hub's defer gate). That gate only re-fires on a `turn_end`, so an armed renewal has a **second fire trigger** for the case no `turn_end` ever follows: a `system/task_updated`|`task_notification` that leaves the instance drained-idle fires the clear immediately (`_onArmedDrain` → the same `_fireClear` the turn_end path uses). Exactly those two subtypes, mirroring `IdleSubscriptionHub._onTaskEvent` — a broader "any event while idle" trigger would `/clear` before a test's next `send_prompt`, breaking the `go1 < /clear < seed` ordering — and no settle window, because the hub's exists to avoid waking one turn EARLY while the only risk here is a concurrently-opening turn, after which the queued `/clear` still reseeds correctly. A `.unref()`'d `ORCH_RENEW_CLEAR_TIMEOUT_MS` watchdog (default `CLEAR_ROTATE_TIMEOUT_MS` in `src/sessionRenew.ts`) abandons a renewal that never rotates rather than wedging the instance. `buildRenewSeed({summary, followUp?, stateBlock?})` composes the seed text, each part under its own fence: the self-authored summary, then the conductor's post-renewal `followUp` (a task, as against the summary's memory), then `stateBlock`, the mechanical state block. `buildRenewRequest({directive?})` composes the turn-A prompt a targeted request sends (ask → decline path → the summary call), and `RENEW_SUMMARY_TEMPLATE` is the ONE home for the summary structure, read from here by the `summary` argument description in `src/mcp/tools.ts` too. `buildStateBlock(manager, callerInstanceId)` enumerates `manager.liveOwnedBy(callerInstanceId)` (live instances the caller spawned, via the same `callerInstanceId` tracking the sub-agent panel uses — `{sessionId, project, worktree, status}`) and `manager.idleSubscriptionsOf(callerInstanceId)` (the caller's pending idle-subscription targets, an inversion of `IdleSubscriptionHub.snapshot()`) — framed as a safety net: it wins for **existence**, the self-authored summary wins for **intent**. `InstanceManager` delegates `armSessionRenew`/`requestSessionRenew`/`dropSessionRenewRequest`; `remove()` calls `_sessionRenew.purge(id)` (a `requested` entry holds no rotation window, so purging it closes nothing).
- **Overage trip detection + central routing** (in `src/instances.ts`) — the *decision* of what to do on an overage trip moved off the per-Instance handler (which can't reach the idle-subscription graph) up to `InstanceManager`. Resume timing keys off the five-hour `resetsAt` (read camelCase epoch from the live event by `parseResetEpochSecs`), **not** the far-future `overageResetsAt`. Orchestrator-injected prompts — the idle-subscription wake stub and the conductor overage steer — pass `prompt(..., {internal:true})` so their `user_prompt` does **not** cancel a pending resume (an overage-stopped conductor still gets woken when its worker finishes); only a genuine user/MCP prompt, or the auto-resume's own non-internal fire, runs `_cancelAutoResume`. **Domain-scoped exemption:** every routing decision gates on `_inUsageWindowFlow(inst)` (see `usageWindowDomains.ts`) so a session whose agent tree is purely in an unmonitored domain (e.g. no `claude`-backed agent) sits entirely outside the flow: `_handleOverageTrip` ignores a stream trip from such an instance (the `null`-inst poll trip is account-global and unaffected); `_routeOverageStop` filters those instances out of `live` (never stopped/steered/marked); the per-instance `_overageGate` returns `active:false` for them (so their sends never queue **and** `summary().overageActive` stays false → no overage badge); and `resumeRestart.ts` skips re-arming a restored deadline onto one. Arming is thus unreachable for exempt instances without extra guards.

Anchoring on the ring-head *event* instead (`_seq === trimmedBefore` appearing in the slice) put the marker on whichever page happened to serve it, and otherwise on the terminal page far below the real boundary, since `gap` is only computed on pages that load the archive and those sit at or below the seam, not above it (2026-0054). The terminal-page append survives, narrowed to pages whose whole window sits **above** the seam with `hasMore:false` — reachable on forward (`after`) paging only, where no lower page will follow to carry it. What makes "some page carries it" hold at all is that backward pages **tile unconditionally**: every window is served (none is ever skipped — see the backstop note below), so each page's `nextBefore` is its own served start and the next page's end is this page's start. So: never silently dropped. It can still be emitted **twice** in one narrow case — when the snap lands a straddling page's start exactly *on* the seam, that page splices at offset 0 and the page below it splices at its own end. Known, much narrower than the pre-seam-anchoring double class it replaced, and deliberately not closed). The archive is loaded for two reasons, not one: the requested window's seq extent dips below `trimmedBefore`, **or** the tentative ring window holds a sub-agent child with no owning head inside the ring (`hasHeadlessChildIn`, parser.ts) — group heads are resolved over the whole loaded array, so such a child reads as headless and gets pushed out of the only page whose window covers it unless the (usually archive-side) head is loaded with it. Backward pages return an opaque `nextBefore` cursor that jumps the numeric gap between the two seq spaces. Rejected-window backstop: when the quiescent snap would reject a window outright (`start >= end` — the window's only content was sub-agent children with no reachable head), the page is instead served from `lastQuiescentAtOrBefore(rawStart)` (parser.ts) — the window's own pre-snap start, down-snapped to the nearest quiescent cut — rather than coming back empty; a backward page is empty **iff** the window itself is empty (`end === 0`), which is terminal (`hasMore` is already false there), so this is total: every non-empty window is served, on some page, exactly once. Headless children served this way ride along and park client-side (`Conversation.orphanChildEvents`) rather than rendering, which is strictly better than the events being dropped along with their whole merged component; window starts snap to **quiescent points** (`snapStartToQuiescent`, parser.ts: no open outer block, every `tool_use` resolved; outer `user_echo`/`turn_end` force-reset the scan; sub-agent events are scan-opaque — nested-block wholeness comes from the group-boundary resolver, which moves the cut EITHER way: an available head is dragged into the page with its whole group, while a child with no head at or before it in the loaded array has the cut pushed past it (unreachable by design rather than served orphaned); the archive→ring seam is passed as `resetIdx` so state is never scanned across missing events). Also splices synthetic `task_completion` bubbles into paged history (see `taskReconstruct.ts`).

  - **Harness-state invariants (derived by probing the real CLI — treat as spec).** The CLI rebuilds its read-before-edit cache (`readFileState`) by REPLAYING THE TRANSCRIPT on resume, reading `input.file_path` off every Read/Write/Edit `tool_use` and pairing it with the matching `tool_result`. So: **(1)** never rewrite a `tool_use.input` key set — only string *values* are edited and path keys are skipped at any depth; replacing an input with a marker object drops `file_path` and every later Edit fails with "File has not been read yet". **(2)** never touch `toolUseResult` — it is a disk-only sidecar (pruning it saves zero *context*) and its ABSENCE is the CLI's discriminator for "this is a human user turn". **(3)** `tool_result.content` stays a string **except for pruned Read/Write results, which use a block array deliberately**: the CLI only reconstructs a `readFileState` entry when `typeof content === "string"`, so the array form is what makes the read-before-edit guard RE-ARM once the file's content has left the context. Normalizing (3) back to a string would look like a cleanup and would silently re-break that guarantee — the model would be allowed to edit a file it can only "remember", reconstructing an `old_string` that may not match or may match the wrong occurrence. Switchable via `PRUNE_STUB_AS_BLOCKS` (default `true`). An Edit-seeded cache entry is out of reach either way: the CLI re-reads that path from DISK using only `input.file_path` and a non-error result. The reconstruction pass branches on exactly three tool names — **Read, Write, Edit** — so `SEEDING_TOOLS` is `{Read, Write}` (Edit's result content is irrelevant to it). `NotebookEdit` is a defined tool-name constant that the pass never references: a notebook result cannot seed the cache, and since nothing seeds it from a transcript, a notebook edit already needs a live Read after ANY resume — pruning neither causes nor worsens that. The guard is only *enforced* for a fixed model set (haiku-4-5, sonnet-4-5/4-0, opus ≤4-6, 3-x) — which is why `tests/prune.real.test.mjs` pins `claude-haiku-4-5`; on Opus 5 / Sonnet 5 it would pass vacuously. **(3a)** Truncate mode cuts with `sliceCodePoints`, which backs off one unit when the cut would land inside a surrogate pair — `slice` counts UTF-16 code units, and a lone high surrogate has no valid UTF-8 encoding, so a naive cut writes unencodable content into a jsonl whose whole contract is that it resumes cleanly. Minimal mode replaces whole values and is immune. **(4)** No entry and no block is ever removed, which is what keeps the `parentUuid` chain and the `tool_use`/`tool_result` pairing invariant safe with zero relinking. **(5)** Sidechain entries are never pruned and never counted in the estimate; the sibling sub-agent directory (`<encoded-cwd>/<sid>/subagents/`) is COPIED to the new sessionId, without which every sidechain silently vanishes from the pruned session's transcript view (`loadSubAgentTranscript` keys off the sessionId — `forkSessionAtUserMessage` has this same gap today). **(6)** Some tools are EXEMPT by name (`isPruneExemptTool`): their `tool_use` and the `tool_result` answering it are copied verbatim in every mode, at any cut. Two classes — **`AskUserQuestion`**, because the question card is rebuilt entirely from `input.questions` on replay (`transcript.ts`) and the answer is recovered by *string-matching* the question text and option labels against the following `user_echo` (`public/userQuestionAnswers.js` → `isUserQuestionAnswerText`/`parseUserQuestionAnswers`, driven from `public/conversation.js`), so squeezing either side leaves an unreadable question and silently drops the answer off the card; and **core conductor MCP calls** (`mcp__code-conductor__<tool>`), the orchestration record of what was spawned, approved, merged, filed. The MCP half is exempt by NAMESPACE so a core tool added later is exempt by default, minus a hardcoded two-entry denylist `PRUNABLE_CONDUCTOR_MCP_TOOLS` = {`project_read`, `project_bash`} whose results are bulk file/command output — precisely what Prune exists to shed. **Not configurable**: which class a tool falls in is a property of the tool, not a user preference. Matching the prefix alone is not enough: what remains after it must ALSO contain no further `__`, since a plugin-forwarded tool carries one (`mcp__code-conductor__code-kanban__file_task`, `mcp__code-conductor__acme-tools__run`) and stays prunable. The separator tested is `__` and not `_`, which keeps a core tool whose own name contains a single underscore (`spawn_instance`, `merge_worktree`) on the exempt side; testing for `__` rather than for the first-party `code-*` plugin naming habit is deliberate, so a third-party plugin id classifies the same way. An orphaned `tool_result` (no `tool_use` in context ⇒ no name) stays prunable. Thinking blocks keep their `signature` when their text is stubbed: an *unsigned* thinking block survives the CLI's own other-model strip pass (which only removes SIGNED blocks) and would then reach the API unsigned; a stale signature was measured to provoke no rejection, and the CLI has a strip-all-and-retry recovery path regardless.

- **src/sessionActivity.ts** — `lastActivityOf(path, stat)`: when a session transcript was last ACTUALLY active, as epoch ms. The ISO `timestamp` on the LAST timestamped record in the jsonl (last in file order, not newest by value — records are appended in real time, so the two differ only where interleaved sidechain records land a few ms out of order), found by a bounded 64 KB tail read; falls back to `stat.mtimeMs` when the tail holds no timestamped record. **Not mtime**, because the CLI appends untimestamped bookkeeping records (`last-prompt`, `mode`, `ai-title`) as its process exits — so a mass subprocess exit (a server drain/restart) stamps every live session's file within the same millisecond, collapsing distinct sessions into one indistinguishable minute days after they actually stopped. Feeds `SessionRow.lastActivity`, `ArchivedSessionRow.lastActivity` and `summarizeSessions().lastActivity`, so every surface reports one definition of recency. Results are memoized in a process-lifetime LRU (`createLastActivityCache({max})`, cap `LAST_ACTIVITY_CACHE_MAX`) keyed on the path with a `(dev, ino, ctimeMs, mtimeMs, size)` validity tuple. `ctimeMs` is what makes it sound — it cannot be rolled back from userspace, so it catches even an in-place rewrite that restores mtime and preserves size; `mtimeMs`/`size` catch the common case (an append) without depending on ctime semantics. `dev`/`ino` are **redundant** against every writer in this repo (the two that replace a transcript go tmp→rename, and a rename-over sets a fresh ctime) and are kept only as a guard against a future writer that replaces a file without moving ctime — no test isolates them, because with ctime in the key the case isn't constructible. No stale entry is reachable, so there is no TTL. **In-memory only, never persisted.** Both callers already stat every file, so a steady-state fan-out across every project costs readdir + stat + a Map lookup — the property the "just readdir + stat, no opens" walk in `summarizeSessions` was protecting.

Claude sessions store nothing), `archivedSessions.ts` (archived-sid set — `isArchived`/`markArchived`/`unmarkArchived`), `tempSessions.ts` (durable temp-session markers that survive SIGKILL so a temp stays resumable across the resume-after-restart path). `storeLock.ts` provides the cross-process advisory lock (`withLock()`, `O_EXCL` create) they serialise on: a held lock is reclaimed **only when the owner PID is dead** — a live owner is never evicted on age, no matter how slow. This is load-bearing on Termux: post-restart CPU throttle (~10–75×) can starve a live holder for many seconds mid-write, and the old-server/new-server overlap during a restart is the only window with cross-process contention; the previous 10 s age-based eviction reclaimed the live holder there, letting two writers run the read-modify-write concurrently and drop each other's entries (a lost update) — which silently un-archived a subset of sessions on every restart. A slow holder is now waited out via bounded retries (a truly wedged holder throws on acquire rather than corrupting), and release is **ownership-token-checked** so a process can't delete a successor's lock. `archivedSessions.ts` additionally guards against a **silent full-reset** under the host's frequent OOM/low-disk churn: it keeps a rolling `.bak` (refreshed under the lock only from a non-empty write that is a **superset** of the current backup — never a shrink — so a spurious empty/tiny base can't canonize over the last-good snapshot; consequently `.bak` may lag behind un-archives by design, the safe direction: a recovery from a stale `.bak` only re-archives a few since-unarchived ids, never loses data); a missing primary recovers from `.bak` (missing primary **and** `.bak` = legitimately empty); a corrupt primary is quarantined to `.corrupt-<pid>-<ts>` (under the lock, in the mutation path) and recovered from `.bak` rather than bricking archiving; and a drain-to-empty now writes `{"sessions":[]}` atomically **instead of unlinking**, so an absent primary unambiguously means external loss. Only a genuine unrecoverable I/O error (EACCES etc.) still aborts a mutation. `tempCleanup.ts` writes/sweeps `<store>/pending-temp-cleanup.json` to GC temp jsonl orphaned after exit; it and `resumeManifest.ts` write their sync-before-exit manifests via tmp-write + `renameSync` so an OOM mid-write can't leave a torn manifest.

- **src/jsonStore.ts** — `createJsonStore({file, noun, empty, parse, toDoc, isEmpty, unlinkWhenEmpty?, loadLenient?, loadStrict?, afterWrite?})` → `{load, mutate}`. The one read-modify-write machine behind every `<store>/*.json` session sidecar. `mutate(fn)` = `serialize( withLock( fn(loadStrict(), write) ) )`: the **lock** is the correctness guard (O_EXCL, `storeLock.ts` — it excludes same-process callers too), the **chain** is a contention guard keeping same-process writers off the lockfile so a burst can't exhaust the bounded acquire retries, and the strict re-read **inside** the lock is what makes the base canonical. `load()` is lenient (any failure → empty + warn, for the query surface); `loadStrict()` throws on anything but ENOENT so a transient read error can't be laundered into "the store was empty" and written back as truth. Writes go through `writeFileAtomic` (`src/projects.ts`, documented above) and unlink when empty by default. The returned surface is deliberately just those two: `loadStrict` and `write` stay INTERNAL, reachable only through `mutate`, because a public bare `write()` would be an UNLOCKED atomic write on the very primitive that exists to guarantee the lock. The three optional hooks exist for `archivedSessions.ts` alone (`.bak` recovery, always-write-a-document, rolling-backup refresh inside the lock) — see that module. **Behaviour change on adoption:** `sessionTitles`/`sessionSummaries` previously did their in-mutation read with the LENIENT loader, so corrupt JSON degraded to an empty map that was then written back carrying only the new entry — silently discarding every other title/summary in the file. On `createJsonStore` they read via `loadStrict`, so corrupt JSON now throws and the mutation aborts with the file untouched. This is the intended fail-loudly direction and matches what the four already-hardened stores did on main; a class of silent data loss became a loud failure. Pinned by `tests/store-lock-lost-update.test.mjs` (the cross-process lost update) and `tests/store-lock.test.mjs` (the lock primitive, including that the lock is held until `fn`'s BODY settles — `return await fn()`, not `return fn()`).

Two distinct failure modes, treated differently: a **vanished fragment/scaffold file** is skipped with a warning, same as always — the convention just contributes nothing, same as if it were never declared. A **failed cwd resolution** is transient infra (e.g. a worktree checkout not yet mounted), not "contributes nothing", so it additionally flags `.degraded` on **every** scope array the function returns — including ones left empty — because an empty-and-unflagged array is exactly what "this scope genuinely has no plugin contributions" looks like, and the one plugin that failed may have been the only would-be contributor to that scope; see `fragmentCatalog.ts`'s `CatalogList` and the `src/projectClaudeMd.ts` bullet below for what a reader does with that. The cache is dropped wholesale (the registry calls `contributions.invalidate()`) at the start of `rescanInternal()`, at the top of `doStart()`'s async body, right after `setActiveVersion()`'s `saveRegistry()`, and right after `enable()`'s `saveRegistry()` — every explicit "the checkout on disk moved, or a disabled plugin's fragments are about to matter again" gesture (rescan, start/restart, an active-version switch even on a stopped/backendless plugin, and enable — a fragment can be edited while its plugin sits disabled) — so neither a `git pull` into an already-loaded checkout nor an edit made while disabled keeps serving stale fragment text for the process lifetime. `conventions()` itself is **memoized**, because it is not a cheap read (it walks `contributingEntries()` and calls `resolveCwd()` per contributing plugin, and `resolveCwd` → `reconcileActiveVersion` does a dynamic `import('../worktrees.ts')` plus a store read for any worktree-pinned plugin — and `server.ts` wires **two** providers onto it, so one `GET /api/settings/conventions/conductor` was two full scans and a mutating plugin route fanned out through `regenerateAllProjectConventions` at two scans per project). The invalidation signal has **two parts, both load-bearing**: (1) a `registryGeneration` counter, owned here and bumped through `noteRegistryChange()` from `saveRegistry()` (which every mutation of `persisted.plugins` is immediately followed by — so the set is provably complete rather than hand-enumerated, and it is what catches `disable()`, which deliberately does *not* drop fragment bodies), inside `invalidate()` (so a stale fragment body can never survive in a cached result), and — again via `noteRegistryChange()` — immediately after `doStart()`'s `entry.manifest = result.manifest` reassignment (which happens ten lines *after* that function's own invalidate, so a concurrent read landing in between would otherwise be cached pre-reassignment); and (2) a per-call `existsSync` liveness re-check of the checkout dirs the cached scan actually read — both the discovered project dir and the resolved cwd. A checkout deleted from under a running server mutates no registry state, so the counter alone cannot see it, and serving a cached "still here" would silently disable the `.degraded` flag that `ensureProjectConventionsMd`'s never-blanks decline depends on; a vanished dir simply falls through to the real scan, which degrades exactly as it does uncached. The generation is snapshotted **before** the scan loop, because `reconcileActiveVersion` can `saveRegistry()` mid-computation when it self-heals a vanished worktree pin — the result is then tagged stale and recomputed once, and the idempotent self-heal does not bump again. **The returned object is shared by reference and must be treated as read-only**; both consumers are verified non-mutating (`fragmentCatalog.ts` reads `.degraded` then copies every entry via `raw.map(r => ({...r, builtin:false}))`; `server.ts`'s two providers only index `.project` / `.conductor`). No defensive shallow copy is made — the entry objects would still be shared, so it would buy the appearance of safety rather than safety. `server.ts` wires it to the projectConventions and conductorConventions providers. `conventions()` is **grouped by the required per-entry `scope`** (keyed by `SUPPORTED_CONVENTION_SCOPES` from manifest.ts; `project`/`conductor` today, `workspace` rejected at load); `server.ts` routes the `project` group to `projectConventions` and the `conductor` group to `conductorConventions`, so adding a scope is a one-line enum move + one provider wiring, not a redesign.

A failed rename is itself non-fatal — the notice carries `backup: null`. Notices reset per `load()` pass, and `load()` reads registry.json before runtime.json. **Reads hand out shallow copies and every mutator writes** (`upsert`/`setEnabled`/`setActiveVersion` for registry.json; `recordStart`/`clearRuntime`/`clearRuntimeDetached`/`adopt` for runtime.json) — that is what the boundary buys: no code outside this module can change persisted state without going through a method that persists it. `onRegistryChange` fires from the single registry.json save path, BEFORE the write (a failed write still leaves the contributions cache invalidated), which is what makes the invalidation set provably complete rather than hand-enumerated. `adopt({isAdoptable})` is **inverted** rather than lifted whole: the store iterates only its own records, asks the injected predicate, clears the rejects in one write (only when something changed) and returns the adopted ids for the registry to mark ready — moving the whole pass here would have needed back-references to discovery and lifecycle. bounded timeout, never throws — `{code,stdout,stderr}` shape), cleans up a partial directory on failure (502 + stderr tail) so a retry isn't permanently blocked, and on success calls `pluginHost.rescan()`, **enables the freshly-discovered plugin by default** (only a `state:'discovered'` row — an invalid/conflicting manifest is left disabled; `enable()` is start-neutral so no process launches at install time), then runs the entry's `postClone` if set. `update(id)` is the symmetric counterpart: 404 if not installed, `git pull --ff-only` via the same `runGitLive`, 502+tail on pull failure (never attempts a merge), else rescan (drops the registry's fragment-body cache), run `postPull`, then resolve the eligible-to-restart set via `resolveRunningIds(pluginHost, projectName)` (reads `pluginHost.list()`, filters to this project's rows whose `state` is `ready`/`starting`) **before** looking at `postPull`'s outcome — this ordering matters: an empty set always reports `null` regardless of `postPull`, so "nothing was running" is never mislabeled as a skip. A non-empty set with a failed `postPull` skips the restart outright — `restarted = {skipped:'postPull-failed'}` — rather than attempting it, because a failed `postPull` leaves the checkout half-built and restarting into it would trade a healthy child serving old code for a crash-looping one serving no code at all; otherwise `restartIds(pluginHost, ids, onChunk)` restarts (`pluginHost.restart(id)`) each of them and returns `{ids, ok, error}` on success/failure; never throws (a restart failure is soft, exactly like a failed `postPull` — the pull already landed on disk) and never starts a stopped plugin (it'll pick up the new code lazily on its next start). `update()`'s result gains a `restarted: {ids,ok,error} | {skipped:'postPull-failed'} | null` field carrying that value. Update **detection** in `list()` runs a bounded best-effort `fetchOriginBounded` (`src/gitLive.ts`) then `getProjectUpstreamStatus` (`worktrees.ts`) per installed row, flagging `updateAvailable`/`behind`. Both `postClone`/`postPull` go through a shared `runHook()`/`runHookCommand()` pair: `runHookCommand` runs the command via `spawn('bash', ['-lc', cmd], {detached:true})` with a process-group kill on timeout (mirrors `worktrees.ts`'s `runPostWorktreeHook`, not `cloneRepo`'s simpler `execFile` timeout — a hook like `npm install` can spawn grandchildren a plain child-kill would orphan) and never rejects; `runHook()` wraps it into `{ran, ok, code, tail}` (or `null` if the entry has no such field). Failure handling is deliberately asymmetric: a failed clone/pull is a hard failure (reject + rollback for clone); a failed post-hook or restart is a **soft warning** on an otherwise-successful `install()`/`update()` response — the clone/pull already succeeded and is already discoverable, so the result resolves with `postClone`/`postPull: {ok:false, tail}` / `restarted: {ok:false, error}` instead of throwing.

- **src/waitFor.ts** — `waitFor({initial, subscribe, timeoutMs, onTimeout})`: the one promise shape behind every LISTENER-driven wait. `initial()` is the already-satisfied fast path, checked before any listener is attached (returns `{value}` or `null`); `subscribe(settle, fail)` attaches whatever listeners it likes and returns an opaque teardown that detaches all of them — which is why the N-listener case needs no special support; `onTimeout()` picks the timeout's disposition by RETURN TYPE — an `Error` rejects, anything else resolves. The point is that the `clearTimeout` + teardown pair is written **once** and runs exactly once, on whichever of settle/fail/timeout fires first, instead of being hand-rolled on both paths at each call site. Four adopters: `waitForStatus` + `waitForEvent` (`mcp/handlers.ts` — `wait_for_idle` and `send_prompt({wait})`'s turn_end, both rejecting on timeout; `waitForEvent` also `fail()`s from a second `status` listener when the instance exits/crashes mid-wait) and `waitForIdleOnce` + `waitAllIdle` (`resumeRestart.ts` — the per-instance and all-idle drains, both **resolving** on timeout, with `'timeout'` / `{timedOut:true, stragglers}` respectively). Deliberately **not** adopted by the two POLLING loops (`plugins/registry.ts` `waitSettled`, `plugins/supervisor.ts` `poll`): both re-enter a `setTimeout` over a synchronous accessor or an HTTP/regex probe, so there is no emitter and nothing to detach — the helper's entire value is nil for them, and unifying those two with each other would need a three-knob helper for two call sites.

The `'event'` listener is synchronous and so cannot await the write: `appendCostRow` is itself **synchronous** — it snapshots the row (incl. `ts`, the live `inst`'s `project`/`model`/`sessionId`, and the resolved `costsPath()`) in the emit tick and hands the write to `writeCostRow` via a module-level promise chain (`serialize`, the same idiom as `tempSessions.ts`/`archivedSessions.ts`). Each `by_model[]` entry and each `by_project[]` entry (plus its nested `by_project[].by_model[]`) carries a `cache_misses` field — a plain count of that model's/project's rows with `cache_miss === true` — and a `sessions` field — the count of distinct `sessionId`s among that model's/project's rows (rows with `sessionId == null` excluded) — both folded into the same reduce loop that builds cost/token totals (no separate aggregation pass). Cache-miss detection is **cross-turn**, captured live in `src/instances.ts`, and catches *partial* (minority) evictions a stateless single-request rule cannot. Each turn is one or more API requests; `message_start` carries per-request cumulative usage and `cache_read` accumulates across a turn's tool-call iterations (there is no per-iteration array — `parser.ts` passes `result.usage` through verbatim). So the detector uses two points: `read_N` = this turn's **first**-request `cache_read` (`_turnFirstReqCacheRead`, pre-tool-call); `P` = the **previous** turn's **last**-request full prefix `cache_read + cache_creation` (`_prevTurnPrefix`), captured by overwriting `_turnLastReqPrefix` on every `message_start` and latching it at `turn_end`. **Miss ⇔ `read_N < P − max(1024, 1% of P)`** — this turn served less of the prefix than was cached at the end of last turn ⇒ eviction (full or partial); a warm continuation reads exactly `P` (drop 0, never flagged), the tolerance absorbs tokenization-boundary noise. **Turn 1** (`_prevTurnPrefix === null`) and any turn where `_prefixBaselineInvalid` is set fall back to the stateless `creation > read` rule, which still flags a genuinely cold prefix (cold start, expiry, resume, cold rewind). **Guards** against legitimate prefix shrink: compaction (`system`/`compacting` in `_handleStdoutLine`), model switch (`_trackModel`'s real-switch branch — cache is model-specific), and rewind/respawn (`_wipeForResume`) each set `_prefixBaselineInvalid`; the next turn's first request consumes it (forces the fallback, re-establishes `P` fresh) so the cross-turn rule never false-fires. **Known limitation:** a miss on a request *after* the first (e.g. a turn outliving the ~1h cache TTL) isn't caught — first-request-only. Per-turn capture (`_turnFirstReqCacheRead`/`Creation`/`_turnMissDetected`/`_turnLastReqPrefix`/`_turnEvicted`) resets in `_setStatus`'s into-`turn` branch and on (re)spawn; cross-turn state (`_prevTurnPrefix`, `_prefixBaselineInvalid`) intentionally persists across the turn boundary. Each `turn_end` is enriched with `cacheMiss`/`firstReqCacheRead`/`firstReqCacheCreation`/`firstReqEvicted` (`P − read_N` on the cross-turn path), persisted as `cache_miss`/`first_req_cache_read`/`first_req_cache_creation`/`first_req_evicted` (additive), and an informational `system`/`cache_miss` notice fires once per miss turn. The old read-time session-relative heuristic (`cache_creation_tokens >= max(50000, 4 × session median)`) was retired to a one-shot backfill, **migration 0014**, which stamps `cache_miss` on legacy rows; a row still carrying the old `cache_flush` key (a decisive verdict captured before the field was renamed) is renamed in place rather than recomputed, so historical rows are heuristic-or-renamed while new rows are decisive. Migration 0014 additionally stamps `cache_miss_heuristic: true` on any row whose verdict IT decided (neither key present, or a renamed `cache_flush` row lacking `first_req_cache_read` — an old-migration guess, not a live capture); presence is checked, not truthiness, since a decisive row can legitimately have `first_req_cache_read: 0`. `appendCostRow` never sets this field, so its absence always means "decisive."

## Conventions

Load-bearing rules this codebase follows — keep new work inside them so the project stays manageable as it grows.

1. **YAGNI — build for the requirement in front of you, not the one you imagine.** Implement only what a current, concrete caller or test needs; don't add speculative abstractions, config knobs, or extension points "for later" — they add surface area without a real user, and the eventual real requirement rarely matches the guess. If code stops being exercised by a real caller or test, delete it rather than keeping it "just in case" or "to trim later" — dead code rots silently and misleads the next reader into thinking it's load-bearing.
2. **Frontend: `installX({…})` modules; `app.js` is wiring-only.** Feature logic lives in a `public/` module exposing an `installX({…getters,…callbacks})` factory (or a class for a stateful widget). `app.js` only builds `state`/the DOM map, calls each `installX` once, holds the returned handles, and wires `wsRouter` last. Modules read live state through injected getters (`getActiveId: () => state.activeId`) — they never reach into globals. Don't grow `app.js` with feature logic; add a module and wire it.
3. **No god-modules — extract composed collaborators.** When a module takes on a second responsibility, lift it into a collaborator the owner *composes*, keeping the public surface stable via delegation. Cf. `InstanceManager` → `IdleSubscriptionHub` + `OverageResumeController`; `mcp/handlers.ts` → `diffPaging` + `messageReconstruction` + `content` + `textRender`/`readRenderers`; whisper/tts install → the `makeInstallRunner` factory; the convention scopes' catalog → `conventionSelection.ts`'s `createSelectionStore`.
4. **One service layer for REST + MCP — don't reimplement per surface.** Git / worktree / diff / session logic lives once in `src/worktrees.ts` (+ siblings) and is imported by **both** `src/routes.ts` and `src/mcp/handlers.ts` (shared: `isGitRepo`, `mergeWorktreeIntoParent`, `syncWorktree`, `getWorktree`, `getWorktreeMergeStatus`, `buildRebasePrompt`, `removeWorktree`, …). A new git/worktree op goes in the service layer and is called from both surfaces — never duplicated.
5. **Single-source-of-truth catalogs, shipped to the client — never client literals.** Curated catalogs (`modelVersions.ts`, `whisperModels.ts`, `ttsModels.ts`) own the authoritative list + allow-list + policy server-side; the client *fetches* them (`/api/settings/models` → `public/models.js`) instead of hardcoding the canonical set. (`public/models.js` keeps a `DEFAULT_VERSIONS` first-paint fallback — a fallback, not a second source of truth. `tests/models-fallback-drift.test.mjs` is what keeps that fallback honest: it asserts every one of its eight mirrors still equals the server value it mirrors, so a catalog change that forgets the client fails the suite instead of silently showing a stale default until the boot fetch lands.)
6. **Cross-surface magic strings get one owner module.** A canonical string shared across surfaces lives in a single module. Cf. `planApproval.ts` — the approve/reject prompts shared by the UI buttons, the server-side auto-approve, and the MCP `approve_plan`/`reject_plan` tools; `public/userQuestionAnswers.js` — the AskUserQuestion answer formatter shared by the UI question card and the MCP `answer_question` tool (a DOM-free module under `public/` that the server imports directly, avoiding a mirror); `public/wakeCallback.js` — the idle wake-stub marker (`WAKE_CALLBACK_MARKER`/`WAKE_BODY_SEP`) shared by the server (build) and the client (parse/render); `SOFT_INTERRUPT_MARKER` in `parser.ts`; `isTaskNotificationContent` and `isInterruptMarkerContent` in `parser.ts` — the CLI's re-injected `<task-notification>` tag and its post-abort `[Request interrupted by user]` line, both recognized by shape (no marker to inject, since the CLI produces the string) and checked at the same three sites as `SOFT_INTERRUPT_MARKER`. On the client the same rule covers the rate-limit vocabulary: the ordered bucket key list (`RL_BUCKET_KEYS`) and the long-form window label map (`RL_WINDOW_LABEL`) have exactly one home, `public/usage.js`, read by `accountUsage.js`'s fetch merge, `header.js`'s popover rows and `blocks.js`'s `rate_limit_event` lines. The order is load-bearing for both uses (which single window is most immediate, and the popover's row order), so a second list would let the chip and the popover disagree. The terse chip-only `RL_BUCKET_LABEL` stays private to `usage.js` — that long/terse split is deliberate, not drift. Likewise `el` (`dom.js`) and `apiFetch` (`http.js`) are the single owners of DOM construction and the fetch-error idiom.
7. **Test-only exports carry an explicit marker.** An export with no production caller that is kept for its tests opens its doc comment with `// Test-only export: no production caller.` followed by one line of *why it is kept rather than deleted with its tests*. Cf. `hasSessionBackend` (`sessionBackends.ts`), `snapStartToGroupBoundary` (`parser.ts`), `getSubstitutionBackends` (`appSettings.ts`), `isKnownVersion` (`modelVersions.ts`). Reset hooks (`_resetForTest`, `_resetCache`) are a distinct, self-naming category and need no marker. An export with **no** caller at all — production or test — is deleted, not marked.

## Instance lifecycle
```
create → spawning → idle ←─ turn ─→ turn_end ─┐
            ↓        ↓                          ↓
        load-hist  prompt                  exited / crashed
        fails                                   │
                                                ▼ respawn --resume <sid>
                                            (back to spawning)
```

On **resume**: `loadHistory(sessionId)` runs before flipping to `idle` — replays jsonl into UI events and emits a `system/history_replayed` divider. A history longer than the ring cap trims during the replay itself; the evicted prefix stays reachable via `GET /api/instances/:id/events`. On **turn end** or **mode change**: append `{"type":"last-prompt", …}` + `{"type":"permission-mode", …}` lines so `claude --resume`'s interactive picker can discover the session.

**`displayStatus` overlay (additive, not a 6th state).** The diagram above is the real `status` enum — untouched. A backgrounded `Agent` tool call's tool_result resolves immediately (`isAsync:true`), so `turn_end` (→ `idle`) can fire while the CLI's own `system/task_started`/`task_updated` task-tracking is still open for that call. `Instance._activeAgentTasks` (a `Map<task_id, tool_use_id>`) tracks this: incremented on `task_started` **unless** `task_type === 'local_bash'` (backgrounded/promoted Bash — a promoted long-lived command never emits a terminal event and would pin the count forever; unknown `task_type`s still count), decremented on a terminal `task_updated` (`patch.status` one of `completed|failed|cancelled|error` — an unrecognized status is treated as non-terminal on purpose, to avoid flipping back to idle early) or on `task_notification` (belt-and-suspenders). `summary().displayStatus` reads `'running'` instead of `'idle'` while the map is non-empty; every other `status` value passes through unchanged. Reset on (re)spawn. `Instance.activeAgentTaskCount` exposes the live map size. `IdleSubscriptionHub._onTurnEnd` **gates on TWO conditions**: a `turn_end` **defers** the idle wake (the subscription + its watchdog stay armed) while **either** `activeAgentTaskCount > 0` (a subagent is still running) **or** `taskNotificationPending` is set — a `task_notification` fired *during* the turn now ending **and no top-level tool_result followed it**, which per the CLI's queue semantics means the notification is still queued and an unprompted **re-invocation turn** will deliver it. Both cleared, the wake fires — so a wake means "the worker AND all its subagents finished, and no re-invocation turn is still owed." `Instance._taskNotificationPending` (getter `taskNotificationPending`) mirrors the CLI's stdout-invisible message queue by event order: SET in the `task_notification` handler only when `status === 'turn'` (a completion while *idle* re-invokes immediately — that turn is its processing turn); CLEARED by any top-level (`parentToolUseId == null`) `tool_result` event — a sync-delivered task's own held-open result (fast Agent calls, long Bash promoted to a task, e.g. a full test run) or the outer tool round-trip the CLI attaches queued notifications to (batched flush) — by every idle→turn transition in `_setStatus` (the dequeued notification IS the new turn's input), and on (re)spawn. Nested (subagent-forwarded) tool_results never clear it. Every status-gated frontend control still keys off the real `status`; the cosmetic surfaces (sidebar dot, sub-agents strip, header chip) read `displayStatus`.

**Idle task-drain settle (the third wake path).** A background task can finish while its worker is ALREADY idle with **no re-invocation turn ever following** (verified trace: a subagent's nested Monitor completed after the subagent — the stream's last lines were `task_updated` + `task_notification`, no `turn_end` ever re-sampled the gate, and the subscription orphaned until the watchdog). `IdleSubscriptionHub._onTaskEvent` runs on every `task_updated`/`task_notification`: when a watched target is fully drained (`status === 'idle'`, `activeAgentTaskCount === 0`, `!taskNotificationPending`, `!idleWindowDirty`) it arms a **settle timer** (`ORCH_IDLE_DRAIN_SETTLE_MS`) recording the target's proc identity and `ring.nextSeq`; `_fireSettle` delivers the wake only if the subscription still exists, the SAME proc is live and still fully drained, and `ring.nextSeq` is **unchanged** — literally zero events since the arming task event. The trap this must not reintroduce is waking ONE TURN EARLY: an idle completion that DOES get a re-invocation turn announces it with CLI-local `system/init` + `system/status` writes within ms of the notification, while the `message_start` that flips `status` to `'turn'` waits on the API (seconds — no settle length can safely outwait it). Re-invocation evidence is therefore caught structurally on both sides of the drain event: **after the arm** by the frozen-seq check (init/status advance the ring before the timer fires → drop, the re-invocation's `turn_end` owns the wake), and **before the arm** by `Instance._idleWindowDirty` (getter `idleWindowDirty`) — SET when any non-task-lifecycle event (`TASK_LIFECYCLE_SUBTYPES` = task_started/updated/notification) is processed while `status === 'idle'`, CLEARED at `turn_end` and on (re)spawn — covering a task that drains *inside* another task's already-opening re-invocation window. Every failed re-check drops the settle silently (subscription + watchdog stay armed): the fail direction is always "wake later via turn_end/watchdog", never "wake early" or "wake twice". The proc pin exists because respawn/rewind reuse the Instance AND its id but mint a new proc and reset the ring (`_wipeForResume`), making cross-run seq comparisons meaningless; history replay can't arm (it runs while `status === 'spawning'` and always trails a seq-advancing `history_replayed` event) and can't corrupt the dirty flag (replay bypasses `_handleStdoutLine`). `_justConsumed` stays turn_end-only — no worker `turn_notification` exists at settle-fire time. Accepted residuals: a CLI stalling longer than the settle between the notification and init writes (consecutive process-local writes, normally sub-ms — the window never scales with API latency) would wake one turn early; non-task noise in an idle window with no turn following falls back to the watchdog, same as before this path existed.

## Playbooks

Four modules, layered so the policy is pure and the wiring is thin. The wire contract, the tool arguments and the known limitations are in [protocol.md → Playbooks](protocol.md#playbooks); this is the internal shape.

- **`src/playbooks.ts`** — definition catalog (built-in seeds + user overlay through the shared `fragmentCatalog.ts` factory), the load-time validator, and the **pure** policy decision `decide({toolName, args, projection, playbooks, isLive})` → `{ok, patchedArgs, move}` or `{ok:false, code, reason, legalMoves}`. `isLive: (sessionId) => boolean` is a **required** parameter, never defaulted — a default reading the projection would reintroduce the second liveness authority this shape exists to rule out — so every call site is a compile error away from being found. A bad definition is rejected **at load time**, not at spawn time. The governable-tool index resolves through a **memoized dynamic import** of `mcp/tools.ts` specifically so `handlers.ts → playbooks.ts` (which the read tools need) cannot close a cycle; `validatePlaybook` is pure and synchronous, taking that index as a parameter.
- **`src/playbookLedger.ts`** — the append-only JSONL log (`fs.appendFile`, **never** `writeFileAtomic` or a rewritten document — the `archive-store-corruption` failure was a rewritten JSON store wiping itself) and the in-memory **projection** folded from it. One `applyEvent` serves both the boot fold and each live append, so an incrementally-updated projection cannot diverge from one folded from the file. Event kinds: `spawn`, `transition`, `retire`, `refusal`, `enforcement`, `resume`. The projection carries **no liveness bit** — `retire` and `resume` are audit-only, folding to no state beyond the event itself — so `WorkerState` has nothing for a second reader to consult by mistake. `resume` still un-retires a worker **in place** in the sense that matters (nothing else about it changes): it is a distinct kind rather than a second `spawn` precisely because the `spawn` arm *replaces* the worker's state, which would reset `stageHistory` and empty `provenance` (see [protocol.md → Resuming a playbook-tracked worker](protocol.md#resuming-a-playbook-tracked-worker)). Run membership is **derived** — the connected component over `provenance` edges ∪ same-worker transitions, via union-find — so there are no run ids and no external entity to keep in sync. `stageHistory` is what makes a `needs` entry's provenance half answerable; its `liveness` half is answered from `InstanceManager.isSessionLive` (`src/instances.ts`), THE single liveness authority — `liveSessionsInStage(p, anchor, stage, isLive)` takes that oracle as a required parameter rather than reading a fold. The store path resolves through a **lazy** function so a `PROJECTS_ROOT` override is honoured per call.
- **`src/mcp/playbookGate.ts`** — the single enforcement point, composed by `buildMcpRouter` so `mcp/server.ts` stays transport. Owns the conductor predicate lookup, the enforcement-level read, `decide()`, the refusal payload, and **every** ledger write — exactly TWO writers: the `tools/call` checkpoint's commits, and the manager's `status` stream (below). A `refusal` row records every worker the call named — `sessionId`, plus `forwardSessionId` when the call carried a forward — since the `code` alone says which side was refused (one `subjects(args)` helper, shared with the `playbook_warn` payload). Under `warn` it also pushes a UI-only `system`/`playbook_warn` event onto the **calling conductor** (`_emitUi`, strictly after the append) — the ledger has no reader, so without it the mode that exists to warn a human warns nobody; the conductor *agent* is unaffected, since `_emitUi` never reaches the CLI. Appends are serialized through one chain (`append` reads the seq then awaits the write) and the ledger path is **pinned on first resolution**, because some appends are fire-and-forget and a deferred write must not land in a different store than the one it was decided against. The stream writer carries the two things no `tools/call` can report: `retire` when a subprocess exits (an audit record — capacity no longer reads it) and `enforcement` when the level changes — watching the stream rather than each toggle's call site means a spawn-time value, the WebSocket flip and a restart restore are all recorded without any of them knowing the ledger exists. The gate also exposes `isLive(sessionId) => instances.isSessionLive(sessionId)`, the SAME oracle every `decide()` call here uses, so a read surface (`playbook_state`, `describe_playbook`'s dry-run) answers from the identical source rather than re-deriving its own. A host reboot (or an orchestrator crash) needs no boot-time repair any more: capacity and `needs.liveness` both read `isSessionLive` directly, so a session this process's registry never heard of simply holds no slot — see [protocol.md → Playbooks](protocol.md#playbooks).
- **`src/playbookConvention.ts`** — the pure renderer `renderPlaybookConvention(pb)` behind the preferred-playbook convention (contract in [protocol.md → Playbooks](protocol.md#playbooks)). Pure and store-free so it is unit-testable against a definition object; composed by `conductorConventions.ts` (`getDefaultPlaybookSelection`/`setDefaultPlaybook`/`resolveDefaultPlaybookId`/`defaultPlaybookConvention`), which resolves the selected id through `loadPlaybooks()` rather than a second discovery layer. Authored `description` text is passed through **verbatim** — the definition is its one home, and a renderer that reflowed or truncated it would become a second.
- **`src/mcp/handlers.ts`** — the three read tools, reading the gate's one projection through `readProjection()`/`readHistory()` rather than folding a second. Both load on demand, and that load is read-only, which is what lets a read tool answer on an install with no ledger yet without materialising the file.

**Definitions are the authority on what the graph is; the projection is the authority on where workers are; the instance field is the authority on the enforcement level.** The persisted `defaultPlaybookEnforcement` (`conductorConventions.ts`) supplies only the level a conductor is **born** at, applied in `Manager._doCreate` before `launch()`; nothing writes back to it, so the runtime authority is never split. `projection.enforcement` is written for the audit trail and deliberately has **no reader** — `playbook_state` reports the calling conductor's live mode off its instance instead, which also means nothing can surface a non-conductor as a governed actor.

## Testing
All tests via `node tests/run.mjs` (programmatic node:test runner — Termux's glibc-runner wrapper hoists leading `--flags` into `NODE_OPTIONS` and refuses `--test`).

**TypeScript toolchain.** Server-side `src/*.ts` runs directly under Node 24's native type stripping — no emit, no `dist/`, no bundler — so converted files are limited to **erasable syntax** (`tsconfig.json`: `strict`, `erasableSyntaxOnly`, `verbatimModuleSyntax`, `allowImportingTsExtensions`, NodeNext ESM). Because stripping never type-checks, `npm run typecheck` (`tsc --noEmit`) is an **enforced gate**, not an optional script: it runs as `pretest`, before every `npm test` (including the mutation harness's `npm test` baseline/test commands). Converting a module renames it `.js` → `.ts` and every importer's specifier with it (Node resolves import specifiers literally — no extension fallback); a still-`.js` sibling is imported via a minimal hand-written `.d.ts` that declares only what the `.ts` consumer uses (`src/projects.d.ts` today). Round 1 converted `modelVersions`, `usageWindowDomains`, `storeLock`, `sessionBackends`.

Test **files run in parallel** (node:test `isolation:'process'` — one child process per file). The suite is isolation-safe: `bootServer` binds an ephemeral port (`listen(0)`) and `mkdtemp`s a unique home per server, so files never contend over ports or paths. Concurrency defaults to a cores-derived cap (see `resolveConcurrency` in `tests/run.mjs`). Override with `TEST_CONCURRENCY=<n>` (`1` = fully serial). Measured ~79s serial → ~29s at the default on an 8-core device.

**Port ownership.** Picking a port by binding it and freeing it leaves a window in which another file's `bootServer()` `listen(0)` is handed the same port — after which an HTTP readiness probe is answered by that stranger and a destructive `POST /api/admin/restart` kills *another test file's process* mid-run. Two rules:

1. **Hold the socket when you can.** `tests/eaddrinuse-retry.test.mjs` and `tests/plugins-supervisor.test.mjs` bind `listen(0)` and never release until the test says so, which also makes the collision deterministic rather than lucky. **`tests/server-restart.test.mjs` deliberately does not** — it keeps bind-then-free `getFreePort()`. Card **2026-0157** proposed converting it to hold-then-release; that was **measured and declined**, not deferred (16-core host, idle; 5 instrumented runs + forced-contention runs):
   - **Window A**, `getFreePort()` resolve → the child's banner: **241–278 ms** (median 268; spawn lag 0–2 ms, the rest is boot). Hold-then-release does **not** close it — the gate is the child's first `EADDRINUSE on port` stderr line, which `listenWithRetry` (`server.ts`) writes at the *start* of its 100 ms sleep, leaving a measured **111–114 ms** residual.
   - **Window B**, `scheduleRestart`'s `server.close()` (`src/restart.ts`, before the replacement spawns) → the replacement's banner: **254 ms**, and it is not test-side at all — a competing bind took the port on its **first attempt, 2 ms after** the parent's `restart: spawned replacement pid=` log. No test change narrows it. Tracked separately.
   - So the conversion narrows **window A — the larger of the two (median 268 ms vs B's 254) — by ~2.4×** (268 → 111–114 ms). **Two different ratios, do not conflate them:** the per-file aggregate falls only **~1.43×** (2 tests × each window: 536 + 508 = ~1044 ms → 224 + 508 = ~732 ms), because window B is untouched and carries 508 of the remaining 732 ms. That is **~0.022% → ~0.016% collision per suite run** (~261 ephemeral binds per run over ~30–60 s against 28232 free ports, `/proc/sys/net/ipv4/ip_local_port_range`). The reason to decline is not that A is the smaller window — it is the larger — but that a production window **nearly as large** survives untouchable from a test while the machinery reads as "window closed". Declined on those numbers; do not re-open without new ones.
   - What makes ~0.022% acceptable is rule 2: forced contention on either window ends at `waitForBanner` rejecting (`child never printed listening banner #<n> for port <p>`), and in both forced runs the stranger received **zero** requests. The cost of a collision is this file timing out, never another file's process.
   - Dead alternative: spawning with `PORT=0` and reading the bound port back from the banner would close window A entirely, but `spawnReplacementAndExit` passes `env: process.env` (`src/restart.ts`), so the replacement inherits `PORT=0`, binds a *different* port, and destroys the same-port invariant.
2. **Never trust the port as identity.** Readiness on a spawned `server.ts` waits for that child's own stdout banner `code-conductor listening on http://<host>:<port>`, printed from the address it actually *bound* — never an HTTP probe a stranger answers just as happily. The rule lives once in **`tests/serverBanner.mjs`** (`waitForBanner(captured, port, {nth})`; the restart replacement inherits the same stdout, so its banner is occurrence #2) and is imported by every test that waits on a `server.ts` child. Additionally, never send a destructive request to a port whose owner you have not established: `server-restart.test.mjs` asserts the port is still `EADDRINUSE` immediately before each restart POST.

`tests/restart-port-identity.test.mjs` is the regression guard — a decoy `node:http` server answers the old probe while the real child cannot bind, and the test asserts that `waitForBanner` (the same import the restart tests use, which is what makes the guard cover them) rejects rather than reporting ready.

**Store isolation (`tests/safeStoreRoot.mjs`).** The sidecar stores resolve their on-disk root from `PROJECTS_ROOT`, falling back to a source-relative default (`src/../..`) that IS the real production `.code-conductor` when it's unset — so a test touching a store with `PROJECTS_ROOT` unset corrupts the live store. `run.mjs` pins the whole run to a throwaway temp root (`createSafeRoot()`) before any file forks — every child inherits it — and asserts via `assertStoreIsolated(orchStoreRoot())` that the store never resolves into the real workspace (aborting the run if it would). `bootServer` teardown restores `PROJECTS_ROOT`/`CLAUDE_PROJECTS_ROOT` to that safe root, never to unset, so out-of-window writes stay in the temp dir. `tests/store-isolation.test.mjs` is the regression guard.

**harness/playwright depth.** `harness/playwright/boot-orch.mjs`'s orchestrator cwd is derived from its own directory depth; `4c1a3da` added a level and left it one short, breaking every `bootOrch()` caller with an opaque `child server exited before binding`. The constants now live in `harness/playwright/paths.mjs` — node builtins only, so it imports cleanly without the sibling `code-playwright` clone — and `tests/harness-playwright-paths.test.mjs` is the ungated regression guard. `boot-orch.mjs` consumes the same exports behind a fail-loud `existsSync` precondition.

**Forcing a fire-and-forget sidecar write to land late.** A store write fired without `await` (e.g. `markSessionBackend` at `Instance.spawn()`) can race a test's post-spawn read. Sample-then-assert is flaky by construction; the deterministic pattern (`tests/backend-spawn.test.mjs`, describe `'a sidecar write that lands after the spawn response'`) pre-creates `<dataFile>.lock` with a live PID (this test process's own) *before* triggering the write: `storeLock.ts` reclaims a held lock only when the owner PID is dead, so the write provably cannot have landed while the lock stands — a hard mutual-exclusion barrier, not a timing delay. Assert the miss first (proves the forcing engaged), release the lock, then read through a `waitFor`-based helper (`settledSessionBackend` in `tests/helpers.mjs`) rather than sampling again.

**DOM-vs-null assertions (`tests/dom-assert.mjs`).** Never compare a DOM node against `null`/`undefined` with `assert.equal`/`strictEqual`/`deepEqual` — use `assertNull(node, label)` / `assertUndefined(node, label)`. On failure node serializes `err.actual` across the per-file child-process boundary, walking a live happy-dom element's circular `ownerDocument`/`Window` graph: the file stalls **33–120s** and then aborts, so **every later test in it silently never runs**. Supplying a message makes it *worse*, not better (3-arg measured slower than 2-arg at the same site — `err.actual` crosses the boundary regardless), so the rule is unconditional on arity. `deepStrictEqual` never terminates at all: it grows unboundedly until the OS kills it (`exit 137` on a smaller device; **27 GB RSS** on a 30 GB host, killed by hand at ~2 min before the kernel acted), and `--max-old-space-size` does **not** bound it — do not raise that flag to chase the symptom. Reproduce **only** under a hard address-space cap, which does bound it because it cuts below V8's own accounting: `( ulimit -v 2000000; node repro.mjs )` aborts in **0.9s** with `exit 134` (SIGABRT) and never passes 2 GB. Without it the process consumes the whole machine, not just its own test run. The helpers compare without handing the node to `assert` and throw an `AssertionError({message, stackStartFn})` carrying only a short `<tag#id.class>` summary, leaving `actual`/`expected` `undefined` — that is what keeps the cycle off the wire. Always pass a `label` naming the element and its source (`'copy button must not be inside <pre>'`): nothing enforces it (a missing one just yields `undefined — expected null, found …`), but it is the whole failure message.

**Enforcing the DOM-vs-null rule — two guards, non-overlapping ownership.** The 2026-0150 sweep fixed ~50 occurrences but nothing stopped re-accumulation, and only *failing* assertions stall, so a green suite hides the pattern. Both guards are needed; each module's header says why the other cannot be deleted as redundant.

- **`tests/dom-assert-scan.mjs` (+ `tests/dom-assert-guard.test.mjs`) OWNS the invariant** *no equal-family assertion in `tests/` is written against a DOM-valued expression.* It is the only guard that fails at authoring time on a site that currently **passes** — a latent site is invisible at runtime, which is exactly how the sweep's occurrences accumulated.
- **`tests/dom-assert-tripwire.mjs` GUARDS THE PATH, for one shape only:** *a DOM node compared against `null`/`undefined` by a positive equal-family assertion never reaches assert's serializer.* Preloaded into every per-file child via the `execArgv: ['--import', …]` option on `run({…})` in `tests/run.mjs`; it wraps only the positive family (`equal`/`strictEqual`/`deepEqual`/`deepStrictEqual` — `not*` can only fail when the operand is already nullish) and throws an `AssertionError` carrying just the `<tag#id.class>` summary. It covers DOM-ness the scan is structurally blind to. **Not covered, and still stalling 33–120 s:** a node compared against a non-nullish value (`assert.equal(node, 5)`, `assert.equal(el.parentElement, otherNode)`) and a node nested inside a compared structure. Tracked as card **2026-0163**; do not widen the tripwire, because intercepting any node operand breaks legitimate node-vs-node assertions that currently pass.

The shared predicate `isDomNode` and the `describeFound` formatter live in **`tests/domNode.mjs`, which must have ZERO imports**: `dom-assert.mjs` imports `node:assert/strict`, and instantiating assert's ESM namespace during the preload is what creates the hole below.

**The scan is comment-stripped and paren-balanced, not a line regex.** A line regex both over-matches prose (`tests/header-playbook-enforcement.test.mjs:165-169` names `assert.equal(node, null)` in English) and misses multi-line-formatted calls (`tests/notifications.test.mjs:200,208,213`). `stripNonCode` blanks comments, string bodies, template *text* (`${…}` stays live) and regex bodies; **line numbers stay valid because newlines are preserved**, not because the output is the same length. The argument splitter then walks a `()[]{}` stack. **No JS parser is available** — `typescript@7.0.2` is the Go-native `tsgo` shim (exports only `version`/`versionMajorMinor`), there is no acorn/babel/espree, and `CONVENTIONS.md` forbids adding one.

**Scan direction, and why there is no allow-list.** Enumerating every legitimate primitive-vs-null comparison in `tests/` is intractable — they take too many arbitrary shapes and share no primitive signal. The scanner instead keys on DOM-*producing* signals in **tail position** — so `root.querySelector('a').length` correctly does not match. Receiver scoping on the `DOC_PROPS` and `PICKS` signal sets is load-bearing, not decoration: an unscoped `.body` produced the only false positives measured (5, all HTTP response bodies), and an unscoped `.find` conflates `[...root.querySelectorAll('.x')].find(…)` with `list.body.find(…)`. There is deliberately **no escape hatch**: a genuine future false positive is fixed by narrowing a signal constant in one place, never by an inline ignore comment.

**Measured recall: 46 of the 50 pre-sweep sites, at zero false positives across every legitimate primitive-vs-null comparison in `tests/`** (unchanged after widening `isDocumentReceiver` to accept a `.document` tail and adding the destructuring arm). Exact counts drift as unrelated cards add nullish assertions, so they are not restated here — `tests/dom-assert-scan.mjs`'s header carries a MEASUREMENT RECORD with the numbers, the sha and the date; re-derive with `scanTestsDir('tests')`. The 4 residual occurrences are 3 distinct expressions — `conv.emptyNode`, `main.leadingAssistantWrap` (×2), `batch.leadingWrap` — whose DOM-ness lives in `public/` return values and is absent from the test syntax entirely. Two further shapes are **waived** known misses, named in the scanner's false-negative note: redundant parens around a whole call, and declare-empty-then-assign. **None of this is an oversight and must not be "fixed" with a name list**; the tripwire bounds them at runtime.

**The tripwire must use `createRequire(import.meta.url)('node:assert')`, never a static ESM import.** Measured: with `import assert from 'node:assert'` in the preload, a test file's `import { strictEqual } from 'node:assert'` **bypasses the patch** — the ESM namespace snapshot of the CJS named exports is taken when the preload instantiates it, before the patch lands. `createRequire` leaves the namespace uninstantiated, and all four styles (both modules × named/default) end up patched. Patch `assertObj.strict[k]` as well (`assert.strict` is `node:assert/strict`'s default export). Forward `arguments` (`orig.apply(this, arguments)`) — named parameters would turn `assert.equal(1)` into `assert.equal(1, undefined)` and lose `ERR_MISSING_ARGS`. If the preload itself throws, the child exits 1 before the body runs and `run.mjs`'s `test:fail` counter increments; it cannot silently no-op.

`tests/dom-assert-guard.test.mjs` holds T1–T11, each titled with the invariant it pins: tree-is-clean (T1), induced-violation recall across seven shapes (T2), comment/string immunity incl. the real prose comment (T3), `not*` never flagged (T4), historical-recall floor (T5), tripwire behaviour parity via two child processes over a 12-case table (T6), tripwire installed-and-fires via a node-*ish* plain object — never a live node, so an absent tripwire fails instantly instead of stalling (T7), `dom-assert.mjs` reads the shared predicate (T8), the predicate accepts a real happy-dom node (T9), all four import styles patched (T10), throwing-preload fails loudly (T11). **Cost:** scan ≈300 ms including its extra `node:test` child (~180 ms of blanking + matching over all of `tests/`); the tripwire's per-child cost is below the ±7 ms run-to-run noise floor; T6/T10/T11 add 4 child spawns ≈200 ms.

**ClaudeLauncher seam (in-process fake by default).** `Instance` never calls `child_process.spawn` directly — it spawns through an injected `ClaudeLauncher.launch({command,args,cwd,env})` (`src/claudeLauncher.ts`), threaded `createServer({claudeLauncher})` → `new InstanceManager({claudeLauncher})` → `Instance`. Production default is `RealClaudeLauncher` (a raw `child_process.spawn` — behavior byte-for-byte unchanged). `src/claudeLauncher.ts` also owns the two pure launch-resolution primitives — `resolveClaudeBin()` (splits `CLAUDE_BIN`, default `claude`, into `{command,prefixArgs}`; test injection via `CLAUDE_BIN="node fake.mjs"`) and `resolveBackendLaunch(backendRecord, model, claudeBin)` — so one-shot spawners that need no `Instance` (`health.ts`'s boot probe, `summarize.ts`'s summary generation, `claudeShellEnv.ts`'s bundle-gen) can import just these without pulling in the 2000+-line `instances.ts`. **Backend-agnostic spawn:** `resolveBackendLaunch` computes only command + prefix (plus the backend's `env`) from the **backend record**; every caller then appends the same claude args (including `--model <model>`) uniformly. A blank `template` returns the resolved claude bin's `{command,prefixArgs}` unchanged; otherwise the template is whitespace-split with `{model}` substituted **inside each token** (so `--model={model}` works too), token 0 becoming the command and the rest the prefix — e.g. the built-in `ollama` row yields `['launch','claude','--model',<model>,'--yes','--']` (the model also rides in the forwarded `--model` — a harmless no-op duplicate). Because templates are DATA, there is no per-command env shim: a test pointing a backend at a fake binary just registers a row whose template names it. The helper owns the **null-model invariant** — it throws whenever the template is non-blank and no model resolved (unconditional on the template shape; see the create-time guard below), rather than emit `--model undefined` — so `Instance.spawn()` wraps the call in a try/catch only to add its own `_setStatus('crashed')` side effect before rethrowing. A backend needing a non-default host sets it as an `env` pair on its registry row (e.g. `OLLAMA_HOST`) rather than through any dedicated plumbing. Only `model` + `backend` thread `create()→_doCreate→Instance ctor→spawn()`; both appear in `summary()` (so the resume manifest carries them) and survive an in-place `/clear` renewal. On resume, `backend` is recovered from the `session-backends.js` marker; `model` is recovered from that same marker's tagged value for substitution-backend sessions (the jsonl `message.model` is bare — tag dropped by the inner CLI — so a jsonl-only recovery would relaunch the unpullable tagless name), falling back to the jsonl (`readLastSessionModel`) for Claude sessions and legacy model-unknown entries. There is **no** spawn-time reachability preflight — a bad backend or model fails at launch, and a subprocess on a substitution backend that dies on its own emits a `system/launch_failed` event with captured stderr (`_handleExit`, gated by a `_killing` flag so a commanded kill isn't mislabeled). That event is therefore the only failure signal for a misconfigured backend. Two create-time guards still fire before any spawn: `422 BACKEND_MODEL_MISSING` when a substitution backend has no resolvable model (unconditional on the template shape — the model also rides in the forwarded claude args and drives the context-window env, so a template that omits `{model}` is no exception), and `422 BACKEND_GONE` when the named backend isn't in the registry, whether it came in explicitly or from the session sidecar. `Instance.spawn()` re-checks the record and refuses a null one, so a row removed under a live instance crashes it visibly instead of falling into resolveBackendLaunch's identity branch and launching the real `claude` with a foreign model id. A live "Change model" (`Instance.setModel(model, backend)`) is **blocked** (`409 BACKEND_LOCKED`) whenever either side is a non-`claude` backend, including substitution↔substitution (the running endpoint is fixed at launch), with a "kill and respawn" message; only Claude↔Claude live switches proceed. **`bootServer()` defaults to `InProcessClaudeLauncher`** (`tests/inProcessLauncher.mjs`): the fake-claude engine runs on the event loop against in-memory `PassThrough` streams — **zero OS subprocesses per instance**. This is the forget-proof default (an Android phantom-process-killer defense: the app UID is killed above ~32 processes), so a normally-written test forks nothing. The in-process handle is a `FakeChildProcess` (EventEmitter + 3 PassThrough + `pid=null`); it defers engine start to `setImmediate`, gates `'exit'` on the readable-side `'end'` of stdout/stderr (so a trailing `turn_end` is never delivered after `'exit'`), and maps `kill('SIGKILL')` → `exit(null,'SIGKILL')`, `kill('SIGTERM')`/`stdin.end()` → graceful `exit(0,null)`. `pid=null` makes the manager's OS-`process.kill` sync-shutdown paths (`shutdownTempSync`/`shutdownForResumeSync`) a safe skip.

The fake-claude **scenario engine** lives once in `tests/fake-claude-engine.mjs` (`runFakeClaude({argv,env,cwd,stdin,stdout,stderr,onReaderReady})`): silent until first stdin message, auto-acks `control_request`s, emits canned events from `env.FAKE_CLAUDE_SCENARIO`, matches `control_response`s so scenarios can branch on allow/deny. `env.FAKE_CLAUDE_ARGV_DUMP` / `FAKE_CLAUDE_ENV_DUMP` capture the launch argv / computed child env; `FAKE_CLAUDE_TRANSCRIPT` records stdin. It reads everything from its params (not `process.*`), so the same engine drives both the in-process launcher and the thin subprocess entrypoint `tests/fake-claude.mjs`. Config flows through `env` (bootServer sets `FAKE_CLAUDE_SCENARIO`), and for the in-process path `CLAUDE_BIN` is a **bare sentinel** (`claude`, no script path) so `resolveClaudeBin`'s `prefixArgs` stay empty and the argv the engine sees equals the real CLI flag set.

**`bootServer({claudeLauncher})`** injects a custom launcher (e.g. `tests/backend-spawn.test.mjs`'s `ControllableLauncher`, whose child stays alive until the test triggers a spontaneous `crash()` or a `kill()`) to exercise post-launch crash paths. A test needing a **substitution backend** that reaches a real fake binary registers a registry row whose `template` names it (`addBackend`) — templates are data, so that is the injection seam; there is no per-command env shim.

**`bootServer({realProcess:true})`** opts a test back into a real `node fake-claude.mjs` subprocess (`RealClaudeLauncher`) — needed only where a test uses a real `.pid` / OS `process.kill(pid)` / the SIGKILL+reap sync-shutdown path: the `instances.test.mjs` crash+respawn test, and the two `shutdownTempSync` tests (`archive-sessions.test.mjs`, `restart-temp-cleanup.test.mjs`). Each opts in per-test (booting its own dedicated realProcess server) so the rest of its file stays in-process. `shutdownForResumeSync` is graceful (`stdin.end()`), so `resume-after-restart.test.mjs` stays fully in-process.

**Process-count guardrail** (`tests/run.mjs`): samples the peak concurrent `fake-claude.mjs` subprocess count via `/proc/*/cmdline` (~100 ms) and fails the run if it exceeds a process-count budget `FAKE_CLAUDE_BUDGET` (`tests/run.mjs`) — catching a regression that flips the default back to subprocess or a new test that spawns real processes without `realProcess:true`. A clean default run peaks at ~2–3 (only the realProcess opt-in tests). Enforcement is skipped under `RUN_REAL_CLAUDE=1` and when `/proc` is unavailable. (Use `/proc` reads only here — `pkill`/`lsof` misbehave on this host.)

The subagent-aware idle-wake deferral (`IdleSubscriptionHub._onTurnEnd` gating on `activeAgentTaskCount` **and** `taskNotificationPending`) is covered by `tests/idle-subagent-defer.test.mjs` (two layers: hub-gate tests with injected fake instances driving `manager.emit('event', turn_end)`, and Instance-lifecycle tests feeding captured-shape raw stdout lines to a real unspawned `Instance._handleStdoutLine` — sync-delivered result clears, attach-batch clears, nested tool_result does NOT clear, a queued notification survives turn_end until the re-invocation turn start, an idle notification never sets) and end-to-end in `tests/mcp-subscribe-to-idle.test.mjs` via four fixtures — `scenario-bg-task-hang.json` (turn_end while a subagent is live, never completes → wake deferred), `scenario-bg-task-complete.json` (subagent completes *between* turns + follow-up turn_end → single delivery), `scenario-bg-task-midturn-complete.json` (mid-turn `task_notification` with no tool_result after it → wake deferred to the re-invocation turn's turn_end, single delivery), and `scenario-bg-task-midturn-consumed.json` (mid-turn `task_notification` followed by a top-level tool_result → consumed in-turn, wake fires at that same turn_end — regression for the indefinite-defer hang).

The idle task-drain settle path is covered by `tests/idle-drain-settle.test.mjs` (sets `ORCH_IDLE_DRAIN_SETTLE_MS=400` before a dynamic import — the settle length is a module-load-time constant). Three layers: hub-gate tests (fakes extended with `ring.nextSeq` + `idleWindowDirty` — orphan drain wakes once and cancels the watchdog; post-arm seq advance and pre-arm dirty window both refuse the early wake; fire-time drops on status flip / removal / proc replacement; re-arm resets the freeze baseline; turn_end/purge/unsubscribe/watchdog all cancel a pending settle; `wasConsumed` stays false on a settle-fire), Instance-lifecycle tests for the `_idleWindowDirty` edges, and two end-to-end fixtures — `scenario-bg-task-idle-drain.json` (turn_end deferred on a live bg task, then `task_updated`+`task_notification` at idle and silence → the settle delivers the folded wake, exactly once, with no second turn_end ever) and `scenario-bg-task-idle-reinvoke.json` (same drain followed by the re-invocation's `init`/`status`/`message_start`/`turn_end` at 150 ms spacing, so the 400 ms settle deadline falls inside the pre-`message_start` silence → no early wake, single wake at the re-invocation `turn_end`).

`tests/instance-liveness.test.mjs` covers `InstanceManager.isSessionLive`. Mostly unit-level, no server: bare `InstanceManager` plus prototype-only `Instance` stand-ins pin the THREE completeness windows bare `liveForSession` would miss — a resume in flight via `_resumingPublicIds` (live with no `byId` entry at all), a prune's kill→relaunch window via `rotationPending` (live with `proc` null), and rewindToUserMessage's/`InstanceManager.respawn`'s identical window via `_relaunching` (added after an independent review found the first cut of the oracle incomplete for those two paths) — alongside the ordinary proc-attached and genuinely-dead cases. A `describe` block boots a real server (fake-claude launcher, no real subprocess) to prove `rewindToUserMessage`/`respawn` actually SET `_relaunching` at the right moments (per-path, via a `launch()` monkey-patch that captures `isSessionLive` at the instant it is invoked — a synchronous call-then-check trick does not work here, since neither path has a genuine multi-tick async gap for a plain worker) and CLEAR it once the relaunch lands, so a worker killed afterward with no further relaunch pending reads not-live — the dangerous direction: a flag that outlives its window would read a dead worker live forever, wedging a `workers:"one"` slot and satisfying `needs …@live` permanently. `tests/playbook-liveness.test.mjs` covers the gate level: a hand-seeded ledger file plus a stub `InstanceManagerLike` (`isSessionLive` is the only liveness input it exposes) drives `gate.check()`/`gate.readProjection()` directly — a `needs:@live` entry is satisfied or refused purely from the stub's `isSessionLive`, independent of what the ledger's own `retire`/`spawn` history says, and a `workers:"one"` slot seeded with no `retire` event anywhere reads free the moment the stub reports the occupant not-live, with **no boot-time write**: every allowed-decision case asserts the ledger file is byte-identical afterwards, which is what kills a reintroduced repair writer even if it computes the right answer. `tests/playbook-enforce.test.mjs`'s `setup({seedLedger})` option writes a hand-authored ledger (a complete relay run with no `retire` event, under sessionIds that never existed in this test process) **between** `bootServer()` and the conductor spawn — the conductor's first status tick reaches `ensureLoaded()` before `setup()` returns, so seeding any later would fold against a bare projection — and asserts a fresh `workers:"one"` spawn into that stage succeeds with no `retire` event written for the orphaned row at all, by construction rather than by a boot repair.

Opt-in real-claude smoke (`smoke.real.test.mjs`, `RUN_REAL_CLAUDE=1`): spawns the actual CLI, asserts `system/init` + ≥1 `text_delta` + non-error `turn_end`. Cleans the session jsonl on exit.

`prune.real.test.mjs` (same `RUN_REAL_CLAUDE=1` gate) is the regression test for Prune's harness-state invariants — it cannot be replaced by a fake, because what it checks is how the real CLI reconstructs state from a transcript. It reads a file, prunes, resumes, asserts the Edit is refused with the CLI's own "File has not been read yet", then re-Reads and asserts the Edit applies. **Pinned to `claude-haiku-4-5`**: the read-before-edit guard is only enforced for a fixed model set, so on a newer model the test would pass vacuously. It also has to point `CLAUDE_PROJECTS_ROOT` at the real `~/.claude/projects` after `bootServer` — HOME is not overridden for the child, so the real binary writes its transcript there while the temp store would otherwise be read server-side. (The other real-claude tests only inspect the event stream, so they never hit this.)

The plugin system tests against **`tests/fixtures/fake-plugin/`** — a dependency-free `node:http` child (health, relative-asset HTML, streaming `/echo`, hand-rolled WS echo, MCP endpoint with `echo`/`sleep`/`fail`/`transport-bug` tools pinning both halves of the child contract) plus `crash.mjs`/`slow-ready.mjs`/`forker.mjs` for the supervisor edge cases; `tests/plugin-helpers.mjs` clones it into temp projects roots. `bootServer` exposes `pluginHost` (and `pluginLibrary`) and stops plugin children on close. `tests/plugins-library.test.mjs` unit-tests `createPluginLibrary()` directly (mirrors `plugins-registry.test.mjs`'s direct-construction style) with `_cloneImpl`/`_runHookImpl` test-only overrides standing in for the real `git clone` child process and postClone/postPull commands — no network needed; its `update()` pull-success test uses a small real local git fixture (a bare "remote" + a seed clone that pushes a second commit, mirroring `plugins-registry.test.mjs`'s own local-git-fixture `git()` helper) so the real `runGit`-based `--ff-only` pull is exercised end-to-end. `tests/plugins-api.test.mjs` covers the `/api/plugins/library*` HTTP surface for listing + validation-error paths (invalid scheme, already-installed, not-installed) without ever invoking a real clone or pull.

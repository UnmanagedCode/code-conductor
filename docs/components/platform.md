# Components: the host-OS seam and shared helpers

The Platform seam, grouped commands, small shared helpers, and the `shared/` modules the web UI imports.

## `src/platform/`

the host-OS seam.
`Platform` (`platform.ts`) has these members besides `capabilities`: `commandFor(spec)` (`{shell}` → login shell, `{argv}` → executable + args; a script is `{argv:['bash', script]}`), `spawnOptions('child'|'group'|'daemon')` (base spawn options, spread FIRST at each spawn; `child` is tied to cc, `group` leads its own process group, `daemon` must outlive cc), `killProcess(pid|handle, signal)` (a handle wherever the caller has one), `killGroup(pid, signal)`, `processStartTime(pid)` (an opaque token naming when the process started — equal across reads of one process, different for a later process reusing the pid — or null when unknown; compared, never parsed. posix: field 22 of `/proc/<pid>/stat` through `procStartSync` where `/proc/self/stat` exists, else `ps -o lstart= -p <pid>` (macOS), capped at `START_TIME_TIMEOUT_MS` (`platform.ts`). win32: `startTimeArgv` — `<SystemRoot>\System32\WindowsPowerShell\v1.0\powershell.exe -NoProfile -NonInteractive -Command "(Get-Process -Id <pid> -ErrorAction Stop).StartTime.ToUniversalTime().Ticks"`, run hidden, capped at `START_TIME_TIMEOUT_MS`, digits only.
The running record's orphan-CLI reap is its caller, `src/runningRecord.ts`), `splitCommand(line)` (`CLAUDE_BIN` / backend template → argv) and `pathKey(p)` (equality key for two host paths; used through `samePath` for exact comparisons against paths git prints), `terminalShell()` (the argv a local terminal runs when its caller names none — posix: `posixLoginShell()` from `src/systems/ptyHost.ts`, the user's shell with `-l`; `null` where cc has no pty helper, and `LocalSystem.openTerminal` refuses `PTY_UNAVAILABLE`), plus `softSigterm` (data: true when SIGTERM lets the target run its shutdown handler, false where it is `TerminateProcess`), `cliEnv()` (variables the claude CLI needs on this host, merged UNDER the caller's env by `cliEnvBase(platform)` in `src/cliEnv.ts` — the one chokepoint for the session spawn, `sessionOneShot.ts` and `claudeShellEnv.ts`) and `canonicalPath(p)` (the spelling the CLI's `getcwd()` reports for an existing directory, or null when p cannot be resolved because it does not exist yet; `projectsRoot()` returns it through `canonicalRootMemo(platform)` in `src/storeRoot.ts`, memoised per raw `PROJECTS_ROOT` — but only a resolved spelling, so a root created later is re-asked — and every cwd derived from the root names the transcript dir the CLI will use).
`posix.ts` and `win32.ts` are the implementations (posix: `softSigterm` true, `cliEnv` `{}`, `canonicalPath` identity, never null); `index.ts` holds `selectPlatform(os)`, `hostPlatform = selectPlatform(process.platform)` — the only `process.platform` in the repo — and `samePath(a, b)` (the host's `pathKey`).
**Injection — one rule:** a **holder** (a class or `createX` factory, or `createServer`/`start`) takes `platform` once, as a constructor/factory option defaulting to `hostPlatform`, and passes its own platform to every helper it calls; the holders are `createServer`, `start`, `Instance`, `InstanceManager`, `RealClaudeLauncher`, `LocalSystem`, `createPluginHost`, `createSupervisor`, `createPluginLibrary`.
A **free function** reads `hostPlatform` itself.
A free function a holder calls takes `platform` as a **required** parameter (no default), so a holder that forgets to forward fails the typecheck; host-only callers (`selfUpdate.ts`) pass `hostPlatform` explicitly.
Process singletons — `localSystem()` and `projectsRoot()` — are host-bound: the platform injected into `createServer` does not reach them.
No setters, and nothing assigns to a `hostPlatform` member.
`tests/platform-seam-guard.test.mjs` pins which files may hold a `hostPlatform` default (`HOLDERS`).
**Left unrouted:** liveness checks (`storeLock.isProcessAlive`, `plugins/ports.pidAlive`, `fuse/driver.pidIsAlive` use `process.kill(pid, 0)`, which is portable); `procStartSync` (FUSE-mounted sessions directly; everything else through `processStartTime`); `writeFileAtomic`; `isWithin`; voice (`installRunner.ts`, `tts.ts`, `transcribe.ts`) and `src/systems/**`, which `Platform.capabilities` gates (below); `fetchOriginBounded`'s `execFile` `killSignal`.
Pinned by `tests/platform-posix.test.mjs`, `tests/platform-win32.test.mjs`, `tests/platform-injection.test.mjs` and `tests/platform-seam-guard.test.mjs`.

## `src/platform/win32.ts`

`createWin32Platform({env, exists, execFileSync, realpathNative, realpathJs})` (injectable, so it is unit-tested on Linux; `path.win32` throughout); `win32Platform` binds it to this process. All capabilities off, `softSigterm` false, `terminalShell()` null (no local terminals). `resolveGitBash`, `gitRootOfBash` (Git root from `<root>\bin\bash.exe` or `<root>\usr\bin\bash.exe`) and `taskkillArgv` are also imported by `bin/windows-launch.mjs` ([windows.md](../windows.md)).
- **Git Bash** (`resolveGitBash`, exported and pure): first existing of `CLAUDE_CODE_GIT_BASH_PATH`; per `PATH`/`Path` dir holding `git.exe`: `<dir>\..\bin\bash.exe` then `<dir>\bash.exe`; `%LOCALAPPDATA%\Programs\Git\bin\bash.exe`; `%ProgramFiles%\Git\bin\bash.exe`. None → throws naming every candidate. Success only is memoised. `commandFor({shell})` → `bash -lc`; `{argv}` maps `bash`, `sh` (`<Git>\bin\sh.exe`) and `env` (`<Git>\usr\bin\env.exe`), and for `env` also the first token after the leading `NAME=value` args (the post-worktree hook); anything else passes through (`git`, `claude` resolve via PATHEXT). `commandFor` throws only when the mapping needs bash and it is unresolved: `runGroupedCommand` turns that into a `spawnError`, `checkClaudeReadiness` into a `shell_missing` issue.
- **`cliEnv()`** → `CLAUDE_CODE_GIT_BASH_PATH` when the operator left it unset and Git Bash resolves, else `{}`.
- **`spawnOptions`**: `windowsHide: true` for every role; only `daemon` is `detached`. libuv's `detached` is `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`: no console, and the child leaves its kill-on-close job — and a console grandchild of a console-less parent allocates a visible console. `group` needs no leader because the tree kill goes by parent pid.
- **Kill**: `killGroup` and `killProcess` both run `<SystemRoot>\System32\taskkill.exe /T /F /PID <pid>` (`taskkillArgv`, ~65 ms). `killGroup` throws on a non-zero exit (`ESRCH` for 128) so `killProcessGroup`'s fallback runs; `killProcess` falls back to the handle's `kill` (e.g. "Access denied" over an SSH logon, where a tree kill is impossible).
- **`splitCommand`**: whitespace tokens, `"…"` groups (quotes removed), backslashes literal, empty tokens dropped. **`pathKey`**: `path.win32.normalize`, trailing `\` stripped except a drive root, lower-cased. **`canonicalPath`**: `realpathSync.native`, else native of the JS realpath (resolves a junction native refuses), else null (unresolvable).

## Stopping the CLI without `softSigterm`

(`CLEAN_STOP_GRACE_MS`, `src/instances.ts`): `softSigterm` is read at two sites only — `Instance.kill` and the `InstanceManager` constructor's sync-stop policy (`_syncStop`). Where SIGTERM is not soft, `Instance.kill` calls `interruptTurnForStop()` (a busy turn gets `control_request interrupt` and `_stopInterruptedTurn` is set), ends stdin, and raises `graceMs` to `CLEAN_STOP_GRACE_MS` so the SIGTERM/SIGKILL timers (tree kills) are only a backstop. `IdleSubscriptionHub._onTurnEnd` ignores, and `liveTurnEnds` does not count, the `turn_end` of an instance with `_stopInterruptedTurn` set — neither reads the platform — so a conductor's armed wake resolves through the exit path and a killed busy session never reads as Finished. `_stopInterruptedTurn` resets on every `spawn()`. The sync-stop policy: `shutdownForResumeSync` waits its grace over all instances together — a fixed 2 s where SIGTERM is soft, `CLEAN_STOP_GRACE_MS` where it is not — and kills survivors only where SIGTERM is not soft; it sends no interrupt (every turn is idle by contract). **Known limit — a synchronous stop cannot deliver EOF:** `stdin.end()`'s shutdown runs on the event loop, which `_stopAllSync`'s `Atomics.wait` blocks, so a CLI sees EOF only once cc exits. Where SIGTERM is not soft, every CLI still live at the deadline is therefore tree-killed. On posix the poll cannot observe an exit (an unreaped child still answers `kill(pid, 0)`), so the wait runs its full grace and the CLIs exit after cc.
- Pinned by `tests/instance-kill-hard-signal.test.mjs`.

## Platform capabilities

(`Platform.capabilities`, `src/platform/platform.ts`; the refusal codes and helpers are in `src/capabilities.ts`). A flag marks a feature this host can run; when off, the feature is hidden in the UI and refused with a stable code. POSIX has all three on. The modules stay statically imported (they do nothing at import), so only behaviour is gated.

| Flag | Hides / refuses | Code |
|---|---|---|
| `remoteSystems` | `/api/settings/systems*`, `PUT /api/projects/:name/remote`, a non-local `system` on `POST /api/projects` (501), `POST /api/exec` (501, also a project placed on one) and `POST /api/projects/external` (200 soft); MCP `system_bash`, `system_transfer`, `set_project_remote` and `enumerate_remotes` (omitted), `create_project` / `adopt_project` with a non-local `system`; Settings → Systems and the New/Adopt system pickers | `SYSTEMS_UNAVAILABLE` |

| `voice` | `/api/transcribe*`, `/api/tts*`, `/api/settings/transcribe*`, `/api/settings/tts*`; Settings → Voice, the composer mic and the 🔊 probe | `VOICE_UNAVAILABLE` |

## `src/groupedCommand.ts`

the local implementation of the System `exec` primitive (its option/result shapes ARE `ExecOptions`/`ExecResult` from `src/systems/system.ts`; its output accounting IS `ExecOutputCollector` from `src/systems/execCollector.ts`, shared with the wire implementation).
`runGroupedCommand({argv}|{shell}, {cwd, env?, timeoutMs?, cap?, headCapBytes?, maxBufferBytes?, onChunk?, killGraceMs?, stdin?, envOverlay?, encoding?}, platform?)` → `{code, stdout, stderr, output, timedOut, truncated, outputMayBeIncomplete?, durationMs, spawnError, stdoutBytes?, stderrBytes?}`, plus `killProcessGroup(pid, {graceMs, fallback, platform?})` and `GROUP_OUTPUT_CAP`.
The one process-group runner.
The platform's `group` spawn options make the child its own group leader so one `platform.killGroup` reaches every grandchild — a timed-out `npm ci` otherwise keeps running after the request that started it is gone — and a SIGTERM → unref'd SIGKILL backstop handles a script that traps SIGTERM.
Never rejects: a spawn failure is `{code:1, spawnError}`, a timeout is `{code:124, timedOut:true}` (the `timeout(1)` convention callers already branch on).
**The stdio drain.**
It settles on the direct child's `exit`, not on stdio `close`: once the child has exited it waits `STDIO_DRAIN_GRACE_MS` for the pipes to end, re-arming while output keeps arriving, and defers the give-up one `setImmediate` so a stalled event loop never discards data already in a pipe.
It never waits past `STDIO_DRAIN_MAX_MS` after the exit (or the command's timeout, if sooner), and the command's own timeout timer is cleared at exit, so reaching either is not `timedOut`.
Giving up on unended streams destroys them, on POSIX signals the command's process group with the timeout's SIGTERM → SIGKILL (a background child that stayed in the group is stopped; a detached one escapes it, as it does a timeout's kill; on Windows the child leads no group and its pid is gone, so nothing is signalled — decided through `platform.spawnOptions('group').detached`) and resolves with the direct child's own exit code and `outputMayBeIncomplete: true` — distinct from `truncated`, which only a cap sets.
So `sleep 60 & echo started` returns after the drain grace, not after the timeout.
The redirected-Bash path does not use this runner: a redirect placement is built only when `proj.system.id !== LOCAL_SYSTEM_ID` (`src/instances.ts`), and `isRedirectable` duck-types on `execOneShot`, which `LocalSystem` does not implement.
Consumers reach it either directly — `plugins/library.ts` hooks, `selfUpdate.ts` npm install, `gitLive.ts` (uncapped: git porcelain is parsed whole), all of which act on cc's OWN checkouts and are local by construction — or through `System.exec`, which is how `runGit`, the `worktrees.ts` post-worktree hook (keeping its own truncation-marker shaping and `timedOut`-flag result) and `project_bash` now run.
Pinned by `tests/grouped-command.test.mjs` (drain, ceiling, stall, reaping); `plugins/supervisor.ts` takes the group kill only, since it owns its long-lived child's lifecycle.

**Two caps, opposite ends, because two callers need opposite things.** `cap` keeps the TAIL, per stream, in characters — a log's last N chars are what diagnoses a failure. `headCapBytes` keeps the HEAD, across both streams, in bytes, and keeps draining: `project_bash` truncates what is *shown* while letting the command run to completion, matching the built-in Bash tool. One caller wants one end: they are not enforced against each other, and setting both would simply compose two clips nobody has a use for.

**`maxBufferBytes` is a third thing entirely — a fence, not a cap.** Past it the command is killed and the result is a FAILURE (`{code: 1}`) carrying exactly the first `maxBufferBytes` of output. It exists for callers that parse output WHOLE, where a clipped-but-successful result is read as the truth: worse than an error. The failure is set explicitly, not inferred from the kill — a command that finishes before the signal lands would otherwise report its own `0`. The diagnostic goes into `stderr` (appended if there is already one) because `stderr || stdout` is the near-universal caller shape here and an empty stderr would promote megabytes of partial output into an error message. It rides on `runGit` (see `GIT_OUTPUT_LIMIT_BYTES` under [`src/worktrees.ts`](restart.md#srcworktreests)) and on `ProviderShell`'s non-persistent-shell fallback (the **Output fence** bullet under [The System modules](systems.md#the-system-modules)). `stdin: 'ignore'` hands the command a closed stdin so an interactive one sees EOF instead of hanging until the timeout (`project_bash`'s documented behaviour, and the same `< /dev/null` a redirected `Bash` will frame each command with — matching the CLI's own Bash tool, which takes no stdin parameter). **One deliberate non-adopter remains:** `restart.ts`'s `spawnReplacementAndExit` is not this idiom at all — a fire-and-forget `detached` + `unref()` replacement spawn with no capture, no timeout and no group kill.

## `shared/uiEvent.ts`

the UI event stream's one type, no runtime code. `UiEvent` is a union discriminated on `kind` with no index signature; `UiEventOf<K>` names one member. Payload types: `SystemData`, `UserEchoAttachment`, `AssistantWireMessage`, `AssistantContentBlock`, `CompletedTask`.
- **Producers:** `src/parser.ts`, `src/transcript.ts`, `src/instances.ts` and the history pagers (`src/eventArchive.ts`, `src/lineagePager.ts`). **Consumers:** `ConversationModel` (`web/src/conversation/model.ts`), the header trackers (`shared/usage.ts`, `shared/tasks.ts`) and the server's own readers.
- **The CLI boundary asserts, it does not check.** A field is typed as its producer emits it. Where the parser holds only an `unknown` CLI value, it asserts the type once, where it builds the event (e.g. `turn_end.stopReason`). A CLI `system` frame passes through whole via `cliSystemEvent` (`src/parser.ts`).
- **`system` has one `SystemData` interface, not a per-subtype union.** Subtypes are an open set (the parser passes any CLI system frame through), so `SystemData` names every `data` field a consumer reads, each optional.
- **`ConversationModel.renderEvent` is exhaustive over the union.** Its `default` arm is `ev satisfies never`, so a kind left without a `case` fails `tsc -p web`. At runtime an unknown kind (from a newer server) still reaches `default` and is dropped. Pinned by `web/src/conversation/unknownKind.test.ts`.
- **Adding a UI event kind:** declare its member in `shared/uiEvent.ts`, add its `case` in `renderEvent` (a no-op `case` if the transcript draws nothing for it), and document it under "UI event kinds" in [protocol/ws-events.md](../protocol/ws-events.md).

## `shared/userQuestionAnswers.ts`

`formatUserQuestionAnswers(questions, answers)`, its exact reverse `parseUserQuestionAnswers`, and `parseCanonicalUserQuestionAnswers` (the parsed answers only when the text is the formatter's exact output, else `null`; never throws — the replay-time entry point for the answer bubble and the card lock), plus `isUserQuestionAnswerText` / `isQuestionAnswerShape`.
DOM-free source-of-truth for the AskUserQuestion answer text.
Lives in `shared/` and is imported by **both** the browser (the question card in `web/src/conversation/cards.tsx` formats the answer; `web/src/conversation/model.ts` parses it) and the server (`src/mcp/handlers.ts`'s `answer_question` tool), so an MCP answer is byte-identical to a UI submit — a *true* shared import, not a mirror.
**Prefix-safety invariant:** answers are delivered unconditionally (mid-turn included), and `Instance.prompt`'s `MID_TURN_NOTE` rides as its OWN content block rather than a text prefix — `user_echo` is emitted from the raw text before the `unshift`, and every replay path drops the block via `isMidTurnNoteContent` (`src/parser.ts`) inside the shared `consolidateUserContent`.
That is what keeps `isUserQuestionAnswerText`'s `startsWith` matching.
Concatenating the note into the text instead would silently unpair every mid-turn answer from its card; pinned by `tests/mid-turn-card-answer.test.mjs`.
The same invariant binds `POST_STOP_STEER_NOTE` (`src/instances.ts`), the note a steer delivered after a block-edge stop carries instead: it is built by splicing its extra clause **inside** `MID_TURN_NOTE`'s `<system-reminder>` wrapper, so `isMidTurnNoteContent`'s three shape signals hold by construction and the note is neither rendered as a second user bubble nor counted in the rewind/fork index; pinned by `tests/deferred-steer.test.mjs`.
A conducted worker's **author marker** (`src/promptAuthor.ts`) is a second block of the same kind — its own block, appended **last**, dropped (and read into `user_echo.author`) by `parseAuthorMarker` inside `consolidateUserContent` — so it never reaches the echo text either, and a reader taking a line's first text block as the prompt still gets the prompt; pinned by `tests/prompt-author-parse.test.mjs`.
The answer text is the only persisted record of the picks, so its grammar is self-delimiting:
- **Quoting:** every value — question text, label, note, custom text — is `JSON.stringify`-quoted, so `"`, `\` and line breaks are escaped and ` — ` / `, ` inside a value stay inside its quotes. Question text is whitespace-collapsed first (fallback `Question` / `Question <n>`, also used when `question` is not a string).
- **Single question:** `Answer to "<Q>": <BODY>`. **Several:** `My answers:` then one line per question, `<i>. "<Q_i>": <BODY_i>` (1-based), matched by index — duplicate question text is fine.
- **BODY:** `(no answer)` (skipped, `NO_ANSWER`) · `(own answer) "<text>"` (custom / Other, `OWN_ANSWER`; marked even when the text equals a label) · `"<label>"(, "<label>")*` optionally followed by ` (note: "<note>")`. The question's `multiSelect` flag decides `option` vs `multi`, so `answer_question`'s `{option}` on a multiSelect question parses back as a one-label `multi` (same card render and lock).
- **Canonical form:** notes trimmed and omitted when empty, custom text trimmed, labels verbatim.
- **Strict parse:** the whole text must be consumed, every label must be offered by the question, a single-choice question takes exactly one label, and a multi-question answer has exactly N lines. Anything else — an older answer format, a coalesced steer's trailing text, an unoffered label, a malformed quote — returns all-`{kind:'none'}`; it never throws.
- **Pairing is prefix-only:** `isUserQuestionAnswerText` matches the single-question prefix (built by the same private `questionPrefix` the formatter uses) or `My answers:\n`, so an answer the strict parse rejects still pairs and locks its card. `isQuestionAnswerShape` is the questions-free form (`/^Answer to "[^\n]*": /` or `My answers:\n1. `), read by `promptOrigin.ts`.

## `shared/forwardFrame.ts`

the `send_prompt({forward})` frame format: `FORWARD_FRAME_HEADER`/`FORWARD_FRAME_FOOTER`, the bare `--- message i/n ---` boundary line (module-private), `buildForwardFrame({messages, instruction})`, `parseForwardFrame(text)` → `{payload, instruction}` or `null`, and `splitForwardedMessages(payload)` → per-message bodies. Same cross-boundary shared-import pattern as `renewSeed.ts`: `src/mcp/handlers.ts` builds the frame, `web/src/conversation/model.ts` parses it (`parseForwardFrame`) and `ForwardBody` (`web/src/conversation/items.tsx`) renders the forwarded-output bubble, and `src/awaitingUser.ts` recognises it by `FORWARD_FRAME_HEADER`, and `firstPromptHead` (`shared/promptPreview.ts`) parses it to store a forward-first session's first prompt as the frame's tail. `parseForwardFrame` accepts only the full header plus a blank line at offset 0 and splits at the **last** footer standing as its own paragraph; `splitForwardedMessages` finds boundaries scanning backwards and falls back to the whole payload as one body when any is missing — a presentation split that never drops a byte.

## `shared/promptPreview.ts`

a session's stored first prompt and its label.
`firstPromptHead(text)` is the head both capture points store (`Instance.prompt` live, `readFirstPrompt` in `src/projects.ts` from disk), cut to `FIRST_PROMPT_CAP`; a forward frame (`parseForwardFrame`) is stored as its tail instead — `FORWARD_FRAME_FOOTER`, a blank line, then the instruction `trimStart()`ed — because the instruction sits past any head cut.
`readablePrompt(firstPrompt)` names a server-written one: `Wake: <summary>` via `parseWakeCallback`; a value opening with the footer + blank line reads as the instruction's first non-empty line (trimmed), or `Forwarded worker output` when there is none; `Forwarded worker output` by `FORWARD_FRAME_HEADER`'s first line, which covers a head cut inside the header (a value stored before the tail was kept, or a frame with no END paragraph); `Context renewed` by `RENEW_SEED_PREAMBLE`'s first sentence, since the stored first prompt is cut inside the preamble and the full-text parser never matches it — each lead is cut at module load, which throws if its constant lacks the separator rather than yield an empty lead that would match every prompt; `Context renewed` also for a post-`/clear` file head, the CLI's `<local-command-caveat>` record or `<command-name>/clear</command-name>` line, and the bare command for any other `<command-name>` line; any other text is returned as is.
`promptPreview(firstPrompt)` is that cut to the sidebar's 80-char, whitespace-collapsed preview.
`sessionLabel(row)` is a session's label: the trimmed `title`, else `promptPreview(firstPrompt)`, else `(new session)` when the row is `synthetic` (a live instance not on disk yet), else the sessionId's first 8 chars and `…`.
`parseForwardFrame` splits at the **last** END-marker paragraph, so for an instruction containing that paragraph the label is the first line of the text after it (its head lands in the payload), and an instruction ending on that paragraph reads as `Forwarded worker output`.
`readFirstPrompt` reads `FIRST_PROMPT_READ` bytes and grows its buffer (doubling, up to `FIRST_RECORD_CAP`) only while the line it is on has not ended; a record not ended within `FIRST_RECORD_CAP` yields `null` — never a later record's prompt — and the label then shows what it shows for a missing first prompt (`resumeRestart.ts`'s persisted value still fills an empty `inst.firstPrompt` on restart).
`sessionLabel` is used by `summary().displayLabel` (`src/instances.ts`, over the synthetic row), the sidebar's `SessionRow`, and `shared/conductors.ts` (`conductorTitle`, `ownerLabel`, so the Conductors lens, needs-you strip and attention notifications).
`promptPreview` / `readablePrompt` are also used by the sidebar's `SessionRow` tooltip, the Workers panel and **Settings → Archived**, and `src/mcp/readRenderers.ts` (the `list_sessions` / `describe_session` rows' first prompt).
DOM-free.
- **Adding a folded user bubble** follows these three: a DOM-free parse module in `shared/` that `src/` imports (the server builds, the client parses one format), parsed in one hook, `ConversationModel.renderUserEcho` (`web/src/conversation/model.ts`), into a user-node variant that `web/src/conversation/items.tsx` renders inside `Folded` — the hook covers live, replay and backward paging alike. Recognise the bubble by the text format the server already emits, not a new wire marker.
- **The compaction bubble is the exception** (the `compaction` node, `web/src/conversation/model.ts`): the summary has no text format of its own, and its only reliable line-level marks differ per surface (`isCompactSummary` in the jsonl, boundary adjacency on stdout), so the server stamps `compactSummary` on the `user_echo` and emits a `compaction` event for the boundary; `ConversationModel` completes a running block, folds the stamped echo into it and absorbs the command's stdout line. The echoes stay `user_echo`s, so the prompt-index space is unchanged.
- **The AskUserQuestion answer bubble is the other exception** (the `answer` user-node variant): a typed prompt can carry the same text as an answer, and the jsonl stores only the text, so the server pairs the echo with its `user_question` and stamps `questionAnswer` (`src/questionAnswerStamp.ts`); `renderUserEcho` renders from the stamp alone, after the compaction checks, and `lockAnsweredCard` reads the same stamp to lock the card (an unstamped answer-shaped echo locks nothing).

## `shared/injectedTurns.ts`

leaf module holding the fixed leads of every server-authored text that reaches a session as a user turn (`RENEW_REQUEST_LEAD`, `RESTART_NOTICE_TRUNK`, `RESTART_ABORTED_LEAD`, the three overage preambles, `QUEUED_SECTION_LEAD`, `REBASE_PROMPT_LEAD`). The builders (`src/sessionRenew.ts`, `src/resumeRestart.ts`, `src/overageResume.ts`, `buildRebasePrompt` in `src/worktrees.ts`) compose from them and `shared/promptOrigin.ts` recognises by them, so a builder cannot drift from its recogniser. In `shared/` because the browser recognises the same bytes; DOM-free.

## `shared/planApproval.ts`

`buildApprovePrompt(feedback)` / `buildRejectPrompt(feedback)` and their reverse `parsePlanDecision(text)` (`{decision, feedback|null}` or null). Source-of-truth for the magic strings the UI's Approve & Implement / Reject buttons (the plan card, `web/src/conversation/cards.tsx`), the server-side auto-approve, and the MCP `approve_plan` / `reject_plan` tools all send to the worker. `src/` imports it directly (`src/instances.ts`, `src/mcp/handlers.ts`).

## `shared/promptOrigin.ts`

who wrote a user turn, from in-band text shape plus the event flags (no author field exists on any event, frame or record). `isInjectedUserTurn(ev)` is the text/flag rule set `classifyUserTurn` (`src/awaitingUser.ts`) delegates to; `promptOrigin(ev)` → `typed` / `template` / `synthetic` (set by `ConversationModel.renderUserEcho` and rendered as `data-prompt-origin` on every outer user bubble by `web/src/conversation/items.tsx`); `isPinEligible(origin, {conducted})` is the pin rule. The signal table and the stated degradations are in [features/conversation.md](../features/conversation.md) → Sticky prompt header.

## `web/src/features/session/SessionWidthHandles.tsx`

the session column's pointer-only edge handles: an `aria-hidden` overlay (`[data-session-handles]`) mounted last inside `SessionView`'s `[data-session-body]`, with a frame carrying the column's `maxWidth` so the strips sit on the column's edges. The drag's room is read once at `pointerdown` from the transcript scroller's `clientWidth` (the basis every box's `100%` resolves against); the live width goes through `sessionWidthDragStore`, and `setSessionWidth` runs once on release. Behaviour: [features/projects.md](../features/projects.md) → Session width.

## `web/src/app/viewport.ts`

`startViewportFollow({win, root})` sets `--app-height` on `root` to `visualViewport.height × scale` when that is more than `HEIGHT_SLACK_PX` under `innerHeight`, else removes it; at a scale within `ZOOM_EPSILON` of 1 it calls `scrollTo(0, 0)` when the page or visual viewport is offset (never while pinch-zoomed). No `visualViewport`: no-op. Tests: `web/src/app/viewport.test.ts`.

## `web/src/features/session/promptFocus.ts`

`focusPromptAfterSelect(userGesture, prompt, {win, doc})`; `SessionView` runs it one animation frame after each `select` event (`web/src/app/events.ts`) whose `userGesture` is true, on the composer textarea (`#composer-input`). `prompt.focus()` runs only when `userGesture === true` **and** the textarea is not `disabled`, `TOUCH_QUERY` (`(hover: none)`, shared with the modals from `web/src/lib/textEntry.ts`) does not match, no open dialog or modal matches `MODAL_SELECTOR`, and `doc.activeElement` is the textarea or not a text-entry field (`textarea`, a text-like `input`, contentEditable). `selectInstance` (`web/src/app/controller.ts`) emits `select` with the caller's `userGesture`. Tests: `web/src/features/composer/promptFocusBlockers.test.tsx`.

# Components: instances, idle wake and session renewal

The server entry, the instance and its manager, the idle-wake, overage and renewal controllers, session lineage, and overage trip detection.

## `server.ts`

the entry block hands an argv carrying a headless flag to `headlessMain` (see Headless mode) and otherwise boots the server.
Express + ws boot, `app.disable('x-powered-by')` → `hostSecurityHeaders()` → mounts `/api` → `/mcp` → `/plugins` (reverse proxy) → `GET /pluginBridge.js` (`web/src/features/views/pluginBridge.js`, served from its source, so with no build in place) → `pluginThemeRouter()` (`GET /pluginTheme.css` + `/pluginTheme/fonts/…`, `src/pluginTheme.ts`, also served from sources) → `webHandler()` at the root (the web UI), binds `127.0.0.1:8787`.
The API, MCP and plugin mounts come first, so the UI mount cannot shadow them.
`createServer({webDistDir})` is a test-only seam handing `webHandler` another dist dir (`tests/web-routes.test.mjs` boots on an empty one through `bootServer({ webDistDir })`, `tests/helpers.mjs`); production serves `web/dist`.
`start({buildWeb, syncDeps, webBuild = ensureWebBuild})` fires `webBuild()` after the server is listening unless `buildWeb` is false (`CC_SKIP_WEB_BUILD`); `webBuild` is injectable so a test can observe the call.
It hands `buildWeb` and `syncDeps` (`CC_SKIP_DEPS_SYNC`) to `createServer({relaunch: {flags}})`, which passes them to `buildRoutes` as the restart route's `RelaunchOptions` (`prep` and `spawnAndExit` there are test seams).
The WebSocketServer is `noServer: true` with a manual `server.on('upgrade')` dispatcher: every upgrade first passes the Origin guard (`createUpgradeOriginGuard`, `src/upgradeOrigin.ts`), then `/ws` → wsHub, `/api/terminal` → the host terminal endpoint (`createTerminalEndpoint`, `src/hostTerminal.ts`, built once with `platform.capabilities`), `/plugins/<id>/…` → plugin proxy raw-socket pipe, anything else destroyed.
(With `noServer` the ws lib never attaches to the http server, so the old EADDRINUSE error-forwarding guard around `listenWithRetry` is gone — `tests/eaddrinuse-retry.test.mjs` covers the retry path.)
Creates the plugin host and, after listen, feeds it the bound port + fires its adopt-on-boot init.
Sets `process.title = 'code-conductor'` on entry so `pkill -f code-conductor` targets it precisely and `pkill -f server.ts` misses it.
`start()` first warns (`console.warn`, boot continues) when the running Node does not satisfy `package.json` `engines.node` — `warnIfNodeUnsupported` in `src/nodeEngines.ts`, which reads only a `>=MAJOR[.MINOR[.PATCH]]` range and warns that any other shape cannot be checked; self-update never updates Node.
Launched via `npm start` (`node server.ts`); `conductor.sh` is the same `exec node server.ts`, kept for `docker/entrypoint.sh`.
The entry check compares `import.meta.url` with `pathToFileURL(process.argv[1]).href`, so it holds for Windows drive paths and `%`-encoded characters.

## `src/securityHeaders.ts`

the response policy: `HOST_SECURITY_HEADERS` (framing and `nosniff`), the `hostSecurityHeaders()` middleware `server.ts` mounts first, and `proxiedPluginHeaders()` for the plugin proxy. Contract: [protocol/rest-settings.md](../protocol/rest-settings.md) → Response headers.

## `src/upgradeOrigin.ts`

the cross-site WebSocket hijacking guard: `upgradeOriginAllowed(headers)` (the pure Origin-vs-Host rule) and `createUpgradeOriginGuard({log, now})`, whose `admit(req, socket)` writes the raw 403, destroys the socket and warns — deduped per distinct pair in a memo bounded by `WARNED_PAIRS_CAP`, and rate-limited to `WARN_LIMIT` warns plus one suppression line per `WARN_WINDOW_MS` (memo and window are per guard; `now` is the injectable clock). `server.ts` builds one guard and calls it first in the upgrade dispatcher. Contract: [protocol/websocket.md](../protocol/websocket.md) → WebSocket protocol → Handshake: Origin check.

## `src/pluginTheme.ts`

the host theme for plugin pages: `composePluginTheme()` builds `/pluginTheme.css` per request from the installed Geist fontsource packages' `index.css` (their `url(./files/…)` rewritten to `/pluginTheme/fonts/<pkg>/<file>`, throwing when a package yields none) and `web/src/themeTokens.css`; `pluginThemeRouter()` serves it (a compose failure is logged and answered `503 text/plain` with a fixed body) and the allowlisted `.woff2` files (`FONT_PACKAGES`); both take `tokensFile` and `fontDirs` (URL segment → package directory) test seams. Contract: [plugins/runtime.md](../plugins/runtime.md) → Theme stylesheet.

## `src/instances.ts`

Instance class, InstanceManager, capped event ring (`EventLog`: drop-oldest at `ORCH_EVENT_RING_CAP` (default in this module); `_seq` stamped at push and never renumbered; `trimmedBefore` = first retained `_seq`; `seams` (`RingSeam[]`, `src/instanceTypes.ts`) partition the ring's whole seq space by backing segment — the segment of seq `s` is the last seam with `startSeq <= s`, `seams[0].startSeq === 0` once spawned, and the last seam names `backingSessionId`.
`markSeam(segmentId)` records `{segmentId, startSeq: nextSeq}` — except the **first** seam, which always claims `startSeq: 0`, so anything retained before it (the create path's pre-`launch()` diagnostics, e.g. `_doCreateResolved`'s inert-exclude `system/stderr` reports for a remote project) belongs to the segment the ring is filled from and a seam with `startSeq > 0` only ever follows an earlier segment.
Two call sites: the **fill seam** in `spawn()` (after `assertBackingId`, before the `loadHistory` replay — every `launch()` runs on a ring with no seams, so it is always `{backingId, 0}`, and after a prune it names the pruned segment) and the **rotation seam** in `_handleStdoutLine`'s rotation branch (the rotation's own `system/init` takes `_seq === startSeq`).
`_trim` never touches them (seqs are never renumbered); `clear()` resets them, reached only via `_wipeForResume`, which a `launch()` always follows.
A seam carries no echo ordinal (see `eventArchive.ts` for why ordinals are calibrated per file) and is never persisted; trim snaps the surviving head to an outer `user_echo` turn boundary, falling back to the nearest **quiescent point** (`firstQuiescentAtOrAfter`, parser.ts) when no echo is in reach so the gap-case head still opens on whole blocks — plain cut only for a giant non-quiescent span; `snapshotTail()` serves the trailing window around `ORCH_SNAPSHOT_TAIL` (default in this module) events for WS subscribe, quiescent-snapped via `snapStartToQuiescent` — the snap moves the start EITHER way (forward, past an open block or a headless run, when the raw cut lands mid-block; back, to an earlier quiescent point, when the forward search finds nothing before the ring's end), so the served tail can be shorter OR longer than the cap and no inequality holds in general — backstopped by `lastQuiescentAtOrBefore` (parser.ts) when the forward snap would push past the ring's own end (the tail's only remaining content was sub-agent children with no reachable head), serving from the nearest quiescent cut rather than returning an empty tail; **retention is storage-only, decoupled from the live feed** — `push()` declines to retain the CLI's per-token floods (see the `thinking_tokens` entry in [protocol/ws-events.md](../protocol/ws-events.md) for which models were observed emitting that one; prose streams one `text_delta` per token on every backend) so a single long turn can't overflow the ring and strand the archive mid-turn: `system/thinking_tokens` (a live-only last-value-wins counter, never persisted) is dropped from the ring entirely, and consecutive `thinking_delta` **or** `text_delta` of one `(msgId, blockIdx)` block fold into ONE slot — the same one-delta-per-block shape disk replay produces (`src/transcript.ts`), so ring + jsonl-archive reconstruct identically.
The two kinds never fold into each other (`tail.kind === v.kind`), and `msgId` is per-message so a sub-agent block can never fold into an outer one; async sub-agents interleave their deltas with the outer turn's, breaking adjacency, so folding does not apply inside background-task regions.
`context_usage` (the `message_delta`-sourced ctx reading — see [protocol/ws-events.md](../protocol/ws-events.md)) is declined for the same storage-only reason: a re-subscribing client is seeded from the `lastContextUsage` field, and on the only backends that emit it every in-tail `message_start` carries `usage: null` and so cannot clobber that seed.
The replay-path `message_start` (`replayed: true`, emitted by `loadHistory` to seed the ctx readout — see [protocol/ws-events.md](../protocol/ws-events.md)) is declined too: it is synthetic, so it must not become history, and keeping it off the ring also keeps it from ever becoming the ring head (`message_start` is quiescent, so a trim could snap there and its non-`user_echo` head would read as mid-turn and mark a spurious `history_gap`).
It also never advances `ring.nextSeq`, which `idleSubscriptions.ts` arms on as its "activity since arm" marker — which matters because `loadHistory`'s emit loop can land after a turn has started (`prompt()` has no spawning guard), inside an arm→fire window.
A declined event gets no `_seq`, so `_emitUi` still emits it seq-less and the LIVE per-token stream is untouched; the first delta of a block anchors the slot with its `_seq` so a later forward page dedups via the client's `seenSeq`.
In-place `tail.text +=` is **append-only** — the slot is never shrunk, replaced, or renumbered — so a consumer holding a shallow snapshot across an `await` (`ringSnapshot` → `pageInstanceEvents`, `snapshotTail` → `wsHub`) can only observe a longer extension of the same `_seq`, never a torn or duplicated one.
That, not synchronous serialization, is what makes it safe: `wsHub` subscribes the socket **before** calling `snapshotTail()` and awaits `reconstructActiveTasks` before sending, but the client clears before replaying a snapshot (the `snapshot` listener in `web/src/app/controller.ts`) so live frames emitted inside that window are discarded in favour of the grown slot, and on the paging path the client's `_seq` dedup drops an already-applied slot outright.
The current counter isn't lost for a client joining mid-stream: `_emitUi` also keeps the latest count as O(1) `_liveThinkingTokens` state (set per `thinking_tokens`, cleared on `thinking_start`/`thinking_end`/`turn_end` so a finished block shows none), exposed via `inst.liveThinkingTokens` and re-attached by the WS subscribe path as a trailing seq-less `system/thinking_tokens` on the snapshot — so a fresh subscriber sees the coalesced partial thinking text (from the ring slot) AND the current count with no flicker.
A block that has already CLOSED gets nothing re-attached, so a redacted one — which replays no text at all — would rebuild as a bare `thinking (redacted)`; `_emitUi` therefore stamps the final estimate onto the retained `thinking_redacted` slot as `estimatedTokens` before pushing it.
Ring-resident only — the `thinking_tokens` entry in [protocol/ws-events.md](../protocol/ws-events.md) enumerates the jsonl-backed rebuild paths that lose it), absolute `userIndex` stamping on outer user_echoes (the rewind/fork anchor — immune to trimming), the three transcript rewrites behind the tagged `_mutating` / `rewriteBlocksPrompts` interlock (under `src/sessionPrune.ts`) and the mid-turn fork's pin + per-attempt snapshot (under `src/sessionEdit.ts`), control_request round-trip, mode validation.
The **context-size** reading rides the same O(1)-state-on-the-snapshot pattern as `_liveThinkingTokens`, for the same "the ring is not a reliable carrier" reason: `_emitUi` latches every **usage-bearing** `message_start.usage` — or `context_usage.usage`, the fallback kind for a backend whose `message_start` is all-zero — as `_lastContextUsage` (a null-usage frame of either kind leaves it alone — see those two kind entries in [protocol/ws-events.md](../protocol/ws-events.md) for why the parser produces them; exposed via `inst.lastContextUsage`, sent as the snapshot's `lastContextUsage` **field** — not an appended event, which would also reach `conversation.apply`).
Only those two kinds feed the client's `UsageTracker`, and a turn whose final text block outruns the tail leaves the quiescent snap no cut except past the whole block, so every `message_start` lands below the window and a re-subscribe would otherwise rebuild an empty tracker (`ctx —` — the symptom on a backend that answers in one long block).
Two deliberate differences from the thinking counter: it is **not** cleared at `turn_end` (the reading stays valid between turns, which is exactly when a reload would lose it), and it is reset in exactly two places.
`_wipeForResume` (rewind/prune/respawn) is the first — a fork or a resume-after-restart needs none, since each builds a new Instance whose constructor starts it `null`, and a fork must leave the parent's value alone because that session continues.
`_announceModelSwitch` is the second: the shared helper BOTH model-switch sites (`_trackModel`'s real-switch branch and `setModel`) route through, which pairs the `system`/`model_changed` emit with the clear so the two cannot drift apart.
It drops the reading because a switch moves the window denominator (`_refreshModelCapabilities`) without changing what the retained numerator measured — the same known-wrong-is-worse-than-none rule `pruneSession` applies through `_skipUsageSeed`.
The clear is safe unconditionally because of where it sits: `_handleStdoutLine` calls `_trackModel` BEFORE the per-event loop's `_emitUi`, so a switch frame that also carries usage re-latches the new model's own reading in the same line and the chip never flashes `ctx —`.
The helper's contract is announce + drop, nothing else — `_prefixBaselineInvalid` stays at its own site in `_trackModel`.
Wire shape and the client half in [protocol/ws-events.md](../protocol/ws-events.md) → `model_changed`.
**Resume idempotency:** `create()` is a thin synchronous wrapper over `_doCreate()` that guards duplicate resumes of one sessionId — an already-live session (`i.proc`) throws 409 `already attached`, and a still-in-flight resume (tracked in `this._resuming`, keyed on the session's PUBLIC id when it is already in memory, so two callers naming one session by different forms still coalesce rather than racing two subprocesses onto one transcript) is **coalesced** (the second concurrent caller gets the same restored instance, one subprocess).
The checks run in the wrapper's synchronous prefix (before any `await`), closing the window `_doCreate` opens between the guard and `spawn()` attaching `.proc`; the map entry is released when the create settles (success OR failure).
This makes a user's resume racing the manifest restore — and manual stop+resume — safe regardless of caller.
**Deferred steers** (`_pendingSteers`, `queueSteerAfterStop`/`_flushPendingSteers`/`steerPending`) park a message bound for a model that cannot take a mid-turn injection: the SOFT block-edge stop is armed (`interrupt()`, idempotent — N queued steers arm one abort and are delivered as one joined message) and the queue is flushed from the `turn_end` branch on a `queueMicrotask`, so the event reaches every subscriber — `IdleSubscriptionHub` reads `steerPending` synchronously — before `prompt()` flips the status back.
The queue is drained before the send (exactly-once), rejected with a `system`/`stderr` annotation when `_setStatus` reaches a dead status, and any drain that starts no turn emits `system`/`steer_settled` so a wake deferred behind it is never stranded.
Callers reach it through `promptOrQueueSteer(text, attachments?)` — which tests the one `needsPostStopSteer` predicate and never awaits the block edge — rather than testing the flag themselves; which route ran is deliberately not reported to any caller.
Attachments ride along on `PendingSteer`.
Routed-site inventory in [protocol/subprocess.md](../protocol/subprocess.md).

**Seam modules:** `src/instances/overageRouting.ts` holds the bodies of `InstanceManager`'s overage trip, stop routing and lock release (`_handleOverageTrip` … `_clearOverage`) and `softInterruptDeadlineMs`, as `this: InstanceManager` functions; the class keeps a same-name one-line delegate for each.
`src/instances/steer.ts` holds the bodies of `Instance`'s steer/interrupt/drain controller (`interrupt` … `interruptTurnForStop`) as `this: Instance` functions, plus `MID_TURN_NOTE`, `POST_STOP_STEER_NOTE` and `CLEAN_STOP_GRACE_MS` (re-exported); the state and a same-name delegate per function stay on `Instance`.
`src/instances/rewind.ts` holds the bodies of `Instance`'s rewind and boundary-fork paths (`rewindToUserMessage` … `_fileOrdinalFor`) as `this: Instance` functions, plus their refusal codes and fork-wait constants (re-exported); `forkAtUserMessage`, `forkAtTip`, `_claimForkSource` and a delegate per function stay on `Instance`.
`src/instances/restartSwitch.ts` holds the bodies of `Instance`'s model-switch restart and relaunch window (`setModel` … `_lastExitCause`) as `this: Instance` functions, plus `RELAUNCH_FAILED` (re-exported) and `assertBackendLaunchResolvable`; `setEffort`, `_wipeForResume` and a delegate per function stay on `Instance`.
**Raw stdout tap:** `Instance` emits `stdout_line` for every raw CLI stdout line, before its parse; `InstanceManager`'s relay, attached before the first launch, re-emits it as `{instance, line}` only while the manager has a listener, with `runTreeIds`/`inRunTree` naming the run tree `isTreeQuiescent` judges — [components/headless.md](headless.md#headless-mode) → The stdout tap.

## `src/idleSubscriptions.ts`

`IdleSubscriptionHub`, the idle-wake graph extracted from `InstanceManager` as a composed collaborator.
**Wake-on-turn-end is a property of OWNERSHIP, not of a registration verb:** a conductor owns a target if it spawned it (`Instance.callerInstanceId`) or has ever dispatched to it (`noteDispatch`, called by every turn-starting MCP handler BEFORE the send), and `ownersOf(targetInstanceId)` is the union of the two minus self, filtered to live instances.
Two maps, both **keyed by the stable instanceId** (the event stream carries it, and it survives an in-place `/clear`, so keying by instanceId needs no migration): `_owners` (`targetInstanceId → Map<callerInstanceId,{timeoutMs}>`, the durable dispatch edges plus each owner's preferred heartbeat window) and `subscribers` (`targetInstanceId → Map<callerInstanceId,{timerId,timeoutMs}>`, the ARMED wakes — so it is empty for every target that is neither mid-turn nor holding its owners' wakes, below).
`onTurnStart(targetInstanceId)` arms one entry per live owner, driven by `InstanceManager`'s per-instance `'turn_start'` wiring off `Instance._setStatus`'s into-`turn` branch, so prompted and **unprompted** turns re-arm identically (the auto-approved-plan case) and the arm is synchronous inside `prompt()` — there is no registration window for a fast `turn_end` to fall into.
`subs.has(caller)` makes it idempotent: a mid-turn steer on an already-armed pair delivers ONE wake. sessionId lives only at the boundary: `noteDispatch`/`setIdleTimeout` translate the MCP-supplied sessionIds to instanceIds on entry (via `liveForSession`), `deliver` translates the target instanceId back to its current sessionId for the wake stub, and the test-only `snapshot()` projects instanceIds back to sessionIds.
Nothing is persisted and every map is purged on `remove()`, so there is nothing to "survive a restart."
**The hold.**
Every path that consumes because the target reached idle — `_onTurnEnd` (after its defer gate and the `_justConsumed` mark), `_fireSettle`, `_onRotationComplete` — first asks `_holds(target)`; true ⇒ it returns with the entries and their heartbeats left armed.
`_holds` is false for a pass-through, else `_waitsOnWork(target.id, new Set([target.id]))`:
- **Pass-throughs:** `_asked` — the target's turn put a top-level `user_question`, or a `plan_request` without `autoApproved`, to the user (`askFactsOfEvent`, `src/awaitingUser.ts`, fed in `onEvent` from every non-replayed event, conducted workers included); cleared with the abort qualifier at a turn start no armed wake survived into, and by `purge` — and `turnForceAborted` (reported now, so INTERRUPTED describes its own turn). `onTargetExit` never holds.
- **`_waitsOnWork(x, seen)`:** a wake is on its way to x (`_inFlight` / `_parked` / `_deferredWakes`), or x is armed on a target in `byId`, not `_goneForGood`, that is not `idle`, carries a target-side defer (`targetDefers`: `activeAgentTaskCount` / `taskNotificationPending` / `rotationPending` / `steerPending`), is idle and NOT in `_holding` — its armed wake to x is owed by something other than a hold: a settle pending, or one that dropped or was refused on a dirty idle window, which the target's next turn end, or, once the target is gone for good, the heartbeat's retirement, ends — or is in `_holding` and itself `_waitsOnWork`. `seen` stops the recursion: ownership (spawn ∪ dispatch) can be cyclic, and a held target only waiting back on x must not count, or two sessions owning each other hold each other forever.
- **`_holding`** — the targets a hold decision is holding: `_holds` adds its target when it answers true; `_consume`, `_dropArmed` emptying a target, `purge`, `onTurnStart` and `_redecideHold` (the overage sever's re-decision, for a caller that no longer holds) delete it. It is the line between "held — recurse" and "owed — work".
- **`_releaseHeld(x)`** — the release when a wait of x ends WITHOUT a turn: consumes x's entries iff not suspended, x is in `_holding` (an armed wake x owes for any other reason is not a hold to release), x has a `proc`, is `idle`, has armed owners, no target-side defer, and no longer `_holds`. Called for every caller that lost an entry in `purge(target)` (after the maps are clean — remove, `removeAllForProject`, the normal-exit drop; `removeAllForProject` passes its victim set as `purge(id, {removing})`, and a caller in it is skipped, so the sweep's kill order cannot wake the owner of a session it is deleting), from `_endInFlight` (a refused/abandoned send; a sent one has already moved x to `turn`) and from `disarmSilently`. Not from `_dropArmed`: `onTargetExit` and the heartbeat retirement drop and then deliver, so the caller is `_inFlight` by the time it matters. `severForOverageStop` calls `purge(id, {release:false})` — a release there would prompt into the throttled account — which instead re-decides each severed caller's `_holding` membership with no delivery (`_redecideHold`), so a caller that lost its last wait reads as owing its owner a wake, not as held with nothing outstanding.
- `_consume(targetInstanceId, {announce})` is the consume-and-deliver tail all of these share. `isCaller` is unchanged, so a held owner reads `awaitingWake` throughout.
- `suspend()` (`InstanceManager.suspendWakes`, called by the resume-restart drain) sets `_suspended`: `deliver` returns at once until `resume()` (`InstanceManager.resumeWakes`, called by `abortDrain` when the restart is refused after the drain) clears it. A wake dropped while suspended stays dropped.
- **`_humanPrompts`** — `targetInstanceId → string[]`, the text of every `user_echo` with `author:"human"` and no `parentToolUseId` (`onEvent`, non-replayed), oldest first. Same lifetime as `_asked`: it belongs to the wake it travels with. **Taken** (`_takeHumanPrompts`) by `_consume` — passed to every `deliver` of that batch as `DeliverOpts.humanPrompts` — and by `onTargetExit`, armed or not; **dropped** by `purge` and by an `_onTurnEnd` that finds nobody armed, including a stop-interrupted one (`_stopInterruptedTurn`); **never** cleared in `onTurnStart`, since `prompt()` emits its echo before `_setStatus('turn')` and that clear would lose the prompt that started the turn. A deferred wake carries it inside its `opts`. `deliver` renders it once (`humanPromptsNote` → `DeliverOpts.humanNote`) for both builders: `_plainStub` puts it ahead of the decline/stale prefix, `buildWakeStub`'s `humanNote` ahead of the summary, and the folded builder's soft fallback passes it on. The heartbeat passes none. `peekHumanPrompts(target, caller)` is the read-only view behind `InstanceManager.pendingHumanPrompts` — the prompts in the caller's held `_deferredWakes` entries for that target, in queue order, then the target's pending list — (quoted with `quoteHumanPrompts`), which the conductor sends read for their `humanPrompts` field.

An armed wake is consumed by whichever of these trigger paths lands first — `turn_end`, the **idle task-drain settle** (`ORCH_IDLE_DRAIN_SETTLE_MS` — see the wake state machine below), **rotation completion** (`_onRotationComplete`, for a rotation that comes up idle with no turn at all — i.e. a prune; a renewal declares `comesUpIdle:false` and is delivered by its reseed turn's `turn_end`), the **release** of a hold (`_releaseHeld`), or the **target's CLI exiting on its own** (`onTargetExit`, called by `InstanceManager`'s per-instance `exit_cause` listener when the exit carries a cause and the instance is not `relaunching` — emitted before the status transition, so BEFORE a normal target's `_purgeIdleFor` — each armed entry is dropped with its heartbeat and woken with the EXITED stub, whose `DeliverOpts.exited` carries the sessionId so a held wake still names it once the target has left `byId`) — plus two non-delivering clears: `purge` (instance removal) and `disarmSilently` (the `interrupt_turn({force:true})` path — CALLER-SCOPED: it clears only the interrupter's own entry, BEFORE the abort's own `turn_end`, so that turn wakes the interrupter not at all while every OTHER owner is woken there with the interrupted variant.
Clearing the whole per-target map instead stranded every other owner with no stub and no heartbeat, on a wait nothing could end — and the interrupter need not even be an owner.
`_owners` is left intact, so the next turn re-arms).
Alongside them runs a **repeating heartbeat** (`_arm`'s `setInterval`, `.unref()`'d, window = the owner's `timeoutMs` else `DEFAULT_SUBSCRIBE_TIMEOUT_MS` via `ORCH_SUBSCRIBE_TIMEOUT_MS`): it delivers the `timedOut` "did NOT finish" stub and mutates **nothing**, so the pending turn-end wake is untouched and a hung worker keeps reporting.
Its single exception is a target that is GONE FOR GOOD (`_goneForGood`) — no `turn_end` can ever follow, so that ping retires the entry rather than pinging forever.
That is deliberately NOT just `!proc`, which is equally true across a prune/rewind/respawn's kill→relaunch gap: the check also requires that nothing is reviving it (`relaunching` / `rotationPending` / `_mutating` — `rotationPending` covers the whole rotation window, and reading `rotationInFlight` beside it was the same `_rotation` field spelled twice), because retiring inside that gap would drop an entry whose wake is still owed (the rotation's own completion, or the reseed turn's `turn_end`) and leave the owner with "did NOT finish" as its last word.
`setIdleTimeout` records the window AND re-arms a running heartbeat (an armed pair — mid-turn or held); `noteDispatch` on an already-armed pair restarts that pair's interval too, so the window counts from the latest dispatch.
`onEvent` receives every instance event: `_onTurnEnd` **defers** delivery while the target's `activeAgentTaskCount > 0`, `taskNotificationPending`, or `rotationPending` (keeping the wake and its heartbeat armed), so a wake fires only once the worker's turn ends with no live background subagents and no context rotation in flight; `_onTaskEvent` covers the drain-at-idle-with-no-re-invocation case; a subagent that never finishes shows up as a repeating heartbeat.
The rotation defer reads `Instance._rotation` (opened at `arm()` / at the top of `pruneSession`, closed by `endRotation`) rather than any controller state, so it holds regardless of listener registration order — the hub's listener is registered *before* the renew controller's, so reading controller state here spends a wake on the **armed** `turn_end`, a turn early.
Cross-instance lookups + `subscription_changed` emission route back through the manager.
`InstanceManager` delegates the `noteDispatch`/`setIdleTimeout`/`disarmIdleSilently`/`isIdleCaller`/`ownedWakeTargetsOf`/… surface and exposes the live `_idleSubscribers` getter.
`ownedTreeOf(rootId)` is the transitive version over instance ids (BFS over `ownersOf`, visited set, root excluded), read by the headless completion predicate `InstanceManager.isTreeQuiescent` (see Headless mode).
`ownedWakeTargetsOf(callerInstanceId)` backs the `renew_session` mechanical state block (see `src/sessionRenew.ts`) and deliberately reports the OWNED set rather than the armed one: the armed set is empty whenever a target is idle, which would gut that block's "never orphan a worker" purpose precisely in the case it exists for.
`noteRenewalDeclined(targetInstanceId, requestedBy)` records a one-sentence note in `_pendingDeclines`, keyed target→**caller** and only when that caller is actually waiting (`_isWaitingOn`: still armed, or armed at the turn_end being dispatched — `_justConsumed` now carries the caller set for exactly this).
`_takeDecline` read-and-deletes one pair's note, and every path that ends a single caller's wait calls it — delivery before its first `await`, the dead-caller drop in `deliver()`, `disarmSilently`, and `purge`'s **caller-end** loop; `purge`'s **target end** drops that target's whole inner map in one `_pendingDeclines.delete` instead.
`severForOverageStop(instanceId)` wraps `purge` for a session that is being STOPPED but is still alive: it additionally drops wakes already deferred behind other recipients that name this session as their target (which `purge` keeps, since a removed target still reports honestly) and returns every instance that lost a pending callback — the overage stop marks each.
See the overage entry below.
Either way a note reaches the conductor that asked, exactly once, and can never linger onto an unrelated wake.
`deliver()` picks its stub (`_plainStub`/`_buildFoldedStub`): a real `turn_end` to an already-idle caller **folds** the worker's recent output inline (reusing `buildRecentMessages` from `mcp/handlers.ts` + `flattenPayload` from `mcp/content.ts`, tagged with the `shared/wakeCallback.ts` marker for the collapsible UI bubble); the heartbeat and live mid-turn steering paths keep the plain pointer stub (a mid-turn wake is injected live into the caller's running turn), and so does the **interrupted** variant — a `turn_end` produced by a FORCE-abort (`Instance.turnForceAborted`) is never folded even to an idle caller, since the body separator is the client's "finished result" signal and partial aborted output must not read as one.
The **exited** variant is never folded either: there is no result.
That qualifier is READ by all three consuming paths (`_abortQualifier`) and cleared by neither: its lifetime is owned entirely by the two turn-start rules, so it stays true from the abort until the next turn begins.
`onTurnStart` clears it when NO armed wake survived into the transition — armed means the wake is the aborted turn's own deferred one and the qualifier still describes it (the CLI resolves such a wake by opening exactly an unprompted re-invocation turn), while nothing armed means there is nothing left for it to describe, which is the only state a sole owner's own force-abort can leave behind.
`prompt()` clears it in the case that check deliberately does not: a wake DID survive, but a new instruction supersedes the abort.
Clearing at resolve time as well was removed for being indistinguishable from doing nothing — after any consuming path the target's `subscribers` entry is empty, so the next turn start necessarily sees no survivor and clears.
A caller whose model declares `midTurnSteering:false` (`acceptsMidTurnSteering`) takes neither: its wake is **held** in `_deferredWakes` (caller-keyed) and flushed by `_flushDeferredWakes` at that caller's own next `turn_end` — or on `system`/`steer_settled` when a queued steer drains with no turn to end — re-deferring once more while `caller.steerPending`; a held wake whose target went busy again is marked stale (plain stub + `STALE_WAKE_NOTE`) rather than folded.
`steerPending` is also a fourth `_onTurnEnd` defer reason on the TARGET side, for the same reason `rotationPending` is: the `turn_end` came from a block-edge stop, not from the worker finishing.
See [protocol/mcp.md](../protocol/mcp.md) and [models.md](../models.md#mid-turn-steering-capability).
No import cycle — nothing in `handlers.ts`'s import graph reaches back to `instances.ts`.

## `src/overageResume.ts`

`OverageResumeController`, the overage auto-resume timer machine extracted from `InstanceManager` as a composed collaborator.
Owns the `instanceId → fireAtMs` (wall-clock epoch-ms **deadline**) map (**keyed by the stable instanceId**, so a due-tick resolves the Instance by a direct `byId.get(id)` rather than a scan) and `AUTO_RESUME_TEXT` (re-exported from `instances.ts` for back-compat); the per-Instance overage flags (`autoResumeAt`/`autoStoppedForOverage`/`_overageHandled`/`_overageResetsAt`) stay on the Instance.
Firing is driven by a **single shared wall-clock sweep interval** (`ORCH_OVERAGE_RESUME_SWEEP_MS`, `unref()`'d — started on first arm, stopped when the map empties), **not** one `setTimeout` per session: each tick re-reads `Date.now()` and fires every deadline that is now due, so a deadline that lapsed while the process was suspended (Android Doze / Termux backgrounding freezes the libuv monotonic clock a `setTimeout` rides) fires on the first tick after wake.
`resetsAt`-based scheduling, deadlines in-memory but persisted in the resume manifest (survive a graceful restart), never kills/respawns.
**Usage-verified fire:** a due deadline does NOT resume on our clock alone — the tick does ONE coalesced `fetchUsage()` (`getAccountUsage`, injectable seam; its usage-cache cadence + backoff absorb the pressure — one fetch shared across all sessions due that cycle, guarded by `_ticking`) and only resumes when `usageOverThreshold(usage) === false` (five-hour util `< 100` and under any enabled threshold — the SAME evaluator the poll trip uses).
Still-over → `_reschedule` to `max(resetsAt, now + ORCH_OVERAGE_RECHECK_MS)` (also pushes the manager's global `_overageResetsAt` forward so the lockout gate's future-resetsAt rail stays satisfied while parked), naturally polling at each recheck until the account clears — which is what kills the boundary re-trip (no resume turn is ever sent while still throttled).
Can't-confirm (null/backoff/malformed) reschedules too, up to `FAIL_OPEN_AFTER` consecutive failures, then fails open and resumes so a persistently-down usage API can't park a session forever.
`arm()` no longer dead-ends on a missing/past `resetsAt` — it schedules the first check at `now + recheck`; **`auto_resume_skipped`** now fires ONLY for the genuine "process gone" case in `run()`.
`armRestored` (restart) re-inserts its persisted deadline as-is (keyed by the freshly-created Instance's new instanceId — the manifest persists the deadline by sessionId, and restore re-arms off the live restored `inst` after `create()`) and inherits the same usage-verified fire.
`InstanceManager` delegates the `_armAutoResume`/`_cancelAutoResume`/… surface (also called from the normal-session exit branch so a disposed normal session never leaves an orphan deadline) and exposes the live `_autoResumeTimers` getter.
**Message queueing:** while a session is auto-stopped-and-armed, a non-internal `Instance.prompt()` is intercepted **before** `emit('user_prompt')` and pushed onto `inst._overageQueue` (`{text, attachments, ts}`) with an `overage_message_queued` UI event — it does NOT resume or cancel.
`run()` flushes on fire: it snapshot-empties the queue, calls `cancel(sid)` FIRST (clears `autoStoppedForOverage`/`autoResumeAt` so the follow-on resume send isn't re-queued — `cancel` is idempotent), emits an `auto_resume` system line, then sends ONE combined `internal:true` `prompt()` (`buildCombinedResumeText` = the kind's base preamble + numbered list, with all queued attachments concatenated) with `_overageResumeFiring` set around it.
**The preamble selector is THREE-way**, owned by the single `overageResumeKind(inst)` mapping: `_overageWasStopped` → `AUTO_RESUME_TEXT` ("continue where you left off"); `_overageWasIdleParked` → `IDLE_PARKED_RESUME_TEXT` (the stop found it idle, so nothing of its own was interrupted); neither → `QUEUED_ONLY_RESUME_TEXT` (the softened line, non-empty queue only).
Both conductor clauses ride all three.
`cancel()` also clears `_overageQueue` (kill/remove/normal-exit/shutdown cleanup).
`summary()` exposes `queuedCount` (rides every status emit → header/sidebar badges append `· N queued`).
`fireNow()` is the sweep-internal + test seam and is also the primitive `InstanceManager.reevaluateOverageResumes()` drives (one `fireNow` per parked instanceId, snapshotting `timers.keys()` first since `fireNow` synchronously deletes its own entry) — called after a Settings → Account Apply that raises/disables the threshold, so a session parked under the OLD bar resolves against the new one immediately instead of waiting out its deadline.
There is still **no** early-resume UI/button — this is a settings-save side effect, not a user-facing control.

## `src/usageWindowDomains.ts`

the backend-scoped **usage-window domain** seam that decides whether an instance is subject to the overage flow at all.
A usage/rate-limit window is a provider concept: `usageDomainOfBackend(backend)` maps the identity `claude` backend to `'anthropic'` and every other registry backend to a domain named after itself, and `MONITORED_DOMAINS` (today just `{'anthropic'}`) names the domains with an active monitor.
`InstanceManager` composes four helpers on top: `agentTreeRoot(inst)` (walks `callerInstanceId` **UPWARD** through `byId` to the tree's root; terminates on no-parent, a parent no longer live, or a cycle via a `seen` set, returning `inst` itself in every degenerate case), `agentTreeBackends(inst)` (cycle-safe **DOWNWARD** walk of `inst` + its conducted-worker descendants by `callerInstanceId` → `Set` of backend ids; in-process Agent-tool subagents share the parent CLI's launch-fixed backend so they add nothing), `usageWindowDomainsOf(inst)` (that same downward subtree, mapped to domains), and `_inUsageWindowFlow(inst)` — which evaluates `usageWindowDomainsOf(agentTreeRoot(inst))`, i.e. the **ROOT's** whole tree, because the unit of stopping is the tree.
A root tree with no Claude agent → e.g. `{ollama}` → exempt; a root tree with any Claude agent → in-flow *for every member*, so a non-Claude conductor with Claude workers **and** a non-Claude worker under a Claude conductor are both in.
Root resolution deliberately stays out of `agentTreeBackends`/`usageWindowDomainsOf`: they promise the argument's own subtree, and pushing it down would make `usageWindowDomainsOf(worker)` report its conductor's domains.
**Stop vs trip:** `_handleOverageTrip` does NOT use `_inUsageWindowFlow` — it tests the emitting session's OWN backend (`isMonitoredDomain(usageDomainOfBackend(inst.backend))`), since only that backend says which account's window a `rate_limit_event` reports; it is strictly narrower, so it cannot admit a trip the root-scoped predicate would reject.
Shipping a monitor for another backend's window later = add its domain to `MONITORED_DOMAINS`; no exemption logic changes.

## `src/usageOverageMonitor.ts`

`UsageOverageMonitor`, the server-side usage poller composed by `InstanceManager` as a second, equal-footing overage-trip source alongside the stream `rate_limit_event`. On an `ORCH_USAGE_POLL_MS` interval (`unref()`'d), `_tick()` is heavily gated (skip if `_overageActive`, threshold disabled, `getOnOverageAction()==='none'`, or nothing mid-turn — so it doesn't fetch needlessly), then calls `getAccountUsage()` (injectable as `fetchUsage` for tests; a throw or null is swallowed → no false-trip) and, when the **five-hour** window's `utilization` (a 0–100 percent) `>= overageThresholdPct`, calls `manager._handleOverageTrip(null, { resetsAt })` — the *same* seam the stream trip lands in. It writes no parallel stop logic and injects no prompts (routing's `internal:true` prompts are inherited), so dedup (`_overageActive`), conductor/conducted/plain routing, and resume all behave identically regardless of source. `start()`/`stop()` are idempotent; the server starts it after `listen()`, and both `shutdown()` and `shutdownForResumeSync()` stop it. The point: the stream event only reports near Anthropic's own ~90% mark, so a *low* threshold (e.g. 25%) is invisible to it — only the poll catches it. `parseResetEpochSecs` lives in the leaf `src/rateLimitReset.ts` and is reused here to turn the bucket's ISO `resets_at` into epoch seconds. `forceTick()` is a thin public passthrough to `_tick()` — the same gates apply — used by the Settings → Account Apply handler (`src/routes/models.ts`) so a *lower* threshold that's already crossed trips a mid-turn session immediately instead of waiting up to `ORCH_USAGE_POLL_MS` for the next scheduled tick.

## `src/sessionLineage.ts`

the rules that make a session's identity permanent, run over the unified store (`src/sessionStore.ts`'s `mutateSessions`/`loadSessions`): a record's `current` + `segments: [{ id, reason, at, dropped? }, …]` (plus the segments' `persistent`/`archived` flags, which the store owns). `LineageRow` is the store's `SessionRecord` and `Lineage` its `SessionIndex` (`byPublic`, plus the **backing → public reverse index built in memory at load and never persisted** — a second on-disk copy is a divergence surface). `loadLineage()` is `loadSessions()` (behind the store's kick-anchored read barrier); `trackLineageWrite` is re-exported from the store. A session's **public id** is minted once from the first 8 hex chars of its first CLI `session_id` (`mintPublicId`, extending to `xxxxxxxx-xxxx` on collision, then to the full id with a `console.warn`); derive-check-extend-**and-write** is one mutation under the lock, or two concurrent spawns mint the same id. The collision universe is every **public** key (a candidate is a slice of a UUID and can never equal a full backing id; a minted id that prefixes another session's segment is resolution's job — exact beats prefix). **BASE CASE**: no record, or a single `initial` record named by its own key, ⇒ public id == backing id and every resolver is the identity. `resolveBacking(id)` → a public id's `current`, a segment → itself, unknown → unchanged; `publicIdFor`, `segmentsFor` (live), `chainFor` (tombstones included — the lineage scroll-back's reader only).
- **Rotation, one path for all three mechanisms.** `recordRotation(pub, newId, reason)` appends the segment, advances `current`, and gives the new segment its predecessor's `persistent` in the same write; it creates the record lazily for a record-less session and is idempotent on a retry. `retireSegment(oldId)` / `retireSegments(ids)` set archived on in ONE mutation, leaving `persistent` untouched (a restored session resumes as what it was) (the restart/boot paths retire a whole batch at once). Session facts are keyed by the public id, so no rotation touches them — there is no carry.

  | Rotation | Durable write | Old segment | New segment | Session facts |
  |---|---|---|---|---|
  | Managed renew / typed `/clear` | the `system/init` rotation branch kicks ONE `_kickLineageWrite` item (`Instance._rotationWrite`): `recordRotation(…,'renew')` then `retireSegment(old)`; `retryRotationWrite` re-kicks the same item (old = `_segments.at(-2)`) | archived; `persistent` untouched | inherits `persistent` | untouched |
  | Prune | `await recordRotation(…,'prune')` → `launch` → `await retireSegment(old)` | archived after a successful launch | inherits `persistent` | untouched |
  | Prune rollback | `revertRotation` removes the new segment and **keeps the record** (it holds the facts); a left-over single-`initial` record resolves as the base case | untouched | removed | untouched |
  | Renewal undo (`Instance.rewindAcrossRenewal`) | `undoRenewal(pub, {pre, post, persistent})` **splices** the post run (the renew entry to the chain's end, prune copies and tombstones included) out of the record — no tombstone, or the lineage walk would draw a seam and a gap for a segment no longer in the lineage — and points `current` at `pre`; refuses 409 `RENEWAL_MOVED` unless the chain ends exactly in live `pre` + `post` with `current` = `post`'s last entry; no-op once applied. The caller then deletes the post run's jsonls and sub-agent dirs | `pre`: archived off, `persistent` set to the instance's | removed with its files | untouched |

**Tombstones.**
`dropSegment` marks an entry `dropped: true` in place instead of removing it (an already-tombstoned id is a no-op, no write), clears its `persistent`/`archived`, and moves `current` to the newest live entry.
The parser keeps `dropped` only when `=== true` and skips a record with no live entry.
The store's **record invariant** holds across every mutation here: a persisted record has ≥ 1 live entry and `current` is live; a mutation that would leave none deletes the record — and every session fact on it.
So `dropSegment(id, {unlessLast: true})` does nothing when this is the record's last live entry: `loadHistory`'s ENOENT branch passes it, because a respawn of a session killed before its first turn finds no transcript and must not lose its kind/title/mode.
Only the explicit session delete (`deleteSessionForCwd`) drops without it.
**Reader rule:** every reader sees `liveSegments(row)` only — `indexSessions` (builds `byBacking`), `segmentsFor`, and through them `resolveBacking`/`publicIdFor`, `resolveToBackingId`, `findSessionLocation`, the session-list projection and `GET /api/archived`, `resolveResumeRef`, the create path's `_segments` seed and the MCP `SESSION_NOT_A_HANDLE` check — which is exactly the chain a removal would have left.
The ONE full-chain reader is `chainFor(publicId)`, whose only caller is the lineage scroll-back (`src/lineagePager.ts`): a tombstone keeps its renew boundary and its role as a prune's original visible to the walk.
**Entries missing outright** (absent from the chain rather than tombstoned — undetectable except L1): **L1** a chain whose oldest entry is not `initial` renders one gap above the oldest content; **L2** a removed entry followed by a `renew` leaves its neighbours with one divider and no marker; **L3** a removed prune original makes the walk skip the entry before it as if it were the original.
There is no `prunedFrom` field: chain adjacency already names every prune's original, and a second field could disagree with it.

**BASE CASE, not a legacy branch:** no record, or a single `initial` record named by its own key, ⇒ public id == backing id. Every resolver returns its input unchanged for an unknown id, and nothing anywhere asks "is this a legacy id?". Any session-level write for a never-minted session creates exactly that single-`initial` record (the store's base-case promotion).

`reason: 'initial' | 'renew' | 'prune'` is load-bearing, not polish. Every segment's file survives on disk in both mechanisms — except an undone renewal's post run, which `undoRenewal` splices out and `Instance.rewindAcrossRenewal` deletes — so segments are uniform for *identity* — but not for *content*: a `renew` segment is **disjoint** from its predecessor (full history is their concatenation) while a `prune` segment is a filtered **copy** that **overlaps** it (`src/sessionPrune.ts` writes a new file and leaves the original untouched) and must never be concatenated. `reason` alone carries that — do **not** add a second boolean that can disagree with it.

API: `loadLineage` · `mintPublicId` (only caller: `Instance.launch()` on a fresh spawn) · `recordRotation(publicId, backingId, reason)` (appends + advances `current`, the new segment inheriting its predecessor's `persistent`; **creates the record lazily** for a previously record-less session by promoting its public id to an `initial` segment; idempotent on a retry) · `retireSegment(id, {owner?})` / `retireSegments(ids, {owner?})` (archived on, `persistent` untouched, one mutation) · `revertRotation` (drops the newest LIVE segment iff it is the one named — trailing tombstones stay — and keeps the record unless no live segment is left — only caller: `pruneSession`'s rollback) · `undoRenewal(publicId, {pre, post, persistent})` (see the table above; `RENEWAL_MOVED` — only caller: `Instance.rewindAcrossRenewal`) · `resolveBacking` (public → `current`; a known **segment → itself**, deliberately, so clicking an archived row opens *that* transcript rather than silently redirecting to the newest) · `publicIdFor` · `segmentsFor` (live entries) · `chainFor` (full chain, tombstones included) · `dropSegment(id, {unlessLast?})` (tombstones).

**Read tolerance, not writes on reads.** A row can outlive the files it names (Claude prunes its own `~/.claude/projects` after ~30 days). `findSessionLocation` therefore resolves, probes, and on a miss walks the row's segments **newest-first**, returning the first that exists — read-only, because a write inside a hot read path races concurrent readers. Places are composed lazily and memoised, so a place is composed at most once per lookup and only the stats repeat per segment. **Recorded place, last.** When every registered place misses, the record's own `project` + `worktree` (written for every spawn by `setSessionPlace`) name one more place, `recordedPlace(proj, worktreeName)` = `worktreePathFor` under that listed project, probed for the backing id and then the older segments: this is what keeps a worktree session locatable — readable, describable, listed in Settings → Archived, deletable — after `delete_worktree` removed its registration, and what makes its resume refuse `WORKTREE_UNKNOWN` rather than land elsewhere. The hit's `worktreeName` then names a worktree that no longer exists. **Limitation:** a non-conducted session recorded before `setSessionPlace` existed carries no place (only conducted ones did), so if its worktree was deleted it stays orphaned — `findOrphanedTranscript`'s `SESSION_NOT_LIVE` / `SESSION_UNLOCATABLE` refusal; there is no backfill. The two places that *do* tombstone are the ones that know a file is gone for good: `deleteSessionForCwd` (the only jsonl-deleting path in the repo) and `Instance.loadHistory`'s ENOENT branch, both via the one `dropSegment` (pinned identical by `tests/session-lineage-tombstone.test.mjs` TL3); the ENOENT branch passes `unlessLast`, so it never drops a record's last live segment.

**The path chokepoint.** `sessionFilePath(place, backingId)` / `subAgentDirPath(place, backingId)` in `src/projects.ts` are the only constructors of a transcript path. Both take a **`TranscriptPlacement`** (`{ system, remoteId, cwd }`), never a bare cwd: a remote-backed worker runs at the remote's own path spelling, so `/root/app3` is one cwd on every box that has it and the machine coordinate is what tells them apart. Each joins `transcriptRoot(place)` — `claudeProjectsRoot()` for a local place, `<remoteConfigDir(place)>/projects` otherwise — to the unchanged `encodeCwd(place.cwd)`. `localPlace(cwd)` is the explicit spelling for a place that is local by construction (`.conduct`, the summariser's scratch dir, a fixture); there is deliberately no local default, because a silent one is how a remote place would resolve against the wrong root. Both call `assertBackingId` — which THROWS when handed something shaped like a minted public id. It is an assertion, not a branch: nothing resolves differently by id length. `isMintedPublicId` (same regex, one source) lets a route that has already resolved and *still* sees that shape decline cleanly as an unknown session (null / false / 404) instead of turning a clean miss into a 500. `tests/session-lineage-chokepoint.test.mjs` fails the build on any other `.jsonl` path literal, with a small named exempt list and a vacuity guard.

## `src/sessionRenew.ts`

`SessionRenewController`, the managed session-renewal machine composed by `InstanceManager` (the `renew_session` MCP tool).
Owns a `instanceId → {state:'requested'|'armed'|'clearing', opts, oldSid, timerId}` map.
**Keyed by instanceId, not sessionId**, because renewal's whole job is to rotate the caller's sessionId out from under it — only the stable `byId` key survives.
`arm(instanceId, {summary, followUp?})` (idempotent; re-arm refreshes opts, always carrying `followUp` forward) registers a pending renewal, and CONSUMES a `requested` entry for that instance if one is pending — folding its `followUp` in.
`request(instanceId, {followUp, requestedBy})` registers the conductor-side ask (`requestedBy` is the asking conductor's sessionId, so the decline can be reported to IT and no other watcher) (see the `renew_session` targeted form in [protocol/mcp.md](../protocol/mcp.md)); it overwrites another request but never a live `armed`/`clearing` renewal, and deliberately opens NO rotation window, so a decline rides the worker's ordinary `turn_end`.
`dropRequest` un-registers one whose prompt never went out.
`onEvent` acts on `turn_end` for a pending instance: `requested` → the entry is deleted and `manager.noteRenewalDeclined(id, requestedBy)` is called SYNCHRONOUSLY in that dispatch (the decline; the ordering that makes it reach the already-queued wake is documented on `noteRenewalDeclined` in `idleSubscriptions.ts`); `armed` → the caller's next `turn_end` drives `Instance.clearContext()` (a server-managed `/clear`, see protocol/subprocess.md) and remembers the pre-clear sessionId → `clearing`; `clearing` → the first `turn_end` where `inst.backingSessionId` has rotated off the pre-clear id (i.e. `/clear`'s own turn_end, after its `system/init`) builds the mechanical state block (`buildStateBlock(manager, id)` — **at this point, not at arm time**, so it reflects current state) and injects `buildRenewSeed({...opts, stateBlock})` (imported from [`shared/renewSeed.ts`](platform.md#sharedrenewseedts)) as the cleared session's first user turn (`prompt(..., {internal:true})`).
The public `inst.sessionId` is pinned throughout — only the backing id moves.

**The reseed waits on durability.**
`system/init` corrects in-memory truth in its own tick and kicks the rotation write (`recordRotation`, then `retireSegment` on the pre-clear segment) onto the instance's serialised `_lineageWrite` chain immediately — the earliest possible point, since the CLI has ALREADY written the new transcript by the time we see that line, making durable-before-first-use physically impossible.
`_onClearingTurnEnd` then **awaits `inst.flushLineage()` before the reseed** (`flushLineage` rethrows the first failure since the last flush; the error is remembered rather than swallowed so a failed write cannot wedge later rotations).
On rejection it RETRIES — up to `LINEAGE_RETRY_ATTEMPTS` (`src/sessionRenew.ts`) rounds of `inst.retryRotationWrite()` + `inst.flushLineage()`, so the worst case is 1 + that many flushes.
The retry is a re-kick, not a re-implementation: `recordRotation` and `retireSegment` are idempotent, so it either lands what is missing or no-ops on what was already written.
**No sleep between rounds, and that bounds what it can recover to exactly one mode: a cross-process lock-contention throw** — a failed attempt has already spent its whole ~10s `withLock` backoff window (`src/storeLock.ts`) waiting out the contender, so a fresh attempt is a real second chance if it released late.
A DETERMINISTIC store error (EISDIR / EPERM / ENOSPC / corrupt JSON) is NOT recovered: `retryRotationWrite()` is synchronous and the re-kicked `recordRotation` reaches the store's strict read on the next microtask, so it re-throws the same error milliseconds later and exhausts every attempt.
Only once every attempt has failed does it emit a `system`/`renew_error` UI event (once, carrying the LAST error) naming the orphan risk, and it **still reseeds** — the clear already happened irreversibly and the summary is the only thing that can save the session.
Failure-visible, not abort.
The reseed's own failure gets the same event, replacing a `.catch(() => {})` that silently lost a cleared-context-with-no-summary.
**Consequence for readers: "rotated" no longer implies "seeded"** — the reseed is dispatched one or more ticks after the rotation.

**The rotation window.**
`arm()` calls `inst.beginRotation('renew')` — mid-turn, when the tool is called, well before that turn ends — and every exit path closes it via `_clear(id, {ok})` → `inst.endRotation({ok, comesUpIdle: !ok})`.
The window lives on the `Instance` (not in either controller) so `IdleSubscriptionHub`'s defer works regardless of listener registration order; `comesUpIdle` is `false` only on the success path, where a reseed turn follows by construction.
Every abandonment — dead proc at either `turn_end`, a `clearContext` throw, the rotate watchdog, `purge()` — declares `comesUpIdle: true`, because no turn is coming at all and the completion event is then the only wake point a waiting conductor will ever get.
The session's durable facts need no carrying either: title/mode/backend/conducted are keyed by the public id, and the rotation write kicked in `system/init` (`recordRotation` + `retireSegment`, see `src/sessionLineage.ts`) gives the new segment `persistent` and archives the pre-clear one — the same write a typed `/clear` gets.
No side-structure migration is needed — the idle-wake graph and overage timers are keyed by the stable instanceId, which `/clear` preserves.
A `turn_end` that has NOT rotated (a mid-turn-queued user turn the CLI ran before `/clear` took effect) is ignored, so an intervening turn can't reseed into the wrong session.
The `armed` state **defers** the clear while the caller has an overage-queued turn (`_overageQueue.length`), live subagents (`activeAgentTaskCount`), or an owed re-invocation (`taskNotificationPending`) — so queued/background work is never stranded by the rotation (mirrors the idle hub's defer gate).
That gate only re-fires on a `turn_end`, so an armed renewal has a **second fire trigger** for the case no `turn_end` ever follows: a `system/task_updated`|`task_notification` that leaves the instance drained-idle fires the clear immediately (`_onArmedDrain` → the same `_fireClear` the turn_end path uses).
Exactly those two subtypes, mirroring `IdleSubscriptionHub._onTaskEvent` — a broader "any event while idle" trigger would `/clear` before a test's next `send_prompt`, breaking the `go1 < /clear < seed` ordering — and no settle window, because the hub's exists to avoid waking one turn EARLY while the only risk here is a concurrently-opening turn, after which the queued `/clear` still reseeds correctly.
A `.unref()`'d `ORCH_RENEW_CLEAR_TIMEOUT_MS` watchdog (default `CLEAR_ROTATE_TIMEOUT_MS` in `src/sessionRenew.ts`) abandons a renewal that never rotates rather than wedging the instance.
`buildRenewSeed({summary, followUp?, stateBlock?})` — imported from [`shared/renewSeed.ts`](platform.md#sharedrenewseedts), the DOM-free module shared with the client — composes the seed text, each part under its own fence: the self-authored summary, then the conductor's post-renewal `followUp` (a task, as against the summary's memory), then `stateBlock`, the mechanical state block whose header line is that module's `MECHANICAL_STATE_HEADER`.
`buildRenewRequest({directive?})` composes the turn-A prompt a targeted request sends (ask → decline path → the summary call), and `RENEW_SUMMARY_TEMPLATE` is the ONE home for the summary structure, read from here by the `summary` argument description in `src/mcp/tools.ts` too — its `## <heading>` titles are interpolated from `RENEW_SUMMARY_SECTIONS` (`shared/renewSeed.ts`), so the client's `splitSummarySections` can never drift from what the worker is asked to write.
`buildStateBlock(manager, callerInstanceId)` enumerates `manager.liveOwnedBy(callerInstanceId)` (live instances the caller spawned, via the same `callerInstanceId` tracking the sub-agent panel uses — `{sessionId, project, worktree, status}`) and `manager.ownedWakeTargetsOf(callerInstanceId)` (every session the caller OWNS — spawn or dispatch — whose next turn will wake it) — framed as a safety net: it wins for **existence**, the self-authored summary wins for **intent**.
`InstanceManager` delegates `armSessionRenew`/`requestSessionRenew`/`dropSessionRenewRequest`; `remove()` calls `_sessionRenew.purge(id)` (a `requested` entry holds no rotation window, so purging it closes nothing).

## Overage trip detection + central routing

(in `src/instances/overageRouting.ts`, reached through `InstanceManager`'s same-name delegates) — the *decision* of what to do on an overage trip moved off the per-Instance handler (which can't reach the idle-wake graph) up to `InstanceManager`.
Two sources reach `_handleOverageTrip`: the per-Instance stream path below, and the `UsageOverageMonitor` poll (above) — deduped by the global `_overageActive` one-shot so they never double-trip (whichever observes the crossing first wins).
Flow: `Instance._isOverageTrip(data)` (hard `isUsingOverage` flag OR, when `getOverageThreshold().enabled`, `utilization >= pct/100` for any window) → `Instance` emits an `overage` signal (throttled per run by `_overageHandled`) → `InstanceManager._handleOverageTrip` holds a global one-shot `_overageActive`/`_overageResetsAt`/`_overageClearTimer`, returns early when `getOnOverageAction()==='none'`, else `_routeOverageStop` (**the stop SENDS NOTHING to anything** — the account is throttled, so a message into it is the burn the stop exists to prevent.
Every session routing touches goes through the one `_directOverageStop`: mid-turn → soft-interrupt via `interrupt()`; already idle → the same notice + sever + arming, with `interrupt()` a no-op it returns from on `status !== 'turn'`.
Pass 1 resolves in-control conductors (`_ownerConductor` = `byId.get(worker.callerInstanceId)`, in-control = mid-turn, `isIdleCaller`, or a **job waiter** — `InstanceManager._jobWaiters()` (`jobWaiters`, `src/backgroundJobs.ts`, the same set `list()` reads for `waitingOnJob`): its worker, or a session below it, holds a live background Bash job whose exit will re-invoke it.
A job that never ends (a promoted dev server) still counts, so that conductor takes one idle-parked resume turn per reset) and their `protectedWorkers`; Pass 2 stops each such conductor — the ONLY path an idle session reaches, since Pass 3 skips anything not `status === 'turn'`; Pass 3 stops every *other* mid-turn instance, protected workers included, in ONE branch.
The collapse is behaviour-identical for a `.conduct` orchestrator that is **not** itself a conducted worker — the ordinary case, where `unarmed` is false and it takes exactly the arming the deleted conductor branch gave it.
It is NOT identical for a `.conduct` session spawned through MCP `spawn_instance`, which carries `conducted:true` + `callerInstanceId`: mid-turn under an in-control owner it is now treated as a protected worker (stopped un-armed, owner marked) where the old branch armed it.
That is the intended reading of "protected worker" — its owner is the sole driver on resume — so the collapse is kept, not special-cased.
`.conduct` has no routing special case left: a mid-turn orchestrator is soft-interrupted like anything else), and arms `_armOverageClear(resetsAt)`.

**A conductor's workers are stopped un-armed, and its callbacks are dropped.**
Pass 3 passes `armResume:false` for a member of `protectedWorkers`, so it is interrupted and emits `auto_stop_overage` but sets no `autoStoppedForOverage` — no per-session resume timer, because the conductor is the sole driver on resume.
Arming both would have the conductor's re-drive land mid-turn on a worker that just self-resumed, which is the mid-turn injection this path exists to avoid.
**Severing the subscription graph has ONE owner.**
`InstanceManager._severOverageWakes(inst)` wraps `IdleSubscriptionHub.severForOverageStop(inst.id)` + the mark loop, and has exactly TWO callers: `_directOverageStop` (the stop) and `_guardOverageTurnStart` (the turn-start lockout guard, below).
It is called for every session the stop touches: an interrupted session's `turn_end` would otherwise wake its watcher with an `internal:true` prompt, which the overage queue intercept deliberately does **not** hold, so the watcher starts a fresh turn *inside* the lockout — the burn the stop exists to prevent.
Keyed on the **idle-wake** graph, not on the conducted-SPAWN graph — a distinction that survives the graph becoming ownership-keyed, because ownership there is spawn OR dispatch: a conductor can be waiting on a session it never spawned, and keying on spawn alone left exactly that case armed.
Both directions (the stopped session must wake nobody and nobody may wake it) plus wakes **already** deferred behind a mid-turn recipient — `purge()` deliberately keeps those, because a *removed* target still reports honestly through `deliver()`, but a stopped-and-alive one must not be reported at all.
It returns every instance that lost a pending callback, including the stopped session itself, and each is **marked** `_overageDroppedCallbacks` — marked, not notified: the mark only reaches an instance that has a resume prompt of its own to carry it, which an un-armed worker or any session under plain `Stop` does not.
**The mark loop also ARMS** (`_armSeveredCaller`): for each marked caller it resolves the **sole driver** and arms it **idle-parked** (`_overageWasIdleParked`, `_overageWasStopped` false → `IDLE_PARKED_RESUME_TEXT` + the dropped-callbacks clause) when nothing else will — idle → `_armResumeNow`, mid-turn → `autoStoppedForOverage` set and the status handler arms at idle.
The driver resolves exactly as routing's does (Pass 1/2): a conducted caller's **immediate** live owner (`_ownerConductor`, one hop, never further), else the caller itself; it is marked `_overageDroppedCallbacks`.
So **a conducted caller with a live owner is never armed by a sever, in any order of severs** — its conductor is, and stays its sole driver on resume, with one deadline per worker–conductor pair.
In a chain O → C → W (C an MCP-spawned sub-conductor): W losing a wake arms C and leaves O untouched; C losing a wake arms **O**, not C — C is a conducted caller with a live owner like any worker.
C keeps only the sever's own `_overageDroppedCallbacks` mark, which no resume of its own carries; it restarts when O's resume (dropped-callbacks clause → re-check its sessions) re-drives it.
That is the same treatment routing gives a sub-conductor it stops un-armed under an in-control O. It covers what Pass 1 cannot see: a wake re-armed **after** the trip by a self-triggered turn (a background job's exit re-invocation, then cut by the guard), a dispatch-only owner (Pass 1 finds conductors only through `callerInstanceId`), and a conductor whose own resume already fired while other parked sessions hold the lockout.
Nothing is armed when: the lockout is off (`_overageActive && _overageResumeMode` — deliberately not `_overageGate().active`, whose future-`resetsAt` rail would skip a trip with no reset time that routing still arms); the caller is dead or root-exempt (`_inUsageWindowFlow`; the owner shares the caller's root tree); the **caller** is already armed (`autoStoppedForOverage`; the `autoResumeAt` / timer terms are defensive) — checked BEFORE driver resolution, so it is only marked, its own resume carries the clause and its owner is untouched: this covers a routed session's own sever (`_directOverageStop` sets the flag before severing) and a queued-only session (`overage_queued`) severed later; the resolved driver is already armed (it is marked, no second deadline); or the driver is a worker Pass 3 stopped un-armed whose owner is gone (`_overageStoppedUnarmed` — the protection holds after the owner is removed).
Every check precedes the arming writes: a stray `autoStoppedForOverage` with no deadline blocks `_maybeReleaseOverageLock` forever.
An armed wake a stopped conductor holds on a target Pass 3 leaves running is covered by the same call (the predicate is ROOT-scoped, so the reachable case is a **non-owned** backend-exempt target — a standalone session with no `callerInstanceId` to walk up, held via `noteDispatch`; a *conducted* exempt worker is now in-flow and Pass 3 stops it); left armed, the heartbeat (`DEFAULT_SUBSCRIBE_TIMEOUT_MS`, well inside a five-hour window) would fire mid-lockout — repeatedly — delivering an `internal:true` wake the queue intercept does not hold.
**Why the turn-start GUARD severs too:** `purge()` clears the dispatch edges but not spawn ownership — `ownersOf` re-adds the parent from `Instance.callerInstanceId` on every call — so a stopped, already-severed worker whose turn starts again re-arms its conductor's wake at `onTurnStart`; without a sever there, the guard's own interrupt produces a `turn_end` that delivers an `internal:true` wake stub, i.e. a message sent during the lockout.
`purge()` itself is deliberately unchanged: a *removed* target must still report honestly through `deliver()`, which is exactly why `severForOverageStop` exists as the overage-specific wrapper.

**The conductor resume prompt is composed from TWO independent flags, each gating its own clause** (`buildConductorResumePreamble`, `src/overageResume.ts`): `_overageDroppedCallbacks` (a callback was severed → re-check the sessions directly instead of waiting to be woken) and `_overageUnarmedWorkers` (set on the OWNER when Pass 3 stops a worker un-armed → those workers will not resume themselves, re-prompt them). Either can hold without the other — a conductor can lose a callback on a session it does not own, or own an un-armed worker while holding no subscription at all — so one selector for both would make the other clause assert something that did not happen. Neither clause describes *how* anything was stopped: the conductor does nothing differently for that, and it cannot be stated truthfully for a mixed set. Both clauses ride the queued-only preamble too (`appendConductorClauses`), since the human typing into a stopped conductor arms it queued-only and it would otherwise lose them. Both persist in the resume manifest alongside `overageWasStopped`, for the same reason — losing either delivers a resume prompt missing a fact the resumed session — a conductor, or any session the sever armed idle-parked — must act on, and it then waits forever for a wake nothing will send. The manifest key `overageStoppedWorkers` is the **pre-rename spelling** of `_overageDroppedCallbacks` and is deliberately not renamed: a manifest written before the rename is read during exactly the restart it exists for.

**A worker left un-armed also refuses queued sends.**
`_overageStoppedUnarmed` is **assigned** (never latched) per trip on it — a later trip can find the worker un-protected, and a stale `true` would refuse every send to an ordinary session while the only thing that could clear it is the send it refuses.
It is surfaced on the status frame — **ungated**, because `_clearOverage` clears the flag in the same loop that re-emits every summary, so the frame is already accurate (a second `gate.active` guard there would be redundant and unkillable).
Three clears, none redundant with the others: `_clearOverage` is global at window release; `OverageResumeController.cancel()` is per-session and reachable while the window is still active; `InstanceManager.syncOveragePolicy()` is fleet-wide and fires when the operator moves `models.onOverage` OFF `stop-resume`, cancelling every marked session (it iterates `byId`, not `timers`, so a session mid-verify or soft-interrupted-but-not-yet-idle is caught too) and dropping `_overageResumeMode` — but deliberately leaving `_overageActive` and the clear timer alone, so the fleet lands exactly where a native `stop` trip does rather than re-enabling trip detection mid-window.
The paired guard is in `_resolveDue`, which returns early on an unmarked instance: `fireNow`/`_tick` delete their `timers` entry before awaiting `fetchUsage`, so the sweep cannot see that session and only this guard stops its resolver resuming it after the policy changed.
`restoreFromResumeManifest` gates its re-arm on the same live policy.
Pass 3's `= unarmed` assignment is *equivalent* to a conditional set, since `_handleOverageTrip` returns early on `_overageActive` and routing therefore runs once per window.
It is read via `Instance.overageSendRefused` (the one test of the condition, ANDing the flag with the live window so the refusal lifts by itself at reset).
The AND is **load-bearing, not defensive**: the gate also requires `_overageResumeMode` and `atMs > Date.now()`, so it is inactive under plain `Stop` — where Pass 3 still sets the flag but there is no queue to strand anything in — and during the `_armOverageClear` buffer between the window expiring and `_clearOverage` running by `Instance.prompt`'s overage intercept: queueing would strand the text forever (the queue is flushed only by a fired deadline, and `cancel()` discards it) and `_armResumeNow` must not arm one, since a self-resuming worker plus a re-driving conductor is the mid-turn injection this rule closes.
So the send throws instead (CONVENTIONS: fail loudly), `_armResumeNow` guards as a backstop, and `web/src/features/composer/Composer.tsx` offers neither Send nor "Queue" for such a session (`overageStoppedUnarmed`) and says its conductor resumes it.
On the **MCP** surface the four sending tools turn it into a soft `OVERAGE_STOPPED_UNARMED` refusal (`overageUnarmedRefusal`) rather than a throw — this surface's convention, and a conductor just told to re-drive these workers hitting one early is a correctable mistake it should branch on; the WS path keeps the throw.
The `auto_stop_overage` event carries **`armResume`**, not the routing mode, because `systemLine` (`web/src/conversation/format.ts`) renders `resume:true` as "Auto-resuming at ⟨time⟩" and an un-armed worker has no resume to name.
**Global release is unified with the per-session rechecks:** the clear timer's callback is now `_maybeReleaseOverageLock` (a BACKSTOP for the never-armed case), which clears the global flag ONLY when nothing is parked (`_overageResume.timers.size === 0`) AND no live instance is still `autoStoppedForOverage` (a session whose interrupt is armed but which has not yet arrived at idle will arm imminently — closes the past-resetsAt backstop race).
The resume controller calls `_maybeReleaseOverageLock` after every deadline-removing outcome (verified resume, fail-open resume, process-gone teardown), so the lockout lifts exactly when the last parked session resolves — the release and the resumes can't disagree because they're the same usage-verified sweep.
`_clearOverage` (backstop fire, that release path, or manual takeover of an `autoStoppedForOverage` session via the `user_prompt` handler) releases the flag and resets every instance's `_overageHandled`.
For `stop-resume`, a stopped conductor arms its own resume either way, but **by two different routes**: a MID-TURN one sets `autoStoppedForOverage` before the abort and its timer arms on the next status→idle transition, while an IDLE-PARKED one never transitions at all (it is neither prompted nor interrupted) and so is armed at routing time by `_armResumeNow(inst, resetsAt)` — the same controller entry point a queued-only session uses (a later sever skips it as already armed).
`_directOverageStop` reads `midTurn = inst.status === 'turn'` BEFORE the interrupt to pick between them, and that same boolean sets the preamble selectors (`_overageWasStopped` vs `_overageWasIdleParked`).
Its `protectedWorkers` are the one exception (`armResume:false`, above).
Resume timing keys off the five-hour `resetsAt` (read camelCase epoch from the live event by `parseResetEpochSecs`), **not** the far-future `overageResetsAt`.
**A prompt runs `_cancelAutoResume` iff it is NOT `internal`** — the flag is the whole test the `user_prompt` handler applies, so no site list here can go stale.
`internal:true` senders today, as examples: the idle-wake wake stub, the renewal reseed (`sessionRenew.ts`), and the auto-resume's own send.
Note that "server-authored" is NOT the same classification: two server-side sends go out **non-internal** and so do cancel a pending resume — the restart notify (`resumeRestart.ts`, harmless because `!e.overageStopped` excludes exactly the sessions that have a resume) and the auto-approved-plan approval (via `promptOrQueueSteer`, contrived to reach).
A new server-side notification must therefore pass `internal:true` deliberately rather than inherit it from those precedents.
The auto-resume's own fire is `internal:true` too and tears its deadline down by calling `cancel()` directly inside `run()`.
**Turn-start lockout guard** (`_guardOverageTurnStart`, wired on the existing `turn_start` listener AFTER `_idleHub.onTurnStart` so the survived-a-wake / abort-qualifier bookkeeping is untouched): any turn that begins while `inst._overageGate().active` is soft-interrupted — wakes severed first, then `interrupt()` (never `force:true`) — and a server-side `system`/`soft_interrupted` carrying `data.text` names the lockout as the cause.
The gate call is the single owner of every scope condition (active + resume-mode + future finite `resetsAt` + `_inUsageWindowFlow`), so plain `Stop`, an expired window and a **root**-exempt session all fall out of it.
Root-exempt, not domain-exempt: a session on an unmonitored backend whose ROOT tree contains a `claude` agent (an ollama worker under a Claude conductor) is deliberately guarded — that guard is the backstop for the F1 wake-stub burn.
The one exemption is `inst._overageResumeFiring`, set around the auto-resume's own send in `OverageResumeController.run` and cleared in the prompt's `.finally()` — **the flag is what exempts the turn in every interleaving**, not any ordering.
Ordering only explains why the gate is still observably active at `turn_start` for an EMPTY-QUEUE resume: `prompt()`'s only `await` is its attachment loop, so with no attachments `_setStatus('turn')` → `turn_start` runs inside `run()`'s own frame, before `_resolveDue` calls `_maybeReleaseOverageLock()` at all.
A resume carrying QUEUED ATTACHMENTS yields at each `await saveAttachment(...)` before `_setStatus('turn')`, and `run()` does not await its own prompt — so the release can interleave first and, with nothing else parked, the gate is already lifted by the time that turn starts.
Parked count is not what guarantees passage; the flag is.
A context rotation started during the lockout IS guarded (`clearContext` sets `turn` directly and its reseed is a real API-burning turn): accepted, bounded by `CLEAR_ROTATE_TIMEOUT_MS` + `signalRotationTurnLost`.
**Domain-scoped exemption, resolved from the tree's ROOT:** every *routing* decision gates on `_inUsageWindowFlow(inst)` (see `usageWindowDomains.ts`), which asks the question of the **root's** whole tree, so a session is outside the flow only when that whole tree is purely in an unmonitored domain (no `claude`-backed agent anywhere in it): `_routeOverageStop` filters such instances out of `live` (never stopped or marked); the per-instance `_overageGate` returns `active:false` for them (so their sends never queue **and** `summary().overageActive` stays false → no overage badge); `_guardOverageTurnStart` inherits that through the gate; and `resumeRestart.ts` skips re-arming a restored deadline onto one (a no-op in practice — restored entries carry `callerInstanceId: null` and worker-group entries are skipped, so a restored instance is always its own root).
Arming is thus unreachable for **root-exempt** instances without extra guards.
A non-Claude worker under a Claude conductor is NOT root-exempt: routing handles it exactly as it would a Claude sibling in the same position — stopped and badged, then armed-and-queueing *or*, when it was **mid-turn at the trip** **and** its conductor is in control, stopped **un-armed**, which refuses sends rather than queueing them.
Both conjuncts are load-bearing: Pass 1 adds to `protectedWorkers` regardless of the worker's status, but Pass 3 visits only `status === 'turn'` and is the only writer of `_overageStoppedUnarmed` whose value is **decided** rather than an unconditional reset to `false` — every other write is such a reset (the constructor, the respawn wipe, and the two clears named earlier in this paragraph), so the mark's *presence* is proof Pass 3 visited.
A worker of an in-control conductor that had already gone idle is therefore skipped entirely — never stopped, never marked — and queues like any other in-flow session (an ordinary shape, not an edge: workers idle out before a window trips).
Which case a session lands in follows from its position in the tree and its status at the trip, per Pass 1/Pass 3 above; membership is what root-scoping fixes, not the per-case verbs.
What matters is that it never RUNS a turn inside the lockout — mid-turn ⇒ stopped by Pass 3; idle ⇒ any turn it starts is aborted by the turn-start guard, which fires off the same gate — and that is what makes its `turn_end` unable to deliver a wake stub into the throttled account mid-lockout.
`_handleOverageTrip` is the one site that does **not** use this predicate — it tests the emitting session's own backend instead (see the `usageWindowDomains.ts` bullet above); the `null`-inst poll trip is account-global and unaffected by either.

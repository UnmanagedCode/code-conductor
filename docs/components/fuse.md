# Components: the FUSE-union chroot (cc side)

The cc-side modules of the FUSE-union chroot: control channel, tier table, plan, wrap, mount session and teardown, the boot sweep, and where the file bridge's duties land.

## `src/systems/fuse/`

the **FUSE-union chroot**, MANDATORY for a remote-backed worker and refused by name where it cannot mount. The one exemption is structural, not configurable: `LauncherLike.inProcess`, the test-only launcher that runs the CLI inside cc's own process and so has no subprocess to put in a mount namespace.  A remote-backed worker's CLI runs inside a private mount namespace whose root is a union filesystem, so the FILESYSTEM decides which bytes appear at a path instead of a pull/push hook. Engaged for every session on a non-local project.

- `control.ts` — **the control channel, cc's half.** A unix stream socket at `<rundir>/control.sock`, created by `FuseSession.prepare()` before the spawn (the daemon refuses to mount without one) and closed by `FuseSession.teardown()` — **outside the teardown latch**, because `prepare()` may have opened a newer one. Fixed binary frames, big-endian, **no payload ever**: `request: u32 'CCU1' | u8 op | u8 flags | u16 pathlen | path`, `reply: u32 'CCU1' | u8 status | u8 pad | i32 errno | u32 reserved`. Ops are `STAT`/`LIST`/`FETCH`/`DIRTY`; statuses `READY`/`ABSENT`/`REFUSED`, and the **errno is cc's** so the daemon never invents one. **The flags byte is OP-SCOPED** — each bit is meaningful for exactly one op, and naming which is part of the definition: `FOR_CREATE` 0x01 (FETCH), `FOR_WRITE` 0x02 (FETCH: take the claim; DIRTY: keep it), `REMOVED` 0x04 (DIRTY), `RELEASE_ONLY` 0x08 (DIRTY). They exist because cc cannot tell the worker's intent from its own cache management, so the intent is DECLARED. A frame cc cannot act on kills the CONNECTION — the stream is out of frame and every later byte would be misread.

  **THE ADDRESS IS NOT THE PATH.** `sockaddr_un` is `char sun_path[108]`, so bind(2)/connect(2) take 107 usable bytes — and the socket's real path grows with the store root, which would make a deep root a spawn-time `EINVAL` with nothing naming the limit. Both ends address the socket as **`/proc/self/fd/<dirfd>/control.sock`**, formed from a directory fd each opens on the socket's parent: `sunPathAddress(dirfd, name)` here, and `control_connect()` in `union.c`. The socket **file is unmoved**; only the address string is, from one that grows with the store root to one bounded at ~34 bytes.
  - **cc HOLDS its dirfd until after `server.close()` resolves**, then closes it — and also on the `listen` failure path, WITHOUT WHICH a refused spawn would leak one per attempt. (A spawn refused *after* a successful listen leaks nothing either: the fd is held by the `ControlServer` with the same lifetime as the socket file, and `teardown()` or the next `prepare()`'s `#control?.close()` reclaims both.) libuv unlinks the pipe by the name it bound with, and a closed fd number is reused immediately — closing first would point that unlink at a `control.sock` in whatever directory took the number. `close()`'s `fsp.rm` on the **real** path is the authoritative unlink.
  - **The daemon holds none — it opens one per connect.** `control_connect` runs lazily per FUSE worker thread and again after every framing error (`control_drop`), so a held fd would need a lifetime rule spanning the whole mount; it unlinks nothing, so the hazard above does not apply. It splits the path with `strrchr`, never `libgen`'s `dirname()`, which mutates its argument — and `CC_UNION_CONTROL` points into `environ`.
  - `O_RDONLY|O_DIRECTORY` on the node side: `fs.constants.O_PATH` is `undefined`, and this needs no magic number for an address-only fd.
  - **Containment is unchanged and `SO_PEERCRED` is deliberately not taken.** `/proc/self/fd` resolves in the *calling* process's own fd table, so the address names nothing a chrooted caller can reach; `<rundir>` keeps its `hide` pin and `route()` still answers `-ENOENT` for the socket's real path. A same-uid process in the chroot can already reach the socket through the bind-mounted `/proc/<ccpid>/root/…` — pre-existing — so authenticating this route would imply a boundary the `/proc` bind mount does not provide.
  - `FUSE_CONTROL_SOCK_PATH_TOO_LONG` survives **as a diagnostic on the formed address**, not on any path on disk. It cannot fire in production: `/proc/self/fd/` (14) + the fd's digits + the basename tops out around 34 bytes and the store root is not in it. Firing means cc chose an ~80-character basename — a cc defect, and the message says so instead of the old, now-false *"move the store root somewhere shorter"*.
  - **Per-open revalidate**, `#fresh`: `p → (source size, source ms-mtime, MIRROR INODE)`, recorded at every materialisation and compared before the next copy. Without it every open transfers the whole file — `#shape` alone skips re-truncating a stub whose size and ms-mtime match, but the copy after it runs regardless — which across a wire is the whole file, per open, for the life of the session. **The mirror inode is what makes it SOUND rather than merely fast**: source size and mtime alone would let cc skip a copy for a mirror entry it is no longer the author of (one re-shaped under it, or replaced by a rename) and serve whatever now sits there as fresh; the inode changes in every such case and in none of the safe ones. `bigint` inodes, because a Number comparison answers "same" for two different files above 2^53. **The order is the policy — `source.stat` → `#shape` → cap → freshness → copy**: `#shape` already leaves a matching file alone so the two agree, but freshness first would skip a `#shape` that a kind change needs. **A CLAIMED PATH REACHES NONE OF IT** — `#fetch`'s claim short-circuit precedes `#fetchBody` and therefore precedes every source call, the freshness check included, which is what keeps revalidate out of the two-handle window. What it rests on: millisecond mtime — the wire's `find -printf '%T@'` is seconds.nanoseconds on GNU, so no precision is lost at the source, and **a source whose `stat` collapses sub-second precision must be refused before this check is trusted**, which nothing in cc enforces today. A source file rewritten within one mtime tick **at an identical size** is missed — nanoseconds wide, named rather than defended against.
  - **The protocol cap, checked before the transfer is attempted.** A source file above `MAX_FILE_BYTES` (32 MiB) is refused `REFUSED`/**`EFBIG`** — a named errno, not the catch-all `EIO` — from the size the stat already carried. The saving is real rather than cosmetic: `readFileBytes` refuses over-cap too, but LATE, because `ProviderSystem.#read`'s fence counts what cc **keeps** — the provider streams `data` frames until cc's accumulation crosses the cap and only then does cc send `close`, so up to 32 MiB of base64 crosses the wire to be discarded. Whole-file materialisation is structural: the mirror must hold the whole file to serve arbitrary offsets, so the read frame's `offset` would buy nothing.
  - **The mode ledger**, `#mode`: `p → (the mode the SOURCE had when cc last looked, the MIRROR INODE that was carrying it)` — written by `#record`, in ONE CALL with the fingerprint. The two values are not one observation and the invariant does not claim they are — the mode is the **source's** (`st.mode`) and the inode is the **mirror entry's** (`cur.ino`); what holds is that they are recorded TOGETHER, so the pair can never be half-updated and the inode a mode is compared against is always the entry that was carrying that mode. **THE DISCRIMINATOR IS THE INODE, and it has to be.** An atomic write ends in a `rename`, which REPLACES the mirror entry, so the mode cc is about to push is the tmp file's fresh 0644 and the pre-edit 0755 is gone; a deliberate `chmod` KEEPS the inode, so the mirror's mode is the one the worker asked for and restoring anything would discard it. *"Always restore" breaks chmod; "never restore" breaks Edit.* On a `push`, `#restoreMode` chmods the MIRROR back to the recorded mode when the inode differs and does nothing when it matches. **cc chmods the mirror rather than passing a mode through `push`**: `RemoteSource.push` keeps one signature so both sources behave identically, the invariant `#shape` maintains (*the mirror entry's mode is the source's*) is restored rather than bypassed, and the property becomes observable on this machine. A path with no recorded mode is a file the worker created and pushes the mirror's own mode. `tests/fuse-transport.test.mjs` T11 drives both arms; `tests/fuse-union-routing.real.test.mjs` R10 drives the rename at the real mount.
  - **The fault record**, `#faults`: `p → Fault`, **sticky for the session's life**, and per-session like the mirror it describes. **CLEARED BY EXACTLY ONE THING:** a SUCCESSFUL push of the same path, which is the moment the diverged sentence becomes false. The reason for "cleared by nothing" — cc cannot resync without destroying the bytes the worker wrote — is true of every path except that one, where the bytes are the ones that LANDED. An `over-cap` fault is cleared by nothing at all. Two kinds, differing in what stays reachable:
    - `{kind:'diverged', detail, refuses:'writes'}` — set when a `push` fails. **THE CLAIM IS KEPT**, and that is the whole of what makes the criterion hold: cc stops managing the path as a cache, so the worker's unpushed bytes survive in the mirror rather than being re-shaped away by the next `STAT` or parent `LIST`. Reads still succeed and serve those bytes — the recovery channel the refusal points at — and writes are refused. **Recorded on the `push` branch ONLY**: the wording promises the local copy is intact and readable, which is true exactly there, so a failed `remove` and a claimed path whose mirror entry vanished under cc are released as before.
    - `{kind:'over-cap', size, cap, refuses:'all'}` — set where the cap is enforced, so a FILE TOOL can be refused by a sentence naming the cap before the worker ever opens the path. Refuses reads too, because cc never materialised the file and has nothing to serve.
    **THREE SPELLING RESIDUALS, named so the next reader does not re-derive them.** `#faults` keys the daemon's raw `req.path` while `#mirrorPath` normalises, so a fault and a tool lookup can disagree about one path in three ways: a tool input naming a **symlink** (the VFS resolves the leaf before FUSE sees it, so the control frame keys the resolved target while `faultAt` is asked about the link's spelling); a non-normalised absolute input (`..` segments); and the raw-vs-normalised key itself. **All three are exactly the exposure `classifyForTool` already carries** — it is a longest-prefix rule over the caller's own spelling and never resolves a path either — so the fault surface is never *weaker* than the tier gate, only equally literal. A miss costs a refusal not made, never a refusal wrongly made.
    `#fetch`'s fault gate runs **ahead of the claim short-circuit and of every source call**. Two accessors serve the hook — `faultAt(p)` (a plain map lookup, no probe) and `settle(p)` (await the path's in-flight frame, never rejects) — wired in `src/instances.ts` as **getters through the instance**, because the redirect is constructed before the `FuseSession` and a rewind hands the same redirect a new control server.
  - **`CCU_FLAG_RELEASE_ONLY` (0x08, DIRTY):** release the claim and reconcile nothing. `pt_release` sends it when `fd_dirty[fd]` is clear — a `flush` already landed the bytes, so the releasing frame has nothing left to carry. Without it **every written file uploaded twice**, once at `flush` and once at `release`, because the releasing frame is also a reconciling one. A DEDICATED BIT and not a flag combination: one bit, one meaning, one op. **`policy_abandon_claim` carries it too**, and that is the other reason it exists: an abandoned claim — a mutating op that took one and then failed before mutating — has cc's own unmodified cache copy in the mirror and nothing to reconcile, and a BARE frame is indistinguishable from `pt_release`'s frame for a handle that wrote and never flushed. Without the bit cc pushes that copy, and a failed push records a divergence for a file the worker never wrote and freezes the cache on it for the session (T13c). **The killed-process backstop is preserved by the condition itself** — a handle whose `flush` never ran, or whose `flush` refused, still has `fd_dirty` set and therefore sends a FULL reconcile, which is the whole of what is owed when there is no `close(2)` left to answer. cc answers a release-only frame before any source call and **does not clear a fault**, which is consistent in both directions: a diverged `flush` returned non-zero, so `fd_dirty` is still set and `release` sends a FULL reconcile — and that reconcile's own outcome decides. It fails again and the fault stands, or it lands and the fault is cleared, which is the only way a fault is ever cleared.
  - **`CCU_FLAG_MODE_SET` (0x10, DIRTY):** the worker CHMODDED the path, so the mirror entry's mode is its exact request. `pt_chmod`'s path arm sends it. It exists because a mirror DIRECTORY always carries cc's owner rwx (see the mode paragraph below), so the mirror's mode is not the worker's unless declared. `#dirty` pushes a directory's mode only on this bit or when the path's claim is `createdHere` (the worker's `mkdir`); any other directory DIRTY (a `utimens`) ensures the directory exists and sends no chmod. A directory's mtime never crosses.
  - **After a successful push cc re-stats the source and stamps the MIRROR entry with the mtime the source now carries** (`#adoptWriteMtime`). An atomic write gives the source a fresh mtime the fingerprint has never seen, so the next open would re-download the file the worker just wrote. One round trip on the write path, saving a whole download on the following read. The **mirror** is stamped and never the source: setting the source's mtime to the mirror's would misreport when the source changed, which build tools on that machine depend on. **AND IT IS GUARDED, because it is the only writer of a fingerprint that does not materialise the bytes it describes** — every other one stats the source BEFORE copying, so a source change during the copy leaves the fingerprint stale and the next FETCH conservatively re-copies; this one stats AFTER. The fingerprint is recorded only while the source's size still equals the mirror's, so a box-side writer landing in that window cannot have cc pair the mirror's bytes with another writer's `(size, mtime)` and then serve the worker its own stale bytes as the file's content. What a same-length race still costs is named above and is not defended against.
  - **WHAT THE TRANSPORT COSTS, and STATE THE CONFIGURATION, because a number whose configuration is unstated is a claim.** Re-measure the double reconcile's second upload with `node tests/fuse-transport-bench.mjs --case write-close --arm reference --sizes 64k,1m --runs 30 --release-only {on,off}` — the observed `writeFile` frame count per close sequence is **1 with the bit and 2 without**. Report the run count per size per arm alongside any figure taken from it. The bench's `docker` arm requires `--provider-argv` and `--remote` and has no defaults, so a figure from it names the remote it was taken against or it is not a figure.
  - **Two limits accepted by name, so neither is rediscovered as a bug.** (a) **Which syscalls the CLI's own `Write`/`Edit` emit at a project-tier path inside the union is UNMEASURED**, because `RUN_CLI_CONTRACT` has not been re-run against it. Mode preservation does not depend on the answer: it is inode-driven, so a rename replaces the mirror inode and the recorded mode is restored, while an in-place write keeps the inode and the mirror's mode is already the source's. The mechanism is proven by DRIVING the syscall sequence (T11), not by observing which one the CLI picks. (b) **The two-handle window stays deferred, and the premise is a STANDING CONDITION with a check** rather than an argument to re-derive — stated in full below.

    **THE TWO-HANDLE WINDOW.** `fd_claimed` is per-FD in the daemon while cc's claim is per-PATH, and `release` is the only releaser — so with two OVERLAPPING write handles on one path, the second handle's close releases the path's only claim while the first is still live. cc resumes cache management over a path with an open writable handle, and a `STAT` or a parent `LIST` can re-shape the mirror over the first handle's unpushed bytes, which its own `flush` then publishes.

    It is **unreachable while the marked population is the CLI alone**: it needs two overlapping write handles on one path, and the CLI's file tools are open→write→close sequential (Bash is proxied to the system by `bashForwarder`; an unmarked caller resolves in `VIEW_HOST`, which never names the remote tier). **That premise is what expires**, so it is a standing condition, not a closed question. It holds **on three legs, none of which is about the source**: (1) the marked population is unchanged by the transport — marking is driven by `CC_UNION_MARK_PATH`, a resolution of the CLI binary's own path, not by where bytes come from, and the transport is a `System` handle *inside cc*, not a caller of the mount; (2) `atomic: true` means the write target is a fresh tmp path, so a create-write-rename is two paths and not two handles on one; (3) per-open revalidate cannot reach a claimed path, because `#fetch`'s claim short-circuit precedes `#fetchBody` and therefore precedes every source call, the freshness check included (pinned by T10b in `tests/fuse-transport.test.mjs`).

    **WHAT EXPIRES IT:** a second *marked* writer — mark inheritance, which this design forecloses because cc's plumbing IS the worker's process subtree and no ancestry cut separates them, or a second marked binary — or a CLI file tool that opens a project path for write twice concurrently.

    **THE CHECK IS NARROWER THAN "no overlapping interval".** A `CC_FUSE_TRACE=1` capture of a real turn, counted offline by `tests/fuse-trace-count.mjs`, reports distinct marked TGIDs (leg 1) and write-opens per project-tier path — the latter only because `tr()` carries the frame intent, so `open` at `cflags & 0x02` is a write open. It **cannot measure an interval**: `tr()` records no timestamp and `release` is not traced, so a write-open's WINDOW is not in the capture. The overlap question is therefore answered structurally and only while the count allows it — if no path has more than one write-open in the capture, then no two write-opens of one path can overlap, whatever their windows were. A path with two or more is reported **by name and without a verdict**; that is the case a timing instrument has to settle, and inventing an ordering from this capture is the failure the intent field exists to prevent.

    **The fix, when the premise expires, needs no protocol delta**: the daemon knows `fd_claimed` per fd and can keep `FOR_WRITE` set on a `release` while another claimed fd for the path survives, sending the releasing bit-clear `DIRTY` only from the last one. cc cannot do it alone — the frame carries no handle id.

    **The consequence accepted deliberately:** two handles on one path share the mirror inode, so a second reader sees a writer's in-progress bytes. That is ordinary POSIX — a filesystem giving each handle a private snapshot would be the surprising one — and it is recorded, not fixed. It is also the boundary of what freshness buys: `#fetch` copies **unconditionally** — `#shape` may skip a file whose size and ms-floored mtime already match, but the copy after it always runs — so freshness *against the source* holds at every open, while isolation *within one session* does not, and a second `FETCH` would copy over unpushed bytes.

  **THE HANDLER TOUCHES THE MIRROR AND THE SOURCE ROOT, NEVER THE MOUNT**, which is what makes a daemon↔cc deadlock structurally impossible: a FUSE thread is blocked on the reply to the frame being served. `STAT` shapes a **sparse stub** (`truncate`d to the source's size, mode and mtime carried) so metadata is faithful and no bytes move; `LIST` shapes every child and removes the ones the source lost, so `readdir` shows no ghosts; `FETCH` always copies, with no revalidation shortcut.

  **MIRROR DIRECTORIES ARE WIDENED, MIRROR FILES ARE TRUE.** cc runs as a non-root uid and the source may be read-only (`/` and `/root` at 0555/0550, `.git` objects at 0444), so:
  - Every SHAPED mirror **directory** is `source | 0o700` (`widenDirMode` in `mirrorPerms.ts`), applied by `#shape` and again after every directory push, so cc can always write into it. An intermediate made by `mkdir -p` is `0777 & ~umask` — still owner-writable — until it is shaped. `#shape` never chmods a directory whose claim is held (it re-checks immediately before the chmod), so a worker's chmod is not overwritten before its `DIRTY`. The worker's local view of a directory's owner bits is therefore widened; that is accepted because a worker's Bash runs on the remote and sees true modes, and the CLI's file tools do not surface modes.
  - Every mirror **file** keeps the source's mode. A read-only one is never opened for write: `#shape` and `#fetchBody` stage the replacement in `<mirror>.refresh` (a cc-owned sibling of the mirror, `hide`-tiered inside the run dir) and `rename` it over the stub, so a reader on the old inode is undisturbed and no temp file shows in a listing. Writable files still refresh in place, keeping the inode the revalidate fingerprint is recorded against.
  - A directory's mode reaches the source only on declared intent (`CCU_FLAG_MODE_SET`, or a create claim); cc's added bits never do:

    | Worker op | Source before | Source after | Mirror after |
    |---|---|---|---|
    | `chmod 555 d` | 0755 | 0555 | 0755 |
    | `chmod 555 d` | 0555 | 0555 | 0755 |
    | `chmod 755 d` | 0555 | 0755 | 0755 |
    | `touch d` | 0555 | 0555 (no chmod sent) | 0755 |
    | `mkdir -m 555 d` | — | 0555 | 0755 |

  - `#unmirror` and `runTeardown` (so the boot sweep) use `removeOwnedTree`, which opens read-only directories below the target before retrying; `#unmirror` logs a removal it cannot perform (`could not unmirror`) instead of swallowing it. A worker-chmodded directory is writable again only after its DIRTY re-widens it, and in that window a child shape fails REFUSED EIO with a log line.
  - **User-visible consequence of widening:** the kernel no longer refuses a mutating op inside a remote-read-only directory. An `unlink` or create in a remote-0555 dir, as a non-root exec user, proceeds on the mirror and is refused at the reconcile (`DIRTY` → EIO); the entry reappears on the next `STAT`/`LIST`. Previously the kernel answered EACCES up front.
  - A read-only file's replacement is serialised per mirror path (`KeyedLock`, leaf-only) and the parent `LIST`'s stub swaps only if the file is unchanged since it was read, so a `FETCH` that holds the lock is not overwritten by a stub. It is not airtight: a `LIST` whose source listing raced a COMPLETED `FETCH` (the source changed during the copy, so the fetched bytes carry the pre-copy mtime) can still leave a sparse stub. The NEXT `FETCH` repairs it, not the next `STAT` — after the swap size and mtime match the source, so `STAT` early-returns. For read-only files that is newly silent: on `main` the same re-stub failed with EACCES.

  **`DIRTY` IS A RECONCILE, not a write-back**, and that generality is what lets the whole set of mutating ops land through ONE frame instead of a frame per op: it means *make the source entry at P match the MIRROR entry at P, whatever the mirror now holds there — including nothing*. The daemon mutates the mirror and then says the mirror is authoritative, and `mkdir`, `unlink`, `rmdir`, `symlink`, `chmod`, `truncate`, `utimens`, each end of a `rename`, and the ordinary write-then-`release` are all that one sentence. A file's mode and mtime cross because they are part of the entry being matched; a directory's mode crosses only on declared intent (`CCU_FLAG_MODE_SET` or a create claim) and its mtime never does. **A rename is therefore NOT source-side atomic**: it is a mirror rename followed by TWO INDEPENDENT reconciles, one per end, and a failure of the second leaves the source holding **neither** end — the old name already unlinked, the new one never created. A single `renameat2` on the source would be one syscall; this is not that, and the failure is reported rather than hidden. **ITS DOMAIN IS EXACTLY WHAT `RemoteStat` EXPRESSES** — file, dir, symlink, absent — and the three ops outside it (`mknod`, `link`, `chown`) are REFUSED by the daemon rather than applied to the mirror alone — `mknod` with `-EPERM`, a container refusing a device node being the permissions reading a caller already expects; `link` and `chown` with the shared `-EOPNOTSUPP` (`policy_unreconcilable`) — because a device node has no faithful mirror representation, a hard link is an alias where a reconcile copies, and the system's uid space is not the orchestrator's. **No project-tier mutation reports success having landed nowhere.** A failed reconcile fails the op; making that divergence *sticky* is the write path's own rule (below).

  Serialised per path — the PATH alone, with the op deliberately out of the key, so two frames naming one path never run concurrently. **That is all it does, and it is NOT protection for an open writable handle**: the worker writes through the mirror inode directly, cc sees no frame at all between the open's `FETCH` and the release's `DIRTY`, and there is therefore nothing at that path for the queue to order. Guarding that window is the claim record's job, not the queue's.
  **A FILE CREATED THROUGH THE UNION IS TRACKED UNTIL ITS PUSH.** It exists in the mirror from `create` and on the source only at `release`, and libfuse issues a `getattr` immediately after every create — so without that record the post-create stat answers `ABSENT`, the create fails, and `STAT`'s stale-entry removal deletes the file the worker just wrote. Found at the real gate (R3), pinned deterministically in `tests/fuse-control-channel.test.mjs`.
- `remoteSource.ts` — the one interface behind the handler (`stat`/`list`/`fetch`/`remove`/`push`), and `localDirSource`, **the deterministic source**. It proves the channel, the mirror discipline and the tier policy, and **no transport, no latency and no `System` call**. It is no longer production — `systemSource.ts` is — but it is KEPT, with three live jobs: the unit suite's source (`tests/fuse-control-channel.test.mjs`, no provider, no latency), the real lifecycle gate's (criteria 3 and 4 are only checkable when the remote's bytes DIFFER from the host's at the same path, and that gate must not need a container), and **the measurement control** the transport's cost is reported against. `CC_FUSE_SOURCE_OVERRIDE_ROOT` selects it and moves its root; `src/instances.ts` is the ONE reader of that variable and reports it on the session's own stream at every launch, because a session using it is not talking to its system at all.
- `mirrorPerms.ts` — cc's permissions on its own mirror tree under read-only source modes: `widenDirMode`, `removeOwnedTree`, and `replaceViaScratch` (the rename-from-scratch refresh of a read-only file).
- `systemSource.ts` — **the production source: `RemoteSource` over a real `System` handle**, and the only source that crosses a wire. **No root argument, and that is the whole point**: a path `P` from the daemon IS the path on the system, so there is no `root + P` arithmetic and no place for one to be wrong. `stat` is one `lstat`; `list` is ONE `readDir`, which is what the widened `SystemDirent` bought (a name-and-kind listing costs a round trip PER CHILD); `push` is `writeFileBytes(atomic, mode)` for a file — the `mode` is what makes it preserving — `mkdir` for a directory, plus `chmod` only when `push` is given a `dirMode`, `symlink` for a link, and it RETRIES ONCE via `removeEntry` on `EISDIR`, the one kind change a rename cannot land over. **Only `ENOENT` and `ENOTDIR` become `null`**: `remoteSource.ts`'s header records what conflating absence with unreachability costs — an EMFILE read as "absent" removed a live mirror entry and then, at the reconcile, a live SOURCE file. `ETRANSPORT`, `EACCES`, `ETIMEDOUT`, `EUNKNOWN` are each `{error}`, which the handler turns into REFUSED and no mutation.
- `preflight.ts` — `assertFuseAvailable`, criterion 9. The probes run in root-cause order (`/dev/fuse` → `sudo -n` → the bootstrap binaries → `fusectl` in `/proc/filesystems` → `gcc` + `pkg-config fuse3` → the binary compiles), each throwing `httpError(501, …, {code:'FUSE_UNAVAILABLE'})` naming the FIRST failure and the package that supplies it. **Assert, never install.** Probes are injected, so the refusal path is testable with each dependency stubbed absent.
- `build.ts` — `ensureUnionBinary()`: lazy `gcc` compile to `<store>/systems/fuse/bin/union-<sha256(union.c + policy.h + flags)>`, content-addressed (an edit to EITHER source rebuilds; a stale binary is impossible), single-flight under `withLock`, compiled to a temp name and renamed. A compile failure is the same `FUSE_UNAVAILABLE` refusal carrying gcc's stderr. **`policy.h` is in the address because it is a header** — nothing else observes an edit to it, so hashing `union.c` alone would leave a stale binary at a live address. `detectToolchain()` is the ONE detection: `ensureUnionBinary` builds through it and the C policy test skips through it, so that test cannot skip where the product would have compiled.
- `tierTable.ts` — **THE** tier/deny artifact, one table with **two consumers holding the same array**: `renderPinsFile` (the daemon's pins file) and `classifyForTool` (the hook's deny surface). They must be one artifact or they drift, and the mechanism is **identity, not equality** — `src/instances.ts` calls `buildTierTable` once and hands the same `TierEntry[]` to `SessionRedirect` and to `buildFusePlan`; neither builds its own.
  **Five kinds**, longest prefix wins at a component boundary (the same rule as `union.c`'s `tier_of`): `host` / `project` / `hide` / `fail` / `bind`. Each entry also carries **`toolAccess`** (`allow` for `project`, `deny` for everything else, except a `localRoots`-derived entry, which carries the bit its declaration gave it) and a **`why`** that renders into both the pins file's comments and the refusal a worker reads. A `localRoots`-derived entry also carries **`localRoot: true`** (set by `addLocal` and nothing else; `renderPinsFile` ignores it), which picks its refusal wording — see `host-pinned` below.
  Seeded from cc-owned facts: `localRoots` (read, not restated), the claude binary, its realpath and the realpath's install chain (`installPins` — the common ancestor where it clears the 3-component floor, otherwise the realpath's ancestor chain floored the same way; the **command** side is never chained, because it is walked before the mark fires), `process.execPath`, `selfProjectDir()`, `projectsRoot()` (one prefix covering the cc repo, the store and the plugin dirs), the whole `os.homedir()`, the `/etc` + TLS + loader/NSS/gconv set (`ETC_PINS` and `LOADER_OBJECTS`, `src/systems/fuse/tierTable.ts`), `hide` on the run dir and `project` on the project's real remote path.
  **`localRoots` is a DECLARATION, not a list**: `LocalRoot = {prefix, access, why}`, one construction site (`src/instances.ts`), and **the file-tool ALLOW set is that array, plus ONE hook-side `Read`-only exception for the session's own `tool-results/` dirs (`ownToolResultDirs`, below)** — there is no other list of allowed prefixes in cc. Every entry is host-pinned for the daemon whatever `access` says.
  **ONE hook-side exception, `Read` only:** `SessionRedirect.#classifyFile` allows `Read` of a path within the session's own `tool-results/` dirs — `SessionRedirectOptions.ownToolResultDirs`, wired in `_doCreateResolved` as `toolResultsDirPath(inst.transcriptPlace, b)` (`src/projects.ts`) for every `b` in `Instance._segments` — the session's live segments; after a restart `_segments` is rebuilt from the lineage row's live segments, so a dropped segment's dir is not included. That is where the CLI saves a tool result too large to show inline (`<remoteConfigDir>/projects/<encodeCwd(cwd)>/<backingId>/tool-results/`), under the config dir's `deny`. It cannot be a `LocalRoot`: the backing id is minted at launch and rotates on `/clear`, renew and prune (a rewind relaunches under the same segment), while the table is built once at create. Every live segment counts, because history carried across a rotation cites the older dirs. A subagent's oversized output lands in its **parent's** `<parentBackingId>/tool-results/` (flat, no `subagents/` dir), so it is covered. The exception overrides a `host-pinned` deny and nothing else (the tier gate runs first), matches by `withinPosix` (so `..` out of an own dir is not within), and never applies to `Write`/`Edit`/`NotebookEdit`. Other sessions' tool-results, the session's own transcript and `subagents/`, and the config dir's credentials and settings stay denied. The daemon's pins are unaffected: the path is already served from the host under the `remoteConfigDir` localRoot. Pinned by R1–R3 in `tests/systems-file-tool-refusals.test.mjs` and the wiring by `tests/systems-remote-worker.test.mjs`.

  **The per-remote CLI config farm needs NO tier-table entry — do not add one.** `<store>/claude-config/<dirName>/.claude/` is already covered, at its exact spelling, by `add('host', input.projectsRoot, …)`: `orchStoreRoot()` is `projectsRoot()/.code-conductor` by construction, so the store sits inside that one prefix. The farm's *entries* are symlinks into `$HOME`, which `add('host', input.homeDir, …)` pins whole and separately — the union follows a pinned symlink and the target has its own tier, the same property `realpathsOf(ETC_PINS)` relies on. What `localRoots` DOES contribute there is `access`, not reachability: the session's own `<cfg>/plans` is `allow` (the CLI resolves plan mode's `Write` to `<configDir>/plans`, so denying it breaks plan mode outright for every remote-backed worker), its own `<cfg>` is `deny`, and `claudeConfigFarmRoot()` is `deny` beneath both so longest-prefix lets a worker reach its own config dir while refusing every other remote's. Pinned by `A9b` (the cross-remote deny) and `A9c` (that both sides of every link carry a tier) in `tests/systems-file-tool-refusals.test.mjs`.
  **TWO MECHANISMS, NEVER MERGED, and both now reach the daemon.** `BIND_MOUNTS` (`/proc`, `/sys`, `/dev`) is a **separate constant** and renders as kind `bind`, because `bootstrap.sh` binds the orchestrator's own over those three paths and a `mount --bind` onto a target the daemon answers `-ENOENT` for kills the launch. A provider's `exclude` renders as kind `fail`, derived only from the advertisement, and **only for entries inside the mirror root** — one outside it is *inert* (criterion 4) and renders nothing, having already been reported on the session's stream. Where the two coincide (`/proc` excluded), first-occurrence-wins keeps `bind`; the tool is denied either way.
- `tierTable.ts` → `classifyForTool(entries, {exclude, mirrorRoot, systemId, systemPath}, p)` — the hook's half. Returns `allow`, or `deny` with one of **four classes** and its wording: `excluded` (`excludedRefusal`, `src/systems/mirror.ts`), `outside-mirror-root`, `bind-mount`, `host-pinned`. **It never touches the filesystem** — deciding by probing the mirror would deny the first read of every file in the project, since the union materialises a path when the CLI opens it. **All four name Bash**, and what differs is what each has to say about the answer Bash gives. `excluded` and `outside-mirror-root`: Bash reaches the path on the system under no such restriction. `bind-mount`: additionally whose KERNEL, since a file tool there would answer about the orchestrator's. `host-pinned`: additionally which MACHINE, because the same path exists on both — see the wording contract below for why that qualifier is load-bearing. A `host-pinned` deny from a `localRoot` entry takes `orchestratorOnlyRefusal` instead of `hostPinnedRefusal`: same class, no `cat` pointer, ends "do not retry this path through Bash". All four state that this is cc refusing to carry the file and **not** the file being absent.

  `tracePath` is `<rundir>/trace.log` when `CC_FUSE_TRACE=1` and `''` otherwise — the daemon's `CC_UNION_TRACE`, opt-in because `tr()` resolves ids per op and reads `/proc`.
  **The bootstrap must not set `CC_UNION_TRACE` EMPTY**: the daemon tests the pointer, and an empty string is non-NULL in C, so it would `fopen("")` and refuse to mount on every ordinary spawn.
  **`CC_UNION_MARK_PATH` carries the same hazard and closes it at the daemon instead**: an empty value passes the `if (!mark_path)` NULL test, and `mark_maybe`'s `strcmp` then matches no routed path, so the mount comes up and marks nobody — the silent host-only filesystem the presence refusal exists to prevent.
  `union.c` therefore also runs `policy_cwd_normalised(mark_path)` (the path the kernel hands the daemon is always absolute and normalised, so no other spelling could match anyway), and `InstanceManager._doCreateResolved` refuses `FUSE_LAUNCHER_UNRESOLVED` before that, where `CLAUDE_BIN` can be named.

  `CC_FUSE_TRACE` is cc's own flag, keyed exactly on `'1'`, and cc is its only reader; `CC_FUSE_TRACE_LOG` is the path `wrapLaunch` writes into the PLAN file, named only when the plan has one — an emitted `export CC_FUSE_TRACE_LOG=''` is inert under the bootstrap's non-emptiness test, but it is a value where the plan means an absence.
  **Two guards keep an operator's value out of that slot, and neither is the names being different**: `planVars` is composed from `plan` and `ctx` alone, so nothing in `spec.env` is an input to it, and the name is in `PLAN_KEYS`, so it is stripped out of the worker file, which bootstrap.sh sources LAST and which is `{...process.env}` as `instances.ts` built it.
  The precondition that would have to come back is a producer feeding that object from `spec.env`: an operator's `CC_FUSE_TRACE=0` — the natural way to turn a thing off — is in `spec.env` at every launch, and under one name it lands in the path slot, where the bootstrap's non-emptiness test reads it as ON and the daemon gets `CC_UNION_TRACE="0"`.
  The distinct names are cc's own reader contract, not that guard.
  The off path is byte-identical to before the trace existed **for an unset switch**; for any other value it is byte-identical only because both ends are keyed apart.
  `MOUNT_OPTS` fixes `attr_timeout=0,entry_timeout=0,negative_timeout=0` — zero kernel caching, because FUSE's attribute cache is per-inode and not per-caller.
- `wrap.ts` — `wrapLaunch`, **pure**: it returns a `{command,args,cwd,env}` spec AND the bytes of two files, and writes neither.

  **It does not survive a bootstrap run at all**: step 0's `EXIT` trap covers every `die` from step 1 to step 9, so a union that never mounts strands nothing either.
  What neither covers is an external SIGKILL, which runs no trap — `runTeardown`'s reclaim of `<rundir>` is what covers that.
  `#prepare` puts **every level cc creates on the way to the run directory** at `0700` (`fuseStoreChain` + the run directory), because `ensureUnionBinary` makes two of those levels on its own way to `bin/` and write access at ANY of them is write access to the environment files' directory NAME.
  Applied at the launcher seam (`RealClaudeLauncher.launch`'s `wrap` option); the in-process test launcher ignores it.
- `bootstrap.sh` — runs as root in the new namespace and **execs at every link**, so cc's three pipes pass through and the final pid is the CLI's. Ordered: **step 0** — verify the two environment files cc wrote AND the directory holding them (each a regular file / a directory, cc-owned, not group- or other-writable), capture `rm` absolutely, source the plan file (whose path arrives positionally with cc's uid), and arm an `EXIT` trap that unlinks the worker file →  re-assert preflight (including that cc's control socket exists) → scaffolding → the **namespace anchor** → start the daemon → wait on `/proc/self/mounts` (never `mountpoint -q`) → **capture the connection minor from `/proc/self/mountinfo` while the mount exists** → write `mount.json` atomically → `fusectl` at a private path (not `/sys/fs/fuse/connections`, which would hand the worker an abort surface against its own filesystem) → bind `/proc`, `/sys`, `/dev` OVER the union, onto the three `bind`-tier synthetic nodes → source the worker environment file and unlink it, HOST-SIDE and before the `exec chroot`, which is why it needs no spelling inside the root → `chroot`, `cd`, `setpriv`, exec.

  For the same reason **no command name is resolved against `PATH` after the source**: `rm` is captured absolutely at step 0 and stashed, so a caller-supplied `PATH` (cc's Backends settings put user pairs in that environment) cannot make the unlink an exit 127 with the mount and the handshake already made.
  Its chroot'd script **fires no marking event** — the mark is the CLI's own `execve`, and the `cd` is answered by the cwd chain (see the pre-mark window in [fuse-daemon.md](fuse-daemon.md#unionc--policyh)).

## What `fileBridge` carried, and where it has to land again

`src/systems/fileBridge.ts` is **deleted** in the FUSE-union geometry: the filesystem decides which bytes appear at a path, so there is no pull in `PreToolUse` and no push in `PostToolUse`. Two of its semantics were not incidental and are not reproduced by a passthrough mount: they are the specification the daemon's write path has to meet, recorded here because the file that held them is gone.

**Mode preservation.** The bridge remembered the system-side `st.mode` at pull time and passed it back on push (`fileBridge.ts` `#modes`). The reason is `atomic: true`: an atomic write ends in a `rename`, and a rename hands the replacement file *fresh* permissions — so an edited shell script silently loses its executable bit. Any write-back that renames must carry the original mode across, or re-`chmod` after it.

**A failed push is loud and sticky.** On a push failure the bridge marked the local path diverged (`#diverged`) and the layer above **refused every later write to that path** until a pull resynced it. The reason is that the local file then holds content the system does not, and the worker has no way to see that: without the sticky refusal the divergence surfaces as a wrong belief rather than as an error. A write-back that can fail needs the same property — a failed `release` must poison the path, not just log.

**The provider `exclude` list's per-path refusal lives in `mirror.ts`** — `isExcluded` and `excludedRefusal`, consumed by `classifyForTool` (`src/systems/fuse/tierTable.ts`) rather than by a local path map. The wording contract is recorded here IN FULL, because a subset of it is not a contract — every clause earns its place against one failure mode, *a model that mistakes a refusal for file-not-found concludes the file is absent instead of using the channel that works*:
- **`cc will not bridge`** — names cc as the actor and the act as a refusal. Never "cannot", which reads as inability.
- **the PREFIX, not just the path** — so the model generalises instead of retrying sibling by sibling.
- **`NOT the file being absent — cc has not looked`** — the anti-ENOENT clause, twice: a denial AND a positive statement of ignorance.
- **`Bash runs on … under no such restriction`, with `cat` / `sed -i` / `>`** — the channel that works, with concrete verbs for both directions, delivered at the point of use.
- **the negative rule:** the refusal never claims the file was absent. It has its own assertion rather than a comment, because no positive assertion can catch a rewording that keeps every clause above and inverts the meaning — and the assertion forbids the CLAIM'S WHOLE VOCABULARY (`found`/`find`/`finds`/`finding`, `does not exist` in both spellings, `no such file`, `missing`, `not there`), not one inflection: a round-1 review found the single-word form surviving its own documented killer, because `cc could not find` contains no `found`. `absent` and `exists` are deliberately NOT forbidden — the contract's own clauses use both.
- **`Bash runs on <system>`, and every one of the four wordings carries it.** The host pin is not an exception. A **dead end** there that never mentions Bash, on the reasoning that Bash cannot see the orchestrator's files either, is **withdrawn reasoning, not softened**: the dead end buys no concealment, because a worker reaches the system's `~/` through `ls ~/` whether the sentence mentions it or not, and it costs the agent its next move. The four classes and the failure mode each clause earns its place against:
  - **`excluded`** — the system advertises the prefix as excluded. Names the prefix and points at Bash. *Failure mode: the model reads the refusal as file-not-found and concludes the file is absent instead of using the channel that works.*
  - **`outside-mirror-root`** — outside the mirror root (advertised, or the project path when nothing was advertised — the wording says "advertises" either way; see [systems-protocol.md](../systems-protocol.md) §2 → `remoteDescriptors`). Names the root, points at Bash, and names **the project's own tree**, because a refusal that says only "not that one" costs a call to find out where the files are.
  - **`bind-mount`** — `/proc`, `/sys`, `/dev` are the orchestrator's own, bind-mounted so the CLI works. Points at Bash **and states whose kernel**. *Failure mode: a file tool there answers about the wrong machine, and the worker cannot tell.*
  - **`host-pinned`** — pinned to the orchestrator's machine so the local CLI can run. **Two wordings, one class**, chosen by `TierEntry.localRoot`: an OS or home pin takes `hostPinnedRefusal`, described here; a denied `localRoots` entry (cc's store, a config dir, another session's data) takes `orchestratorOnlyRefusal`, which keeps every clause below but drops the `cat '<p>'` pointer and the "right answer for a question about the system" clause, ending "do not retry this path through Bash" instead — such a path exists only on the orchestrator, so the system's copy is no answer at all. Pinned by R4 in `tests/systems-file-tool-refusals.test.mjs`. Points at Bash **and names the machine Bash answers from**. *Failure mode, and it is why the qualifier is load-bearing rather than decoration: the same path exists on both, so `cat ~/.claude/…` through Bash returns a real file that is the SYSTEM's, not cc's — and an unqualified "use Bash instead" would have the agent read it as the file cc just refused.* The wording therefore says which machine answers and that what it answers with is **not** the orchestrator's copy. Asserted in both directions by `tests/systems-file-tool-refusals.test.mjs` (A2b, A4) with the rule's own discrimination self-test, because a rule satisfied by the sentence it was added to forbid is worse than none.
- **the enumeration `Read, Write and Edit` inside the sentence is HISTORICAL, and must not be "completed".** It predates `NotebookEdit` being in the set, and the sentence is a **byte-for-byte** restoration whose verbatim-ness is itself a verified acceptance property — adding a word voids that claim for no gain. Tool coverage is guaranteed structurally instead, by `FILE_TOOLS` enumeration: `classifyForTool` is reached for every key of that map, and `tests/systems-file-tool-refusals.test.mjs` (A3) loops the exported map rather than transcribing it, so a fifth file tool is covered the moment it is declared.

`MirrorScope.exclude` is still live besides — `resolveMirrorScope` refuses `MIRROR_EXCLUDE_COVERS_PROJECT`, and the list is pinned per session and compared on relaunch. Containment is decided with `path.relative`, never a string prefix: a prefix test claims a merely prefix-*sharing* sibling (`/app-backup` under `/app`) is inside.

Two more of its rules existed because every file op carried a whole file over a control channel: the 1 MiB whole-file cap (`SESSION_FILE_CAP_BYTES`) and the refusal of binary files. **The MOUNT reads and writes ranges; the TRANSPORT does not** — claiming the distinction away is false of the transport. `readFile`/`writeFile` are whole-file frames, cc never sends the frame's `offset`, and the mirror must hold the whole file to serve arbitrary offsets, so the frame's `offset` would buy nothing. What each rule became:

- **the binary refusal is genuinely retired.** `writeFileBytes` (`src/systems/system.ts`) carries bytes end to end; `writeFile(path, data: string)` mangles binary and is no longer on the reconcile path. `tests/fuse-transport.test.mjs` T5/T6 round-trip a NUL and a 0xFF in both directions.
- **a size limit survives, at `MAX_FILE_BYTES`** (`src/systems/protocol.ts`, 32 MiB). `ControlServer.#fetchBody` refuses **before a byte moves** — the size is already in hand from the stat — with `EFBIG`, and records an `over-cap` fault so the FILE TOOL is refused by a sentence that names the cap and points at a range read through Bash (`overCapRefusal`, `src/systems/fuse/faultRefusals.ts`). Checked-before, not checked-after: `readFileBytes` also refuses `EFBIG`, but only after up to 32 MiB of base64 has crossed to be discarded, so `tests/fuse-transport.test.mjs` T7b asserts the **frame count** rather than the failure.

**Divergence and over-cap are a separate STATEFUL surface, consulted AFTER the tier gate** — so a reader counts **four** tier wordings above and not six. They live in `src/systems/fuse/faultRefusals.ts`, carry no `ToolDenyClass`, and `SessionRedirect.#classifyFile` asks them only once `classifyForTool` has already returned `allow`. The ordering is a ruling, not a style choice: the tier gate is the subsystem's most important property, and a surface consulted ahead of it is a bypass route by construction whatever it returns today. It costs nothing, because a fault can only exist for a path written through the union, which is project tier, which the gate allows. Pinned two-directionally by `tests/systems-file-tool-refusals.test.mjs` T23/T24.

## FUSE teardown

One implementation — `runTeardown` in `src/systems/fuse/session.ts` — reached from four places: `Instance.kill()` (the commanded path, which **awaits** it), `Instance._handleExit()` (the crash path, fire-and-forget beside `_redirect.close()`), and `sweepFuseSessions()` at boot. `bootstrap.sh` owns none of it: it `exec`s into the CLI and ceases to exist as a supervisor, and a shell trap cannot survive `SIGKILL`.

Ordered, every step bounded, every failure branch continuing rather than stopping:

| # | step | on failure |
|---|---|---|
| 0 | Read `mount.json`; fall back to `intent.json`. **Re-verify every recorded pid** against `/proc/<pid>/stat` field 22. | mismatch ⇒ that pid is treated as **gone** and never signalled (pid reuse); no record at all ⇒ `NO-RECORD`, nothing signalled |
| 1 | Stop the worker: `stdin.end()`, `SIGTERM`, `SIGKILL`, polling to a deadline. Unprivileged — `setpriv` dropped the CLI back to cc's uid. | still alive ⇒ **continue anyway**. A worker wedged in `D` on the mount cannot be signalled until the connection is aborted; the abort is the universal solvent |
| 2 | Unmount **deepest-first**, from `/proc/<nsPid>/mounts` (never `mountpoint -q`), via `nsenter` as root, `umount -l` on failure. Two mounts are **held back** for step 3: **`fusectl`**, which the abort is written through, and the **union root** (`record.root`), whose attachment on the recorded minor is the only proof that minor is still this session's. | no live recorded pid ⇒ the namespace is gone and its mounts with it |
| 3 | Abort the FUSE connection **by the minor captured at mount time**, never one re-resolved from mountinfo, and **only while the union root is attached in the namespace on that minor** — `MountDriver.abortOwnConnection` checks `/proc/self/mountinfo` in the same root shell as the write (`ABORT_OWN_CONNECTION_SH`, `src/systems/fuse/driver.ts`). **Then unmount the held-back root**, plain then `umount -l`, if it is still in the namespace's table. | checked in this order: root not attached on the minor ⇒ `not-mounted`, nothing aborted — **first**, so a root both detached and unlisted is `not-mounted`, never `ABORT-UNAVAILABLE`; no fusectl entry ⇒ `ABORT-UNAVAILABLE`; write refused, or the command never reached an exit (sudo refusal, timeout) ⇒ `abort-failed`; each recorded, continue |
| 4 | `SIGTERM` then `SIGKILL` the daemon, **privileged** (it is root-owned and is not cc's child), each re-verified by starttime. | — |
| 5 | Bounded poll of `/proc/<daemonPid>/task`. Terminal states: `GONE` \| `ZOMBIE-ORPHAN` \| `NO-PID` \| `WEDGED(threads=n states=…)`. Then unmount the held-back `fusectl`. | `WEDGED` ⇒ **reported, never blocked on** |
| 6 | `SIGKILL` the **namespace anchor**, last. | survives ⇒ noted; the namespace stays open |
| 7 | **Confirm death positively**, and take the verdict from **namespace membership**: enumerate `/proc` (`procScan.ts`), re-verify the worker, the daemon **and** the anchor against their recorded starttimes, and read mounts from every vantage point — cc's own, `/proc/1/mounts`, any live recorded pid, and any member the record never named. | any survivor, any member, any residue, **or a scan that could not run** ⇒ the wedge branch |
| 8 | Re-read `mount.json` **immediately before** the irreversible step, then `rm -rf` the run directory. | on a wedge, **keep** it and rewrite `mount.json` with `{wedged, terminalState, residualMounts, survivingPids, at}` |

**A FUSECTL LISTING IS NEVER PROOF OF OWNERSHIP; AN ATTACHED ROOT ON THE RECORDED MINOR IS.** fusectl is one global superblock and lists every FUSE connection on the host. Unmounting the union root destroys the session's superblock — which aborts its connection and removes its fusectl entry — and frees its anon minor, which the kernel allocates lowest-free, so the next FUSE mount anywhere (typically another session's bootstrap) gets the same number. An abort issued after the root's unmount therefore kills that session: its bootstrap dies at the `/proc` or `/sys` bind (`move_mount() … ENOTCONN`, code 78) or at `chroot` (`Transport endpoint is not connected`, code 125), or its CLI dies later (`SIGBUS`). The abort goes **before** the root's unmount, not after it with a skip, so it stays the solvent for a busy root that only `umount -l` detaches; the aborted daemon sees `POLLERR` on its device and skips its own unmount, and step 4 stops it as before.

**THE CLEAN VERDICT COMES FROM NAMESPACE MEMBERSHIP, NOT FROM THE RECORDED PID SET.** The recorded set is what the bootstrap wrote down; the namespace is what is actually there, and the two differ in the ordinary case — Bash is a real subprocess family and there is deliberately no process-group kill on this path, so a live worker child holds mounts open while naming nothing cc recorded. **Anything cc cannot enumerate is a wedge, not a pass**: a scan that could not run yields `ok: false`, and an empty result read as "nothing is there" is exactly how a leak stays invisible. Three separate defects on this ticket were this one flaw in different clothes — a leaked anchor whose record had been deleted, an intent-only teardown that signalled nobody, and an unrecorded namespace member holding mounts.

**THE RECORD IS THE LAST THING DESTROYED, AND ONLY AFTER A POSITIVE DEATH CHECK — never after merely having issued a signal.** Both teardown and the boot sweep iterate *records*, so a record deleted while a process it names is alive makes that process permanently unreclaimable by name. This was a measured leak, not a hypothetical: a root `sleep infinity` anchor holding a live private mount namespace, orphaned to pid 1, with its run directory already removed. **Neither half of the obvious leak check could see it** — its namespace is private, so it can never appear in `/proc/1/mounts`, and its record was gone, so it was in no recorded set to re-verify. The two repairs are paired: `bootstrap.sh` writes the record *before* anything it starts (so an intent-only run directory provably has nothing behind it, which is what makes deleting one safe), and step 7 refuses to destroy a record whose pids are not confirmed dead.

**An intent-only run directory (no `mount.json`) is NOT presumed empty.** It means the bootstrap died after starting something, or is still mid-handshake — reachable in production every time `_awaitFuseMount` times out and tears the launch down. That path runs the marker scan scoped to its own run directory, unmounts through and kills what it finds (**including the bootstrap itself**, which is what stops a mid-handshake write rather than racing it), and re-reads `mount.json` afterwards: a record that appeared during teardown is never deleted over.

**A schema-violating record is a reported wedge, never a mid-machine throw.** `fusectl` must equal `path.join(rundir, 'fusectl')` and `root` must equal `path.join(rundir, 'root')`, by exact match, and `minor` must be `/^\d+$/`, because all three reach a root-executed command line. A violating `root` also means no abort is attempted — ownership would be checked against a path cc never mounted. This is about robustness rather than a threat model — the chroot is not a security boundary here. What is closed is the no-adversary variant: a malformed field makes `execFile` throw mid-machine, `runTeardown` rejects, both callers swallow the rejection (`kill()` catches, `_handleExit` uses `void`), and the daemon, the mounts and the record all survive with **no wedge report at all**. The whole machine is additionally wrapped so any unexpected throw becomes the loudest verdict it has.

**`prepare()` releases the teardown latch and refuses a wedged directory.** Rewind and prune both kill the subprocess and call `launch()` again on the same `Instance`, so a session's lifecycle repeats in the same run directory. A latch that never reset made the *second* `kill()` a silent no-op — no unmounts, no abort, no signals, a root daemon and a private mount surviving until restart, and a `null` return the caller could not distinguish from idempotent-done. `teardown()` now returns `{ alreadyTornDown: true }` for that case, and `prepare()` throws `FUSE_PREVIOUS_TEARDOWN_WEDGED` rather than mounting a second session over the handle to a wedged first one.

**`prepare()` also refuses a run directory another instance owns: `FUSE_RUN_DIR_FOREIGN`.** `mkdir(root, {recursive:true})` adopts a pre-existing directory silently, so two instances mapped to one name would share a control socket, a mirror and a record set — and the `rm(recordPath)` two lines later would destroy the *live* session's mount record. The predicate is **ownership, not existence**: it compares `intent.json`'s `instanceId` to the plan's, because the relaunch above is ordinary and lands in the same directory with the same id, so a bare `EEXIST` refusal would break it. The whole uuid in the directory name already makes a collision impossible; this turns any future change to that shape from a silently shared socket into a named refusal.

### The `/proc` enumeration and the record-independent backstop (`procScan.ts`, `orphans.ts`)

Two identities, both **carried by the process**, neither a name or a pattern: `/proc/<pid>/ns/mnt` compared against the recorded `nsMntId` (membership by definition — it sees processes no record names), and `CC_FUSE_INSTANCE_ID` / `CC_FUSE_RUNDIR` in `/proc/<pid>/environ`, put there by `execve` before the bootstrap forked anything (the only handle left when a record is gone or was never written). **Never** comm, cmdline, or any pattern: `sleep infinity` is about as generic a needle as exists on a Linux box, and a pattern match here is the mechanism that once killed this devcontainer.

**Two uid passes, unioned by pid.** Both files are `ptrace_may_access`-governed, which without `CAP_SYS_PTRACE` grants access only on a uid match — so cc as itself sees the worker and its children (uid 1000), cc through `sudo` sees the bootstrap and the anchor (uid 0), and neither sees the other's. `ok` is true only if **both** passes ran: a missing half is a blind spot, and a blind spot is not an empty result.

**`ok` means "this pass enumerated", not "the command exited 0"** — the canary. On a host missing `awk`, `sed` or `tr` every row is skipped by the scanner's own `[ -n "$st" ] || continue` guard, the shell still exits 0, and zero rows would read as an empty namespace with everything in it alive. The scanning shell is itself a process in `/proc`, so it prints its own pid and a pass that cannot find that pid among its rows is not `ok`. `passEnumerated` owns this.

**The intent-only path keeps its own scan rows.** It re-verifies each by a fresh liveness check and carries the survivors into the verdict as members, rather than trusting `reclaimProcess`'s return value — a marker process that survived its `SIGKILL` (`killed: false`, the shape of a bootstrap wedged in `D` inside a hung mount syscall, which `SIGKILL` cannot touch) is a live namespace member and therefore a wedge. `markerReclaimed.some(r => !r.killed)` is a second disjunct behind it.

It fails closed at every step: an unreadable field, a missing `starttime`, `pid <= 1`, a `rundir` outside this store's run root, or a starttime that moved since the scan all mean *not ours, not signalled*. A run directory that still holds a `mount.json` is left to the record pass rather than raced with it. Ordering within a reclaim: unmount through the process first (it is the handle), then re-verify, then signal — privileged, because an orphan may be the root-owned anchor or bootstrap and an unprivileged signal at one is `EPERM`, which reads as "already gone".

**What it cannot see, stated so the guarantee is not overstated.** A process that has changed credentials *and has not exec'd since* is invisible to both passes — which is exactly the union daemon (`setfsuid` per request). The worker is visible: `execve` resets dumpability, so after `setpriv` it is an ordinary uid-1000 process. The **anchor** is visible because it is credential-stable, and that is what matters: it is the last process holding the namespace open, and freeing its mounts closes the `/dev/fuse` connection, which is what makes the daemon exit. The record remains the only handle on the daemon's pid — which is why the ordering guarantee, not this module, is the repair.

**`wait(2)` is never called**, and that is not a preference: it blocks on the whole thread group, a thread stuck in FUSE I/O never leaves the kernel, and an orphan reparented to pid 1 cannot be waited on at all (`ECHILD`). cc is never the daemon's parent in any case, so `REAPED` is not a state it can produce — a single-threaded zombie is `ZOMBIE-ORPHAN`.

**The wedge branch is a reportable state, not a silent one:** a `system`/`stderr` event on the session's stream (what an operator watching the session is already looking at), a `console.warn` (which survives the session's death and lands in the orchestrator log), and the kept record (so the next boot sweep **re-reports** it rather than silently rediscovering it).

**`fusectl` entries with no record of ours are counted and never aborted.** Stale minors free nothing, survive abort and are inert: a count of fusectl entries is not a count of live daemons.

### The namespace anchor

cc reaches a session's mount namespace with `nsenter --mount=/proc/<pid>/ns/mnt`, and that open is governed by `ptrace_may_access`. Where `/proc/sys/fs/suid_dumpable` is `2` and `CAP_SYS_PTRACE` is **not in the container's bounding set** — the shape this runs in, and one in which not even uid 0 has it — a process that has changed credentials is non-dumpable and needs that capability; a process that has not is reachable by a caller of the same uid. The daemon calls `setfsuid` per request and the worker is `setpriv`'d, so **both become unreachable within milliseconds of the mount coming up** — measured: the first `nsenter` after the handshake succeeds and every later one fails `cannot open /proc/<pid>/ns/mnt: Permission denied`.

The anchor (`bootstrap.sh` step 2b) is a credential-stable root process (`setsid sleep infinity`) whose `ns/mnt` therefore stays openable by root for the life of the namespace. It is a **handle, not a supervisor**: it holds no state, watches nothing and cannot restart anything. `pickNsPid` prefers it, falling back to the daemon and then the worker for hosts where `CAP_SYS_PTRACE` **is** available. Teardown kills it last, which is a second and independent guarantee behind step 2 — a namespace whose last process has gone takes every mount in it with it. Its cost: after a hard orchestrator crash the namespace and its (private, `/proc/1/mounts`-invisible) mounts persist until the boot sweep, instead of evaporating.

### The boot sweep

`sweepFuseSessions()` runs from `server.ts` immediately after `sweepSessionTmpDirs`, before `createServer()`, and is licensed by the same argument: an instance id is a fresh uuid per process, so any record under `systems/fuse/run/` at boot is dead by construction. It is **load-bearing, not defence in depth** — nothing about a running process is persisted anywhere else in cc, `shutdownForResumeSync` (the end of every restart and shutdown) cannot run the (async) mount teardown at all, and a killed or crashed cc runs none. `shutdownForResumeSync` signals the **recorded inner pid** (`killablePid`) rather than `inst.pid`, which under the wrap is `sudo`'s and cannot forward `SIGKILL`. The running record's `clis` leave FUSE-wrapped sessions out for this reason: this sweep is what verifies and kills their pids, immediately before the orphan-CLI reap (`src/runningRecord.ts`). Best-effort throughout: a directory cc cannot reclaim must never stop a boot.

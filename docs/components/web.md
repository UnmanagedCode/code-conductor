# Components: project instructions, MCP, the web build and the web UI

Project CLAUDE.md regeneration, the WebSocket hub, usage and cost, the MCP server, the web build, and the web UI layout.

## `src/projectClaudeMd.ts`

regenerator of **every** project's in-tree `CONVENTIONS.md` (imported by its `CLAUDE.md` via `@CONVENTIONS.md`). The file carries **both** convention scopes, in this order: line-1 marker, blank line, the composed **workspace** conventions (`composeCurrentWorkspace()`, unconditional — the installation-wide selection, which deliberately does not travel with the project), then, only when there is something to put there, an H1 `# Project conventions` separator (`PROJECT_HEADING`; workspace sections are H2s under an H1, so without it project fragments would read as workspace ones) followed by the note and/or the project bodies. The **project** selection travels with the project: line 1 is a marker (built/parsed by `buildMarker`/`parseMarker`) so any cc instance regenerates that part from the file alone (survives move/rename/import into a store with no record of it, and does not require the project to sit under the projects root). The selection is tri-state, `ProjectConventionSelection`:

| State | Marker | Meaning |
|---|---|---|
| `{mode:'unset'}` | `<!-- cc:conventions -->`, a non-marker line 1, or no file | never chosen; the sidebar flags it |
| `{mode:'none'}` | `<!-- cc:conventions :none -->` (inner exactly `NONE_TOKEN`) | chosen to have no project conventions; not flagged |
| `{mode:'selected', slugs}` | `<!-- cc:conventions a,b -->` | these slugs, marker order, verbatim (may repeat) |

`NONE_TOKEN` can never be a slug: built-in and custom slugs are `SLUG_RE` (`src/identifiers.ts`) and a plugin's is `<plugin-id>/<slug>` of two of them, none starting with `:`.
Parsing is exact: a hand-edited `:none,foo` is `selected` with an unresolvable `:none` slug.
`slugsOf(sel)` is a selection's slugs (`[]` for unset and none); `slugSelection(slugs)` maps a list to a selection (`[]` → unset, never none).
Request input is narrowed in this file too, for both surfaces: `selectionInput` (the PUT's `selection` and `expected`) and `creationSelection` (`POST /api/projects` and `create_project`: `noProjectConventions: true` → none; omitted or `conventions: []` → unset; both together → 400 `CONVENTIONS_NONE_WITH_SLUGS`).
No migration exists for the states: a zero-slug marker stays unset, since whether it meant none cannot be recovered.
An older cc reading a none marker parses it as the one slug `:none`, rebuilds the marker byte-identically (so the choice survives), shows it as unavailable, and — on a degraded catalog — freezes the file, as it does for any unresolvable slug.
`composeProjectConventionsDoc(selection, missing?)` composes the whole document (its sibling `composeProjectConventionsDocWithMeta` returns `{text, degraded}` off the same catalog read, for the create path that warns on a degrade; the regeneration path below deliberately takes the plain form and stays silent, since it reaches this composition once per project per sweep); a visible in-body note (`` > Convention unavailable: `slug`[, `slug`…]. `` — `unresolvedNote`) names any `missing` slug in place of its body.
Unset or none ⇒ marker + workspace text and nothing else (no heading, no note).
`ensureProjectConventionsMd(name,{log})` reads the target (**ENOENT is not a skip** — it means unset, same as a non-marker line 1 and a zero-slug marker; all three, and none, regenerate with an empty project part and the old body discarded), fetches the catalog (`getCatalog()`, returning a `CatalogList` — see `fragmentCatalog.ts`) and resolves each marker slug against it: **resolvable slugs recompose normally**; an **unresolvable** slug (custom convention absent here, disabled/absent plugin, retired seed) **stays in the marker** — so it recovers verbatim if it resolves again — but is named in the note instead of contributing a body.
It also calls `ensureConventionsImport(proj.path)` (`src/conventionsImport.ts`, shared with `src/conduct.ts`) on every non-declining run, so a project whose `CLAUDE.md` never had the import gains it — a `CONVENTIONS.md` nothing imports delivers nothing.
The write is **declined, leaving the committed file untouched**, in exactly **one** case: ≥1 slug is unresolvable AND the catalog is `degraded` (its `extraProvider` threw outright, a plugin's own **placement** resolution transiently failed, or the last **discovery scan** could not resolve a project an enabled plugin lives in, so its manifest was never read and the plugin is absent from the catalog entirely — that third source is latched to the scan and stands until the next Rescan (or until the affected plugin is disabled), and it is a deliberate **superset** of the second: with the manifest unread, an enabled record is the only term left to flag on, so it flags even for a plugin that would have turned out to contribute no conventions at all (the compose-vs-scan split is tabulated in [plugins.md](../plugins.md) → *Discovery rules*) — any of the three being indistinguishable from "genuinely gone", so declining avoids mistaking a hiccup for a removal and stripping real text; a plugin whose project cc no longer has any record of is NOT this case — that absence is confirmed, so those projects regenerate — see [plugins.md](../plugins.md) → *Discovery rules* for the full split) → `{skipped:'catalog-degraded', missing}`.
That freeze is **whole-file**, so the workspace region stays stale for that cycle too — bounded, for the first two sources, by the transience of the degradation, and for the scan-sourced one by the Rescan (or plugin disable) that ends it rather than by any transience; logged either way.
The condition is unreachable for an unset or none project (`missing` is empty, so none is never frozen), and the **workspace** catalog carries no `extraProvider` at all (`src/workspaceConventions.ts`), so degradation can never leave a project with no conventions file.
There is no `unresolvable` or `no-body` decline: both were permanent conditions whose only purpose was protecting committed text, and freezing them would permanently starve that project of workspace-convention updates.
**No sentinel/backup/hand-edit detection**: the file is cc-owned and overwritten, whatever is in it; recovery for a hand-authored body is git (a project is a repo from birth when git could make one, and the file is tracked there).
Line 1 is read without its `\r` and a rewrite keeps the existing file's line ending (a new file is LF), via `src/lineEndings.ts` (`firstLine`, `eolOf`, `withEol`), so a CRLF checkout (Git for Windows `core.autocrlf=true`) keeps its selection and is never mixed-EOL; the same applies to the `CLAUDE.md` import line.
Because only line 1 is ever parsed — the previous body (note included) is discarded wholesale before recomposition — the document is a **pure function of (marker selection, workspace selection, project catalog)**: repeated regeneration is byte-identical, neither the note nor the workspace block can accumulate, and the note vanishes cleanly (real text back, byte-identical) the moment the slug resolves again.
**`ensureProjectConventionsMd` itself** (not the fan-out below) emits the three per-project log lines: `"CONVENTIONS.md left as-is for '<project>': catalog degraded, unresolvable <slugs>"` (catalog-degraded), `"CONVENTIONS.md regenerated without unresolvable <slugs>: <path>"` (partial resolution), and `"CONVENTIONS.md regenerated: <path>"` (full resolution).
**Boot ordering is a real constraint on this one call, and its violation is silent.**
`regenerateAllProjectConventions` composes the PROJECT catalog — the one carrying an `extraProvider` — so it must run *after* `createServer()` has wired `setPluginConventionsProvider`.
Unwired, that provider is a no-op stub returning `[]`, every plugin-namespaced slug lands in `missing` and is filtered out *before* compose, and each project's committed `CONVENTIONS.md` is rewritten with the plugin's real text replaced by the `> Convention unavailable:` note.
Nothing throws and the boot log is clean.
Pinned by `tests/boot-plugin-conventions-order.test.mjs` (a subprocess boot of the real `server.ts` — the only shape that can fail when the statement order moves).
Only the **project** part is at risk: the workspace block in the same document composes from the workspace catalog, which passes no `extraProvider` at all.
`regenerateAllProjectConventions({log})` fans out over `listProjects()` (per-project try/catch) and owns exactly one line of its own — the only one signalling an actual fault rather than a designed decline — on a per-project exception: `"CONVENTIONS.md regenerate failed for '<project>': <message>"`.
Called on boot (`server.ts`, non-fatal, after `ensureConductProject`) and after every Settings → Conventions → **Workspace** *and* → **Project** mutation (`src/routes.ts`, all seven routes passing `{log:console}`).
**One writer, three entry points.**
`ensureProjectConventionsMd` (keep the marker's selection), the edit `setProjectConventions(name, selection, expected, {log})` (replace it) and every caller of either share one internal writer that takes a `choose(current, catalog)` callback; `readProjectSelection(system, projPath)` is the one reader of a file's selection (ENOENT → unset, any other error rethrown), shared with the `GET /api/projects` `conventions` field.
**Writes to one project are serialized** in-process (`withProjectLock`, a per-name promise chain), so a sweep that read the old marker cannot land after an edit and write it back.
The edit refuses before writing: `expected` ≠ the current selection (`sameSelection`: modes differ, or `selected` slugs differ in content or order) → 409; a slug in neither the catalog nor the current marker → 400 (a slug the catalog lacks is kept, never introduced); and the **freeze rule applies to it** — a kept unresolvable slug on a degraded catalog → 503 `CONVENTIONS_CATALOG_DEGRADED`, file untouched (unset and none keep no slug, so never 503).
A missing project is 404.
Every landed write calls `markProjectsChanged()` (the listing reports the selection), and `regenerateAllProjectConventions` runs inside `projectsOperation`, so a sweep sends one `projects` hint.
Tests: `tests/project-conventions-edit.test.mjs` (the edit, the listing field, the serialization), `tests/projects-changed.test.mjs` (one hint per edit and per sweep).

## `src/conventionsCheckout.ts`

`pullPastGeneratedConventions({system, dir, project, note, run})`: gets a `git pull --ff-only` (`run`, which throws on failure) past cc's own regenerated files in a registered project's checkout. A `CONVENTIONS.md` whose line 1 differs from the marker HEAD's copy derives is the user's change — a hand edit or an uncommitted **Edit conventions…** save — and is never discarded. Callers: `update()` in `src/plugins/library.ts`, `applySelfUpdate` in `src/selfUpdate.ts`. The proof is equal **modulo line endings** (`src/lineEndings.ts`): a CRLF working-tree copy of an LF blob is still cc's output.
- `project: null` → `run()` untouched. `applySelfUpdate` passes `null` unless `findSelfProject` names a project on the `local` system. Can't classify — `git status` non-zero, any classification I/O throwing (a dangling-symlink candidate, `EACCES`, a provider read error; `console.warn`ed), or an operation in progress (`MERGE_HEAD`/`CHERRY_PICK_HEAD`/`REVERT_HEAD` resolve, or `rebase-merge`/`rebase-apply` exists under `git rev-parse --git-path`) → `run()` untouched.
- Candidates: `git status --porcelain=v1 -z --untracked-files=all` entries ` M` or `??` whose path is `CLAUDE.md`/`CONVENTIONS.md` at the checkout root (`??` only when HEAD has no such path). Generated iff — `CLAUDE.md`: equal modulo line endings to `withConventionsImport(HEAD blob or null)` (and that is non-null); `CONVENTIONS.md`: line 1 (without its `\r`) `=== buildMarker(selectionOf(HEAD blob or null))` (body ignored — app-owned; line 1 is the project's selection, which nothing rewrites after creation). Every other entry (staged, deleted, renamed — source and destination both, unmerged, a failed predicate, any other path, a nested `sub/CLAUDE.md`) is **other dirt**, never touched; named once per path.
- Generated ones: `git checkout HEAD --` (tracked) / `git clean -fq --` (untracked) → `run()` → `ensureProjectConventionsMd(project)` on **success and on failure**. Deterministic inputs ⇒ a failed pull leaves the files byte-identical to before.
- Errors: the pull's error keeps its status + `tail`; its message gains `; local changes cc did not generate: <paths>` (and `; regenerating CONVENTIONS.md failed: …` on the failure path). A regeneration throw after a successful pull is a `console.warn` + note, never an error.
- `note` lines: `[discarded cc-generated <paths> before pull]`, `[regenerated CONVENTIONS.md]`, `[CONVENTIONS.md left as upstream: catalog degraded]`, `[CONVENTIONS.md not regenerated: project not found]`, `[regenerating CONVENTIONS.md failed: …]`.

## `src/conventionsImport.ts`

the one implementation of "make this dir's `CLAUDE.md` carry a line whose `trim()` is exactly `@CONVENTIONS.md`" (`CONVENTIONS_IMPORT_LINE`, `ensureConventionsImport(dir)`). Absent ⇒ create with the import alone (`wx` flag); present without it ⇒ **prepend**, every existing byte kept below; present with it ⇒ **no write at all** (no mtime churn on repeat ensures). Detection is **line-level, not substring**, so prose mentioning the filename never reads as an import. Called by `ensureConductProject` (`src/conduct.ts`) and by `ensureProjectConventionsMd` (`src/projectClaudeMd.ts`); its content half `withConventionsImport(existing)` (the bytes written, or `null` for no write) is also `src/conventionsCheckout.ts`'s `CLAUDE.md` predicate; the prepended line takes the file's own ending (`eolOf`), so CRLF input gets `@CONVENTIONS.md\r\n`; `migrations/0031-conduct-conventions-import.mjs` duplicates the literal and the prepend shape (built-ins only).

## `src/wsHub.ts`

Per-socket subscriptions, tail-only snapshot on subscribe (subscribes are serialized per socket; `sendSnapshot` joins the subscriber set, starts holding that socket's frames for the instance and copies the tail in one synchronous step, and after its `reconstructActiveTasks` await sends the snapshot and then the held frames in order — the `event`, `segment` and `reset_snapshot` frames go through `sendInstanceFrame`; a `status` frame is sent unheld — so the snapshot/live seam has no gap and no duplicate; `snapshotTail()` + `tailStartSeq`/`trimmedBefore`/`tailSegmentId`/`currentSegmentId` frame metadata; `insertRingSeamDividers` runs on the tail AFTER `tailStartSeq` is taken, so the cursor stays the first real event's), fan-out (a `pullOnly` event is never forwarded; the forwarder sends a `{t:'segment', id, currentSegmentId}` frame before every outer `system/init` and a `segment_seam` `event` before a rotation init above the ring floor), `prompt/mode/interrupt/kill/auto_approve_plan` over WS. Manager events → hints: `status` → `{t:'status'}` to subscribers plus `{t:'instances'}` + `{t:'projects'}` to all; `list_changed` → both hints; `subscription_changed`, `playbook_changed` and `turn_marks` → `{t:'instances'}` alone. Every `src/projectsChanged.ts` signal → `invalidateAll()` + `{t:'projects'}` to all.

## `src/accountUsage.ts`

`getAccountUsage()`: fetches account-level usage from the Anthropic OAuth endpoint (token read from `~/.claude/.credentials.json`), a bounded cache (shorter cadence after a failed fetch), returns `null` on any error (never throws, never exposes the token).
**Both** failure branches — a non-OK HTTP status and a network error/timeout — `console.warn` the reason plus the backoff they just armed (`Next retry in Ns (failure #N)`); a silent backoff on the network branch makes a persistently unreachable endpoint indistinguishable from "no overage to report" (the chip simply stays hidden).
Strict fresh-or-null by default; an opt-in `{ allowStale, maxStaleMs}` (bounded max-staleness cap) serves the last retained payload — wrapped as `{ data, stale, fetchedAt }` — when a fresh fetch isn't available, used only by `GET /api/usage` so the chip doesn't blank on a transient 429/backoff.
The overage-trip monitor and auto-resume controller call it with no options, so they always see strict fresh-or-null.
`invalidateAccountUsage()` drops the cache and backoff and bumps an epoch — `createServer` calls it from the Claude login flow's `onSuccess`.
A fetch remembers the epoch it started under; if it has moved when the fetch settles, the fetch writes neither the cache nor the backoff state and returns as if nothing were cached, so a fetch begun with the previous account's token never lands that account's usage (or its failure) after a re-login.
The token is read from `.credentials.json` per fetch, in `claudeConfigDir()` — `CLAUDE_CONFIG_DIR` verbatim (empty and relative values included, relative to cc's cwd), else `$HOME/.claude` — which is the directory `claude auth status` reports and the login CLI writes (measured with `auth status` against throwaway dirs for unset, empty, relative and absolute values).
**Known limitation:** where the CLI keeps tokens in the OS keychain instead of `.credentials.json` (macOS), there is no token to read and the usage chip stays hidden; a re-login does not change that.

## `src/cacheEstimate.ts`

`CacheEstimator`, the cache-read estimate for a non-Claude backend whose calls report no cache read (such a backend counts each call's whole context as input, so its `result.usage` reads `cache_read_input_tokens: 0`). One per `Instance` (`_cacheEstimate`), never fed or read when `backend === 'claude'`.
- **Input:** `onCall(call_usage)` from `Instance._emitUi` for each top-level call (no `parentToolUseId`) — the call's final `message_delta` figures, where a null cache field is a key the delta did not send.
- **Capability:** `_reportsCache` turns on at the first call that sends `cache_read_input_tokens` (even 0) and stays on: later keyless calls are genuine misses, not estimated. Cleared only by `resetCapability()`, which `_refreshModelCapabilities` calls on every {backend, model} change.
- **Formula, per estimated call:** prompt `P = input + cache_creation + cache_read`, baseline `B` = the previous call's `P + output`. Cached = `min(P, B)`; 0 when there is no `B` (first call, after a reset) or when `P` is below the previous call's `P` (the context shrank). After every call `B = P + output`, so `B` carries across turns.
- **Reset:** `reset()` from `_dropContextReading` (top-level compaction, `/clear` rotation, model switch, rewind/respawn/prune) clears `B`, keeps `_reportsCache` and the turn's running sum. `abandonTurn()` from `_wipeForResume` (respawn, resume, rewind, prune) additionally drops the open turn's sum, since that turn never reaches `turn_end`; `resetCapability()` does the same and also clears `_reportsCache`.
- **Seed:** the replayed resume `message_start` (`loadHistory`) calls `seed(usage)`: `B` = the transcript's last assistant usage's prompt + output. A prune or a model-switch relaunch skips it (`_skipUsageSeed`); a rewind re-seeds from the rewound transcript.
- **Output:** `endTurn(result.usage)` from `_handleStdoutLine`'s `turn_end` enrichment sets `turn_end.cacheEstimate = {inputTokens: U.input_tokens − sum, cacheReadTokens: sum}` — `input + cacheRead` always equals the reported `U.input_tokens`. Null when the turn estimated no call, `U` is null, or `U.cache_read_input_tokens > 0`; also null, with a `console.warn` naming both numbers, when `sum > U.input_tokens`. Calls the stream never showed (e.g. folded-in subagent calls) stay counted as uncached.
- **Accuracy** (`tests/nonclaude-usage-captures.test.mjs`, the derived capture against its real twin): within 2% on a turn whose calls the provider served warm; a session's first call reads 0 even when the provider served a cached system prompt; an eviction the stream does not report makes the estimate overstate the read.

## `src/costTracking.ts`

per-turn cost persistence.
`initCostTracking(instances)` subscribes to instance events and appends one JSONL row per `turn_end` to `<store>/costs.jsonl` (append-only); `flushCostWrites()` resolves once every append queued so far has landed (the headless result reads costs after it).
The `'event'` listener is synchronous and so cannot await the write: `appendCostRow` is itself **synchronous** — it snapshots the row (incl.
`ts`, the live `inst`'s `project`/`model`/`sessionId`, and the resolved `costsPath()`) in the emit tick and hands the write to `writeCostRow` via a module-level promise chain (`serialize`, the same idiom as `src/sessionStore.ts`).
Without the chain, two `turn_end`s in one tick start two independent `mkdir`→`appendFile` chains whose threadpool completion order is undefined, so rows land in arbitrary order (and two concurrent recursive `mkdir`s race, where a throw is swallowed into a `console.warn` — a dropped row); with it, file order == emit order.
`appendCostRow` omits the row's `cost_usd` field entirely when `inst.backend !== 'claude'` (the CLI's `total_cost_usd` is Anthropic list pricing, meaningless against another provider's model).
The four token fields (`input_tokens`/`output_tokens`/`cache_creation_tokens`/`cache_read_tokens`) come from the turn's `result.usage`, on every backend, and are omitted whenever `ev.usage` is null (`message_start` is a non-summable context snapshot, so there is no other per-turn token total; writing 0 would fabricate data).
The gate is `usage`-presence (mirrors the client `UsageTracker`), and a conditional spread keeps the fields in-position.
On a non-Claude row whose `turn_end` carries a `cacheEstimate` (`src/cacheEstimate.ts`), `input_tokens` / `cache_read_tokens` take the estimate's split and the row gains `cache_estimated: true` after `first_req_evicted`; a Claude row never reads `cacheEstimate`, so its bytes do not depend on it (pinned by the `cost-tracking: a Claude row is byte-identical …` test).
`getCostSummary()` (token sums for both `by_model` and the per-day `daily_trend[]` entries go through one `accumulateTokens` helper, under `tokensKnown`) reads it back into the `{total_usd, row_count, by_project[], by_model[], daily_trend[]}` aggregate behind `GET /api/costs/summary`; it counts a row's tokens exactly when `tokensKnown(r)`: `input_tokens` is a number and, on a row without `cost_usd`, at least one of the four token fields is non-zero (an all-zero non-Claude row is a proxy's all-zero report; a Claude row is counted whatever its values) and emits `tokens_known` per `by_model`/`by_project` entry (false ⇒ the `#costs` dashboard shows `—` instead of a bogus 0) and `tokens_estimated` (true ⇔ any of its rows has `cache_estimated: true`).
`costsPath()` exposes the file path.
Each `by_model[]` entry and each `by_project[]` entry (plus its nested `by_project[].by_model[]`) carries a `cache_misses` field — a plain count of that model's/project's rows with `cache_miss === true` — and a `sessions` field — the count of distinct `sessionId`s among that model's/project's rows (rows with `sessionId == null` excluded) — both folded into the same reduce loop that builds cost/token totals (no separate aggregation pass).
Cache-miss detection is **cross-turn**, captured live in `src/instances.ts`, and catches *partial* (minority) evictions a stateless single-request rule cannot.
Each turn is one or more API requests; `message_start` carries per-request cumulative usage and `cache_read` accumulates across a turn's tool-call iterations (there is no per-iteration array — `parser.ts` passes `result.usage` through verbatim).
So the detector uses two points: `read_N` = this turn's **first**-request `cache_read` (`_turnFirstReqCacheRead`, pre-tool-call); `P` = the **previous** turn's **last**-request full prefix `cache_read + cache_creation` (`_prevTurnPrefix`), captured by overwriting `_turnLastReqPrefix` on every `message_start` and latching it at `turn_end`.
**Miss ⇔ `read_N < P − max(1024, 1% of P)`** — this turn served less of the prefix than was cached at the end of last turn ⇒ eviction (full or partial); a warm continuation reads exactly `P` (drop 0, never flagged), the tolerance absorbs tokenization-boundary noise.
**Turn 1** (`_prevTurnPrefix === null`) and any turn where `_prefixBaselineInvalid` is set fall back to the stateless `creation > read` rule, which still flags a genuinely cold prefix (cold start, expiry, resume, cold rewind).
**Guards** against legitimate prefix shrink: compaction (the `compaction` event in `_handleStdoutLine`), model switch (`_trackModel`'s real-switch branch — cache is model-specific), and rewind/prune/respawn (`_wipeForResume`) each set `_prefixBaselineInvalid`; the next turn's first request consumes it (forces the fallback, re-establishes `P` fresh) so the cross-turn rule never false-fires.
**Known limitation:** a miss on a request *after* the first (e.g. a turn outliving the ~1h cache TTL) isn't caught — first-request-only.
Per-turn capture (`_turnFirstReqCacheRead`/`Creation`/`_turnMissDetected`/`_turnLastReqPrefix`/`_turnEvicted`) resets in `_setStatus`'s into-`turn` branch and on (re)spawn; cross-turn state (`_prevTurnPrefix`, `_prefixBaselineInvalid`) intentionally persists across the turn boundary.
Each `turn_end` is enriched with `cacheMiss`/`firstReqCacheRead`/`firstReqCacheCreation`/`firstReqEvicted` (`P − read_N` on the cross-turn path), persisted as `cache_miss`/`first_req_cache_read`/`first_req_cache_creation`/`first_req_evicted` (additive), and an informational `system`/`cache_miss` notice fires once per miss turn.
The old read-time session-relative heuristic (`cache_creation_tokens >= max(50000, 4 × session median)`) was retired to a one-shot backfill, **migration 0014**, which stamps `cache_miss` on legacy rows; a row still carrying the old `cache_flush` key (a decisive verdict captured before the field was renamed) is renamed in place rather than recomputed, so historical rows are heuristic-or-renamed while new rows are decisive.
Migration 0014 additionally stamps `cache_miss_heuristic: true` on any row whose verdict IT decided (neither key present, or a renamed `cache_flush` row lacking `first_req_cache_read` — an old-migration guess, not a live capture); presence is checked, not truthiness, since a decisive row can legitimately have `first_req_cache_read: 0`.
`appendCostRow` never sets this field, so its absence always means "decisive."

## `src/projectsCache.ts`

short-TTL (default `PRODUCTION_TTL_MS` in `src/projectsCache.ts`) cache of per-project git facts with in-flight coalescing, to cut the `GET /api/projects` fan-out load. `getOrCompute()`/`invalidate()`/`invalidateAll()`, plus `projectCacheKey(systemId, name)` — the key is `<systemId>:<name>` and the composer is exported so key and invalidation cannot drift. The system is not there to disambiguate (names are globally unique): the FACTS are measured on that system, and an entry keyed on the name alone would survive a placement change and be served as facts about the machine the project left. `invalidateAll()` runs on a `projectsChanged` signal (a project, workspace or worktree record write), not on instance spawn or exit: the cached facts hold nothing derived from the instance list. `invalidate()` correspondingly takes the PROJECT NAME and clears every key for it — its callers are mutations that know which project changed and not which system it is on, and a placement change is itself a reason to invalidate.

## `src/projectsChanged.ts`

the `projects` hint's source for cc's own records. The write primitives (`writeProjectRecord`, `writeWorkspacesRegistry` and `removeProjectStoreDir` in `src/projects.ts`; `writeMeta` and `dropWorktreeStoreEntry` in `src/worktrees.ts`; the `CONVENTIONS.md` writer in `src/projectClaudeMd.ts`) call `markProjectsChanged()` once their write lands. `projectsOperation(fn)` scopes an operation of several writes through `AsyncLocalStorage`: the outermost one signals once when it ends, on a return or a throw, if any write landed, and a nested one joins it; a write it starts must be awaited within it, since a detached write's mark is lost. Every call path that makes more than one write after the server listens runs inside one (`grep projectsOperation(`): `removeAllWorktreesForProject` and `repairWorktreesAfterProjectMove` are collapsed by their callers' operations, and the `DELETE /api/projects/:name` cascade in `src/routes.ts` is one of its own. The boot seed `ensureSelfProjectWorkspace` runs unscoped before `listenWithRetry` (`server.ts`), so its signals reach no client; `createProject`'s scope also holds its signal until `git init` and the seed files are done. `src/wsHub.ts` subscribes with `onProjectsChanged`. Tests: `tests/projects-changed.test.mjs` (frames per surface, counted through a same-socket probe), `tests/projects-operation.test.mjs` (the scope rules).

## `src/claudeAuthStatus.ts`

## `src/claudeLogin.ts`

`createClaudeLoginFlow({platform, timeoutMs, killGraceMs, onStart, onSuccess})` → `{start, submitCode, cancel, snapshot, dispose}`, the `claude auth login` state machine behind Settings → Account. One instance per `createServer` (instance-scoped, not a module global); one flow at a time (`start` while active → 409). `onStart` fires once per spawned flow — after the child is tracked and owned by the run, so a throwing hook cannot strand it; a throw is logged (`console.warn`) and the flow goes on — and `onSuccess` once per success.
- **Spawn** — `[...prefixArgs, 'auth', 'login']`, `platform.spawnOptions('child')` (not a group: a terminal Ctrl-C to cc's group reaches it), env `cliEnvBase(platform)` + `BROWSER=true` (stops the CLI opening a browser on the server host). No `HOME`/`CLAUDE_CONFIG_DIR` override, so it writes the store local workers read; remote workers reach it via `CLAUDE_SECURESTORAGE_CONFIG_DIR`. **Known limitation:** `BROWSER=true` is verified to suppress the browser on Linux only; on Windows (and macOS) the CLI may open one on the host, alongside the link Settings shows.
- **Protocol** — `URL_RE` on stdout matches the whole `… visit: <url>` line, terminator included, so a URL split across stdout chunks is never read half-way; it moves `starting` → `awaiting_code`. `submitCode` validates (string, non-empty after trim, single line, ≤ `MAX_CODE_LEN`) and writes ONE stdin line → `verifying`; the code is never stored, logged or returned. Stderr after a submit while the child is alive is the CLI's re-prompt (`Invalid code…`) → back to `awaiting_code` with its last line as `error` — an unterminated last line counts, and a complaint arriving in pieces keeps updating `error` until the next submit. On `close` (stderr drained): exit 0 → `succeeded` + `onSuccess`; anything else → `failed` with the last stderr line. A cancel or timeout settles the state first, and the exit it causes keeps it.
- **Cleanup** — the CLI never exits on stdin EOF, so every path kills: `cancel` and the `timeoutMs` timer (`LOGIN_TIMEOUT_MS`; message `Login timed out after <humanizeDuration(timeoutMs)>`, `10m` at the default) end the run at once — timer cleared, the child's events no longer drive the state — so a `start` right after them never meets a stale run; `dispose()` (`server.on('close')` in `createServer`) ends any flow and kills every child still alive. All three kill through `platform.killProcess`: SIGTERM, then SIGKILL after `killGraceMs` if still alive. A killed child can outlive its run by up to `killGraceMs`, so the flow keeps a set of children not yet closed and holds ONE `process.once('exit')` hook while that set is non-empty (sync SIGTERM to each — covers every `process.exit`, including restart); it is removed when the last child closes, so repeated cancel → start never stacks listeners. **Gap:** cc dying by an uncaught signal orphans a mid-flow `claude auth login`, which then waits on stdin forever; it holds no credentials and writes nothing.
- **Credentials** — cc never reads or writes them; re-login runs in place, no staging. Measured against the real CLI with a throwaway config dir: cancel, kill, a bad code and a malformed code all leave a valid credentials file byte-identical. Not measured (would need a real sign-in): the success output (exit 0 is taken as success) and whether running workers adopt a new credentials file on their next refresh.
- **Overage state survives a re-login on purpose.** `_overageActive`, each session's `_overageResetsAt` and the global lockout record stops applied to specific live sessions, which may still hold the previous account's token in memory; clearing them could resume a session that is still over its limit. They lift as before (window-reset timer, verified resume) — and that verify reads `getAccountUsage()`, which after the re-login is the new account's usage.

## `src/webBuild.ts`

builds and serves the web UI.
- **Inputs.** `webSourceHash(inputs = {root, dirs, files})` is a sha256 over every file under `dirs` plus the `files`, keyed by path relative to `root` (POSIX-separated, so it is identical across hosts). The default is `webInputs(repoRoot)`: `web/` + `shared/`, the root `package.json` and `tsconfig.json` (the build reads both: module resolution reads `package.json`, and `shared/tsconfig.json` extends the root `tsconfig.json`, whose compiler options the transform of `shared/*.ts` takes — measured by tracing a real `vite build`), and `node_modules/.package-lock.json` (npm's hidden lockfile, which records the installed tree, so a dependency change rebuilds; a cache key only), each file left out when absent, all under the given root, so a test hashes a fixture checkout through the same list. `skipDir` leaves out `dist`, `node_modules`, `test-results`, `playwright-report`, `e2e` and any `dist.*` directory (the staged `dist.next`, a killed build's `.tmp-<pid>`/`.old-<pid>`), so build output, Playwright output, the e2e specs and fixtures (not build inputs: a spec edit, or a mutation canary injected into one, costs no rebuild) and a killed build's leftovers never trigger a rebuild. **Stale** = `<dist>/index.html` missing, or `<dist>/.source-hash` ≠ `webSourceHash()`.
- **Vite runs as a child** (`runViteBuild(outDir, {onChunk, root})`): `process.execPath node_modules/vite/bin/vite.js build --config web/vite.config.ts --outDir <outDir> --emptyOutDir --logLevel warn`, cwd the repo root, `NODE_ENV=production`, through `runGroupedCommand({argv})` with a 300 s timeout — no shell, no npx. A child because a long-lived process that has just run `npm install` holds the pre-install vite in its ESM cache. A missing `vite.js` throws `vite is not installed (node_modules/vite/bin/vite.js missing) — run npm install`; a non-zero exit throws `vite build failed (exit N)` with the output `tail`. `buildInto(dir)` builds into `<dir>.tmp-<pid>`, writes the stamp, and swaps it in as `dir`.
- **Staging (a relaunch, or cc's post-merge hook).** `stageWebBuild({onChunk, distDir, inputs, build})`: `<dist>` current ⇒ `{staged:false}`; `<dist>.next` current ⇒ `{staged:true}`; else build into `<dist>.next`. It never touches `<dist>` or the module's serving state — the running process keeps serving its own build, whose server code a newer UI would not match — and on failure throws, leaving no staged or tmp dir, unless a `<dist>.next` of the current sources is there by then: another process (a relaunch and the post-merge hook can stage at once) put it there whole — the stamp is written before the rename — so it is kept and the call returns `{staged:true}`.
- **Making `<dist>` current: `refreshWebDist({distDir, inputs, build, onChunk, log})`**, the one implementation boot and the post-merge hook share. Current ⇒ `'up-to-date'`; else a `<dist>.next` stamped with the current hash is swapped in ⇒ `'adopted-staged'`; else logs `web: frontend sources changed — building web/dist …` and builds `<dist>` (`buildInto`) ⇒ `'built'`. **Every swap is guarded** when the caller passes `guard` (a `SwapGuard`, `src/webBuild.ts`): asked between the finished build and the rename — for the adoption and for a fresh build alike, `buildInto` building and stamping `<dist>.tmp-<pid>` before it asks — and a refusal throws `SourcesMovedError` with `<dist>` untouched, an adopted stage left where it was and a fresh build discarded (never moved to `<dist>.next`, whose stamp it could not honour). Then a `<dist>.next` stamped with any **other** hash is removed — renamed aside to `<dist>.next.old-<pid>` first (`removeAside`), so no reader sees it half-deleted; a failed removal is logged, never thrown. A `<dist>.next` of the current sources is **never** removed: the hook runs in its own process, and a relaunch may be staging that build in the server at the same moment — it is redundant with the `<dist>` just made current at worst. So the worst a concurrent hook and relaunch can cost is a rebuild at the next boot, never a missing or partial `<dist>`. Throws on a failed build or swap, leaving the previous `<dist>` in place. Every build and swap writes `.source-hash` through `buildInto`, so the next boot, refresh or stage finds the match; a stage is adopted only while its hash equals the current sources, so a stale one can never override a newer swap. `npm run build` is not used for this: `web/vite.config.ts`'s `emptyOutDir: true` empties the live `web/dist` mid-write and leaves no stamp.
- **Build (boot).**
  `ensureWebBuild({log, distDir = WEB_DIST, build, drift})` first sweeps `<distDir>.tmp-<pid>` / `<distDir>.old-<pid>` (and the same under `<distDir>.next`) siblings whose pid is not running (`isProcessAlive`, `src/storeLock.ts`; EPERM counts as running), so a killed process's leftovers go but another live server's in-flight build is never touched.
  It then runs `refreshWebDist` (above), with `guard` — `start()` passes `inputs = webInputs(checkoutRoot)` and `bootSwapGuard(checkoutRoot, bootCommit, inputs)` (`src/bootCommit.ts`), one `inputs` value for both, so the build and its guard hash the same tree — asked only while a previous build is in place: a refusal keeps that build serving, the phase `ready`, and logs `web: kept the previous build — the sources moved during the boot build (<reason>); the next start builds them`.
  **What stays unguarded**, so a merge landing during the boot build can go live in front of the boot backend: a first-ever build (no previous build: it swaps whatever it built, since an old-but-present UI beats none), and a boot with no readable HEAD — unborn, unreadable, not a git checkout, or git itself failing — where `bootSwapGuard` returns no guard, having nothing to measure against.
  Current ⇒ ready.
  Else a `<distDir>.next` stamped with the current hash is **adopted** — swapped in, logged `web: adopted the build staged before restart`, no Vite run.
  Else the build runs into `<distDir>.tmp-<pid>` (a mismatched staged dir is removed afterwards), then swaps in by rename-aside (`swapIn`): `distDir` → `<distDir>.old-<pid>`, the temp dir → `distDir`, then the old one is removed best-effort (a failure there is logged; the new build is live and the phase is `ready`).
  If the move-in fails, the old one is renamed back; if that fails too, the error names both, the move-in's first, and no build is left in place.
  A previous build therefore keeps serving until the new one is in place, and a failed build or swap keeps it, short of that double failure.
  Every error that aborts the build or the swap, the input hash included, resolves `{phase:'failed'}` and logs a framed `WARNING  web frontend build failed` (a failed removal of the old build is not one: the phase stays `ready`, with a one-line log); the promise never rejects, since `start()` does not await it.
  When `dependencyDrift` is non-null at that point, the error (and so the 503 page and the log) ends `— node_modules does not satisfy package.json: <reason>; run npm install`.
  The build's own output (warnings only, at `--logLevel warn`) goes to `log.log`.
  `distDir`, `build` and `drift` are injectable for `web/src/build.test.ts`.
- **Serving.** `webHandler({distDir, getState})`, mounted at the root, serves `express.static(distDir)`, then answers `GET /` with a 503: a self-refreshing "Building the interface…" page (`<meta http-equiv="refresh">`) while no build exists, or the build error as plain text after a failure that left none (a previous build is answered by `express.static` first). There is no SPA fallback (routing is by URL hash), so any other path is Express's 404. `distDir` and `getState` are injectable for `tests/web-routes.test.mjs`.

## `src/bootCommit.ts`

what the serving server booted from, and the only way a merge hook learns it.
`measureBootCommit(root)` → `{sha}` or `{unknown: reason}`: HEAD, or unknown when `root` is not a git checkout, HEAD is unborn/unreadable, or `git status --porcelain --untracked-files=no -- . ':(exclude)web'` is non-empty (the running backend ≠ HEAD); tracked changes only under `web/` still give HEAD.
Never throws, writes nothing.
`start()` measures it first once it holds the projects-root lock ([The projects-root lock](headless.md#the-projects-root-lock) is taken before every boot step) — before the boot regenerates any project's `CONVENTIONS.md`, cc's own included — only when `recordBootCommit: true` (set by `entryStartOptions` alone; `checkoutRoot` defaults to the server's own dir and is a test seam), keeps it in memory, returns it as `bootCommit`, and installs `bootCommitHookVars({checkoutRoot, boot, webBuildRunning})` as `src/worktrees.ts`'s merge-hook vars provider (`setMergeHookVarsProvider`), withdrawn when the server closes.
For a merge whose target's realpath is the checkout's: `CC_SERVER_BOOT_SHA` when the commit is known and `webBuildRunning()` (`src/webBuild.ts`: boot's `ensureWebBuild` or a relaunch's `stageWebBuild` in THIS process) is false, else `CC_SERVER_BOOT_UNKNOWN=<reason>`; any other target gets neither.
Read when the hook's turn comes, not when the merge queued.
`bootSwapGuard(checkoutRoot, boot, inputs)` is the boot build's `SwapGuard` (`sourcesUnmovedGuard`, `src/swapGuard.ts`) over the `inputs` the build hashes.
For a known boot commit: HEAD still the boot commit, the inputs hash still the build's stamp, and `git diff --quiet HEAD` clean over the inputs outside `web/` — the capture's own rule, so `web/` edits uncommitted at boot still build and swap.
For an unknown one whose HEAD was readable (`measureBootCommit` keeps it as `head`, e.g. tracked changes outside `web/` at boot): HEAD still that `head` and the hash still the stamp, without the clean check — the tree was dirty by definition.
Any capture without a readable HEAD — unborn, unreadable, not a git checkout, or git itself failing (`measureBootCommit`'s catch) — gets no guard, since there is nothing to measure against.
A pid or a file cannot say which process is serving, so there is no on-disk record: the serving process is the one running the hook.
Two servers serving one checkout share its `web/dist`, and each vouches only for its own backend — a swap one decides is served by the other too.

## `src/webPostMerge.ts` + `src/webPostMergeMain.ts`

cc's own post-merge step, exec'd by `.code-conductor/post-worktree-merge.sh` (`"${CC_SERVER_NODE:-node}" src/webPostMergeMain.ts "$CC_PRE_MERGE_SHA" "$CC_POST_MERGE_SHA"`, cwd = the merge target; so it needs `node` on the hook shell's PATH only when cc did not pass `CC_SERVER_NODE`).
`bootCommitFromEnv(env)` reads the boot commit from `CC_SERVER_BOOT_SHA`; unset is unknown, with `CC_SERVER_BOOT_UNKNOWN`'s reason when the server gave one.
Pure `decideWebPostMerge({inputs, isMainCheckout, boot, bootIsAncestor, changedSinceBoot, changedThisMerge, serverImports})` → `{action: 'swap'|'stage'|'noop', reason}`.
A path is relevant iff `isWebInput(inputs, path)` (`src/webBuild.ts`) — the same dirs, skipped dirs and files `webSourceHash` covers, agreeing with `webInputFiles` on every regular file (pinned by `web/src/build.test.ts`).
It is path-only, since a git path may be deleted, so a symlink inside an input dir counts as relevant though the hash skips it — the one difference, and toward staging or a no-op swap.
A linked worktree (`--git-dir` ≠ `--git-common-dir`) ⇒ noop; a known boot commit that is an ancestor of POST (`git merge-base --is-ancestor`) decides on `boot..POST` — nothing relevant ⇒ noop; otherwise each path, in git's order, is classified by `serverMayLoad` against `serverImports` (`serverImportsAt(root, boot.sha)`, walked only when `boot..POST` was listed) and the first the server may load ⇒ stage, its reason naming that path; none ⇒ swap (`nothing changed since the server booted is code the running server loads (web/, docs/, tests/, README.md, and shared/ modules its imports do not reach)`).
The classes: a path the walk reaches, `web/` included ⇒ `<p> is loaded by the running server (<root> → … → <p>), so a new UI may not match it`; any other `web/` path ⇒ clear; a path under `IMPORT_GATED` (`docs/`, `tests/`, `shared/`, slash included, so `docsite/` is not; and the root `README.md`, an exact path, so `src/README.md` is not, and no other root `*.md` — the server reads `CLAUDE.md`/`CONVENTIONS.md`) ⇒ clear, unless the walk is unknown ⇒ `<p> may be loaded by the running server — <site> — so a new UI may not match it`; every other path (`src/`, `server.ts`, `package.json`, `migrations/`, `bin/`, `playbooks/`, `conventions/`, `.code-conductor/`, other root files, any other dir) ⇒ `changes since the server booted reach <p>, which the running server may load, so a new UI may not match it`.
Only the boot commit is walked: resolution is exact, so POST's graph reaches a new or changed file only through a changed boot-reachable file, which already stages — sound because a reached `web/` path stages too; an unknown, non-ancestor or unverifiable boot commit decides on `PRE..POST` — nothing relevant ⇒ noop, else stage.
Both ranges are listed with `git diff --no-renames --name-only`, so a move names its source as well as its destination (a `src/` → `web/` move is not web-only).
`runWebPostMerge({root, pre, post, boot, build?, log?})` prints one `[post-worktree-merge] web: <action> — <reason> (boot commit: <sha|unknown>)` line, then runs `refreshWebDist` (swap) or `stageWebBuild` (stage) on `<root>/web/dist` with `webInputs(root)`; a failure throws, so the entry exits non-zero and the hook result reports it.
A swapped build is live on the next page load: `express.static` serves `web/dist` from disk whatever the module's in-memory build state.
**The swap is guarded** (`sourcesUnmovedGuard`, `src/swapGuard.ts`): merges are not serialised, only their hooks are, so a later merge can land anywhere between the decision about POST and the swap, and the build reads the working tree.
Between the finished build and the rename — for an adopted stage too — the guard requires (a) `git rev-parse HEAD` still POST, (b) `webSourceHash` of the tree now equal to the build's stamp, and (c) `git diff --quiet HEAD -- <inputPaths(inputs)>` clean.
A refusal swaps nothing, discards the build, prints `[post-worktree-merge] web: swap skipped — the tree moved since this merge (<reason>); web/dist is unchanged, and a later merge's hook decides afresh`, and returns outcome `skipped` — exit 0, not a failure; the later merge's queued hook decides from `boot..` its own POST.
A swap never races the server's own build of the same dirs: while one runs the hook gets no `CC_SERVER_BOOT_SHA` and stages.
A NEW process's boot build (after a restart) can still start while a hook's swap is running; each is guarded against its own commit, and the two swaps' rename-aside leaves one complete build in `web/dist`.
The hook's timeout kills a build's process group; a killed build's `dist*.tmp-<pid>` is swept at the next boot (`sweepLeftovers`).

## `src/serverImports.ts`

what the running server's code imports, read from a commit, for `decideWebPostMerge`.
`serverImportsAt(root, rev, system = localSystem())` lists the tree with `git ls-tree -r -z --name-only <rev>` and reads the candidate lines with `git -c grep.lineNumber=false -c grep.column=false grep -I -z --no-color -E 'import|require|from' <rev> -- *.ts *.mts *.cts *.tsx *.js *.mjs *.cjs` (records `<rev>:<path>\0<line>`).
Only grep exit 0 is read; ls-tree non-zero, or any other grep exit ⇒ `{unknown: 'git grep <rev> failed (exit <n>): <stderr>'}`.
That includes exit 1: git's "no line matched" is indistinguishable from a grep killed at the `GIT_OUTPUT_LIMIT_BYTES` fence (`ExecResult` code 1), killed by a signal (`src/groupedCommand.ts` finishes `code ?? 1`, stderr empty) or failing a classified spawn (code 1), and a real boot commit always matches (`server.ts` imports); a `runGit` refusal (`GIT_TIMED_OUT`, `GIT_DID_NOT_RUN`, …) throws, so the hook fails rather than decides.
`system` is the injection seam the tests fence or fake grep through.
Pure `walkServerImports(files, text)` → `{chains: Map<path, [root, …, path]>}` (shortest chain, breadth-first) or `{unknown: '<file>: <why>: <trimmed line>'}` — the `<why>` literals must not contain what `OPAQUE_IMPORT` / `REQUIRE` match, since the walk scans its own source.
Roots: `server.ts` and every `src/` path in the listing.
Per line of a reached file, trimmed lines starting `//`, `/*` or `*` skipped: a dynamic `import(` whose argument is not one plain string literal, or any `require(`, ⇒ unknown; each `from '…'` / `import '…'` / `import('…')` specifier: `node:…` and a bare package name (`express`, `@scope/pkg/sub`) are ignored; `@shared/…` ⇒ unknown (an alias Node cannot resolve); one starting `/` or `#`, or with any other URL scheme (`URL_SCHEME`, e.g. `file:`), ⇒ unknown; `./` / `../` is an edge, resolved by `path.posix` join to the **exact** path (no extension or index probing, no `.js` → `.ts`), and one naming no file in the tree ⇒ unknown.
Edges are followed through every directory (`migrations/`, `shared/`, `tests/`, `web/`, …); a site in a file the walk never reaches is ignored.

## Markdown rendering

(`web/src/components/Markdown.tsx`, helpers in `web/src/components/markdown/`) — every rendered markdown blob (assistant and user text, plan cards, folds, summaries) goes through `<Markdown text className inlineEnd?>`, which runs react-markdown with remark-gfm (`singleTilde: false`):
- **URL gate** — `markdown/safeUrl.ts` `safeUrl(url, key)` is react-markdown's `urlTransform`: it sees every URL property after entity decoding and URI normalization (a backslash arrives as `%5C`), allows `SAFE_URL` for links and `SAFE_IMG_SRC` for `src`, and removes anything else before a component renders. The `a`/`img` overrides render a removed URL, or a link `classifyLink` calls literal, as its exact source slice (`node.position` offsets): `[label](href)`, the bare URL of an autolink, `<url>`.
- **Raw HTML** — never rendered: no `rehype-raw`, `skipHtml` off, so react-markdown turns each `raw` node into text.
- **Plugins** — `markdown/rehypeBlockWhitespace.ts` drops the whitespace-only text mdast-util-to-hast puts between blocks (under the root, quotes, lists, table parts, and beside a block in a list item), which a `whitespace-pre-wrap` caller would show as blank lines; `markdown/inlineEnd.ts` (`inlineEndHost`, `rehypeInlineEnd`, only with `inlineEnd`) appends `span[data-speak-slot]` at the inline end of the last line of prose, descending through quotes and list items, none when the last block is a heading, code, table, rule or an HTML block's text. The `span` override fills that slot from the `MarkdownInlineEnd` context, so `TextBlock` (`web/src/conversation/items.tsx`) changes its read-aloud control without re-running the pipeline; it marks `data-speak-end` from whether a slot rendered. Both plugins walk iteratively. `markdown/listItem.ts` is remark-rehype's `listItem` handler: mdast-util-to-hast's default, given a stand-in parent that carries the list's looseness computed once per list, since the default rescans every sibling for every item (O(n²) in a tight list's items).
- **Code blocks** — `markdown/CodeBlock.tsx` is the `pre` override: `div.md-code-wrap` > `button.md-code-copy` + `pre > code[data-lang]`, the code text without the trailing newline mdast-util-to-hast adds; Copy goes through `copyToClipboard` and flashes `Copied`/`Copy failed` (`.copied`/`.failed`) until `CodeBlock`'s reset timer returns it to `Copy`.
- **Totality** — an `ErrorBoundary` (`web/src/ui/ErrorBoundary.tsx`) keyed on the text shows the raw source in one bare `<pre>` (`RawSource`) when rendering throws. A slow parse freezes without throwing, so before parsing `parseable` (`markdown/guard.ts`) refuses, with the same `<pre>`, a document longer than `MAX_SIZE` characters or one whose `nestingDepth` passes `MAX_NESTING`; micromark's container cost grows with lines × open depth. `nestingDepth` counts each line's quote and list markers plus half the indentation before them, blind to fences and HTML: it never decides what region a line is in, so it can only over-count, and deep markers inside a code block (a fenced YAML or diff, say) fall back to raw text — the accepted false positive. Known gap: long runs of `*`/`_`/`~` delimiters or of `]` in one paragraph parse superlinearly and are unguarded; the remedy is to render markdown off the main thread.
- **Bundle** — the markdown packages are the `markdown` chunk (`MARKDOWN_PACKAGES` in `web/vite.config.ts`), statically imported, so the entry stays under `build.test.ts`'s per-chunk budget.

# Components: hooks, transcripts, session edits and usage

The hook broker and tool-result nudges, transcript replay and the event archive, pagers, session editing and pruning, and per-call usage.

## `src/hookBroker.ts`

Per-instance PreToolUse/PostToolUse http hook answerer: allows local calls, applies the `SessionRedirect` policy to redirected ones. **Read-nudge branch** (conductor only — `readNudge` option set): a PreToolUse whose tool `ConductorReadNudge.watches` is answered `{}` or `additionalContext`-only, never with a `permissionDecision` and never through the redirect; a call carrying `agent_id` is answered `{}` without touching the run. The body goes out **before** `onReadNudge` emits the UI event, so a throwing emit finds `res.headersSent` and cannot become a deny. **Tool-result nudge branch** (every instance — `toolNudges` option set to `Instance._toolNudges`): a PostToolUse whose tool `isToolResultNudgeTool` is answered from `PendingToolNudges.take(tool_use_id)` as `additionalContext` alone, or `{}`; it never reaches the redirect and ignores `agent_id`.

## `src/toolResultNudges.ts`

tool-result nudges (wire contract: [protocol.md](../protocol.md) → Tool-result nudges), single source for `TOOL_USE_ID_META_KEY` + `toolUseIdOf` (read by `src/mcp/server.ts`'s `dispatch` on every JSON-RPC `tools/call` into ctx `toolUseId`; the REST alias sets `null`), the nudge tools `TOOL_RESULT_NUDGE_TOOLS` (`TOOL_NAME_PREFIX`ed) with `isToolResultNudgeTool` and the anchored `TOOL_RESULT_NUDGE_MATCHER` (built with `conductorReadNudge.ts`'s `escapeRegex`), and the store `PendingToolNudges` (`queue` / one-shot `take` / `clear`; texts deduped per toolUseId). One store per `Instance` (`Instance._toolNudges`, in memory only), filled by `queueToolNudge` from `queueCallerNudge` in `src/mcp/handlers.ts` (never throws), cleared at the read-nudge reset sites below.

## `src/conductorReadNudge.ts`

the conductor read nudge, single source for its tool lists (counted: `project_read`, `project_bash`; delegation: `spawn_instance`, `send_prompt`; all `TOOL_NAME_PREFIX`ed — `project_diff` is neither), `READ_NUDGE_MATCHER`, `READ_NUDGE_THRESHOLDS`, `READ_NUDGE_RULE` (quoted from `conventions/conductor/core.md`; a test fails if that text goes), the one wording constant `READ_NUDGE_TEMPLATE` (`readNudgeText` / `parseReadNudgeText`), the event constructor `readNudgeEvent`, and the replay recognizer `readNudgeEventFromAttachment`.

## `src/taskNotification.ts`

background-task notifications, single source for the rendering rule (`notified`: started in the background — `task_started.is_backgrounded` — and `status` `completed`/`failed`), the sentence parsers (`parseTaskSentence`, `sentenceExitCode`), the event constructor `taskNotificationEvent`, the live adapter `taskNotificationFromFrame` with its per-`Parser` `TaskStarts` record, and the replay adapter `taskNotificationFromEnqueue` (`isTaskNotificationEnqueue`). Wire contract: [protocol.md](../protocol.md) → `system`/`task_notification`.
- **Counter:** `ConductorReadNudge`, one per conductor `Instance` (`Instance._readNudge`, `null` on every other instance), in memory only. A counted call extends the run and `observe` returns a nudge iff the run length is in `READ_NUDGE_THRESHOLDS`; a delegation call sets it to 0. Thresholds are per run, so a later run in the same turn nudges again.
- **Reset sites:** `Instance._setStatus` on every exit from `turn` (turn_end → idle, crash, exit, the `spawning` of a respawn/rewind) — the same chokepoint that clears `interrupting` and `_toolNudges` (a turn cannot end before its tool results' PostToolUse hooks are through, so nothing cleared there was still takeable). A mid-turn steer joins the running turn (status stays `turn`) and does not reset. A resume-after-restart or a fork builds a new Instance, so the run starts at 0 and a partial run is lost.

## `src/settings.ts`

Builds the inline `--settings` JSON. Pure values → JSON string; no Instance state. With a hook URL every session gets the base PreToolUse entry and the tool-result nudge PostToolUse entry (`TOOL_RESULT_NUDGE_MATCHER`); a conductor adds the read-nudge PreToolUse entry, a redirected session its widened PreToolUse matcher and a second PostToolUse entry after the nudge one ([protocol.md](../protocol.md#subprocess-protocol)).

## `src/coreClaudePlugin.ts`

cc's built-in Claude Code plugin root (core skills, [features.md → Core skills](../features.md#core-skills)): `CORE_CLAUDE_PLUGIN_ROOT` (`<selfProjectDir>/claude-plugin`) and `withCoreClaudePlugin(coreRoot, pluginDirs)`, which prepends the root when its `.claude-plugin/plugin.json` exists and otherwise warns and returns `pluginDirs`. Composed in `InstanceManager._doCreateResolved` outside the plugin resolver's try, from `InstanceManager._coreClaudePluginRoot` (a test seam defaulting to the constant). Bare `node:fs`: the root is under cc's own checkout, not a project tree.

## `src/transcript.ts`

Replays `~/.claude/projects/<encoded-cwd>/<sid>.jsonl` into UI-event shape on resume (`loadPersistedTranscript` = read the file + the segment's model-switch ledger entries (`getModelSwitchesForSegment`) + `replayPersistedText({place, sessionId, text, seqHint, modelSwitches})`, which a caller holding one read of the file calls directly; sub-agent sibling files are still read from disk).
**The ledger splice:** `replayPersistedText` emits each entry (`modelSwitchEvent`, marked `replayed`) as its own line — a `null` anchor first, every other one right after the first line whose `uuid` is its `afterUuid`, an anchor never seen at the end (never dropped); splice lines count toward neither `replayedCount` nor `lastLeafUuid`.
`loadPersistedTranscript` is the ONE splice point: the ring replay (`Instance.loadHistory`), `eventArchive.buildArchive` / `loadStampedTranscript` / `pagePersistedEvents`, the lineage pager and `mcp/messageReconstruction` all read through it (the last ignores the divider — it has no `msgId`).
`measureSegmentEchoOffset` and fork call `replayPersistedText` without `modelSwitches` — they count echoes or copy lines.
`readLastLineUuid` gives a switch its anchor: the jsonl's last uuid'd line, not the live leaf marker (the stream also stamps uuids on frames the CLI never persists).
**A ring not rebuilt by a replay** — a wipe followed by `launch({})` under `--session-id`: a rewind or a restart switch relaunching a segment with no conversation (both through `Instance._relaunchSegment`) — is seeded with the segment's null-anchored dividers first (`Instance._seedUnanchoredSwitches`, as `replayed` events), so it leads with what the archive leads with; otherwise the two seq spaces drift by one and the echo-anchored cut marks a false `history_gap` and drops an event; best-effort `last-prompt`/`permission-mode` appends; exports `isPureUserPromptLine`, which excludes the CLI's local-command caveat (`isLocalCommandCaveatLine`, `src/parser.ts`) — `replayPersistedLine` emits nothing for it, so replay and the prompt counter stay 1:1.
A `hook_additional_context` attachment line replays through `readNudgeEventFromAttachment` (`src/conductorReadNudge.ts`): cc's read nudge becomes the same `system`/`read_nudge` event the broker emitted live, and any other hook's context replays nothing.
A `queue-operation` line replays through `taskNotificationFromEnqueue` (`src/taskNotification.ts`): a background task's completed/failed `enqueue` becomes the same `system`/`task_notification` event the parser emitted live; every other queue-operation replays nothing.
Of the notification's later delivery lines, the `type:"user"` one replays a `turn_boundary` (the start of the unprompted turn that delivers it), and a `queued_command` attachment replays nothing.
**`blockCursor`** (per file, `msgId → {next, prev}`, threaded by `replayPersistedText` and `loadSubAgentTranscript`): the CLI persists one message as N single-block lines sharing `message.id`, so `next` continues `blockIdx` across them and `prev` carries the block before a line's first one, which is what lets replay stamp `narration` on a `thinking_delta` across lines exactly as the live parser does (`isNarration`, `src/narration.ts`); a single line replayed without a cursor gets per-line indices and adjacency.
A sub-agent line (`parentToolUseId` set) is never classified.

## `src/planFile.ts`

One `PlanFileTracker` per session, two drivers: the live stdout path (`instances.ts`) and jsonl replay (`transcript.ts` threads it through `replayPersistedLine` exactly like `blockCursor`), so a plan card's `saved to …` line and the MCP `planPath` survive reload/respawn instead of existing only while the event is in the ring.
`loadPersistedTranscript` returns the replay tracker's final path and `Instance.loadHistory` seeds the live tracker with it (`seed`: fills only an empty tracker, so it never overrides a live latch, and never sets the same-turn flag), which is why an `ExitPlanMode` after a restart/resume still binds a plan file written earlier **in the current transcript segment** — `_wipeForResume` resets the live tracker.
The replay reads only that segment (`loadHistory(backingSessionId)`), so a segment rotation (`/clear`, renew) or a prune that drops the `Write` line leaves nothing to seed from: the resumed tracker stays empty and an empty-input `ExitPlanMode` carries no plan or path.
It latches every `Write` whose `file_path` has a `.claude` / `plans` segment pair (either separator, so a Windows `C:\Users\…\.claude\plans\x.md` matches) and ends `.md`, keeping the path exactly as the CLI wrote it; it enriches the matching `plan_request`.
**Branch 1 (inline plan text) and branch 3 (empty ExitPlanMode input) get deliberately different rules.**
Branch 3 reads the file and presents its contents *as* the plan, so path and text cross-check by construction and the session-scoped path is sound.
Branch 1's text came from the model, and the remembered path is only "the last plan file written this session" — nothing ties it to *this* `ExitPlanMode` — so it attaches only when the write happened in the same turn.
`~/.claude/plans/` accumulates files from unrelated runs, so a stale path does not 404: it silently resolves to another task's plan.
`noteTurnBoundary()` therefore clears only the same-turn flag and never the path, or a reject → re-`ExitPlanMode` round that edits the plan file would lose branch 3's path too.
Deliberately not threaded into `loadSubAgentTranscript` — a sub-agent's plan file is not the outer session's.

## `src/eventArchive.ts`

two entry points over one windowing core.
`pagePersistedEvents({place, sessionId, before|after, limit})` is the composition of two exported halves — `loadStampedTranscript({place, sessionId})` (the stamped archive list, `null` when the file is absent) and `pageStampedTranscript(flat, {before|after, limit})` — which the lineage walk calls separately to tell a missing file from an empty one; it serves a RETIRED session straight off its jsonl: no instance, no ring, hence `seamIdx:-1` (its existing "no scan-opaque boundary" meaning), `gap:false` (nothing was evicted-and-unreconstructable) and `trimmedBefore:0`.
Both it and `pageInstanceEvents` stamp their replay through the shared `stampArchiveEvents(lines)` — the one home for "replayed events get dense archive seqs plus absolute `userIndex` on outer echoes", also used by `mcp/messageReconstruction.ts` — and both delegate the windowing/quiescent-snap/`history_gap`/`task_completion` core to the module-private `pageCombined`.
`pageInstanceEvents(inst, {before|after, limit, markFloor})` behind `GET /api/instances/:id/events` (and, per segment, the lineage route): `inst` is a `PagerSource` — `Pick<InstanceLike, 'ringSnapshot' | 'ring' | 'backingSessionId' | 'transcriptPlace' | '_userEchoCount'>`, so a past view of an instance pages through it unchanged; `markFloor` (default `true`, and no MCP or `/events` caller passes it) gates only the floor marker below, never the seam marker.
Retained events come from the ring; evicted ones are reconstructed by replaying the jsonl (`loadPersistedTranscript`) into a dense archive seq space (0..H-1, clamped strictly below `trimmedBefore`), cut so ring + archive never overlap: when the ring head is an outer echo, cut strictly before its own stamped `userIndex`; when it's mid-turn, correlated by content — `(kind, msgId, blockIdx)` or a `tool_result`'s `toolUseId` — into the archive first (an exact stitch, no gap), falling back to the echo-ordinal anchor only when no correlator resolves (`buildArchive`'s `correlateRingHead`/`correlationKey`, src/eventArchive.ts); `gap` is true whenever evicted history exists that a call couldn't reconstruct — a mid-turn head with no correlator hit, an unreadable/missing jsonl, the `trimmedBefore` clamp discarding archive content past its own anchor-derived cut (strictly `>`; `cut === trimmedBefore` is the healthy turn-aligned case and marks no gap), or a trimmed ring with no `sessionId` to replay from — and surfaces as a seq-less `history_gap` event anchored to the **position** of the archive/ring seam — index `archive.cut` in the combined array when the archive was loaded (the **seam** anchor), or 0 for the no-`sessionId` branch, where the combined array is the ring (the **no-`sessionId`** anchor); the **floor** marker below is a third, separate anchor — spliced at that offset inside the served slice, so the page whose window *ends* at the seam carries the marker as its last event.
Anchoring on the ring-head *event* instead (`_seq === trimmedBefore` appearing in the slice) put the marker on whichever page happened to serve it, and otherwise on the terminal page far below the real boundary, since `gap` is only computed on pages that load the archive and those sit at or below the seam, not above it.
The terminal-page append survives, narrowed to pages whose whole window sits **above** the seam with `hasMore:false` — reachable on forward (`after`) paging only, where no lower page will follow to carry it.
It can only ever fire for the no-`sessionId` anchor: while the archive is loaded a forward page's `servedStart` is `firstIndexAtOrAbove(combined, after+1)`, which stays in `[0, cut]` (and equals `cut` for every `after` in `[cut−1, trimmedBefore)`), so the seam offset is never negative.
What makes "some page carries it" hold at all is that backward pages **tile unconditionally**: every window is served (none is ever skipped — see the backstop note below), so each page's `nextBefore` is its own served start and the next page's end is this page's start.
So: never silently dropped.
It can still be emitted **twice** in one narrow case — when the snap lands a straddling page's start exactly *on* the seam, that page splices at offset 0 and the page below it splices at its own end.
Known, much narrower than the pre-seam-anchoring double class it replaced, and deliberately not closed **on the wire** — the client collapses adjacent gap dividers when it splices a page (`ConversationModel.prependPage`, `web/src/conversation/model.ts`), so it never surfaces as two stacked dividers).
The archive is loaded for two reasons, not one: the requested window's seq extent dips below `trimmedBefore`, **or** the tentative ring window holds a sub-agent child with no owning head inside the ring (`hasHeadlessChildIn`, parser.ts) — group heads are resolved over the whole loaded array, so such a child reads as headless and gets pushed out of the only page whose window covers it unless the (usually archive-side) head is loaded with it.
Backward pages return an opaque `nextBefore` cursor that jumps the numeric gap between the two seq spaces.
Rejected-window backstop: when the quiescent snap would reject a window outright (`start >= end` — the window's only content was sub-agent children with no reachable head), the page is instead served from `lastQuiescentAtOrBefore(rawStart)` (parser.ts) — the window's own pre-snap start, down-snapped to the nearest quiescent cut — rather than coming back empty; a backward page is empty **iff** the window itself is empty (`end === 0`), which is terminal (`hasMore` is already false there), so this is total: every non-empty window is served, on some page, exactly once.
Headless children served this way ride along and park client-side (`Conversation.orphanChildEvents`) rather than rendering, which is strictly better than the events being dropped along with their whole merged component; window starts snap to **quiescent points** (`snapStartToQuiescent`, parser.ts: no open outer block, every `tool_use` resolved; outer `user_echo`/`turn_end` and a replayed `turn_boundary` force-reset the scan; sub-agent events are scan-opaque — nested-block wholeness comes from the group-boundary resolver, which moves the cut EITHER way: an available head is dragged into the page with its whole group, while a child with no head at or before it in the loaded array has the cut pushed past it (unreachable by design rather than served orphaned); the archive→ring seam is passed as `resetIdx` so state is never scanned across missing events).
Also splices synthetic `task_completion` bubbles into paged history (see `taskReconstruct.ts`).
**Live rotations** (managed renew, typed `/clear`): the ring and `_userEchoCount` run on across the seam while the archive is only ever the **current** segment's file.
`currentSegmentScope(inst)` reads `ring.seams`/`trimmedBefore`/`backingSessionId` → `{segmentId, startSeq, archivable, priorEvicted}`: `startSeq` from the last seam (0 when `seams` is empty, i.e. pre-spawn); `archivable = !!backingSessionId && trimmedBefore >= startSeq` (the ring head is inside the current segment); `priorEvicted = startSeq > 0 && trimmedBefore > 0` (an earlier segment's ring events were evicted).
With one seam at 0 this is exactly the no-rotation behaviour.
`pageInstanceEvents` loads the archive only when `archivable` and passes `buildArchive` `segmentStartSeq: scope.startSeq`; `Instance.reconstructActiveTasks` does the same.
`buildArchive`'s `segmentStartSeq` (default 0 = the ring was filled from this file alone, ordinals align): above 0 every echo-ordinal site — the echo-head cut, the mid-turn fallback, the empty-ring branch — uses `userIndex + offset`, where the module-private `calibrateEchoOffset(ring, flat, flatIndex)` measures the offset from content (the ring's latest outer echo before its first correlatable outer event, against the last file echo at or before that event's twin), because the CLI writes replay-only echoes at the head of a post-`/clear` jsonl.
No offset measurable ⇒ `{cut: 0, gap: trimmedBefore > 0}`: nothing is served from the file.
The correlated mid-turn path runs first and needs no offset.
Once `cut` is final, the returned events are copies whose outer echoes are **restamped into live space** (`userIndex` = file ordinal − offset; deleted when negative or unmeasurable) — **after** the cut, because the calibration reads the file ordinals; the offset is forced here even on the correlated path.
`measureSegmentEchoOffset({place, sessionId, ring, text?})` is the load wrapper around the same `calibrateEchoOffset` (`null` for a missing file or no correlation) that `Instance._fileOrdinalFor` uses to translate a live bubble ordinal into the file for rewind/fork; its caller passes only the current segment's ring events.
Given `text` (fork: the snapshot its copy comes from) it replays that instead of reading the file; rewind passes none.
There is no runtime precondition check: `archivable` means `trimmedBefore >= startSeq`, `trimmedBefore` IS `ring[0]._seq` for a non-empty ring, and both callers read ring, `trimmedBefore` and scope in one synchronous tick before their first await, so `ring[0]._seq >= segmentStartSeq` holds by construction.
**`floorGap`** (a `pageCombined` input; `pagePersistedEvents` passes `false`) marks evicted earlier-segment events: `true` when the head predates the current segment (`!archivable`, trimmed, `sessionId` present — `combined` is the ring), `scope.priorEvicted` when the archive loaded (`combined[0]` is the file's first event), else `false`.
After the seam block, when `servedStart === 0` and `events[0]` is not already a `history_gap`, one marker is unshifted — for a backward page unconditionally, for a forward page only when its window reaches the evicted seqs (`after < 0 || after + 1 < combined[0]._seq`), so polls from above never carry it.
Never appended by the backstop.
A page starting at 0 that also contains `cut` carries both floor and seam markers; with `cut === 0` the seam marker already sits at offset 0 and the floor is skipped.
Contract table in [protocol.md](../protocol.md) → "Paging across a live rotation".
Two ring-presentation helpers over `RingSeam[]` live here so `wsHub` and the lineage walk share them without `wsHub` depending on the walk: `segmentOfSeq(seams, seq)` (the last seam with `startSeq <= seq`) and `insertRingSeamDividers(events, seams, ringFloor)` (a seq-less `segment_seam` before each later seam's rotation init with `startSeq > ringFloor`).
- **Head-scan skip vs abandon (`correlateRingHead`).** Steps over only `neverPersisted` events (`RING_ONLY_KINDS`, plus every `system` subtype but `soft_interrupted`, `read_nudge`, a `task_notification` with `data.notified` — a non-notified one is live-only and is skipped — and a `model_changed`/`model_switch_failed` carrying a `switchId` — a restart model switch's divider, spliced from the session ledger; an identity `model_changed` has none and is skipped); a model-switch divider correlates by `msw <switchId>`, a `read_nudge` by its `toolUseId` (`rn <toolUseId>` — one PreToolUse per tool call, at most one nudge per hook), a notified `task_notification` by `tn <toolUseId> <status>` (a background Agent may notify more than once per tool use; the pair is unique within a session), a `turn_boundary` by `tb <toolUseId> <status>` (built from that notification's delivery line; replay emits it, so it is not ring-only); any other head with a null or unindexed `correlationKey` abandons to the echo-ordinal fallback, which cuts at the start of the head's turn and marks a gap.
- Adding a kind `replayPersistedLine` emits to `RING_ONLY_KINDS` duplicates it across the seam; a replay-emitted kind whose key can never hit the index turns a correlatable head into a fabricated gap. Judge any skip-set change by enumerating what `replayPersistedLine` and `consolidateUserContent` emit.
- A spurious abandon loses the head's whole turn body, so the loss scales with turn length, not ring size, and the served cut shifts across reloads as the ring head's kind changes. A history truncation that won't reproduce points here before the client.

## `src/lineagePager.ts`

the web UI's lineage scroll-back (`GET /api/instances/:id/lineage-events`): the **cross-segment walk and nothing else**. `pageLineageEvents(inst, {segment, before, limit})` reads `chainFor(inst.sessionId)`, captures ring/`trimmedBefore`/seams/echo count/place in one tick, and composes the single-segment pagers — live `pageInstanceEvents(inst)`, the **view** `pageInstanceEvents(segmentRingView(snap, k))` of the ring-head segment when it is no longer current, and disk steps via `loadStampedTranscript` + `pageStampedTranscript`. `lineageSteps(chain, fromId)` (pure) picks the steps: prune originals skipped by immediate-predecessor adjacency in the full chain, one gap per tombstoned skipped run, `top` gap for a trailing tombstoned run or a non-`initial` oldest entry. `segmentRingView` is the `EventLog.seams` partition applied (ring restricted to `[seams[k], seams[k+1])`, `ring.seams` up to `k`, `nextSeq` = the next seam, segment `k` as backing) plus **one invariant beyond it**: `_userEchoCount` is the echo count at seam `k+1`, read off the first outer echo at or after it in the captured ring (else the live counter) — exact because `_emitUi` is the only stamper and the ring holds every seq ≥ `trimmedBefore`; load-bearing only for `k = 0`. It holds **no cut, anchor, correlation, snap or stitch code** — `tests/lineage-pager.test.mjs` W3 pins its imports and forbids those names, and neither `src/mcp/` nor `src/wsHub.ts` imports it. Contract: [protocol.md](../protocol.md) → "Lineage scrollback". `pageLineageEvents` takes a `LineageSource` (the pager's `PagerSource` plus `sessionId`), which three things satisfy: a live instance, a retired one's frozen copy (`src/retiredPagers.ts`), and `retiredLineageSource(publicId, place)` — a session with **no instance**, whose current segment's stamped transcript stands in for the ring (`trimmedBefore: 0`, one seam at 0, `_userEchoCount` = its outer echoes), behind `GET /api/sessions/:sid/lineage-events`.

## `src/retiredPagers.ts`

`RetiredPagers`: a frozen copy of what an instance's pagers read (ring snapshot, `trimmedBefore`, `nextSeq`, seams, `_userEchoCount`, `transcriptPlace`, ids), taken when the instance leaves `InstanceManager.byId` — at the normal-exit drop in the manager's `status` handler and in `remove()`. `InstanceManager.pagerFor(id)` = the live instance, else this copy; `GET /api/instances/:id/events` and `/lineage-events` read through it, so a pane that was showing a killed worker keeps paging in its own ring-seq cursor space (a transcript's archive stamping counts persisted lines only, so the pane cannot switch to a disk-numbered source). Older history still reads the jsonl at the frozen place, outside the worktree, so it survives `delete_worktree`. FIFO, bounded by `RETIRED_PAGER_CAP` (a recapture moves an entry to the newest end), **in memory only**: a restart or eviction 404s the pane's next page, which the web UI takes as the end of its scroll-back. Pinned by `tests/ended-session-read.test.mjs`.

## `src/taskReconstruct.ts`

`reconstructTasks(events)` → `{completions:[{afterSeq,tasks}], activeAtEnd, hadOrphanUpdate}`: single-pass, chronological reconstruction of task-batch state from raw `TaskCreate`/`TaskUpdate` `tool_use`/`tool_result` events. `hadOrphanUpdate` is true when a non-deleted `TaskUpdate` referenced an id whose `TaskCreate` is absent from the scanned events (the create was evicted below the ring) — the signal `Instance.reconstructActiveTasks` uses to decide whether to widen the scan to the jsonl archive. Server-side mirror of the client `shared/tasks.ts` `TaskTracker` (same create-id binding, batch rollover, and completion edge — keep the two in sync). Feeds the snapshot's `tasksAtTailStart` (via `Instance.reconstructActiveTasks`) and `eventArchive.ts`'s lazy-page `task_completion` injection. `task_completion` is never a real wire event — the tail/live path still synthesizes it client-side in `web/src/app/controller.ts`; this recovers the below-tail batches those paths can't see.

## src/instances.ts `Instance.reconstructActiveTasks(beforeSeq)`

(async) — the snapshot's `tasksAtTailStart` seed. Runs the cheap ring-only `reconstructTasks` first; only when it reports `hadOrphanUpdate` (and the ring has trimmed, and `currentSegmentScope(this).archivable` — the ring head is inside the current backing segment, so a head predating a live renew never folds the new file's tasks into an older update) does it call `buildArchive` (with `segmentStartSeq: scope.startSeq`) (same combine as `eventArchive.ts`'s lazy paging: `archive.events.slice(0, cut)` ++ ring events below `beforeSeq`) and re-run `reconstructTasks`, so a batch whose `TaskCreate` was evicted entirely below the ring is recovered without a deep scroll. A batch that completed inside the archive still yields `[]` (no resurrection).

## `src/renewalBoundary.ts`

pure (no fs, no store): locating a renewal boundary for the "Context renewed" divider's controls.
`renewalBoundaryAt(chain, label)` — `label` is a `segment_seam` `segmentId` (always the newer side, possibly a prune copy); prune entries are stepped over to the `renew` entry they follow; returns `{pre, post}` (`post` = the renew entry to the chain's end, tombstones included) or throws 400 `NOT_A_RENEWAL_BOUNDARY` (unknown, initial, or prune-only label).
`renewalCut(preText, postText)` → `{userMessageIndex, text}` (file ordinal + replayed text, fed to `truncateSessionAtUserMessage` / `forkSessionAtUserMessage`, which re-verify it) or null.
**Managed** iff ANY pure prompt in the post file parses as a reseed (`parseRenewSeed`, `shared/renewSeed.ts`) — not only the first: `prompt()` is open between the `/clear` rotation and the deferred reseed, so a prompt can precede it; read off the post file rather than a `renew_session` call in the pre file, which a `run_code` renewal never records.
Otherwise null (typed `/clear`, or a reseed that never landed) and the pre segment is used whole.
**Anchor:** the last non-sidechain assistant line with a SELF-form `tool_use` named `RENEW_TOOL_WIRE_NAME` (built from `CC_MCP_SERVER_NAME`, `src/settings.ts`, and `RENEW_SESSION_TOOL`, `src/sessionRenew.ts`) — `input` with no string `sessionId`; the targeted form renews another worker — else end of file (a `run_code` renewal).
**Cut:** the last `type:'user'` pure prompt before the anchor — a `queued_command` steer never moves it, a prompt sent after arming falls after the anchor; none → 409 `cannot locate the renewal request …`.
Callers: `Instance.rewindAcrossRenewal` (latest boundary only — refuses 409 `RENEWAL_NOT_LATEST` when a later `renew` entry sits in `post` or `post` does not end at the backing id; 409 `PRE_RENEWAL_GONE` for a tombstoned/missing pre file; kill → truncate → `undoRenewal` (the commit) → `backingSessionId`/`_segments` to pre → delete the post run's files → `reanchorModelSwitches` → `_relaunchSegment(pre, …, 'rewind')`; a failure before the commit rewrites the pre file from the bytes read before the kill and relaunches the untouched post segment, so a retry cuts at the same place — the re-anchor sits after the commit so the truncate is the only thing that window must undo) and `Instance.forkAtRenewal` (any boundary, mid-turn allowed, `_claimForkSource({requireIdle:false})` without `forkAtTip`'s turn-start re-check — the pre file is retired, and its one writer, `rewindAcrossRenewal`, is excluded by `_mutating`; `forkSessionAtUserMessage` or `forkSessionWhole` → `_finishFork(pre, …, undefined)`).

## `src/sessionEdit.ts`

Atomic destructive jsonl edits: `truncateSessionAtUserMessage` (tmp → fsync → rename, appends fresh metadata at the new leaf), `forkSessionAtUserMessage` (copies prefix into a new `<sid>.jsonl` with `sessionId` rewritten on every line), `forkSessionWhole` (copies every complete line of its `snapshot`; refuses 400 `nothing to fork yet` with no `isResumableLine` record; anchors metadata at the last line carrying a uuid).
Both forks share the private write tail `writeForkCopy` (sessionId rewrite → `writeFileAtomic` → `writeSessionMetadata` when a leaf uuid exists).
`truncateSessionAtUserMessage` and `forkSessionAtUserMessage` return `droppedText` for composer prefill — the target's prompt text, except that a CLI command wrapper comes back in its command form — `<command-name>` verbatim (the CLI writes the slash), then ` <command-args>` when non-empty (the guard's own `commandForm` mapping).
`userMessageIndex` is a **file** ordinal (a live bubble ordinal is translated first by `Instance._fileOrdinalFor`).
**Text guard:** `truncateSessionAtUserMessage` and `forkSessionAtUserMessage` take `expectedText` and throw a `PROMPT_MISMATCH` 409 before any write unless the target line's replayed echo text (`replayPersistedLine`, the function every replayed bubble came from) matches it after normalisation — CRLF → LF, trimmed, and a CLI command wrapper (only `<command-name>`/`<command-message>`/`<command-args>` tags) mapped to its command form, as above.
**Fork refuses (400, before any write) a prefix with no user/assistant record** (`isResumableLine`, `src/transcript.ts` — the predicate `hasResumableConversation` uses): the new session could not be resumed.
Rewind at such a target truncates anyway and returns `resumable: false` (the same predicate over the prefix), and the rewind relaunches fresh.
Known limits: two adjacent attachment-only prompts (text `''`) are indistinguishable, and a prompt-type (skill) slash command would refuse.
`verifyUserPrompt` runs the same read and checks with no write — rewind calls it before its kill.
The walk itself is the pure `splitAtUserMessage(text, {userMessageIndex, expectedText})`; rewind's path reads the file and calls it (`readAndSplit`), while `forkSessionAtUserMessage` takes a required `snapshot` string and never reads.
Its out-of-range 400 carries `code: PROMPT_OUT_OF_RANGE` (also in the REST body).
`completeLinesOf(text)` cuts a text after its last `\n`.
**Caveat with its command:** a split landing right after a local-command caveat moves the caveat to the dropped side and recomputes `lastSurvivingUuid`, so its "do not respond" text never precedes the next prompt.
- **Whole-session fork (`Instance.forkAtTip`).** Shares `_claimForkSource` (rotation check, `_mutating` 409, with `requireIdle` the between-turns 409, backing-id 400, pin, synchronous claim) and `_finishFork` (title + `createArgs`, `prefill` only when defined) with `forkAtUserMessage`; one `_readForkSnapshot` → `forkSessionWhole`, no wait loop — an idle source owes no line. A fork blocks no prompt (`rewriteBlocksPrompts`), so a turn can start between the claim and the read's end: `_turnStarts` (incremented on every `_setStatus` transition into `turn`, prompted or not) is captured at the claim and re-checked after the read, and any change refuses the between-turns 409 before anything is written — a status re-check alone would miss a turn that started and ended during the read.
- **Mid-turn fork (`Instance.forkAtUserMessage`, `src/instances.ts`).** Fork is allowed during a running turn and never refuses prompts. Premise: while fork holds `_mutating`, the source file only grows — its writers append (the CLI, `writeSessionMetadata`), its in-place rewriters (rewind, prune) refuse, a rotation moves the CLI onto a new file, and an unlink leaves an open read on the old inode (a later open 404s). So one read is a byte-prefix of the file's eventual contents.
- **Pin**, synchronously and BEFORE the claim (building it can throw; the `try` that releases the flag opens right after the claim): backing id, transcript place, file path, current segment's `startSeq` (`currentSegmentScope`), `proc`; deadline = now + `_forkPersistWaitMs` (initialised from `FORK_PERSIST_WAIT_MS`; per instance so tests can shrink it).
- **Each attempt:** (a) synchronously, refuse 409 `FORK_SOURCE_CHANGED` if the pin no longer matches (`_forkSourceChanged`), then capture the pinned segment's ring slice (null when `startSeq === 0`), `_userEchoCount` and whether `status === 'turn'`; (b) ONE read, `_readForkSnapshot(file, sessionId)` → `{text: completeLinesOf(decoded), size: raw byte length}` (ENOENT → 404; the test seam); (c) `_fileOrdinalFor(L, {sessionId, place, ring, text})` — the offset is calibrated on that same `text` (`measureSegmentEchoOffset({…, text})` → `replayPersistedText`); (d) `forkSessionAtUserMessage({…, snapshot: text})` with the pinned id/place. Every decision about *what to copy* comes from `text`; in-memory values only decide whether to wait and which refusal to give.
- **Wait decision.** An unresolved offset (`_fileOrdinalFor` → null) refuses `PROMPT_UNRESOLVED` at once, never waiting. A prompt not in the snapshot (`PROMPT_OUT_OF_RANGE`): not owed (`L >= echoCount`) → the 400 at once; source changed → `FORK_SOURCE_CHANGED`; no turn running when the attempt began, or deadline passed → 409 `PROMPT_NOT_PERSISTED` at once. So the first read that starts after the source is seen not running is the last one, including for a source idle when the fork starts. A prompt cc sends while idle is always persisted before its turn's `result` (`prompt()` sets `turn` as it sends). A steer still in the CLI's own input queue when a turn ends is not: its line is written only once the CLI picks it up after the `result`, so a fork of its bubble in that window refuses `PROMPT_NOT_PERSISTED`, writing nothing, and a retry succeeds. Otherwise `_awaitForkSourceGrowth`: sleep `FORK_PERSIST_POLL_MS` before every size probe (`_forkSourceSize`, the poll-rate test seam), until the size differs from the last read's **raw** byte length, the deadline passes, the source changes or the file is gone — then the next attempt.
- **Why no copy can be wrong:** within a segment prompt lines appear in echo order, and a turn's lines follow its prompt line, so everything appended after the read — open-turn output, a steer, a new turn — lands after the target or outside `text`; a partial trailing line is cut before anything counts or copies lines; a snapshot without the target line is never copied from.

## `src/sessionPrune.ts`

**Prune**: a mechanical, zero-token context compaction.
`analyzeSessionForPrune({cwd,sessionId})` returns per-turn, per-category prunable-token counts; `pruneSessionToNewId({cwd,sessionId,cutTurnIndex|keepLatestTurns,pruneThinking,inputMode,mode})` writes a stubbed copy under a fresh `sessionId` (same atomic tmp→rename + `sessionId`-rewrite + `writeSessionMetadata` convention as `sessionEdit.ts`) and returns `{newSessionId, turnCount, cutTurnIndex, saved}`.
**Cut range: `0…turnCount` inclusive** — `turnCount` is a full prune, newest turn included; only `turnCount+1` and above 400, and a zero-turn session is refused outright.
The two cut arguments are **XOR** (supplying both, or neither, throws — no silent precedence): `keepLatestTurns` resolves to `Math.max(0, turnCount - keepLatestTurns)` **inside** the transform, which is the only point past `Instance.pruneSession`'s subprocess kill — a caller that pre-read the count via `analyzeSessionForPrune` could have a turn land in between and silently keep one turn too many.
A user prompt's own text and every `text` block survive a full cut untouched (a pure-user-prompt line's `content` is a string, so it is not `touchable`), and the unresolved-`tool_use` thinking exemption is message-keyed and cut-independent, so an interrupted newest turn keeps its signed thinking.
Both passes route every block through ONE `pruneBlock()` helper, so the dialog's savings preview cannot drift from what the transform does — which is also why the exempt-tool check (`isPruneExemptTool`, invariant 6 below) lives **inside** `pruneBlock` rather than in either caller's loop; `pruneBlock` returns the original block whenever the stub would be *larger* by the `blockTokens` estimate, so pruning never inflates the estimated context.
`blockTokens` delegates an `image` block — top-level or inside a `tool_result`'s content — to `src/imageCost.ts`, and a top-level image on a prompt line in the cut is stubbed like a tool output (a text block naming media type plus dimensions and decoded size, or the source kind when the header can't be read, counted under `toolOutputs`).
An image whose size can't be read is costed at `IMAGE_MAX_TOKENS`, so the no-inflate check always passes for it and it is always stubbed.
Images inside `attachment` lines are outside this path: never estimated, never stubbed.
**Estimate:** `blockTokens` divides each block kind's characters by its `TOKEN_CHARS` ratio (a `tool_result`'s text blocks at the tool-output ratio; an `image`, top-level or nested, at its `imageCost.ts` cost and never at a chars ratio; any other nested block, `redacted_thinking` and any other type at a flat /4).
An **encrypted** thinking block (non-string or empty `thinking`) is sized from its signature (`SIGNATURE_OVERHEAD_CHARS`, `SIGNATURE_CHARS_PER_TOKEN`), and `pruneBlock` returns it untouched before scoring — without that guard its cost would make the stub score a saving.
**Compaction:** `readRecords` marks every line before the LAST non-sidechain `system`/`compact_boundary` neither prunable nor in context, so no estimate counts it and the transform copies it verbatim (sessionId rewrite aside); the CLI's compaction-preserved messages are not counted, a conservative under-report.
**Calibration:** `usageCalibration(records)` runs on the same records in both passes.
A *call* is an in-context assistant line with `usage`, a model other than `<synthetic>`, a positive `promptTokenSum` (parser.ts) and a `message.id` new since the previous call (the CLI splits one message over lines sharing id and usage).
A *step* runs from one call's first line to the next call's; its measured growth is the prompt difference, its estimate `blockTokens` over its in-context user/assistant content (attachments are not estimated).
A step is dropped for an `image` (top-level or nested in a `tool_result`), a `redacted_thinking`, a `PRUNE_STUB_RE` match (a stub from an earlier prune — its step's usage still counts the original), an attachment kind outside `PER_STEP_ATTACHMENTS`, or non-positive growth.
`factor = Σgrowth ÷ Σestimate`, clamped to `CALIBRATION_MIN_FACTOR`…`CALIBRATION_MAX_FACTOR`; under `CALIBRATION_MIN_TOKENS` of estimate it is `1` with `calibrated:false`.
`pruneBlock` also returns `imageSaved`, the part of a saving owed to images: the stub's whole cost is charged to the block's images, so it is their cost less the stub's, floored at 0 and capped at the saving.
The analysis returns raw integers (tool outputs with their image part as `toolOutputImage`) plus the factor, and the transform's `saved` is `Math.round((raw − imageRaw) × factor) + imageRaw` per category, so preview = apply stays exact arithmetic and a real image cost is never scaled.
`contextReading(usage)` is the ctx-chip reading both the analysis route (`contextTokens`) and `prune_session` (`contextTokensBefore`, read before the respawn drops it) report.
Turn boundaries come from `isPureUserPromptLine` (transcript.ts) — the same index space rewind/fork use — which is what makes the slider's turn-snapping structural rather than cosmetic: the cut can never land between a `tool_use` and its `tool_result`.
`Instance.pruneSession()` (instances.ts) wraps it in the `rewindToUserMessage` skeleton (`_mutating` guard → idle-only → `kill` → transform → `_wipeForResume` → `launch({resume:newSid})`), recording the `prune` segment before the launch (it inherits `persistent`) and retiring the abandoned segment (`retireSegment`) after it; the session's facts sit on its public-id record, so nothing is carried.
**Only the BACKING id rotates — the instanceId and the public `sessionId` are both preserved**, so the idle-wake graph, overage timers, the renew controller, every worker's `/mcp/<sessionId>` MCP URL and every id a conductor holds stay valid with no migration.
The rotation is recorded as a `prune` segment BEFORE `launch()` (prune is server-minted, so it is the one rotation that can be durable before first use) and the fail-safe catch calls `revertRotation`, so a throw inside `launch()` can never leave a segment the process never ran.
It sets a one-shot `_skipUsageSeed` consumed in `loadHistory`, because the jsonl's newest assistant `usage` still reports the PRE-prune size.
On a mid-transform throw it fails **safe**: the subprocess is already dead by then, so the catch respawns against the ORIGINAL backing id (always possible — Prune only ever writes a new file) and rethrows the real cause, rather than leaving the instance wedged with no proc and no respawn.
**`_mutating` is a tagged holder** (`RewriteKind | null`, `src/instanceTypes.ts`: `'rewind'` / `'fork'` / `'prune'` / `'model_switch'` — the last held by `Instance.switchModel`'s restart for its whole run, [models.md](../models.md) — claimed synchronously after the check, released to `null`).
Any holder makes the other rewrites refuse 409 `another rewind/fork/prune is in progress` (the restart's own refusal names a model switch too), the MCP `prune_session` pre-check soft-refuse, and `IdleSubscriptionHub._goneForGood` keep the wake owed.
Only `rewriteBlocksPrompts` (`'rewind'` / `'prune'` / `'model_switch'`) makes `Instance.prompt()` refuse with 409 — closing the sliver between a caller's idle check and the kill in which a prompt would be written to stdin and its partial tail folded into the rewritten file — and makes both `renew_session` forms soft-refuse, since the reseed is a `prompt()`.
A `'fork'` holder blocks neither: see "Mid-turn fork" under `src/sessionEdit.ts`.
Fork takes no `_exitSuppressed`, unlike its two siblings: they kill their source and respawn it, so the exit archive would fire on a session about to come back, whereas fork never kills anything — a source exiting mid-fork is a REAL exit and must archive.
Sound because the two footprints are disjoint: the archive writes the sub-agent dir and the SOURCE transcript's segment flags, while the fork reads the source jsonl and writes only the new id's jsonl + metadata.
`_archiveSession` itself deletes no jsonl.
`createArgs` carries `persistent` explicitly, so the child of a persistent session is persistent (marked by its own `spawn()`) and the child of a normal one is normal (archived on its own exit); create()'s session-store recovery would not supply it, since forking writes no flag for the new id.
The fork ROUTE (`src/routes/instances.ts`) only parses `userMessageIndex` and spawns the `createArgs` the method hands back — every guard, the flag claim/release and the derivation of those respawn arguments belong to the instance, which is what all three of them are read off.
Not a new failure class for callers, which already tolerate the `not running` throw from the same window.
Unlike `renew_session` it never calls `prompt()` — a pruned session resumes **idle**.
- **Harness-state invariants (derived by probing the real CLI — treat as spec).**
  The CLI rebuilds its read-before-edit cache (`readFileState`) by REPLAYING THE TRANSCRIPT on resume, reading `input.file_path` off every Read/Write/Edit `tool_use` and pairing it with the matching `tool_result`.
  So: **(1)** never rewrite a `tool_use.input` key set — only string *values* are edited and path keys are skipped at any depth; replacing an input with a marker object drops `file_path` and every later Edit fails with "File has not been read yet".
  **(2)** never touch `toolUseResult` — it is a disk-only sidecar (pruning it saves zero *context*) and its ABSENCE is the CLI's discriminator for "this is a human user turn".
  **(3)** `tool_result.content` stays a string **except for pruned Read/Write results, which use a block array deliberately**: the CLI only reconstructs a `readFileState` entry when `typeof content === "string"`, so the array form is what makes the read-before-edit guard RE-ARM once the file's content has left the context.
  Normalizing (3) back to a string would look like a cleanup and would silently re-break that guarantee — the model would be allowed to edit a file it can only "remember", reconstructing an `old_string` that may not match or may match the wrong occurrence.
  Switchable via `PRUNE_STUB_AS_BLOCKS` (default `true`).
  An Edit-seeded cache entry is out of reach either way: the CLI re-reads that path from DISK using only `input.file_path` and a non-error result.
  The reconstruction pass branches on exactly three tool names — **Read, Write, Edit** — so `SEEDING_TOOLS` is `{Read, Write}` (Edit's result content is irrelevant to it).
  `NotebookEdit` is a defined tool-name constant that the pass never references: a notebook result cannot seed the cache, and since nothing seeds it from a transcript, a notebook edit already needs a live Read after ANY resume — pruning neither causes nor worsens that.
  The guard is only *enforced* for a fixed model set (haiku-4-5, sonnet-4-5/4-0, opus ≤4-6, 3-x) — which is why `tests/prune.real.test.mjs` pins `claude-haiku-4-5`; on Opus 5 / Sonnet 5 it would pass vacuously.
  **(3a)** Truncate mode cuts with `sliceCodePoints`, which backs off one unit when the cut would land inside a surrogate pair — `slice` counts UTF-16 code units, and a lone high surrogate has no valid UTF-8 encoding, so a naive cut writes unencodable content into a jsonl whose whole contract is that it resumes cleanly.
  Minimal mode replaces whole values and is immune.
  **(4)** No entry and no block is ever removed, which is what keeps the `parentUuid` chain and the `tool_use`/`tool_result` pairing invariant safe with zero relinking.
  **(5)** Sidechain entries are never pruned and never counted in the estimate; the sibling sub-agent directory (`<encoded-cwd>/<sid>/subagents/`) is COPIED to the new sessionId, without which every sidechain silently vanishes from the pruned session's transcript view (`loadSubAgentTranscript` keys off the sessionId — `forkSessionAtUserMessage` has this same gap today).
  **(6)** Some tools are EXEMPT by name (`isPruneExemptTool`): their `tool_use` and the `tool_result` answering it are copied verbatim in every mode, at any cut.
  Two classes — **`AskUserQuestion`**, because the question card is rebuilt entirely from `input.questions` on replay (`transcript.ts`) and the answer is paired server-side by `QuestionAnswerCorrelator` (`isUserQuestionAnswerText` against the card's question text) and parsed back into per-question picks by `parseUserQuestionAnswers` (`shared/userQuestionAnswers.ts`) from the stamped echo, so squeezing either side leaves an unreadable question and silently drops the answer off the card; and **core conductor MCP calls** (`mcp__code-conductor__<tool>`), the orchestration record of what was spawned, approved, merged, filed.
  The MCP half is exempt by NAMESPACE so a core tool added later is exempt by default, minus a hardcoded denylist `PRUNABLE_CONDUCTOR_MCP_TOOLS` = {`project_read`, `project_bash`, `system_bash`} whose results are bulk file/command output — precisely what Prune exists to shed.
  **Not configurable**: which class a tool falls in is a property of the tool, not a user preference.
  Matching the prefix alone is not enough: what remains after it must ALSO contain no further `__`, since a plugin-forwarded tool carries one (`mcp__code-conductor__code-kanban__file_task`, `mcp__code-conductor__acme-tools__run`) and stays prunable.
  The separator tested is `__` and not `_`, which keeps a core tool whose own name contains a single underscore (`spawn_instance`, `merge_worktree`) on the exempt side; testing for `__` rather than for the first-party `code-*` plugin naming habit is deliberate, so a third-party plugin id classifies the same way.
  An orphaned `tool_result` (no `tool_use` in context ⇒ no name) stays prunable.
  Thinking blocks keep their `signature` when their text is stubbed: an *unsigned* thinking block survives the CLI's own other-model strip pass (which only removes SIGNED blocks) and would then reach the API unsigned; a stale signature was measured to provoke no rejection, and the CLI has a strip-all-and-retry recovery path regardless.

## `src/callUsage.ts`

`CallUsageTracker`, the per-API-call prompt + growth stamped on a live `call_usage` event. Pure; driven from `Instance._emitUi` with the context latch's reading from BEFORE each call's `message_start` updates it (`onMessageStart`), the same call's `context_usage` fallback (`onContextUsage`), `stamp(ev)` before the ring push — all keyed by `msgId`, so a call that never opened stamps nulls —, and `reset()` from `_dropContextReading`, which also voids the open turn. `endTurn(contextTokens)`, from `_handleStdoutLine`'s `turn_end` enrichment, returns the turn's growth over its first opened call's baseline only when that equals the sum of the turn's stamped growths (`turn_end.contextGrowthTokens`). The event contract is in protocol.md → `call_usage`.

**Its two consumers ask different questions of it, which is why it publishes two things**. Paging asks "is state empty AT index i", evaluated *before* applying event i. The live abort asks "has a block boundary been crossed SINCE I armed" — unanswerable from an empty-state reading, because on a stream whose closes never arrive the event that retires a stale block is the same event that opens the next one. So the class carries `boundarySeq`, a monotonic count of retirements, and `Instance` snapshots it into `_interruptArmSeq` at arm time.
A block is retired by its own close, by a turn boundary, or by **progression** — a different `${msgId}:${blockIdx}` key appearing. Progression MARKS the stale block rather than deleting it: a never-closed block is unfinished *permanently*, so a consumer that must render whole blocks is right to keep counting it — deleting instead hands paging extra cuts wherever a stale block is followed by one that closes normally, ending the preceding page on a dangling block, which is what the snap exists to prevent. With marking, quiescent cut indices are identical by construction (pinned in `tests/quiescent-paging.test.mjs`, including the stale-then-normally-closing case). Progression reads ONLY events carrying both a `msgId` and a numeric `blockIdx` — a candidate that read it from any event fired at index 35 of `tests/fixtures/trace-quiescent-boundary.jsonl` while a Bash tool ran until index 47.
**Tool spans are deliberately NOT progressed** — only a matching `tool_result` or a turn boundary discharges one. Measured over 68,431 real outer tool spans across the identity backend and six substitution backends: a msgId change with a span open occurs 85 times and all 85 spans are dangling (0 late-resolving), and orphan `tool_result` ids number 0 — so progression there would buy an unattested class at the cost of discarding live tool work. If that class is ever seen in the wild, re-run the orphan-`tool_result` scan rather than re-deriving this.

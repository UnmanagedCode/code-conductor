# Protocol: REST — settings, voice, auth and costs

## REST endpoints: settings, voice, auth and costs

- `GET` `/api/transcribe/status` — `{available: boolean}` — true when both `WHISPER_CLI` and `WHISPER_MODEL` exist on disk. Drives the composer's mic-button visibility.
- `POST` `/api/transcribe` — Body: raw audio bytes (any `audio/*` content-type, capped at the route's `express.raw` body limit). Returns `{text}`. 400 on empty body, 503 when whisper isn't installed. Route-scoped `express.raw` parser so the global `express.json` body limit doesn't apply.
- `GET` `/api/settings/transcribe` — `{available, activeModel, models:[{name,label,sizeLabel,installed}], install}` — curated whisper model catalog + per-model on-disk state + active model + install status.
- `POST` `/api/settings/transcribe/model` — `{model}` — set the active model. 400 if unknown or not installed. Returns the refreshed state. Persisted to `settings.json`; effective immediately.
- `POST` `/api/settings/transcribe/install` — `{model}` — start `bin/install-whisper.sh` for that model (one at a time). 200 `{started}`, 409 `{running}` if busy, 400 on unknown model. On clean exit the model is set active.
- `GET` `/api/settings/transcribe/install/status` — `{running, model, exitCode, log}` — polled by the Settings page to stream install progress.
- `GET` `/api/settings/models` — `{backends:[{id,label,template,env:[{key,value}],managed}], claudeFamilies:[{family,label,default,versions:[{id,label}]}], tiers:[{tier,label}], tierBackend:{[tier]:{backend,model}}, tierEffort:{[tier]:level}, efforts:[level], defaultEffort:level, roles:[{role,label?,builtin?,plugin?}], roleBackend:{[role]:{kind:'tier',tier}|{backend,model}}, roleEffort:{[role]:{effort:'inherit'|level, inheritsTo:level}}, customModels:[{label,model,backend,contextWindow,midTurnSteering}], backendModels:{[backendId]:[{model,label}]}, ollamaCloudModels:[{label,model,contextWindow}], ollamaCloudTierDefaults, enabledTiers, defaultSpawnTier, conductorIdleNudge:{enabled,value,min,max}, landingRenewNudge:boolean}` — the **backend registry** (`backends`; managed rows are code-owned — see [models.md](../models.md)) + the Claude version catalog (`claudeFamilies` — the `claude` backend's model list) + the fixed capability-tier list + each tier's `{backend,model}` binding + the **merged role list** (built-in + user-custom + plugin-owned; `builtin:true` + `label` on the two seed roles, `plugin:'<id>'` + `label` on a plugin-owned role, a **user-custom role is name-only** — no `label`, the `role` name is the display) + each role's binding (built-in/custom read from the `roleBackend` store keyed by the exact name; a **plugin role's binding is the EFFECTIVE binding**
  — a valid user override from `roleBackend` if present, else the manifest binding live-derived from the enabled plugin) + the user's custom models (each with its **required** native `contextWindow` in raw tokens and the `backend` serving it) + `backendModels`, every **substitution** backend's registered models keyed by backend id (`backendModels(id)`, `src/appSettings.ts`: its custom rows plus, for `ollama`, the curated presets, one entry per id with a custom row's label winning) — what Change model offers every session, each entry sent as a `{model, backend}` pair + the curated Ollama cloud catalog (scoped to the built-in `ollama` backend, each with its `contextWindow`) + its per-tier defaults + enabled tiers + default spawn tier + the **default-effort axis** (`efforts` = the level catalog; `defaultEffort` = the end of the precedence chain, shipped so a client fallback lands where the server would; `tierEffort` = each tier's effective level; `roleEffort` = each role's stored `'inherit'`-or-level plus `inheritsTo`, what `inherit` resolves to right now — shipped so the UI can label the option without recomputing the chain, which lives only in `resolveSpawnEffort`, see [models.md](../models.md#default-effort)) + `conductorIdleNudge`, the idle-renewal nudge setting with the server's minute bounds (`IDLE_NUDGE_MIN_MINUTES`/`IDLE_NUDGE_MAX_MINUTES`, `src/appSettings.ts`), so the client never restates them + `landingRenewNudge`, whether the landing renewal nudge is on (default `true`).
  There is **no** context-window key anywhere in this payload: every model has one native window, resolved server-side from `{backend, model}` and surfaced per session as the instance summary's `contextWindowTokens` (see [models.md](../models.md#context-windows)). (No `activeVersions` — a tier stores a concrete model.)
- `POST` `/api/settings/models/prefs` — `{onOverage?:'none'|'stop'|'stop-resume', overageThreshold?:{enabled,value}, conductorCompactWindow?, conductorIdleNudge?:{enabled,value}, landingRenewNudge?:boolean, tierEnabled?:{tier,enabled}, defaultSpawnTier?, tierBackend?:{tier,backend:{backend,model}}, roleBackend?:{role,backend}, tierEffort?:{tier,effort}, roleEffort?:{role,effort}}` — update model prefs. `tierBackend` rebinds a tier to `{backend,model}` — a Claude version id on the `claude` backend, or one of another backend's configured models (400 if the pair names nothing known); a `window` key sent inside `backend` by an older client is **silently ignored, never persisted** — a binding is exactly `{backend, model}`. `roleBackend` rebinds a **built-in, user-custom, or plugin** role; `backend` is either a tier binding `{kind:'tier',tier}` (known tier) or a concrete `{backend,model}` pair (400 only for an unknown role or invalid binding) — for a plugin role this stores an **override** of the manifest binding, persisted under `models.roleBackend` keyed by the `<plugin-id>/<slug>` id and taking precedence at spawn (re-selecting the manifest's tier/model in the picker reverts it). `tierEffort`/`roleEffort` set the **default-effort axis** of the same rows: `effort` is one of the `efforts` levels, plus `'inherit'` for a role only (400 for an unknown tier/role, an unknown level, or `'inherit'` on a tier — a tier has nothing to inherit from).
  `overageThreshold.value` is clamped to the bounded range/default in `src/appSettings.ts`. `conductorIdleNudge.value` goes through `Number()`, as `conductorCompactWindow.value` does: a non-finite result (e.g. `undefined`, `'abc'`) saves the default, and any other result is rounded and clamped to `IDLE_NUDGE_MIN_MINUTES`…`IDLE_NUDGE_MAX_MINUTES` — so `null`, `''` and `false` (→ 0) save the minimum; and a save restarts or stops the nudge sweep at once (`syncIdleRenewNudge`). `landingRenewNudge` must be a boolean — anything else is 400 `landingRenewNudge must be a boolean` and nothing is written; it is read at each MCP `delete_worktree`, so no sync follows a save. Returns refreshed state (`GET`/`POST` responses also include `overageThreshold`).
- `POST` `/api/settings/models/custom` — `{label, model, backend, contextWindow}` — add a custom model. The `(backend, model)` pair is the **identity** (`model` is the backend's own model id): re-adding a pair replaces that row's values and moves it to the end of the list, and one model id may be registered on several backends ([models.md](../models.md#custom-models)). `backend` must name a **substitution** backend (never `claude`) → 400 otherwise. `contextWindow` (raw tokens) is **REQUIRED** and must be a positive number → 400 otherwise; stored rounded. There is **no** reachability preflight — a bad backend/model fails at spawn (`launch_failed`). Returns refreshed state + `added`. Persisted to `settings.json` `models.customModels`.
- `PATCH` `/api/settings/models/custom/:backend/:model` — `{label?, contextWindow?, midTurnSteering?}` — edit a custom model in place, keeping its list position (`:model` URL-encoded). An omitted field keeps its stored value (`midTurnSteering` has no opt-out default here, unlike `POST`). Same 400s as `POST` for `label` / `contextWindow`. A body naming `backend` or `model` → **400** (the pair is the identity; remove and re-add to change it). An absent pair → **404**, so curated presets and Claude ids are not editable and an edit never creates a row. Takes effect at each session's next spawn or resume. Returns refreshed state + `updated`.
- `DELETE` `/api/settings/models/custom/:backend/:model` — Remove one custom model by its pair (`:model` URL-encoded; 404 if that pair is absent; the id's rows on other backends stay). Any tier still bound to it falls back to that tier's default Claude backend on next read. Returns refreshed state.
- `POST` `/api/settings/models/backends` — `{id, label, template?, env?:[{key,value}]}` — add a backend registry row. `id` matches `^[a-z][a-z0-9-]*$` (≤40) → 400; **409** when the id already exists (including a managed id). `template` blank/omitted ⇒ the bare `claude` command. Returns refreshed state + `added`.
- `PATCH` `/api/settings/models/backends/:id` — `{label?, template?, env?}` — edit a row. A **managed** row (`claude`, `ollama`) is read-only; sending `label`/`template`/`env` → **400** (a no-op PATCH with no fields returns the unchanged row). Unknown id → **404**. Returns refreshed state + `updated`.
- `DELETE` `/api/settings/models/backends/:id` — Remove a user row. **Never cascades:** **409** while any custom model still references it (bound model ids named in `error`); **409** while any *tracked* instance is still on it (session ids named in `error`) — exited-but-respawnable instances count, so the remedy is archiving/deleting those sessions, not killing them; **400** for a managed row; **404** for an unknown id. Returns refreshed state.
- `GET` `/api/settings/systems` — `{systems:[{id,label,managed,launch?,projects:[{name,remoteId},…]}]}` — the **system registry**: the execution environments a project's tree can live on. `launch` is the provider command as **argv** (argv[0] is the executable; never run through a shell) — absent on `local` (in-process) and on a user row that has none, which is registration-only and refuses at resolution. `local` ("This machine") is always present, `managed:true`, and code-owned. `projects` is the projects whose `project.json` NAMES that row, each with the TARGET of it they are on (`remoteId: null` for the provider's default) — one row can serve many targets, so the project name alone would not say which one holds it. `local` is always `[]` (a local project carries no `system` field) and `.conduct` is never listed under any system (it is pinned local ahead of its record).
- `POST` `/api/settings/systems` — `{id, label, launch?}` — add a row. `id` matches `^[a-z][a-z0-9-]*$` (≤40) → 400; `label` required → 400; **409** when the id already exists (including `local`); `launch` must be a non-empty array of non-empty strings or `null` → 400. **A `launch` is VERIFIED before it is persisted:** cc spawns it, completes the handshake and throws the connection away — a provider that does not answer is **502** quoting its own error, and nothing is written. The same call asserts no ancestor of `<store>/systems/<id>/sessions/` is a git repository → **400** naming the repo. Returns refreshed state + `added`. Persisted to `settings.json` `systems.registry` (user rows only).
- `PATCH` `/api/settings/systems/:id` — `{label?, launch?}` — edit a user row (the id is the identity and never moves). An omitted `launch` keeps the current command; an explicit `null` clears it. A **changed** `launch` is re-verified exactly as on POST (502 on failure, nothing written) and drops the live handle, so the process started by the old command cannot serve the new configuration; a label-only edit never touches the provider, so a system that is down stays renameable. The **managed** `local` row is read-only; sending `label` or `launch` → **400** (a no-op PATCH with no fields returns the unchanged row). Unknown id → **404**. Returns refreshed state + `updated`.
- `DELETE` `/api/settings/systems/:id` — Remove a user row. **Never cascades:** **409** while any project record still names it, with those projects in `error` as `name (remoteId)` (or the bare name for one on the provider's default); **400** for the managed `local` row; **404** for an unknown id. Returns refreshed state.
- `GET` `/api/systems/:id/remotes` — Which `remoteId`s the system's provider is configured to route to (`docs/systems-protocol.md` §2.2), asked afresh on every call. **Always 200**; the body is one of three states, never collapsed: `{system, label, state:'listed', remoteIds}` (`remoteIds` in the provider's order, possibly `[]`), `{system, label, state:'not-enumerable', reason}` (`local` — decided by id, never asked — or a provider that does not advertise `remoteListing`), `{system, label, state:'failed', reason, code?}` — an unregistered id (`SYSTEM_NOT_REGISTERED`), a row with no provider command (`SYSTEM_NO_PROVIDER`), an unreachable provider (`SYSTEM_UNREACHABLE`), an `error` answer (its code, `EUNSUPPORTED` included), the backstop (`ETIMEDOUT`), or a list cc will not believe (`REMOTE_LIST_INVALID`). Only `listed` carries `remoteIds`. Same caller as the `enumerate_remotes` MCP tool (`enumerateSystemRemotes`, `src/systems/remoteEnumeration.ts`). **501** `SYSTEMS_UNAVAILABLE` where the platform has no remote Systems
- `POST` `/api/settings/models/roles` — `{role, binding?}` — create a **user custom role** (name-only, no label). `role` must match `^[A-Za-z][A-Za-z0-9-]*$` (≤40) and not **case-insensitively** collide with a built-in tier, built-in role, family alias, another custom role, or a plugin role (`400` for a reserved-kind collision, `409` for a duplicate custom/plugin name). `binding` is **optional** — omit it and the role defaults to the `powerful` tier; when present it's a tier binding `{kind:'tier',tier}` or a concrete `{backend,model}` pair (400 if invalid). Persisted name-only in `models.customRoles:[name]` with the binding in `models.roleBackend[name]`. Returns refreshed state + `added:{role}`.
- `DELETE` `/api/settings/models/roles/:role` — Delete a custom role and its binding (name matched case-insensitively). A built-in or plugin-owned role can't be deleted (`400`); an unknown name is `404`. Returns refreshed state.
- `GET` `/api/tts/status` — `{available: boolean}` — true when the piper venv python + the active voice's `.onnx`/`.onnx.json` exist on disk. Drives the conversation's 🔊-button visibility.
- `POST` `/api/tts` — Body: raw assistant text (`text/*`, route-scoped `express.text`, capped at the route's `express.text` body limit). Streams `application/octet-stream` = a sequence of `[4-byte LE length][WAV]` frames, one per sentence, flushed as Piper synthesizes. 400 on empty body, 503 when piper isn't installed. Killing the response (client disconnect) stops synthesis.
- `GET` `/api/settings/tts` — `{available, activeVoice, voices:[{name,label,sizeLabel,hfDir,installed}], install, enabled, rate}` — curated Piper voice catalog + per-voice on-disk state + active voice + auto-speak/rate prefs + install status.
- `POST` `/api/settings/tts/voice` — `{voice}` — set the active voice. 400 if unknown or not installed. Returns refreshed state. Persisted to `settings.json`; effective immediately.
- `POST` `/api/settings/tts/prefs` — `{enabled?, rate?}` — persist the auto-speak toggle and/or playback rate (rate clamped 0.5–2.0). Returns refreshed state.
- `POST` `/api/settings/tts/install` — `{voice}` — start `bin/install-piper.sh` for that voice (one at a time). 200 `{started}`, 409 `{running}` if busy, 400 on unknown voice. On clean exit the voice is set active.
- `GET` `/api/settings/tts/install/status` — `{running, voice, exitCode, log}` — polled by the Settings page to stream install progress.
- `GET` `/api/settings/conventions/project` — `{conventions:[{slug,name,description,body,builtin,skill?,source?,scaffold?,skillError?}]}` — merged catalog: built-in seeds (`builtin:true`, bodies from `conventions/project/*.md`) + custom conventions from `<store>/conventions/project.json` (`builtin:false`). Selected per project at creation, or later with `PUT /api/projects/:name/conventions`, and recorded in that project's `CONVENTIONS.md` marker (regenerated, not snapshotted) as one of three states — unset, none or selected slugs; no global selection. `skill: {description, body}` is present on an entry whose fragment file, or custom body, carries a skill part; `body` is then its inline part ([components/playbooks.md → Convention skill parts](../components/playbooks.md#convention-skill-parts)). A custom entry also carries `source` (its body as stored, which the Settings editor edits) and, when its stored marker does not parse, `skillError` (its `body` is then the whole stored text); a project custom may carry `scaffold`.
- `POST` `/api/settings/conventions/project` — `{slug,name,description,body,scaffold?}` — add custom convention. `body` may carry a skill marker line (`<!-- cc:skill <description> -->`); a malformed one, a second one, an empty description or skill body, or an explicit name → 400. `scaffold` (one-time setup directive) is accepted here only; `body` may be empty when a non-empty `scaffold` is given. Slug `^[a-z][a-z0-9-]*$` max 40 chars; 409 on duplicate/builtin slug. Returns `{convention}`.
- `PUT` `/api/settings/conventions/project/:slug` — `{name?,description?,body?,scaffold?}` — update custom convention; `scaffold:''` removes it; the same body validation as POST. 400 on builtin, 404 not found. Returns `{convention}`.
- `DELETE` `/api/settings/conventions/project/:slug` — Remove custom convention. 400 on builtin, 404 not found. Returns `{slug}`.
- `GET` `/api/settings/conventions/conductor` — `{core:{name,description}, conventions:[{slug,name,description,body,builtin,skill?,source?,skillError?}], enabled:[slug,…]}` — conductor convention catalog + global enabled selection. built-in seeds (`builtin:true`, bodies from `conventions/conductor/*.md`) + custom conventions from `<store>/conventions/conductor.json` (`builtin:false`); the always-on core is not in `conventions`. Also carries `playbooks` (the `list_playbooks` catalog, same implementation), `playbookErrors` (definitions rejected at load), `defaultPlaybook` (the tri-state selection `{mode:"unset"|"none"|"playbook", id?}`), `defaultPlaybookMissing` (`{id, reason}` when the selection names an id no loaded definition backs — the reason names the owning plugin for a plugin playbook — else `null`) and `defaultPlaybookFallback` (what `unset` resolves to — `DEFAULT_PLAYBOOK_ID`, `src/playbooks.ts`) for the Preferred-playbook picker in the same block, plus `defaultPlaybookEnforcement` (the persisted level new conductors start at) and `playbookEnforcementModes` (`PLAYBOOK_ENFORCEMENT_MODES`, the rows the enforcement picker builds from) for the Playbook-enforcement picker beside it. `skill: {description, body}` is present on an entry whose fragment file, or custom body, carries a skill part; `body` is then its inline part ([components/playbooks.md → Convention skill parts](../components/playbooks.md#convention-skill-parts)). A custom entry also carries `source` (its body as stored, which the Settings editor edits) and, when its stored marker does not parse, `skillError` (its `body` is then the whole stored text); a project custom may carry `scaffold`.
- `PUT` `/api/settings/conventions/conductor/default-playbook` — `{defaultPlaybook: {mode:"unset"}|{mode:"none"}|{mode:"playbook", id}}` — set the preferred playbook composed into the conductor role doc as a generated convention. Unknown `mode` or unknown id → 400; a body with **no `defaultPlaybook` key** → 400 (a state change is explicit, never an empty body). Effect on next conductor spawn. Returns `{defaultPlaybook}` (the stored selection).
- `PUT` `/api/settings/conventions/conductor/default-playbook-enforcement` — `{mode:"warn"|"enforce"}` — set the level newly spawned conductors start at. Anything outside `PLAYBOOK_ENFORCEMENT_MODES` (including the retired `off`, which is readable but never writable) → 400; a body with **no `mode` key** → 400. Effect on next conductor spawn. Returns `{defaultPlaybookEnforcement}`.
- `PUT` `/api/settings/conventions/conductor/selection` — `{enabled:[slug,…]}` — set the global enabled convention selection (unknown slug → 400). Takes effect on the next conductor spawn/resume (the role doc is recomposed then and rewritten to `<projectsRoot>/.conduct/CONVENTIONS.md`, which is where you inspect what a toggle actually produced). Returns `{enabled}`.
- `POST` `/api/settings/conventions/conductor` — `{slug,name,description,body}` — add custom convention (a non-empty `scaffold` → 400 `scaffolds are project-scope only`; a skill marker in `body` is validated as for the project scope). Slug `^[a-z][a-z0-9-]*$` max 40 chars; 409 on duplicate/builtin slug. Effect on next conductor spawn. Returns `{convention}`.
- `PUT` `/api/settings/conventions/conductor/:slug` — `{name?,description?,body?}` — update custom convention (a non-empty `scaffold` → 400). 400 on builtin, 404 not found. Effect on next conductor spawn. Returns `{convention}`.
- `DELETE` `/api/settings/conventions/conductor/:slug` — Remove custom convention (also prunes its slug from the persisted `disabled` deny-list, so a re-created one of the same slug is on). 400 on builtin, 404 not found. Effect on next conductor spawn. Returns `{slug}`.
- `GET` `/api/settings/conventions/workspace` — `{core:{name,description}, conventions:[{slug,name,description,body,builtin,skill?,source?,skillError?}], enabled:[slug,…]}` — workspace convention catalog + global enabled selection. built-in seeds (`builtin:true`, bodies from `conventions/workspace/*.md`) + custom conventions from `<store>/conventions/workspace.json` (`builtin:false`); the always-on core (`conventions/workspace/core.md`) is not in `conventions`. `skill: {description, body}` is present on an entry whose fragment file, or custom body, carries a skill part; `body` is then its inline part ([components/playbooks.md → Convention skill parts](../components/playbooks.md#convention-skill-parts)). A custom entry also carries `source` (its body as stored, which the Settings editor edits) and, when its stored marker does not parse, `skillError` (its `body` is then the whole stored text); a project custom may carry `scaffold`.
- `PUT` `/api/settings/conventions/workspace/selection` — `{enabled:[slug,…]}` — set the global enabled convention selection (unknown slug → 400). Regenerates the app-owned `<PROJECTS_ROOT>/CLAUDE.md`. Returns `{enabled}`.
- `POST` `/api/settings/conventions/workspace` — `{slug,name,description,body}` — add custom convention (a non-empty `scaffold` → 400 `scaffolds are project-scope only`; a skill marker in `body` is validated as for the project scope). Slug `^[a-z][a-z0-9-]*$` max 40 chars; 409 on duplicate/builtin slug. Regenerates. Returns `{convention}`.
- `PUT` `/api/settings/conventions/workspace/:slug` — `{name?,description?,body?}` — update custom convention (a non-empty `scaffold` → 400). 400 on builtin, 404 not found. Regenerates. Returns `{convention}`.
- `DELETE` `/api/settings/conventions/workspace/:slug` — Remove custom convention (also prunes its slug from the persisted `disabled` deny-list, so a re-created one of the same slug is on). 400 on builtin, 404 not found. Regenerates. Returns `{slug}`.
- `GET` `/api/usage` — `{usage, stale, fetchedAt}` — account-level usage from the Anthropic OAuth endpoint (`src/accountUsage.ts`), cached server-side (`CACHE_TTL_MS` in `src/accountUsage.ts`). When a fresh fetch isn't available the last retained payload is served with `stale: true` (bounded by `maxStaleMs`); `fetchedAt` is when that payload was fetched (ms epoch). With nothing usable, `{usage: null, stale: false, fetchedAt: null}` (missing creds, 401, network — common on Termux where Node DNS fails); the token is never exposed to the browser. A successful Claude login drops the cache, and a fetch already in flight then caches neither its answer nor its failure. Drives the rate-limit/usage chip.
- `GET` `/api/claude-auth/status` — `{loggedIn, authMethod, apiProvider, email, orgId, orgName, subscriptionType, apiKeySource, configDirectory}` — the orchestrator CLI's `claude auth status --json`, run with the worker-spawn binary and env (`src/claudeAuthStatus.ts`). Every field but `loggedIn` may be `null`; `authMethod` is `"none"` when absent (seen: `claude.ai`, `api_key`, `none`). `loggedIn` = credentials present, not validated. Cached per server for `STATUS_CACHE_TTL_MS` (`src/claudeAuthStatus.ts`), single-flight (concurrent requests share one CLI run), dropped when a login starts or succeeds; errors are not cached. **502** `{error}` when the CLI can't be started, times out, or prints no parseable JSON (its exit code is ignored: signed out is exit 1 with JSON).
- `GET` `/api/claude-auth/login` — `LoginSnapshot` `{state, url, error, startedAt, endedAt}` (`src/claudeLogin.ts`) — the one server-side login flow, polled by the client. `state` ∈ `idle` · `starting` · `awaiting_code` (`url` set) · `verifying` · `succeeded` · `failed` (`error` set) · `cancelled`; a terminal state stays readable until the next start. `error` during `awaiting_code` is the CLI's complaint about the last code. The submitted code is never returned.
- `POST` `/api/claude-auth/login` — Starts `claude auth login` (`BROWSER=true`, no config-dir override). Returns the snapshot (`starting`). **409** `{error}` while a flow is active.
- `POST` `/api/claude-auth/login/code` — `{code}` — writes the trimmed code as one stdin line. Returns the snapshot (`verifying`). **400** when `code` is not a string, is empty, holds `\r`/`\n`, or is longer than `MAX_CODE_LEN` (`src/claudeLogin.ts`); **409** when no flow is in `awaiting_code`.
- `POST` `/api/claude-auth/login/cancel` — Kills an active flow (SIGTERM, SIGKILL after a grace period) and returns the snapshot (`cancelled`); with no active flow it returns the snapshot unchanged.
- `GET` `/api/costs/summary` — Aggregated spend from `<store>/costs.jsonl` (`src/costTracking.ts`, one row per turn). `{total_usd, row_count, by_project:[{project, cost_usd, duration_ms, duration_api_ms, turns, sessions, cache_misses, tokens_known, tokens_estimated, by_model:[{model, cost_usd, duration_ms, duration_api_ms, input_tokens, output_tokens, cache_creation_tokens, cache_read_tokens, turns, sessions, cache_misses, tokens_known, tokens_estimated}]}], by_model:[…same shape…], daily_trend:[{date, cost_usd, input_tokens, output_tokens, cache_creation_tokens, cache_read_tokens, tokens_known, tokens_estimated}]}`. Each `daily_trend` entry's token sums cover all models and projects for that UTC day and count only `tokensKnown` rows; `tokens_known` / `tokens_estimated` carry the same definitions as on `by_model`. Each `by_model`/`by_project` entry's `cache_misses` is a plain count of its rows with the persisted `cache_miss` flag `=== true` (decisive for new rows, heuristic-backfilled by migration 0014 for pre-existing rows); `sessions` is the count of distinct `sessionId`s among its rows (`sessionId == null` rows excluded); `duration_ms`/`duration_api_ms` sum the persisted turn-walltime / LLM-time (legacy rows contribute 0). `cost_usd` is absent on rows from a non-Claude backend (`src/costTracking.ts`'s `appendCostRow` omits it — the CLI's `total_cost_usd` is Anthropic list pricing, meaningless for a free local backend) and treated as 0 in every aggregate.
  The four token fields (`input_tokens`/`output_tokens`/`cache_creation_tokens`/`cache_read_tokens`) are the turn's `result.usage` sums on every backend, and are **absent** on a row whose `turn_end` carried no `usage` (the only other token signal, `message_start`, is a non-summable context-size snapshot; `appendCostRow` omits the fields rather than write fabricated 0s). **`tokens_known`** is true on a `by_model`/`by_project` entry exactly when at least one of its rows is token-bearing: a numeric `input_tokens`, and — on a row without `cost_usd` (non-Claude) — at least one of the four token fields non-zero (an all-zero non-Claude row is a proxy's all-zero report, not a measurement; a Claude row with `cost_usd` counts whatever its values). Only token-bearing rows contribute to the token sums, so a mixed entry keeps the real totals of its token-bearing rows and an entry with none reports `tokens_known: false` (drives the `—` display). **`tokens_estimated`** is true when any of the entry's rows carries `cache_estimated: true` — its `input_tokens` / `cache_read_tokens` include the cache estimate's split (`turn_end.cacheEstimate`); drives the `≈` display. Zeroed empty shape when no `costs.jsonl` yet. Backs the `#costs` dashboard (`web/src/features/views/CostsView.tsx`). Rows also carry `cache_miss_heuristic: true` when migration 0014 (not a decisive live capture) decided the `cache_miss` verdict — absent on live-written rows, so its absence always means "decisive".
- `GET` `/api/costs/session/:sessionId` — Per-session cost + timing for the `#costs`-independent in-session **Statistics** panel. `{sessionId, own:{cost_usd, duration_ms, duration_api_ms, turns}, rolled:{…same shape…}, workerSessions}`. `own` sums only that session's rows; `rolled` recursively folds in every descendant worker session via the `parentSessionId` tree (cycle-guarded); `workerSessions` is the count of distinct descendants folded in. Zeroed shape for an unknown session.

### Response headers

- **Every response cc produces** carries `HOST_SECURITY_HEADERS` (`src/securityHeaders.ts`): `X-Frame-Options: SAMEORIGIN`, `Content-Security-Policy: frame-ancestors 'self'` and `X-Content-Type-Options: nosniff`. `server.ts` sets them with the app-level `hostSecurityHeaders()` ahead of every mount, and disables `X-Powered-By`.
- **Covered:** `/api` (errors and NDJSON streams included), `/mcp`, the `/plugins` mount's own 301/404/502/503, `/pluginBridge.js`, `/pluginTheme*`, the static UI and the building page.
- **Express's default 404/500 and serve-static's directory redirect** replace the CSP with `default-src 'none'`, which does not govern framing; `X-Frame-Options` is their framing protection.
- **WebSocket upgrades** (101 and refusals) are raw socket writes and render no document; an upgrade failing the [Origin check](websocket.md#websocket-protocol) is a raw `403`.
- **Proxied plugin responses** do not carry cc's policy; see [plugins/runtime.md](../plugins/runtime.md) → Reverse proxy.
- **Pins:** `tests/security-headers.test.mjs`, `tests/plugins-proxy.test.mjs`, `web/e2e/frame-ancestors.spec.ts`.

### Base path and reverse proxies

`CC_BASE_PATH=/apps/cc-2` (an absolute path prefix, fixed at startup; [environment.md](../environment.md)) hosts cc under a sub-path behind a reverse proxy, so a host page, another app or a plugin can embed it same-origin.

- **Strip if present.** `basePathMiddleware` (`src/basePath.ts`) is the first middleware after `hostSecurityHeaders()`, and `server.ts`'s `upgrade` dispatcher does the same first step: a request URL that equals the base, or starts with `<base>/` or `<base>?`, loses the base before routing. A near-miss (`/apps/cc-2x/…`) is not stripped. Every mount stays at root, so a **pass-through** proxy (`/apps/cc-2/api/x` → cc as is) and a **stripping** proxy (`/apps/cc-2/api/x` → `/api/x`) reach the same handler, and loopback callers (`CONDUCTOR_URL`, hook URLs, `--mcp-config`, a plugin's `CONDUCTOR_MCP_URL`, `CC_RUN_URL`) keep using root URLs unchanged.
- **Bare base.** `<base>` or `<base>?…` answers `301 Location: <base>/<search>`. The UI must be loaded at `<base>/` with the trailing slash: its URLs are relative and its app base is the page's directory. A stripping proxy must redirect a bare `<base>` itself (nginx's `location /apps/cc-2/ { proxy_pass http://cc/; }` does).
- **Validation.** `parseBasePath`: unset, empty or `/` is root; otherwise it starts with `/`, one trailing `/` is dropped, and each segment is non-empty, not `.` or `..`, and made only of RFC 3986 unreserved characters `[A-Za-z0-9._~-]` (the base is spliced into rewritten HTML attributes, so no quote, angle bracket, ampersand, `?`, `#` or `%` is ever accepted), and does not start with a root-served name (Ambiguity). An invalid value fails boot (`failed to start:`, exit 1).
- **Ambiguity.** A root path that begins with the base is always read as prefixed, so a base must not begin with any first segment cc serves at root, or its own routes would turn unreachable at root (`CC_BASE_PATH=/api` would 404 `$CONDUCTOR_URL/api/health`, `/mcp` would 301 `POST /mcp`). `reservedRootSegments` (`src/basePath.ts`) lists them: `api`, `mcp`, `ws`, `plugins`, `pluginBridge.js`, `pluginTheme.css`, `pluginTheme`, `assets`, `index.html` and every file of `web/public` (icons, `sw.js`, `manifest.webmanifest`); `parseBasePath` refuses a base whose first segment is one (deeper segments are free: `/apps/api` is valid), and `tests/base-path.test.mjs` checks the list against the mounts in `server.ts` and `src/pluginTheme.ts` and the files in `web/public`. So a cc cannot be hosted under another cc's `/plugins/<id>` mount.
- **Proxy must:** forward `Host` unchanged (the WebSocket [Origin check](websocket.md#websocket-protocol) compares `Origin` with `Host`) and pass `Upgrade`/`Connection` for `/ws` (nginx: `proxy_set_header Host $http_host; proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade";`; `$http_host` keeps the port the browser used, which `$host` drops, so the Origin/Host comparison would fail on a non-default port).
- **Inbound `X-Forwarded-Prefix` is ignored**: the base is the env value, never the request's.
- **Plugins.** The plugin proxy sends `X-Forwarded-Prefix: <base>/plugins/<id>`, prefixes the `Location` it rewrites and its bare-id 301, asks the child for `accept-encoding: identity`, and re-roots `"/pluginBridge.js"` / `"/pluginTheme.css"` attribute values in `text/html` responses. See [plugins/runtime.md](../plugins/runtime.md) → Reverse proxy.
- **Framing headers are unchanged**: same-origin embedding only ([Response headers](#response-headers)).
- **cc has no authentication.** A proxy that exposes it must supply auth.
- **Pins:** `tests/base-path.test.mjs`, `tests/base-path-server.test.mjs`, `tests/plugins-proxy.test.mjs`, `web/src/clientRootUrls.test.ts`, `web/e2e/base-path.spec.ts`.

### Static routes

Mounted after `/api`, `/mcp` and `/plugins` (`server.ts`), so they never shadow those. No SPA fallback: the UI routes by URL hash.

| Path | Answer |
|---|---|
| `/` | The web UI (`web/dist/index.html`, `webHandler()` in `src/webBuild.ts`) and its assets, `sw.js`, `manifest.webmanifest` and icons, all root-relative to the page, served at `/` and, under `CC_BASE_PATH`, at `<base>/` too.

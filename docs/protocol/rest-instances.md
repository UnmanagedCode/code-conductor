# Protocol: REST — instances, worktrees and admin

## REST endpoints: instances, worktrees and admin

- `POST` `/api/instances` — Spawn. Returns summary. A `--replay` under `--ui view` (launchless) answers every call `409` with `code: VIEW_REPLAY_NO_LAUNCH`. A **fresh** spawn (no `resume`) that names **neither `model` nor `backend`** resolves both from a Settings → Models row's binding, so `--model` is always explicit and never the account default (same rule as MCP `spawn_instance`). Which row: `role` if it names a resolvable one, else `tier` if it names a known one, else the default tier (`defaultSpawnBinding()`). The model and the default effort always come from that one row — per-branch mechanism in [models.md](../models.md#same-row). Absence is tested on the **trimmed** value — `model: ""` or `"   "` is the same request as omitting it. A fresh spawn naming **`backend:"claude"` with no `model`** takes the model from the same row when that row is on `claude`, and otherwise refuses **422 `BACKEND_MODEL_MISSING`** — naming a backend is a choice the gate never overwrites, so the row supplies only the model. Optional `tier`/`role` selects the Settings → Models row for BOTH the binding above and the default effort when `effort` is omitted (`resolveSpawnEffort`, see [models.md](../models.md#default-effort)); an unknown name falls back to `DEFAULT_EFFORT` (`high`, `src/effortLevels.ts`) rather than refusing. The web UI always sends `tier` (spawn dialog) or `role` (Conduct) and no `model`/`backend` — the server resolves the row's current binding at spawn time, so a stale client cache can't pin an old model.
  Optional **`persistent`** (boolean): `true` spawns a persistent session (stays listed, stopped and resumable, when it ends); omitted or `false` spawns a normal one (archived on exit); any other value is refused **400 `persistent must be a boolean`** before any instance exists. It never picks the mode: a mode-less spawn is `plan` either way. A `{resume}` that omits it recovers the session's kind from its record (a session cc has no record of resumes normal). Backend refusals, before any subprocess: **422 `BACKEND_GONE`** when the named backend isn't in the registry (explicit `backend`, or the one recorded on the resumed session's record) — never a fallback to `claude`; **422 `BACKEND_MODEL_MISSING`** when a substitution backend has no resolvable model (unconditional on the template shape), or when `backend:"claude"` is named with no `model` and the row the spawn resolves to is bound to a substitution backend (per-backend matrix: [models.md](../models.md#same-row)). See [models.md](../models.md#missing-backends-are-refused-never-downgraded).
  For a project on a system, two more pre-spawn refusals fire before any `Instance` exists: **501 `FUSE_LAUNCHER_UNRESOLVED`** when the `claude` CLI does not resolve to an absolute path on cc's machine (the union's marking event and the CLI's only host pin), and **501 `FUSE_BACKEND_UNRESOLVED`** when the session's backend launch command (the template's first token) does not resolve on cc's PATH — refused for attribution, since an exec failure inside `setpriv` names nothing. Both exempt where the launcher runs the CLI in cc's own process. A `{resume}` on a project on a system resolves at the project's own path there — fixed at registration, so a moved mirror advertisement has nothing to relocate and there is no candidate set to search. Two outcomes: `201`, or **404 `SESSION_UNKNOWN`**. For a project on a system whose worker gets a FUSE-union chroot, two refusals are asked **live at every launch** rather than from any memoised answer, before the mount is prepared and therefore before a run directory exists: **502 `FUSE_REMOTE_UNREACHABLE`** (a `true` on the far side did not answer — the message names the remote, the system and the far side's own reason) and **501 `FUSE_MIRROR_ROOT_ABSENT`** (the far side is up and the advertised mirror root is not on it). The shared error handler sends the message alone, so over HTTP the **status** is what distinguishes the two.
  When `worktree:true` and a `post-worktree-create.sh` hook is found (in-tree `<parent>/.code-conductor/…` first, else central store `<root>/.code-conductor/projects/<name>/…`; read from disk, not the new worktree), the summary's `worktree.postWorktreeCreate` field carries the hook result — including `source: 'in-tree' | 'store'` (see below). `project: '.conduct'` first ensures the hidden conductor project (`ensureConductProject`), so no earlier `/ensure` call is needed. `pristine: true` (New conductor's create, `web/src/features/dialogs/conduct.ts`) starts a **pristine** conductor, listed nowhere until its first prompt (see `GET /api/instances` and the `pristine_*` WebSocket frames); it is accepted only with `project: ".conduct"`, no `persistent: true` and no `resume`, and refused otherwise with **`400 PRISTINE_NOT_FRESH_CONDUCTOR`**.
- `POST` `/api/projects/.conduct/ensure` — Idempotent: create the hidden `.conduct` project if absent and guarantee its `CLAUDE.md` carries the `@CONVENTIONS.md` import. **200** + `{ok:true, path, created}`. Used by seeding (e2e, `tests/conduct.test.mjs`); a conductor create does it itself.
- `GET` `/api/instances` — List live, minus every **hidden** pristine conductor (pristine with no draft title; `InstanceManager.listVisible()`): a pristine conductor listed under a draft is in it. Each row carries `contextTokens` (the same figure and null rule as `turn_end.contextTokens` above) beside `contextWindowTokens`, the session record's turn marks `turnEndSeq` (every real `turn_end`, whoever started the turn) and `viewedSeq` (unread ⇔ `turnEndSeq > viewedSeq`; hydrated from the store at every launch, so they survive a resume or restart; a change rides the `turn_marks` → `{t:'instances'}` hint alone), the live-only attention counters `liveTurnEnds` (outer turn ends this Instance object has seen, not counting one a commanded stop interrupted), `lastTurnError` (the latest counted one's `is_error`) and `liveAsks` (null→ask transitions of `awaitingUser` seen live) — per Instance object, never hydrated, so a resume cannot fake a transition; read by the browser's attention notifier (`shared/attention.ts`), and `rootSessionId` / `parentSessionId` (non-null only on a live conducted worker), `awaitingUser`, `awaitingUserSource` (see [Emitted handles](mcp.md#mcp-tool-protocol)); a change to any of those four rides the existing `status` → `{t:'instances'}` + `{t:'projects'}` broadcasts, with no frame of its own.
  Each row also carries `playbook`/`stage` — the same binding MCP's `list_sessions`/`describe_session` report (`null`/`null` for a worker not bound to a playbook), read via one `playbookGate.readBindings()` batch call off the playbook gate `createServer` shares between the MCP and REST routers; an event-log read failure degrades every row to `null`/`null`, with one server-side warning for the whole request rather than failing the list. Each row carries `displayLabel`, the label the sidebar shows for a live session (`sessionLabel`, `shared/promptPreview.ts`) except where the sidebar reads the transcript's own first prompt, never empty — `(new session)` for an untitled, unprompted instance; see **`summary().pristine` / `title` / `displayLabel`** in [ws-events.md](ws-events.md#websocket-event-payloads).
- `POST` `/api/instances/:id/respawn` — Uses `--resume lastSessionId`. **501 `MIRROR_ADVERTISEMENT_CHANGED`** when the project's system answers a different mirror root or exclude list than the one this session was created under: no worker is started, `cwd` is unchanged, the instance stays registered, and the message names both geometries. **It fires on every relaunch in place** — rewind, prune recovery, resume after a restart — since each takes the same `launch()` path. The `code` rides the manager entry point (`InstanceManager.respawn`); the REST body carries the message only. Also **409** while a `spawn_instance({resume})`/UI resume is in flight for that session — reviving the instance in place would race the resume's reclaim of it — and **409** inside a relaunch window (`relaunching` / `rotationPending`: a restart model switch's whole run, a rewind's kill→relaunch, a prune's rotation), whose owner is about to start the next CLI on the same jsonl.
- `GET` `/api/instances/:id/events` — Paged event history (incl. events evicted from the capped ring, reconstructed by replaying the session jsonl). `before=<seq>` pages **backward** (oldest-first; echo the response's `nextBefore` to continue; wins over `after`); `after=<seq>` pages forward, **exclusive** (events with `_seq > after`; `after=-1` reaches `_seq 0`; exact `limit`); neither ⇒ trailing page. `limit` is clamped to a bounded range with a fixed default (see the event-paging schema). Returns `{id, events, hasMore, nextBefore, trimmedBefore, lastSeq}`. 400 non-integer params, 404 unknown id (a retired instance's frozen pager still answers, as for `lineage-events`). Paging mechanics (quiescent alignment, cursor, synthetic events) in the note below.
- `GET` `/api/instances/:id/lineage-events` — The web UI's scroll-back across the session's **whole lineage** (the live ring, then every earlier backing segment down to `initial`); **UI-only, no MCP caller**. **Backward only.** `segment=<id>` is the cursor space a previous page handed out (absent or empty ⇒ the live space); `before=<int>` the cursor in it (absent ⇒ that space's newest page); `limit` as for `/events`. Returns `{id, events, hasMore, segment, nextBefore, pageSegment, currentSegmentId}` — `segment`/`nextBefore` are the next request's cursor (`nextBefore: null` ⇒ that segment's newest page), `pageSegment` the segment the page's first seq'd event came from, `currentSegmentId` as on the snapshot. Progress rule: accept a page iff its `segment` is unchanged and `nextBefore` strictly lower, or its `segment` is one not yet visited in this walk. 400 `before must be an integer` / `limit must be an integer`; 400 `segment is not an older segment of this session` (`NOT_AN_OLDER_SEGMENT`) when `segment` is neither the ring-head view nor one of the walk's own steps (a prune-skipped original, the current segment, an unknown id); 404 unknown instance — an instance dropped from the manager (a killed or exited normal worker) is still served from a frozen copy of its pager, as `/events` is, until forgotten (`RetiredPagers`, see [components/sessions.md](../components/sessions.md#srcretiredpagersts)). See [Lineage scrollback](#lineage-scrollback).
- `GET` `/api/sessions/:sid/lineage-events` — The same walk and page shape for a session with **no instance** (the web UI's reopened read-only view): the session's current segment's transcript stands in for the ring (`retiredLineageSource`, `src/lineagePager.ts`; its seqs are that file's archive indices, unrelated to any instance's ring seqs), then the older segments as above. Same query params and 400s. Returns `{sessionId, events, hasMore, segment, nextBefore, pageSegment, currentSegmentId}`, `sessionId` the public id. 404 when `findSessionLocation` cannot place the session.
- `POST` `/api/instances/:id/rewind` — `{userMessageIndex, text}` — the bubble's `userIndex` and its raw event `text`. Atomic truncate + respawn (same `sessionId`). 409 during turn, 400 out-of-range, 400 `text must be a string`. 409 `PROMPT_MISMATCH` (`src/sessionEdit.ts`) when the prompt at that index replays to different text; 409 `PROMPT_UNRESOLVED` (`src/instances.ts`) when a rotated instance's live→file offset cannot be measured. Both refusals come before the kill: process, ring and file are untouched. Returns `droppedText` once the relaunch is **confirmed** — up idle and outlived `RELAUNCH_GRACE_MS` (`src/instances.ts`), so every response takes at least that long. A prefix with no user/assistant record (a rewind to the first prompt, whatever leading records precede it) relaunches with `--session-id` under the same id, the jsonl deleted; any other with `--resume`. A relaunch that is never confirmed answers `500 RELAUNCH_FAILED` (or the launch error's own status/code) with `error` = `the transcript was rewound, but the session failed to relaunch: <cause>` — the truncation stands, nothing is left running, a normal session is archived and dropped, a persistent one stays `exited`/`crashed` and resumable.
  **`{boundary}`** (a "Context renewed" divider's `segment_seam` `segmentId`) instead **undoes the latest renewal** (`Instance.rewindAcrossRenewal`): the pre-renewal segment, cut before the prompt that opened the turn which made the session's own `renew_session` call — the self form, with no `sessionId` in its input; a targeted call renews another worker and is no anchor (`renewalCut`, `src/renewalBoundary.ts`); restored whole for a typed `/clear`, i.e. when no post-renewal prompt is a reseed, becomes the live backing segment again — un-archived, `persistent` set to the session's current kind, `current` — and the post-renewal run (the renew entry to the chain's end, prune copies and tombstones included) is spliced out of the record (`undoRenewal`, `src/sessionLineage.ts`), its jsonls and sub-agent dirs deleted. 409 during a turn, as the bubble form (an exited or crashed session is accepted and relaunched); same public `sessionId`; returns `droppedText: null` (nothing prefilled — the dropped prompt is the renewal request). Exclusive with `userMessageIndex`/`text`: 400 `boundary cannot be combined with userMessageIndex/text`; 400 `boundary must be a segment id`.
  Refusals, all before the kill (process, ring, files and record untouched): 400 `NOT_A_RENEWAL_BOUNDARY` (`src/renewalBoundary.ts`; the label is unknown, the initial segment, or a prune-only run); 409 `RENEWAL_NOT_LATEST` (`src/instances.ts`; not the divider directly above the current segment — fork from it instead); 409 `PRE_RENEWAL_GONE` (`src/instances.ts`; the pre-renewal segment is a tombstone or its file is missing); 409 `cannot locate the renewal request in the pre-renewal transcript`; 409 `cannot rewind during a running turn — interrupt first`; 409 `SESSION_ROTATING`; 409 `another rewind/fork/prune is in progress`; 400 no `sessionId` yet. 409 `RENEWAL_MOVED` (`src/sessionLineage.ts`) when the chain changed before the record write — the pre-renewal file is put back to its exact pre-undo bytes and the post-renewal segment is relaunched untouched; any other failure before the record write does the same. A relaunch that is never confirmed after the record write answers as above with `error` = `the renewal was undone, but the session failed to relaunch: <cause>`; a failure after the record write but before the relaunch (re-anchoring the model-switch dividers) reads `the renewal was undone, but finishing it failed: <cause>`, same status/code mapping, nothing left running. The undo stands either way.
- `POST` `/api/instances/:id/fork` — `{userMessageIndex, text}` — the bubble's `userIndex` and raw `text`, as `/rewind` takes them. **`{}` (neither field) forks the whole transcript** (`Instance.forkAtTip`): idle only, so one read with no wait; every complete line is copied, `droppedText` is `null` and the new instance's first `snapshot` carries none; it inherits `persistent`, title, backend/model/context window like a message fork. Its refusals: 409 `the whole session can only be forked between turns …` (status not `idle`, or a turn started while the transcript was being read); 400 `nothing to fork yet — the session has no conversation` (no user/assistant record); 400 no `sessionId` yet; 409 `SESSION_ROTATING`; 409 `another rewind/fork/prune is in progress`. One field without the other is the message form and 400s on the missing one. The rest of this row is the message form: **Allowed mid-turn**, on any current-segment prompt including the running one; the source keeps running and the fork never refuses its prompts. Copies prefix to new `sessionId` from one complete-line read of the source jsonl (an unterminated last line is ignored); original is byte-identical, spawns fresh instance. Composer prefill rides the new instance's first `snapshot` frame as `droppedText` (also returned in the body, informational). A fork inherits its source's `persistent`.
  A titled source's fork is titled `forkTitle(<source title>)` (`src/sessionTitles.ts`), stored via `applySessionTitle` before the spawn; an untitled source's fork is untitled. Refusals (none writes a file; `code`, where shown, is in the body): 400 `PROMPT_OUT_OF_RANGE` (no prompt at that index, and none owed); 400 no `sessionId` yet; 400 `nothing before this prompt to fork from` when the prefix holds no user/assistant record (e.g. a session's first prompt, or a renewed segment's `/clear` bubble); 409 `PROMPT_MISMATCH` (message prefix, `src/sessionEdit.ts`); 409 `PROMPT_UNRESOLVED` (message prefix, `src/instances.ts`; refused at once, no wait); 409 `PROMPT_NOT_PERSISTED` — the prompt's echo was emitted but its line is not in the transcript within `FORK_PERSIST_WAIT_MS` (`src/instances.ts`; waits only while a turn runs, re-checking the file's size every `FORK_PERSIST_POLL_MS`; the first read begun with no turn running is final, so an idle source or a just-ended turn refuses at once — including, briefly, a steer the CLI still held queued when the turn ended; a retry succeeds); 409 `FORK_SOURCE_CHANGED` — the source's backing id, segment or process changed while the fork waited; 409 `SESSION_ROTATING` (a renewal/prune in flight at the start); 409 `another rewind/fork/prune is in progress`.
  **`{boundary}`** (a "Context renewed" divider's `segment_seam` `segmentId`) **forks from before that renewal** (`Instance.forkAtRenewal`) — checked before the anchorless `{}` form, so it never reaches the whole-session fork. Any renewal divider, not only the latest; **allowed mid-turn** (it reads a retired segment no turn writes). Copies the pre-renewal segment cut as `/rewind {boundary}` cuts it (whole for a typed `/clear`) from one complete-line read into a new one-segment session — its scroll-back stops at that segment; the source's files and record are untouched. `droppedText: null`, no prefill; inherits `persistent`, title, backend/model/context window like the other forms. Refusals (none writes a file): the `/rewind {boundary}` body 400s; 400 `NOT_A_RENEWAL_BOUNDARY`; 409 `PRE_RENEWAL_GONE`; 409 `cannot locate the renewal request …`; 400 `nothing before this prompt to fork from` (the request was the segment's first prompt); 400 `nothing to fork yet …` (a typed `/clear`'s pre segment holds no conversation); 400 no `sessionId` yet; 409 `SESSION_ROTATING`; 409 `another rewind/fork/prune is in progress`.
- `GET` `/api/instances/:id/prune/analysis` — Per-turn prunable-token counts backing the Prune dialog. `{turnCount, turns:[{index, preview, thinking, toolInputTruncatable, toolInputMinimal, toolOutput, toolOutputImage, exempt, total}], encryptedThinking, calibration:{factor, steps, calibrated}, contextTokens}`. Per-turn figures are **raw** integer estimates; the client scales a sum by `calibration.factor` and rounds — the same arithmetic `POST /prune` applies to `saved`. `toolOutputImage`: the part of `toolOutput` owed to images — their dimension-driven cost less the whole stub's, floored at 0 — which is real, not estimated, so it is added **unscaled**: tool outputs = `round((Σ toolOutput − Σ toolOutputImage) × factor) + Σ toolOutputImage`. `exempt`: that turn's payload of exempt tools (see features/session-actions.md → Prune → Exempt tools) — kept, never saved. `encryptedThinking`: session-wide estimate of empty-text (encrypted) thinking, which Prune never rewrites. `calibration.factor`: measured ÷ estimated tokens over the session's usable usage steps, clamped to `CALIBRATION_MIN_FACTOR`…`CALIBRATION_MAX_FACTOR` (sessionPrune.ts); `steps`: how many steps were measured; `calibrated`: `false` when the measured estimate is under `CALIBRATION_MIN_TOKENS` and `factor` fell back to `1` (a clamped factor is calibrated). `contextTokens`: the instance's latched ctx reading (`input_tokens + cache_read_input_tokens + cache_creation_input_tokens` — the ctx chip's number), `null` when it holds none (after a prune until the next turn, after a model switch, on a fresh session). Counted over in-context entries only: sidechain lines, `toolUseResult`, and every line before the last `compact_boundary` are excluded. 400 when the instance has no `sessionId`.
- `POST` `/api/instances/:id/prune` — `{cutTurnIndex, pruneThinking?, inputMode?}` (`inputMode`: `truncate` | `minimal`, default `truncate`). Stubs turns `[0, cutTurnIndex)` — minus the exempt tools — into a copy under a new `sessionId`, archives the original, respawns the **same instance** against it — idle, with no seeded turn. Returns `{ok:true, oldSessionId, newSessionId, turnCount, cutTurnIndex, saved:{thinking,toolInputs,toolOutputs}, instance}`; `saved` is calibrated — each category's raw non-image estimate × the analysis's `calibration.factor`, rounded, plus its image part unscaled (see the analysis row's `toolOutputImage`). 409 during a turn (and from `POST /prompt`-style sends while any rewrite is in flight), 400 when `cutTurnIndex` is outside `0…turnCount` (`turnCount` itself is a legal FULL prune) or `inputMode` is unknown. An unknown `inputMode` is rejected before the subprocess is touched; an out-of-range cut is only detectable after reading the file, so that path kills, fails, and respawns against the original session. The response waits for the relaunch to be **confirmed** (`RELAUNCH_GRACE_MS`, as `/rewind`). A pruned relaunch that is never confirmed falls back to the unpruned original (also confirmed) before the error is returned (`500 RELAUNCH_FAILED` with the cause); if that fails too, nothing is left running and a normal session is archived and dropped.
- `DELETE` `/api/instances/:id` — SIGTERM + remove.
- `POST` `/api/instances/:id/persist` — Make a live normal session persistent: sets `persistent` on the instance and its segment, writes `last-prompt` + `permission-mode` so `claude --resume`'s picker can find it, emits `status` so the sidebar moves the row into its Persistent group. 400 `instance is already persistent`, 404 unknown id.
- `POST` `/api/instances/:id/debug` — Flip debug capture **ON** for a running instance (idempotent — `alreadyOn:true`). **No "off" endpoint** — kill the instance to stop.
- `POST` `/api/instances/:id/sync` — Measures and lands only what git can do alone; **never prompts the agent**. The session header's path (the commits view uses the worktree route below). Returns `syncWorktree`'s shared result: `ok:true` + `action: already-in-sync | fast-forwarded | rebased | commit-required | rebase-conflict` (the last two also carry `branch`/`baseBranch`/`baseSha`/`ahead`/`behind`/`rebasePrompt`), or `ok:false` + `reason`, passing through `{code:'WORKTREE_HAS_DEPENDENTS', dependents}` from the shared git layer. 404 unknown id, 400 if no worktree. A dead instance is fine — reporting sync state needs no subprocess.
- `POST` `/api/instances/:id/rebase-prompt` — Sends `buildRebasePrompt(meta, blocker)` to this instance's agent as a fresh prompt — the one place the land flow starts a turn. `blocker` is derived server-side (`worktreeDirtyLines`: dirty ⇒ commit-first brief, clean ⇒ conflict brief), never taken from the client. Returns `{ok:true, action:'rebase-prompt-sent', blocker}`; 404 unknown id, 400 if no worktree; no live subprocess ⇒ 200 `{ok:false, code:'SESSION_NOT_LIVE', reason}` — the same code the MCP surface uses, closing the gap the old `/sync` refusal left. A `git status` that **ran and failed** ⇒ 200 `{ok:false, code:'WORKTREE_STATUS_FAILED', reason}` and no prompt: an unmeasurable tree must not be reported to the agent as a clean one (the conflict brief asserts cleanliness). One that **never ran or never answered** does not reach that code — `runGit` throws, and this route is unguarded, so it surfaces as 502 `GIT_DID_NOT_RUN` / 504 `GIT_TIMED_OUT` (measured: 504). Either way no prompt is sent.
- `POST` `/api/projects/:name/worktrees/:wt/sync` — `/api/instances/:id/sync` addressed by worktree (`:name` = parent project): same result shape, needs no instance. 404 (listing the real worktrees) for an unknown `:wt`. Used by the commits view.
- `POST` `/api/projects/:name/worktrees/:wt/merge` — Parent-side `--no-ff` merge of worktree `:wt`. Body `{allowDirty?: boolean}`. Refusals return 200 with `ok:false, reason` (and `code` where typed, e.g. `WORKTREE_LOCKED`, `NOTHING_TO_MERGE`, `WORKTREE_DIRTY`) so the UI can render inline; a worktree behind its base answers `reason` `… click Sync first to fast-forward / rebase`. `WORKTREE_LOCKED` (the user's lock on `:wt`, see the `/lock` route) is checked before every other refusal and needs no git. 404 (listing the real worktrees) for an unknown `:wt`. Success: `{ok:true, output, newSha, worktreeFastForwarded, postWorktreeMerge}` — the last is the project's `post-worktree-merge.sh` report (see `postWorktreeMerge` below), and the response waits for it.
- `PUT` `/api/projects/:name/worktrees/:wt/lock` — Set or clear the user's lock on worktree `:wt`. Body `{locked: boolean}`; anything else is 400 `locked must be a boolean`. Returns `{ok:true, worktree, locked}` — `worktree` the canonical name, `locked` the stored state. Stored as `locked: true` in the worktree's `worktree.json`; unlocking deletes the key. A locked worktree refuses `WORKTREE_LOCKED` on every merge path and on MCP `delete_worktree` (even with `force`); sync, a child merging **into** it and the REST `DELETE` below are unaffected. Invalidates the projects cache and broadcasts `{t:'projects'}`. 404 (listing the real worktrees) for an unknown `:wt`. **The only writer that clears the lock, or sets it on an existing worktree** — MCP `create_worktree({lock:true})` sets it at creation, and no MCP tool clears it.
- `GET` `/api/projects/:name/worktrees` — List with metadata.
- `GET` `/api/projects/:name/worktrees/:wt/sessions` — Worktree-scoped session list.
- `GET` `/api/projects/:name/worktrees/:wt/diff[?baseRef=&context=]` — Per-file **summary** of `<baseRef|baseBranch>...HEAD` — no hunks, never truncated (a `--numstat`/`--name-status` pass, immune to `DIFF_BYTE_CAP`). `{project, worktreeName, baseRef, files:[{path, oldPath, status, adds, dels, binary}], totalAdds, totalDels, totalFiles}`. `context` accepted for parity with the other two routes but has no effect here (no hunks are read). 404 unknown worktree. Add `?path=<repo-relative path>` to fetch that one file's hunks instead — see below.
- `GET` `/api/projects/:name/worktrees/:wt/diff?path=<path>[&baseRef=&context=]` — Per-file diff, fetched lazily by `FileCard` (`web/src/features/views/ReviewView.tsx`) when that file's card is first expanded. `{project, path, file:{path, oldPath, status, adds, dels, binary, hunks:[{header, lines:[{type:add|del|ctx, content}]}], truncated, oversized, bytes}}`. `context` clamped to a bounded range (default per the `contextLines` schema) and now applies only to this per-file fetch. `binary:true` ⇒ `hunks:[]`, no unified diff read. `adds+dels > FILE_DIFF_LINE_GUARD` (`src/gitDiff.ts`) ⇒ `oversized:true`, `hunks:[]`, unified diff never read (keeps `runGit`'s 16 MB `maxBuffer` unreachable). Otherwise the file's raw unified diff is capped at `DIFF_BYTE_CAP` (`src/gitDiff.ts`) → `truncated:true`, `hunks` = the parsed prefix, `bytes` = full raw size. `path` not part of the change set → 404. 404 unknown worktree; 400 bad `baseRef`.
- `GET` `/api/projects/:name/commits[?limit=]` — Commit log of the project's current branch (HEAD), newest first and `--topo-order`: **a parent never precedes any of its children** in `commits[]`. The frontend's lane assignment (`computeGraph`, `web/src/features/views/graph.ts`) requires it — git's default committer-date order breaks it whenever a rebase stamps a branch with one committer second. `{project, branch, commits:[{sha, shortSha, subject, author, relativeDate, isoDate, parents, ahead}], truncated, limit, hasUncommitted, aheadCount, aheadOf}`. `parents` is the array of parent SHAs (`%P`): `[]` for the root, ≥2 for a merge — the frontend uses it to draw the branch/merge graph. `limit` clamped to a bounded range with a fixed default (see `getProjectCommits`); `truncated:true` when more exist. `hasUncommitted` is **absent** (with `uncommittedUnknown:true`) when `git status` did not answer. `aheadCount`/`aheadOf` are the **number of commits ahead of the base** — not a count of leading rows — and the base it is measured against (upstream, else — on the worktree-scoped spelling below — the named worktree's recorded base branch), both `null` when not applicable. `aheadCount` counts the whole ahead set, which may exceed the window, so `commits.filter(c => c.ahead).length === aheadCount` holds only when `truncated` is `false`.
  Each commit's `ahead` is that commit's **own** answer — reachable from `HEAD` but not from `aheadOf` (`git rev-list HEAD ^<aheadOf>`), resolved from the same `aheadOf` the count was measured against, so both answer about the same base. They answer about the same **tip** wherever `HEAD` is the ref the count was measured for: always on the upstream path, but on the worktree path the count is measured off the recorded branch ref, so a detached `HEAD` inside a worktree can make the count and the flags disagree. It is **not derivable from a commit's index**: the ahead set is not a contiguous prefix of the window, because a branch that merges its moved-on base back in interleaves already-merged commits among ahead ones. When `aheadOf` is `null` — no base, or the set query failed where the count succeeded, in which case `aheadCount` is nulled too — every commit's `ahead` is `false`. Non-git project → `{branch:null, commits:[]}`. 404 unknown project.

- `POST` `/api/instances/:id/bash-forward` — `{command}` → **`application/x-ndjson`, streamed**: `{t:"notice"|"out"|"err", text}` frames as the output arrives, then a terminal `{t:"exit", code}`. The server side of a redirected `Bash`: `src/systems/bashForwarder.ts` runs locally in place of the worker's command and posts the ORIGINAL here, cc runs it on the system as its own `exec`, and the forwarder replays each frame onto its own stdout/stderr as it is parsed, exiting with `code`. **The body carries the command and nothing else** — the tool's `timeout` and the dispatching `agentId` are both absent, the first because cc needs it for nothing — at the tool timeout the CLI **detaches** the forwarder and hands the agent a background task, so the command keeps running under cc's own ceiling — and the second because there are no per-agent shells left to select. **A frame stream, not one object, because the worker must see a long command's output while it is still running** — `run_in_background` + `BashOutput` poll the forwarder's stdout, and an object cannot be parsed until its last byte. `notice` is emitted at most once and always LAST: it reports that the command's `cd` was discarded, which cannot be known until the command ends. The two output streams are separate frame types because the forwarder writes each to a different descriptor.
  **Never a 5xx for a command failure** — a command that destroyed its own framing, a dead provider or an expired ceiling all come back as `err` frames plus a non-zero `code`, because that is the channel the worker reads. **The client disconnecting is load-bearing**: the CLI kills the forwarder when the worker interrupts or stops a background task, and that aborted request is cc's only signal to kill the command on the far side. (At a plain tool **timeout** it detaches instead and **no abort reaches this route** — measured at CLI 2.1.258: the socket stays open and still accepts frame writes long past the timeout, the command runs on under cc's ceiling, and the CLI hands the worker a background task id instead. **`TaskStop` (CLI 2.1.258) on that task id closes this socket**, which is how a detached command is reclaimed before the ceiling expires.) A refusal (404 not redirected, 400 no command) is written **in the same frame shape**, so its reason reaches the worker instead of being ignored as an unknown body.

**`GET /api/instances/:id/events` paging mechanics.**
Backward pages are **quiescent-aligned**: the page start snaps to the nearest quiescent point (no open block, every `tool_use` resolved; outer `user_echo`/`turn_end` reset the scan), so each page holds only whole blocks and complete tool round-trips; sub-agent group integrity pulls a child's Task head (and thus the whole group) into the page, or pushes the page start past any child with no head at or before it in the loaded array.
Quiescent points are dense, so pages stay ~`limit`-sized.
Backward pages are never empty while `hasMore` is true: a window whose only servable cut would be its own `end` (the whole tentative window fell inside a forbidden component anchored by a headless group) is instead served from that window's own pre-snap start, down-snapped to the nearest quiescent cut — so a sub-agent child with no reachable head may ride along on a page and park client-side rather than the page coming back empty.
`hasMore: false` remains the only end-of-history signal, never `events: []`.
The `nextBefore` cursor jumps the numeric gap between the two seq spaces.
Evicted/archived events get their own dense `_seq` space strictly below `trimmedBefore`, cut so ring + archive never overlap — at the ring head's stamped `userIndex` when it's an outer echo (turn boundary), or content-correlated into the archive by `(kind, msgId, blockIdx)`/a `tool_result`'s `toolUseId` when it's mid-turn, falling back to the echo ordinal only when no correlator resolves (full correlator mechanics in [components/sessions.md](../components/sessions.md#srceventarchivets) → `eventArchive.ts`) — a mid-turn head with no correlator hit ⇒ gap, never duplication — marked with a seq-less synthetic `{kind:'history_gap'}` event placed at the archive/ring **seam** — the last event of a page whose window *ends* on that boundary, or spliced at the seam's own offset **inside** the served slice when the window *straddles* it (one page, `[…, 12, <GAP>, 13, …]`) — so in the reassembled stream it always sits between the last archive event and the first ring-side one.
**At least one** marker per backward walk: pages tile unconditionally (every window is served, none skipped), so some page always ends on the seam or straddles it.
Not exactly one — a page whose snapped start lands exactly *on* the seam splices at offset 0 while the page below it splices at its own end, yielding `[…, 12, <GAP>][<GAP>, 13, …]`.
That server-side double is known, narrow and deliberately not closed; the client collapses it at render time — `renderHistoryGap` (`web/src/conversation/model.ts`) skips the append when the last root item is already a gap divider, and `prependPage` (same file) drops a page's trailing gap divider when the rendered items below it begin with one (each page renders into its own `ConversationModel` via `renderPage`, so the append-side check cannot see across a page seam) — so a doubled marker surfaces as **one** "Earlier messages unavailable" divider.
The dedupe is adjacency-scoped: markers separated by real content are distinct seams and both render.
A page serving entirely **above** the seam with `hasMore:false` — only reachable via forward `after=` paging, where no further page follows — appends the marker after whatever it serves instead, so the eviction is never left unmarked).
Synthetic `{kind:'task_completion', tasks}` events (no `_seq`) are spliced in after the completing `TaskUpdate` of any task batch below the tail, so lazily-loaded history shows the finished-task bubble.
Full mechanics in [components/sessions.md](../components/sessions.md#srceventarchivets) → `eventArchive.ts` / `taskReconstruct.ts`.

**Paging across a live rotation** (a managed renew or a typed `/clear` — the instance, its ring and its `_seq`/`userIndex` counters keep running while the backing jsonl changes):

- **The archive is the current segment's jsonl only.** Which segment owns which ring seq range is `EventLog.seams` (`src/instances.ts`); `currentSegmentScope` (`src/eventArchive.ts`) reads it.
- **Ring head predates the current segment** (`trimmedBefore` below the last seam's `startSeq`) ⇒ no archive is loaded: the ring is the whole servable history and `hasMore` is never optimistic.
- **Ring head inside the current segment** ⇒ the echo cut is **calibrated by content**, because the CLI writes replay-only records at the head of a post-`/clear` jsonl (the `<command-name>/clear` line replays as an outer echo; its caveat and `system/local_command` line replay to nothing). When no ring turn correlates into the file, nothing is served from it and the seam marker lands directly before the ring head.
- **Served archive echoes are restamped into live space** with the same offset: `userIndex` = file ordinal − offset, dropped when that is negative or the offset is unmeasurable. So every current-segment bubble — ring-resident or archive-served — carries the live ordinal `/rewind` and `/fork` translate back (`Instance._fileOrdinalFor` → `measureSegmentEchoOffset`). A view of an older segment (`segmentStartSeq > 0`) is restamped the same way.
- **Floor marker.** Evicted events of *earlier* segments are never read and are marked by one `{kind:'history_gap'}` **before the first event this pager can serve** — the current file's first event, or the ring head when no archive is loaded. It is only ever spliced at offset 0:
  - backward: the first event of the terminal page (`hasMore:false`);
  - forward: only when the requested window reaches the evicted seqs — `after < 0` (MCP `fromSeq: 0`), or, with no archive loaded, `after + 1` below the ring head's `_seq`. An incremental poll from `nextFrom` or from `trimmedBefore` never carries it;
  - never appended by the terminal-forward backstop above, which still applies only to the no-`sessionId` marker.
- **Both markers on one page** — `[<GAP floor>, archive…, <GAP seam>, ring…]` — only when a page starts at the floor and also contains the seam: two distinct losses with real content between them. When the cut is 0 they are adjacent and one marker covers both.
- The seam-marker rules above (at least one per backward walk, the known double) are unchanged.
- **Live `get_transcript` shares this pager** (`source:'ring'`): a call without `fromSeq` is the newest backward page and carries the floor marker only when that page reaches the floor; older segments are never read.
- **The lineage route composes this pager per segment** ([Lineage scrollback](#lineage-scrollback)) and passes `markFloor: false` only when it serves what the floor stands for (the ring-head view or an older step) or marks it itself (a `top` gap). The seam marker is never suppressed.

### Lineage scrollback

`GET /api/instances/:id/lineage-events` (`pageLineageEvents`, `src/lineagePager.ts`) owns the cross-segment walk only; every page comes from a single-segment pager MCP also reads through.

**Sources, newest first** — per request, the lineage row's full chain (`chainFor`, tombstones included) is read, then the ring is captured in one tick. `H` = the segment owning the ring head (`segmentOfSeq(seams, trimmedBefore)`; the backing id before the first seam); `current` = the last seam's segment.

| Source | `segment` cursor | Served by | Floor marker (`markFloor`) |
|---|---|---|---|
| **live** | `null` | `pageInstanceEvents(inst)` — exactly `/events`' pager — then `insertRingSeamDividers` | only when nothing older is walked (no view, no step, no `top` gap) |
| **view** of `H` | `H` (only when `H !== current` and `trimmedBefore > 0`) | `pageInstanceEvents(segmentRingView(…))` — `H`'s file cut at the ring head as it stood before the rotation that superseded it; cursor ≤ `trimmedBefore` | only when there is no step and no `top` gap |
| **disk** step | the step's id | `loadStampedTranscript` + `pageStampedTranscript` (the two halves of MCP's `pagePersistedEvents`); a tombstoned step or missing file serves one `[{kind:'history_gap'}]` page | never |

- **Which older segments** (`lineageSteps(chain, H)`): walk the chain from `H` toward `initial`. An entry whose immediate successor (tombstones included) is a `prune` is that prune's original — skipped, never read. Every other boundary is a renew and gets one `segment_seam`, plus one `history_gap` when the skipped run just above it contained a tombstone. `top` = one `history_gap` above everything when the walk ends on a skipped run containing a tombstone, or the chain's oldest entry is not `initial` (an entry missing outright rather than tombstoned). An `H` absent from the chain walks nothing.
- **Marker placement.** Markers go at the start of the newer source's terminal page, top → bottom, so each is served once per walk. When a terminal page has no events and no markers, the next source is served in the same request; a response is empty only when history is exhausted.
- **Continuation.** live → the view (cursor `min(before, trimmedBefore)`, no marker) when viewable, else the first step; view → the first step; step `j` → step `j+1`; the last source → `top`, then `hasMore: false`.
- **The view's one value beyond the seams:** its `_userEchoCount` is the echo counter at seam `k+1` — the `userIndex` of the first outer `user_echo` at or after that seam in the captured ring, else the live counter. The archive cut reads it only for an initial (`startSeq 0`) segment.
- **Dividers inside the live ring**: `insertRingSeamDividers` draws one before each later seam's rotation init whose `startSeq > trimmedBefore`; a seam exactly at the floor is drawn by the walk's own marker instead, so no response carries both. The client additionally collapses a same-label divider repeated across responses, keeping the upper one.
- **Inherited cursor hazard**: a ring trim past the client's oldest rendered seq between two requests mixes the live and file seq spaces, exactly as it does for `/events`.

**`postWorktreeCreate` / `postWorktreeMerge` result fields** — `postWorktreeCreate` is present on `POST /api/instances` responses and MCP `create_worktree` / `spawn_instance({createWorktree:true})` results when a worktree was created; `postWorktreeMerge` on every **successful** (`ok:true`) `POST /api/projects/:name/worktrees/:wt/merge` response and MCP `merge_worktree` result, and never on a refusal (no hook runs for a merge that did not land).
Both reports share one shape: `{ ran: boolean, source?: 'in-tree'|'store'|null, exitCode: number|null, durationMs: number, output: string, truncated?: true, timedOut?: true, descendantsMaySurvive?: true, skipped?: 'disabled'|'STORE_HOOK_LOCAL_ONLY', error?: true }`.
`ran:false` means no hook script existed, or a hook was found and deliberately not run — `skipped` says which: `'disabled'` for the event's own kill-switch — `ORCH_DISABLE_POST_WORKTREE_HOOK=1` for the create hook, `ORCH_DISABLE_POST_WORKTREE_MERGE_HOOK=1` for the merge hook, neither touching the other (it returns before hook detection, so it carries **no `source`**), and **`'STORE_HOOK_LOCAL_ONLY'`** — the one skip that does carry `source:'store'` — for a store-sourced script on a non-`local` system (the script lives under cc's own store, so running it there would hand the remote shell a path that exists only on cc's machine; shipping the body across needs a cc-owned location on the system, which is a later phase).
An **in-tree** hook is unaffected on any system — it is already there.
When `ran:true`, `exitCode` is the script's exit code (0 = success; non-zero = failure, but worktree creation still succeeded).
`output` is capped to a tail bound (`HOOK_OUTPUT_CAP`; `truncated:true` when the raw output exceeded the cap); timeout `ORCH_POST_WORKTREE_TIMEOUT_MS` (default in `src/worktrees.ts`) — `timedOut:true` when the script was killed at the timeout, `exitCode` is null in that case, and `descendantsMaySurvive:true` alongside it means the project's system could signal only the direct child (its provider does not advertise `processGroupSignal`), so whatever the script started may still be running — the timed-out-`npm ci` case.
Absent, never `false`, whenever the process group was reached.
The hook is non-fatal: a failure or timeout never rolls back the worktree.
The merge hook's own differences: its kill-switch is `ORCH_DISABLE_POST_WORKTREE_MERGE_HOOK=1` and its timeout `ORCH_POST_WORKTREE_MERGE_TIMEOUT_MS` (each hook's pair leaves the other hook alone); it runs in the merge target with `CC_PRE_MERGE_SHA` / `CC_POST_MERGE_SHA` added, plus, for a target on cc's machine, `CC_SERVER_NODE` and — for the running server's own checkout — `CC_SERVER_BOOT_SHA` or `CC_SERVER_BOOT_UNKNOWN` ([features/worktrees.md](../features/worktrees.md) → Post-worktree-merge hook); and nothing it reports — a non-zero exit, `timedOut`, `error`, a skip — changes the merge's `ok`.
A throw while resolving or running it (not `system.exec`, which never rejects) reads `{ran:false, error:true, output:<message>}` rather than turning the landed merge into `SYSTEM_UNREACHABLE`.

**The restore files** (`src/resumeManifest.ts`, `src/pendingContinue.ts`; all under `<store>/`, each written tmp + rename):

| File | Shape | Written | Read |
|---|---|---|---|
| `pending-resume.json` | `{writtenAt, deliver, instances: [<entry>], clis: [{sessionId, pid, start, group}]}` — `deliver` ∈ `auto` (prompt each busy session at boot) \| `gated` (hold its notice for the banner); an absent `deliver` reads `auto`; `clis` the CLIs live at the stop, as in the running record | `finishDrain`, at every Restart and Shut down with ≥1 entry or live CLI | the orphan-CLI reap at every boot (not consumed); `takeRestoreSource` at an interactive boot, then unlinked |
| `running-sessions.json` | `{writtenAt, instances: [<entry>], clis: [{sessionId, pid, start, group}]}` — `start` the platform's process-start token (`null` until resolved), `group` whether the CLI leads its own process group | the running recorder, on change, while cc runs; removed by `finishDrain` after the manifest is written and the CLIs are stopped | the orphan-CLI reap at every boot (not consumed); `takeRestoreSource` at an interactive boot, then unlinked — present with no manifest ⇒ an unclean stop, always `gated` |
| `pending-continue.json` | `{notices: [{sessionId, kind, text, workers, at}]}` — `kind` ∈ `restart` \| `unclean`; `text` the exact notice Continue sends; `workers` the conductor's subtree sessionIds; removed when empty | a gated restore (`add`); a session's turn (`drop`); Continue / Dismiss (`take`) | `/api/resume-notices`; the boot session cleanup (its sessionIds and workers are kept) |

A manifest and a record both present (a crash after `finishDrain` wrote the manifest and before it removed the record, the CLI stop included) restores from the manifest; the orphan reap reads both files' `clis`, one row per pid and distinct start: a pid's null-start row is dropped when a row with a known start exists for that pid, and two different known starts are both kept for the start check.
**`<entry>` schema** (one per carried-over session, built by `buildResumeEntries`, consumed by `restoreFromResumeManifest`): `project`, `sessionId` (the cross-restart identity + `--resume` key), `cwd`, `mode`, `effort`, `thinking`, `model` (the concrete id for every backend — a Claude version id OR another backend's model id, byte-exact), `contextWindowTokens` (the session's last known capacity in raw tokens, or `null`; a **fallback only** — used if the model's custom-model row was deleted before the restart, since live registry resolution wins whenever it succeeds), `backend` (a registry id — belt-and-braces alongside the `backend` recorded on the session's record in `<store>/sessions.json`; a resume whose recorded backend has since been REMOVED from the registry is refused `422 BACKEND_GONE` rather than silently falling back to `claude` with a foreign model id), `worktreeName`, `persistent`, `conducted`, `debug`, `title`, `firstPrompt`, `autoApprovePlan`, `group` (`conductor`/`worker`/`other`), `wasBusy` (re-prompt gate), `workers` (conductor entries only).
Pending **overage auto-resume** state — persisted so a resume that was armed in memory survives the restart: `overageResumeAt` (fire deadline, epoch secs = window reset + buffer; `null`/absent ⇒ no pending resume), `overageStopped` (stop-resume intent boolean), `overageWasStopped` and `overageIdleParked` (the two positive resume-preamble selectors — stopped mid-work vs. the stop found the session idle; both false ⇒ queued-only), `overageResetsAt` (window reset, epoch secs), `overageQueue` (messages queued during the wait window — `[{text, attachments, ts}]`, restored onto `_overageQueue` so they still flush with the resume).
On boot, an entry with `overageStopped` + finite `overageResumeAt` **and** a live `models.onOverage` of `stop-resume` re-arms the wall-clock sweep after the session is live + idle — the policy outranks the persisted mark, so under `stop`/`none` the entry restores as an ordinary session instead (its continue notice iff `wasBusy`, no deadline, no badge) and its `overageQueue` is dropped; a deadline already past fires on the first sweep tick, carrying whichever preamble the restored selectors resolve to (`overageResumeKind`) — not `AUTO_RESUME_TEXT` unconditionally, since the restore sets `overageIdleParked` before re-arming (and the continue notice is suppressed for it).

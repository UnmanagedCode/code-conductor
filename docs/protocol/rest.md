# Protocol: REST — projects, workspaces and sessions

## REST endpoints
**Error bodies** are `{error}`, plus `code` only for a deliberate refusal — a thrown error carrying both a `statusCode` and a string `code` (e.g. `BACKEND_MODEL_MISSING`, `SYSTEMS_UNAVAILABLE`); an OS errno (`ENOENT`, `EACCES`, …) is never surfaced. `errorBody` in `src/routes/errors.ts`. Every route that resolves a project or a worktree by name refuses an unknown one **404** with `code` `PROJECT_UNKNOWN` (`getProject`, `src/projects.ts`) or `WORKTREE_UNKNOWN` (`requireWorktree`, `src/worktrees.ts`).

**Caching.** Every `/api` response carries `Cache-Control: no-store` (router-wide middleware in `buildRoutes`, `src/routes.ts`, ahead of the body parser, so a malformed-JSON 400 carries it too); a route that sets its own header overrides it — `GET /api/instances/:id/attachments/:filename` and `GET /api/sessions/:sid/attachments/:filename` answer `private, max-age=3600`. The client sends every REST request with `cache: 'no-store'` (the default in `apiResponse`, `shared/http.ts`; a caller's own `cache` option wins).

**Platform capabilities.** A feature the host platform lacks (`Platform.capabilities`; table in [components/platform.md](../components/platform.md#srcplatform) → `src/platform/`) is refused **501** with a stable code: `SYSTEMS_UNAVAILABLE` on `/api/settings/systems*`, `GET /api/systems/:id/remotes`, `PUT /api/projects/:name/remote`, and `POST /api/projects`, `POST /api/exec` and `GET /api/terminal` with a non-local `system` (for `/api/exec` and `/api/terminal` also a project placed on one); `VOICE_UNAVAILABLE` on `/api/transcribe*`, `/api/tts*`, `/api/settings/transcribe*` and `/api/settings/tts*`. `POST /api/projects/external` with a non-local `system` is the route's soft refusal instead: **200** `{ok:false, code:'SYSTEMS_UNAVAILABLE', reason}`. A session spawn on a non-local project is refused **501** `FUSE_UNAVAILABLE` when `fuseUnion` is off.

- `GET` `/api/health` — Liveness + per-process identity + the platform's feature flags + the UI mode: `{ok:true, app:'code-conductor', pid, bootId, capabilities:{remoteSystems, fuseUnion, voice}, uiMode, focus?}`. `capabilities` is `Platform.capabilities` alone. `uiMode` (`'full' | 'view' | 'interact'`, always present) is the boot's `--ui` ([features/ui-modes.md](../features/ui-modes.md)). `focus:{sessionId}` is present only on a headless-family server (a headless run or a `--replay`; `sessionId` is null until a live run's root has spawned), puts the client in focus mode ([features/conduct.md](../features/conduct.md) → Headless mode), and under `interact` names the one session the UI may control. `app` lets a launcher recognise cc on a port; `pid` is the server's process id (for the Windows launcher's `--stop`). `bootId` (`src/bootId.ts`) is minted once per process, so the client restart flow polls for a *changed* value to confirm it's on the replacement process, not the old server still up during a resume drain.
- `GET` `/api/projects` — List with workspace, git status (`isGitRepo`; `unbornHead` — a repo with zero commits), sessions, worktrees, and the placement pair `system` + `remoteId` (`"local"` + `null` for a project whose `location.kind` is `local`; absence of `remoteId` on a remote project IS the provider's own default target). **`path` is the ONE path field** — the tree's path on whatever machine it is on — so an in-root, a nested, an out-of-root and a remote project's rows differ only in its value; there is no kind flag. A row whose RECORD could not be parsed carries `degraded: "<reason>"` and an empty `path` rather than disappearing. A project whose system cc could not get a git answer out of — one that cannot be RESOLVED (an unregistered system, a system with no provider command, a system that is down), **or one that resolved and then failed the git probe itself**: a provider that died mid-listing (`GIT_DID_NOT_RUN`) or one that accepted the command and never answered it (`GIT_TIMED_OUT`, at `ORCH_OP_TIMEOUT_MS`) — carries `systemUnreachable: "<the refusal's message>"` and **omits `isGitRepo`** — absent, never `false`, since "could not look" is not the claim "not a git repo" — with `mergeStatus` all-null and its worktrees listed but undiverged.
  **`gitRefusal`** is `null`, or — when the system answered but git refused the repository on ownership (`GIT_DUBIOUS_OWNERSHIP`) — git's refusal with the `git config --global --add safe.directory <path>` fix; with it set, `isGitRepo` is likewise omitted, `unbornHead` is `false`, `mergeStatus` is all-null, and `systemUnreachable` stays `null`. Either **degrades that row only**: the listing still returns every other project. `sessions` and each `worktrees[].sessions` are `{count, archivedCount, handCount, lastActivity}` (`summarizeSessions`, `src/projects.ts`): `count` is the non-archived transcripts, excluding live normal sessions; `handCount` is the non-conducted subset of `count`, read by the sidebar's Hand-spawned only filter. **`conventions`** is the project selection line 1 of its `CONVENTIONS.md` records (`ProjectConventionSelection`, `src/projectClaudeMd.ts`) plus `unresolved`: `{mode:"unset", unresolved:[]}` (no file, a non-marker first line or a zero-slug marker), `{mode:"none", unresolved:[]}` (the `:none` marker), or `{mode:"selected", slugs:[slug,…], unresolved:[slug,…]}` in marker order, `unresolved` being the slugs this request's single catalog read lacks — its `{mode, slugs?}` is exactly what `PUT /api/projects/:name/conventions` takes back as `expected`; `{error}` when the file could not be read; **absent** when the project could not be resolved (`systemUnreachable` says why). Read with the git facts, so cached and coalesced with them.
- `POST` `/api/projects` — `{name, conventions?:[slug,…], noProjectConventions?, system?, remoteId?, systemPath?}` — create. With `system` (a registered non-`local` id) the tree is created at absolute `systemPath` ON THAT SYSTEM and under the projects root there is no tree and no directory — only the `<store>/projects/<name>/` record. **Either way the record IS the registration**, and it is written only AFTER the `mkdir` succeeds: the mkdir is what proves the path was not already somebody else's tree, so a refused create leaves no record. A dot-leading `name` is refused at that write (`registerProject`, `src/projects.ts`) — `.worktrees`, `.plugins` and the store are cc's own — with `.conduct` the one exception. Both or neither: `system` without `systemPath` → 400, `systemPath` without `system` → 400, a relative `systemPath` → 400; an unreachable system → its own refusal (501/502) with nothing recorded; a path that already exists on the system → **409**; a name whose TRANSCRIPT DIRECTORY is already held by another project or registered worktree → **409 `TRANSCRIPT_DIR_COLLISION`**. The comparison is the whole directory — `path.join(transcriptRoot(place), encodeCwd(cwd))` — on both sides, and each `(system, remoteId)` has a transcript root of its own, so this refuses only what genuinely IS one directory: two places on ONE target at one path, and two places on one root whose cwds the CLI collapses to one name (`_`, `.` and `/` all become `-`).
  The same absolute path on two systems, on two targets of one system, or on a remote and locally, is registrable. The check runs before the record and before the remote `mkdir`. `remoteId` names WHICH TARGET of that system when it serves more than one (a container name, a hostname, a VM id — **not** a slug: `_` and `.` are legal, whitespace and control characters are not, capped at `REMOTE_ID_MAX` in `src/systems/protocol.ts`); omit it for the provider's own default. `remoteId` without `system` → 400; a system whose provider does not advertise `remotes` → **501 `SYSTEM_NO_REMOTES`**; a target that provider does not serve → **502 `REMOTE_NOT_FOUND`**; both before anything is written. The 201 body carries `system` and `remoteId`. Otherwise `git init`s the new dir, seeds `CLAUDE.md` with `@CONVENTIONS.md` (unconditional) and always writes `CONVENTIONS.md` — the composed workspace conventions plus, under `# Project conventions`, each selected convention's fragment (a request with no `conventions`, or `conventions: []`, still gets the workspace block under a zero-slug marker, recording **unset**; `noProjectConventions: true` records **none** under the `<!-- cc:conventions :none -->` marker instead). `conventions` not an array of strings → **400**; `noProjectConventions` not a boolean → **400**; `noProjectConventions: true` with a non-empty `conventions` → **400 `CONVENTIONS_NONE_WITH_SLUGS`**, nothing created.
  A `git init` that cannot be made (git missing, a non-zero exit, `GIT_TIMED_OUT` 504 or `GIT_DID_NOT_RUN` 502 from `runGit`) is **not an error**: the create still seeds `CLAUDE.md` + `CONVENTIONS.md`, attempts no commit, and answers 201 with a **`gitSkipped`** string — the reason (the init's own stderr, or the throw's text, which names the system and the operation) plus a note that the project has no repository and its first worktree needs `git init` and a commit. `gitSkipped` is PRESENT ONLY WHEN SKIPPED, so a healthy 201 never carries the key; the project lists as `isGitRepo:false`, derived live. A timed-out init may have run on the far side, so the project may in fact be a repository. Both surfaces carry it: `POST /api/projects` returns the body verbatim and `create_project` spreads it. Otherwise creation closes with `git add -A` + `git commit` of everything it wrote, so the 201 names a project whose `unbornHead` is already `false`. Identity is probed per field (`git config --get user.name` / `user.email`) and `-c user.name=code-conductor` / `-c user.email=code-conductor@invalid` injected only for whichever is unset — on that one command, never persisted to any config; a configured value is never overridden. Staging is `add -A` plus a forced add of the paths creation wrote, so a `core.excludesFile` rule cannot silently drop one. Hooks and signing are not bypassed.
  The commit is attempted **only** when `git rev-parse --absolute-git-dir --show-toplevel` in the new directory resolves to that directory's own `.git` and tree — otherwise it is refused untried, so an ambient `GIT_DIR` cannot make creation commit into an unrelated repo. **A refused, failed or unrunnable commit is a `console.warn`, not a status code**: the 201 still returns, with the project created and its HEAD unborn. Any picked convention carrying a scaffold facet contributes its directive, composed in selection order into a framed block RETURNED in the 201 body under `scaffold` (empty/omitted when none; nothing persisted). 400 on unknown slug.
- `GET` `/api/projects/suggestions` — Directories under the projects root that are NOT registered — what the Adopt dialog offers instead of making the user type a path. **No query parameters.** **200** + `{root, maxDepth, truncated, unreadable, candidates[]}`; each candidate is `{path, relPath, depth, isGitRepo, suggestedName?}`. `root` is the projects root's **realpath** (or its unresolved value when it does not exist, in which case the answer is an empty, untruncated list — a missing root is not an error); `maxDepth` echoes the cap applied; `truncated` means the visited-directory cap tripped and the list is a **prefix**; `unreadable` counts directories the walk could not read (EACCES, a raced deletion) — one such directory degrades one row, never the response. `path` is absolute and canonical, `relPath` is relative to `root`, `depth` is 1 for a direct child, `isGitRepo` is "a `.git` entry exists" (true for a repo's `.git` dir and a worktree's `.git` FILE alike), and `suggestedName` is the basename with every character outside `^[a-zA-Z0-9._-]$` replaced by `-` and leading dots stripped — **omitted** when that leaves nothing, so the endpoint never suggests a name `registerProject` would refuse. Two candidates may legitimately share a suggested name; they are not disambiguated (the collision surfaces as `PROJECT_EXISTS`).
  **Scan rules** (`src/projectSuggestions.ts`, caps `SUGGEST_MAX_DEPTH` and `SUGGEST_MAX_DIRS`): dot-prefixed entries are skipped, which is the whole of what keeps `<store>`, `.worktrees`, `.plugins` and `.conduct` out — there is no second exclusion list, and no `node_modules`-style name list; a registered LOCAL placement is skipped **and not descended into** (a remote record's `path` is on another machine and suppresses nothing locally, and a degraded row's empty `path` names no directory); the walk **stops descending at a `.git`-bearing directory**, since every descendant is `TARGET_INSIDE_REPO`; symlinked entries are **neither offered nor followed** (`dirent.isDirectory()` is lstat-based), so the walk cannot leave the root or cycle. **It runs no `git`** — a `.git` stat answers both the ranking and the stop-descend rule. Ranking is total: `.git`-bearing first, then `relPath` ascending. Every candidate is one `POST /api/projects/external` would accept; `tests/project-suggestions.test.mjs` adopts them all to pin it.
- `POST` `/api/exec` — Run one command on a project's System (`project`, `worktree?`) or on a System addressed directly (`system`, `remoteId?`, `cwd`), for plugin backends: `argv` or `shell`, an `env` overlay, `stdin`/`stdinB64`, `encoding: 'utf8'|'base64'`, `timeoutMs`, `maxOutputBytes`. **200** `{exitCode, stdout, stderr, encoding, durationMs, system, remoteId, cwd, descendantsMaySurvive?}` whatever the exit code; refusals `INVALID_ARGUMENT`, `CWD_NOT_ABSOLUTE`, `PROJECT_UNKNOWN`, `WORKTREE_UNKNOWN`, `SYSTEMS_UNAVAILABLE`, the `systemById` codes, `EXEC_SPAWN_FAILED`, `EXEC_OUTPUT_TOO_LARGE`, `EXEC_TIMEOUT`. Own body limit `EXEC_BODY_LIMIT`. Full schema: [plugins/runtime.md → Host exec](../plugins/runtime.md#host-exec--post-apiexec). `src/hostExec.ts`
- `GET` (WebSocket) `/api/terminal?spec=<JSON>` — Open a terminal on a project's System or a System addressed directly, for plugin backends — the same target forms as `/api/exec`, plus `argv?`, `env?`, `cols`, `rows`, `term?`. Every refusal is an HTTP JSON answer before the upgrade: `ORIGIN_REFUSED` (any `Origin`), `INVALID_ARGUMENT`, `CWD_NOT_ABSOLUTE`, `PROJECT_UNKNOWN`, `WORKTREE_UNKNOWN`, `SYSTEMS_UNAVAILABLE`, the `systemById` codes, `SYSTEM_NO_PTY`, `PTY_UNAVAILABLE`, `TERMINAL_LIMIT`, `SYSTEM_UNREACHABLE`, `REMOTE_NOT_FOUND`, `TERMINAL_SPAWN_FAILED`. After the 101: binary bytes both ways, a `resize` control message in, one `exit`/`failed` message out, closes 1000/1011/1008/1009. Full contract: [plugins/runtime.md → Host terminal](../plugins/runtime.md#host-terminal--get-apiterminal-websocket). `src/hostTerminal.ts`
- `GET` `/api/fs/dirs?path=<abs dir>&system=<id>&remoteId=<target>` — Subdirectory names of one absolute path on one system — the path autocomplete in the Adopt and New-project dialogs. Served by `listDirectories` in `src/dirListing.ts` through `systemById(...)` → `System.readDir`, so it answers identically for `local` and every registered system. **`path`** required, absolute on that system, echoed back. **`system`** optional; absent, `''` or `local` is cc's machine. **`remoteId`** optional, blank = the provider's default target, refused on `local`. **200 ok** `{ok:true, system, remoteId, path, entries[], links[], truncated, max}`: `entries` are real subdirectories plus symlinks **resolved** to a directory; `links` are **unresolved** symlinks (past the `DIR_LIST_MAX_LINK_STATS` budget, or unanswered within `DIR_LIST_LINK_DEADLINE_MS`), offered as candidates and not claimed to be directories. Both arrays are sorted by code unit and keep dot-directories; together they hold at most `max` (`DIR_LIST_MAX_ENTRIES`) names — the first `max` by name — and `truncated` means more candidates existed. **Cost bound:** one `readDir` plus at most `DIR_LIST_MAX_LINK_STATS` `stat`s in total per listing (issued in batches of `DIR_LIST_LINK_STAT_BATCH`), whatever the directory holds. **200 refusal** `{ok:false, code, reason}`, the `POST /api/projects/external` contract.
  Codes: `INVALID_PATH` (also a repeated or non-string `path` or `system`), `INVALID_REMOTE_ID` (also a repeated or non-string `remoteId`), `SYSTEMS_UNAVAILABLE` (capability off); from `systemById`, unchanged: `SYSTEM_NOT_REGISTERED`, `SYSTEM_NO_PROVIDER`, `SYSTEM_UNREACHABLE`, `SYSTEM_NO_REMOTES`, `REMOTE_NOT_FOUND`; from `readDir`, the System error code passed through: `ENOENT`, `ENOTDIR`, `EACCES`, `ELOOP`, `ENAMETOOLONG`, `ENOREMOTE`, `ETRANSPORT`, `ETIMEDOUT`, `EUNKNOWN` (a provider on busybox reports the missing `find -printf` here, with its stderr in `reason`). A link `stat` that settles within the link deadline with `ENOENT`, `ENOTDIR`, `EACCES`, `ELOOP` or `ENAMETOOLONG` only drops that link and never refuses the listing; any other code it settles with (`ETRANSPORT`, `ETIMEDOUT`, …) is passed through as the refusal. **`LIST_TIMEOUT`** (`DIR_LIST_DEADLINE_MS`) covers the connect and the `readDir` only — never the link phase, which has its own `DIR_LIST_LINK_DEADLINE_MS`. **500** `{error}` only for a throw that is none of the above. **No auth**, like the rest of the REST surface: it discloses directory names anywhere cc's user, or the provider's user, can read — the trust level of `adopt_project` / `system_bash`, and a `HOST` override widens it.
- `POST` `/api/projects/external` — `{name, path, system?, remoteId?}` — adopt an EXISTING directory at absolute `path` as project `name`. Without `system`: the tree is on cc's own machine, anywhere — **including nested under the projects root**, which is how a container directory comes to hold projects. cc writes only the record. With `system` (a registered non-`local` id): `path` is on THAT system, every check (realpath, stat, `git rev-parse --show-toplevel`, and `--git-dir` when that fails) runs there, the local projects-root containment tests are skipped (a path on another machine neither is inside cc's root nor contains it), the duplicate test compares **(system, remoteId, path)** rather than a path alone — the same path on two targets of one system is two adoptable trees — and the record is the registration either way. `remoteId` names which target (see `POST /api/projects`). Nothing is copied or moved. **201** + `{ok:true, name, path, system, remoteId}` where `path` is the target's **realpath**. `onStaleRecord: 'relocate'|'replace'` resolves the `PROJECT_EXISTS_STALE` refusal below. A refusal is **200** + `{ok:false, code, reason}` (never 4xx/5xx): `INVALID_NAME` (charset, or dot-leading — reserved for orchestrator-managed projects), `INVALID_TARGET_PATH` (not a non-empty absolute path), `TARGET_NOT_FOUND` (only when the system ANSWERED "no such path"
  — a probe that failed for any other reason is `SYSTEM_UNREACHABLE`, since cc has no fact about the tree), `TARGET_NOT_A_DIRECTORY`, `TARGET_ALREADY_MANAGED` (the same (system, remoteId, path) is already registered, or the target CONTAINS the projects root), `TARGET_IS_CC_STATE` (inside `<store>`, `<projectsRoot>/.worktrees/` or `<projectsRoot>/.plugins/` — cc's own state, and the Library's post-clone step is best-effort, so a half-installed checkout can really sit under the last one), `TARGET_INSIDE_REPO` (a subdirectory of a git repository — `reason` names the toplevel), `TARGET_NO_WORK_TREE` (a bare repository, or a repo's own `.git`), `TARGET_DUBIOUS_OWNERSHIP` (git refused the repository because a different user owns it — `reason` carries the `safe.directory` fix; never adopted as a plain directory), `SYSTEM_UNREACHABLE` (the named system could not be resolved, **or** stopped answering during a probe — this also carries `SYSTEM_NO_REMOTES` / `REMOTE_NOT_FOUND`, since both are refusals to resolve), `INVALID_REMOTE_ID` (unusable, or given without a `system`), `INVALID_STALE_ACTION`, **`PROJECT_PLACEMENT_IN_USE`** (a `relocate` of a project on a SYSTEM while it has registered worktrees — the checkout does not move with the tree and `worktreePathFor` derives a remote path from the project's, so stored and derived would diverge permanently;
  delete them, or `'replace'`), `PROJECT_EXISTS` (the name is held by a record whose path still resolves), **`PROJECT_EXISTS_STALE`** (held by a record whose path does NOT resolve — carries `heldPath` and `discards:{attachments,debug,worktrees}`; `onStaleRecord:'relocate'` repoints that record at this target and keeps its store subtree, `'replace'` discards the subtree and registers afresh), **`PROJECT_EXISTS_UNRESOLVABLE`** (held, and cc could not ask whether it resolves — a moved project and a machine that is merely down are indistinguishable, so relocation is NOT offered), `TRANSCRIPT_DIR_COLLISION` (the working directory the project would have is already held by another project or registered worktree, on any system including `local`; `reason` names the holder). Every check precedes the write, so a refusal leaves no record. Also writes `<target>/CONVENTIONS.md` and ensures `<target>/CLAUDE.md` imports it (non-fatal). No `projects` WS hint, matching `POST /api/projects`.
- `DELETE` `/api/projects/:name` — Body `{deleteDirectory?}` (default `false`). Cascade: kill instances → remove worktrees → DEREGISTER the project. **The tree stays unless `deleteDirectory` is `true`**, and for a project on a system that opt-in is refused **400** — cc removes its record of a tree on another machine, never the tree. cc's OWN area always goes: `<store>/projects/<name>/` and `<projectsRoot>/.worktrees/<name>/`. The worktree step runs the ORDINARY guards (`force:false`): a worktree that is dirty, dirty-unknown or depended-on refuses the whole delete **409**, while a checkout that is not there — or whose parent is no longer a repo — has no uncommitted work to lose and has its registration dropped instead, so a project whose tree vanished out-of-band is still deletable. A **remote** project's worktree registrations are dropped with no git run. Deregistering does **not** resolve the system at any layer — the route addresses the project via `getProjectForDelete`, not `getProject` — so a project on a system that is down, on a system not in the registry at all, or with a record cc cannot parse can still be removed; deleting is the repair for exactly those states. Response: `{ok:true, project, killedInstances, system, remoteId, path, directoryDeleted}`. Order is load-bearing: worktrees go first, or the cascade resolves to a 404 and leaves orphan dirs plus stale registrations. Sessions persist under `~/.claude/projects/`.
- `PUT` `/api/projects/:name/workspace` — `{workspace}` — assigns/clears; auto-registers new names.
- `PUT` `/api/projects/:name/conventions` — `{selection, expected}`, each a tagged selection — `{mode:"unset"}`, `{mode:"none"}` or `{mode:"selected", slugs:[…]}` — replace the project's convention selection (the sidebar's **⋮ → Edit conventions…**). Both fields required, else **400**: an unknown `mode` → **400**; `unset`/`none` with a `slugs` key → **400 `CONVENTIONS_NONE_WITH_SLUGS`**; `selected` whose `slugs` is not a non-empty array of strings → **400**; `selection.slugs` repeating a slug → **400** (`expected.slugs` may repeat one, mirroring the marker). `expected` is the selection the caller showed: when the file's selection differs — another mode (unset ≠ none ≠ selected) or other slugs (ordered) — **409** naming the current selection, nothing written. Each `selected` slug must be in the project-convention catalog **or** already in the marker (a slug the catalog lacks is kept, never introduced), else **400** `unknown convention slug '<s>'`. Keeping a slug the catalog lacks while the catalog is degraded is **503 `CONVENTIONS_CATALOG_DEGRADED`**, file left byte-identical; `unset` and `none` keep no slug, so never 503. **404** for an unknown project (`.conduct` included); a system refusal keeps its own status (e.g. **502 `SYSTEM_UNREACHABLE`**). On success the selection is written (a `selected` one verbatim, in request order) through the regeneration writer (`setProjectConventions`, `src/projectClaudeMd.ts`), on the project's system, and left uncommitted: `{ok:true, path, selection, unresolved}`. Sends one `projects` hint. No MCP equivalent.
- `PUT` `/api/projects/:name/remote` — `{remoteId}` — change WHICH TARGET of its system the project is on; `null` or `""` clears it back to the provider's own default. **The field is REQUIRED: a body that omits it entirely is a 400 naming it, never a silent clear** — clearing is an explicit act, and an omitted target is the shape a caller reaches by accident. MCP's twin enforces the same rule structurally, via `required` in its schema. **409 `PROJECT_PLACEMENT_IN_USE`** while the project has live sessions or registered worktrees — and that body is `{error, code, instances:[…], worktrees:[…]}` rather than `{error}` alone, because the list of what to clear IS the answer. **501 `SYSTEM_NO_REMOTES`** / **502 `REMOTE_NOT_FOUND`** are raised before anything is written, and **400** for a project on `local` (one machine has no named targets). On success its cached git facts are invalidated (there is no local session root to remove any more — the worker reads the tree through the union at its real path), and the body is `{ok:true, name, system, remoteId, systemPath}` (`systemPath` here is the project's path on its system, read back off the record's `location`). Twin of MCP `set_project_remote`; both call the one helper in `src/projects.ts`, so neither surface can be built without the guard.
- `GET` `/api/projects/:name/location` — Where a project lives, `{name, system, remoteId, path}`, read off its stored record **alone** via `projectPlacement` (`src/systems/registry.ts`). It runs **no command on any system** and spawns nothing, so it is the cheap per-project placement lookup where `GET /api/projects` runs git for every project. `system` is always set (`local` for local projects and for `.conduct`); `remoteId` is `null` for the provider's default target; `path` is the record's location path and is not checked on disk. **404 `PROJECT_UNKNOWN`** for a name no record holds; **400 `INVALID_ARGUMENT`** for a malformed name. Not capability-gated.
- `GET` `/api/workspaces` — Union of registry + referenced names.
- `POST` `/api/workspaces` — `{name}` — 201 new / 200 idempotent. Same regex.
- `PUT` `/api/workspaces/:name` — `{name: newName}` — atomic rename across all members.
- `DELETE` `/api/workspaces/:name` — Removes the entry **and** clears `workspace` on every member (projects stay).
- `GET` `/api/projects/:name/sessions` — Session metadata list (`SessionRow`, `src/projects.ts`). Each row carries `awaitingUser` / `awaitingUserSource`, derived from the transcript (`src/awaitingUserTranscript.ts`); an **archived** or **conducted** row reports `null` without being derived. No row carries `rootSessionId` / `parentSessionId` — ownership exists only while a session is live. Each row also carries the session record's turn marks `turnEndSeq` / `viewedSeq` (`0` when absent; see `POST /api/sessions/:sid/viewed`). Same fields on the worktree variant and on `GET /api/projects/.conduct/sessions`.
- `GET` `/api/conductors/projects` — `{ "<rootSessionId>": [{ "project", "lastSpawnAt", "worktrees" }] }` — per **root session** (the first non-conducted session up the recorded `parent` chain — a conductor, or a hand-spawned session; `src/conductorSpawns.ts`), every project a conducted worker under it was spawned into, newest `lastSpawnAt` first then by name. `lastSpawnAt` is the newest segment `at` (the stored string, or `''` when the stored `at` is missing or not a string — `''` sorts last) across that root session's workers in the project — a spawn or renew/prune rotation; a conductor resuming an existing worker does not bump it. `worktrees` is the distinct recorded worktree names (`SessionRecord.worktree`) of that root session's workers in the project, sorted by name — no existence or liveness filter. A root session whose current segment is archived is omitted; a worker whose chain hits a missing record, a conducted record with no `parent` (the worker's own included) or a cycle is attributed to no one. Feeds the Conductors lens's idle chips, idle tree rows and recorded worktree rows, and the Projects lens's conductor filter.
- `GET` `/api/sessions/:sid/workers` — `{workers: SpawnedSessionRow[]}` (`shared/wireRows.ts`): the sessions this one spawned directly (recorded `parent`), live or not, each a `SessionRow` plus `project` and `worktreeName`, newest `lastActivity` first. A child with no recorded `project`, an unlisted or degraded project, or no transcript is omitted. An unknown session answers `{workers: []}`; 400 for an invalid id. Feeds the Workers panel's ended list.
- `GET` `/api/sessions/:sid/spawner` — `SessionSpawner` (`shared/wireRows.ts`): `{conducted, parentSessionId, rootSessionId}`, the session's recorded spawn lineage (`conductedLineage`: the recorded `parent` and the root its chain resolves to), live, archived or not. A session that is not conducted, or unknown, answers `{conducted: false, parentSessionId: null, rootSessionId: null}`; 400 for an invalid id. Feeds the ended pane's owner chip.
- `GET` `/api/sessions/:sid/locate` — `{project, worktreeName, archived}`; drives the `#session=` restore and a notification click's resume (the page-load restore opens a non-live session **read-only**, resuming nothing; it also opens read-only when `archived:true`, or when the project no longer lists `worktreeName` — the jsonl is retained after archiving, and a deleted worktree's session is found through its recorded place, so locate still 200s). 404 if not found.
- `GET` `/api/sessions/:sid/pristine` — The live pristine conductor whose exact public `sessionId` is `:sid`, hidden or listed: **200** + its summary. A pristine conductor inside its relaunch window (a restart model switch's kill→relaunch) still answers 200. **`404 NOT_PRISTINE`** for anything else (no such session, not live, already prompted). A lookup, not a list: what a tab opening a hidden conductor's `#session=` anchor (a reload, another tab) resolves it through, ahead of `locate` (`resumeSessionByAnchor`, `web/src/app/controller.ts`), and what a reconnecting tab refreshes its pristine slot from.
- `PUT` `/api/sessions/:sid/title` — `{title}` — set custom session label (length-capped at `MAX_TITLE_LEN` (`src/sessionTitleText.ts`); empty/whitespace clears). Returns `{ok, sessionId, title, maxLength}`; **`404 session not found`** when no in-memory instance, store record or transcript answers to `:sid` (so a mistyped id never creates a record). Broadcasts `projects` hint + pushes updated summary to any live instance with this `sessionId`. Writes through `applySessionTitle` (`src/sessionTitles.ts`), the same write the `set_session_title` MCP tool uses.
- `PUT` `/api/sessions/:sid/chip` — `{title, data}` — set the live session's **context chip**, replacing any current one (`ContextChipSlot`, `src/contextChip.ts`). `title`: a trimmed non-empty single line of at most `CHIP_TITLE_MAX` chars; `data`: a string of at most `CHIP_DATA_MAX` chars. Returns `{ok, sessionId, chip:{title, data, rev}}` and pushes a `chip` frame to every subscriber. **`400`** `code: INVALID_ARGUMENT` for a bad body; **`404`** `code: SESSION_NOT_LIVE` when no live instance carries `:sid` (unknown or ended). `:sid` is the public sessionId.
- `DELETE` `/api/sessions/:sid/chip[?rev=<n>]` — clear it. Returns `{ok, sessionId, cleared}`. Without `rev` it clears unconditionally (a plugin); with `rev` only while that is still the held chip's rev (the composer's ×), so a × never removes a replacement the user has not seen (`cleared:false`). **`400`** `INVALID_ARGUMENT` for a `rev` that is not a non-negative integer; **`404`** `SESSION_NOT_LIVE`. Plugin backends call both through `$CONDUCTOR_URL`.
- `GET` `/api/sessions/:sid/summary` — `{ok, sessionId, data}`: `data` has `short`, `medium`, `long` and `title`, each `{summary, generatedAt, messageCount, isStale}` or `null`. `isStale` is true once the transcript has more user/assistant lines than `messageCount`.
- `POST` `/api/sessions/:sid/summary` — `{length}` (a tier named by `SUMMARY_LENGTHS`) — generate that tier and persist it on the session's record. Returns the GET shape plus the ephemeral `costUsd` (`null` off the Claude backend). **`400`** on an unknown tier; **`404 session not found`**.
- `POST` `/api/sessions/:sid/ask` — `{question}` — a free-form question about the session, answered by one Fast-tier call over the session text (prompt shape: [components/store.md](../components/store.md#srcsessiononeshotts) → `src/sessionOneShot.ts`). Returns `{ok, sessionId, answer, costUsd, usage: {cacheReadInputTokens, cacheCreationInputTokens}}`; each counter is `null` when the CLI reports none (a non-Claude backend). **`400 question must be a non-empty string`** for a missing, non-string or whitespace question, before anything is spawned; **`404 session not found`**. **Stores nothing** (no summary record, no broadcast). A client disconnect aborts the call and kills the child.
- `POST` `/api/sessions/:sid/viewed` — `{seq}` — the browser saw the session's turn end `seq` (`web/src/app/viewedMarker.ts`). Raises the record's `viewedSeq` to `max(viewedSeq, min(seq, turnEndSeq))` — never past the latest turn end, never backwards (`markViewed`, `src/sessionStore.ts`). Returns `{ok, sessionId, turnEndSeq, viewedSeq}`. **`400 seq must be a non-negative integer`**; **`404 session not found`** under the same rule as the title route. Pushes the stored marks to every live instance with this `sessionId` (`applySessionViewed`, `src/sessionViewed.ts`); a change rides their `turn_marks` event → `{t:'instances'}` to every client (no `status`, no `projects` hint). **No MCP equivalent, by design** — no MCP tool, read or forward marks a session viewed.

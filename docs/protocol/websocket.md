# Protocol: the WebSocket

## WebSocket protocol

**Handshake: Origin check** (`src/upgradeOrigin.ts`, the first step of `server.ts`'s `server.on('upgrade')` dispatcher, so it covers `/ws`, `/api/terminal`, `/plugins/<id>/…` and unknown paths alike):
- **`/api/terminal` additionally refuses ANY `Origin`**, a same-origin one included: 403 JSON `{error, code:'ORIGIN_REFUSED'}` from `src/hostTerminal.ts`, so only a non-browser client opens a host terminal ([plugins/runtime.md → Host terminal](../plugins/runtime.md#host-terminal--get-apiterminal-websocket)).
- **No `Origin` header → admitted.** Browsers always send one on a WebSocket, so its absence means a non-browser client (the test suite's `ws` client, a plugin backend, code-live).
- **Otherwise admitted only if** all hold (`upgradeOriginAllowed`):
  - `Origin` parses as a URL with protocol `http:` or `https:` and `new URL(origin).origin === origin` — refuses `null` (sandboxed / `file:` pages), `chrome-extension://…`, an Origin with a path or userinfo, a malformed value, and duplicate headers Node joined into `"a, b"`;
  - `Host` is present and parses as `new URL(`${originProtocol}//${host}`)` with no userinfo, path, query or fragment;
  - the two URLs' `.host` are equal — lowercased hostname plus effective port (a default port dropped on both sides under the Origin's scheme; IPv6 brackets kept).
- **The scheme is ignored**: a TLS front (a tunnel, Tailscale funnel) shows the browser `https://` while cc's own hop is plain http. **`X-Forwarded-Host` is neither read nor trusted.**
- **Refusal:** a raw `HTTP/1.1 403 Forbidden` + `Connection: close`, then the socket is destroyed — before the wsHub sees the request and before the plugin proxy lazy-starts any child.
- **Log:** a refusal `console.warn`s `websocket upgrade refused: Origin … does not match Host …`, subject to two bounds:
  - **Dedupe (memory-bounded):** a pair already warned about is silent, so a reconnect loop logs once. The memo holds at most `WARNED_PAIRS_CAP` pairs (oldest evicted), so a pair evicted by more distinct pairs warns again.
  - **Rate limit (log-bounded):** at most `WARN_LIMIT` refusal warns per `WARN_WINDOW_MS` window, then one `… further refused upgrades not logged …` line, then silence until the window rolls over. Rotating attacker-chosen Origins therefore logs at most `WARN_LIMIT + 1` lines per window. A pair silenced by the limit is not remembered, so it warns in a later window.
  - Constants: `src/upgradeOrigin.ts`.
- **Contract on a proxy in front of cc: forward `Host` unchanged.** code-hub's authproxy (both plain requests and upgrades), its cloudflared and Tailscale tunnels and its raw TCP relays do; the Vite dev server's `/ws` and `/plugins` entries in `web/vite.config.ts` carry no `changeOrigin`, so they do too. A proxy that rewrites `Host` gets every browser upgrade refused, visible as the warn above.
- **Known limitation — DNS rebinding passes:** a rebound name makes `Origin` and `Host` agree. It affects `/api` equally; closing it needs a `Host` allowlist (a new setting), out of scope here. Plain-HTTP CSRF on `/api/*` is likewise not covered.
- **Pins:** `tests/ws-origin.test.mjs` (real server, both paths, the no-lazy-start proof, LAN-share and tunnel acceptance), `tests/upgrade-origin.test.mjs` (the rule's rows, the guard's 403, the dedupe and the rate limit).

**Client → server:**
- `subscribe` — `id`, optional `reqId` (triggers `snapshot` + live `event`s)
- `unsubscribe` — `id`
- `prompt` — `id`, `text`, optional `attachments` (`[{name, mediaType, dataBase64}]`). Refused `ok:false` "session is switching model — retry once it settles" for the whole of a restart model switch (`Instance.prompt`'s `409`); nothing is queued
- `mode` — `id`, `mode` (`plan` / `bypassPermissions`)
- `model` — `id` plus **exactly one** target: `tier` (a known capability tier, with **no** `backend` key; the server resolves that tier's CURRENT `{backend,model}` binding via `getTierBackend` and hands it, with the tier's effort (`getTierEffort`), to `Instance.switchModel`) or `model` + `backend` (the backend is required, never inferred; the pair must be a binding Settings → Models would accept — `isKnownBinding`, `src/appSettings.ts`: the Claude catalog for `claude`, otherwise the backend's custom rows plus, for `ollama`, the curated presets; handed to `Instance.switchModel` with the session's own effort). Either may land on another backend. `claude` session → `claude` model: the live `control_request` `subtype:set_model`, acked when the CLI answers; between turns only — refused `409 SESSION_BUSY` during a running turn, with nothing written to the CLI. Every other pair (within a substitution backend, or across backends either way): a **restart** switch onto the target backend's launch template and env, acked as soon as it is **accepted** — the outcome arrives as `status` frames (`modelSwitch`, then `modelSwitchFailure`, and `backend`/`model` naming the new pair) and a transcript divider (`model_changed` with `restart`, or `model_switch_failed`); re-selecting the running pair acks with nothing done (the same model id on another backend is a switch).
  Refused `ok:false`: both `tier` and `model`, or neither (`the model frame names exactly one of \`tier\` or \`model\``); a `model` with no `backend` (`a model pick names its backend`); a `tier` with a `backend` key (`a tier pick names no backend — the server resolves its binding`); an unknown tier; a pair whose backend exists but does not serve the model (`model '<m>' is not registered on backend '<b>'`); a backend not in the registry (`422 BACKEND_GONE`, `backend '<b>' no longer exists — re-add it in Settings → Backends`); `SESSION_BUSY` for the live switch mid-turn (`Instance.setModel`); for a restart, `SESSION_ROTATING`, "another rewind/fork/prune/model switch is in progress", "not running", `SESSION_BUSY` (turn, spawning, background agents/jobs, pending steer/interrupt) and, on a remote-system session, `501 FUSE_BACKEND_UNRESOLVED` — refusal table in [models.md](../models.md). cc does no transcript compatibility check across providers.
- `effort` — `id`, `effort` (a level from `EFFORT_LEVELS`, `src/effortLevels.ts`). **Not** a `control_request` — the protocol has no `set_effort`; the server writes `/effort <level>` as a lone-text `user` line on the session's stdin, which the CLI runs locally (no model turn). Idle-only: refused `409 SESSION_BUSY` during a turn. An unknown level acks `ok:false`.
- `interrupt` — `id`, optional `force` (omitted/false ⇒ arm a deferred abort; `true` ⇒ abort immediately)
- `kill` — `id`
- `auto_approve_plan` — `id`, `enabled` (server-side flag; while on, an incoming `plan_request` in plan mode auto-fires `setMode(bypassPermissions)` + the approval prompt)
- `playbook_enforcement` — `id`, `mode` (`warn` / `enforce`; validated against `PLAYBOOK_ENFORCEMENT_MODES` in `src/playbooks.ts` — an unknown value, including the retired `off`, acks `ok:false`). See [Playbooks](playbooks.md#playbooks).
- `pristine_view` — `id` — this socket shows the pristine conductor `id` (adds it to the presence set, cancels a pending grace window). A no-op acked `ok:true` on an instance that is not pristine; `ok:false` "unknown instance" for an unknown id, as for the other frames. Rules: [components/store.md](../components/store.md#srcpristinets) → `src/pristine.ts`
- `pristine_draft` — `id`, `text` — the composer's draft for it, sent once debounced; the last one synced decides when a socket close leaves the presence set empty. Same acks as `pristine_view`
- `pristine_leave` — `id`, optional `text` (the composer's live text; absent keeps the last synced draft) — this socket stopped showing it. When the presence set empties the conductor is abandoned at once: blank text (`text.trim() === ''`) removes it, any other text lists it under that text. A socket close leaves its sets too, abandoning after `PRISTINE_REAP_GRACE_MS` (`src/pristine.ts`). Same acks as `pristine_view`

**Server → client:**
- `snapshot` — `id`, `status`, `mode`, `sessionId`, `project`, `autoApprovePlan`, `playbookEnforcement`, `interrupting`, `events[]` (ring **tail** only — target ≤ `ORCH_SNAPSHOT_TAIL` (default in `src/instances.ts`); the window start is snapped to a **quiescent point** — no open text/thinking/tool block, every `tool_use` resolved by its `tool_result` — so the tail holds only whole blocks and complete tool round-trips; quiescent points are dense, so the snap normally moves a few events (worst case, one giant non-quiescent span, is the whole ring); sub-agent group integrity additionally pulls an in-tail child's Task head — and thus the whole group — into the tail, or, for a child with no head at or before it in the ring, pushes the tail start past that child), `tailStartSeq` (`_seq` of first tail event; the web UI pages everything older — the ring, then the session's earlier backing segments — via `GET /api/instances/:id/lineage-events`, starting at `before=<tailStartSeq>`; at `0` it still probes once, see [Lineage scrollback](rest-instances.md#lineage-scrollback)), `trimmedBefore` (first `_seq` still in the in-memory ring), `tailSegmentId` (the backing segment `tailStartSeq` belongs to — `segmentOfSeq` over `EventLog.seams`, else the backing id), `currentSegmentId` (the backing segment the instance runs under now — the last seam's, else the backing id; the client offers rewind/fork only on bubbles from it).
  `events[]` may contain a seq-less `segment_seam` divider before an in-ring rotation init (see `segment_seam` below), `tasksAtTailStart` (the in-flight task batch reconstructed as of `tailStartSeq`, so the client task panel shows a batch whose `TaskCreate` fell below the tail — the client seeds its `TaskTracker` with it before replaying the tail; `[]` when no batch is open; recovered from the retained ring, or — when the create was evicted entirely below the ring — from the jsonl archive), `lastContextUsage` (the last observed context reading — a **usage-bearing** `message_start.usage` **or** a `context_usage.usage` (both kinds below) — or `null` before the first one; a null-usage frame of either kind leaves it alone and the replayed jsonl seed is not wiped by a substitution backend's first live all-zero frame — the client seeds its `UsageTracker` with it **before** replaying the tail, so an in-tail `message_start` still wins. Needed for a different reason per feed. For `message_start` it is a backstop against an unlucky tail: the quiescent snap can leave every one of them below the window — a turn whose final text block outruns the tail has no quiescent cut except past the whole block, so the tail collapses to a few events and a re-subscribing client would rebuild an empty tracker (`ctx —`).
  For `context_usage` it is the **only** carrier, not a backstop: `EventLog.push` declines that kind outright, so it is never in `events[]` at any tail length and a re-subscribe has nothing else to rebuild from. Held as O(1) server state, last-value-wins; deliberately **survives `turn_end`** — between turns is exactly when a reload would otherwise lose the readout. Reset only through `Instance._dropContextReading`, at four sites. The first is `_wipeForResume` (rewind/prune/respawn), so a `reset_snapshot` omits it and a rewound session correctly starts blank; a fork or a resume-after-restart needs no reset because each builds a new Instance that starts it `null` (and a fork leaves the parent's value alone — that session continues). In all three cases the value is then **re-seeded from the replayed jsonl** — `loadHistory` emits the replay-path `message_start` described below, so a resumed/respawned/rewound session is populated before its first live turn instead of reading `ctx —`. The second is `Instance._announceModelSwitch` (see `model_changed` below): a mid-session model switch moves the window denominator without changing what the retained reading measured, so the reading is dropped rather than re-rendered against the new window. Nothing re-seeds it there — the chip reads `ctx —` until the next usage-bearing frame.
  The third and fourth are a top-level `compaction` event and a `/clear` rotation (an `init` naming a new session): the field is then `null`, so a client re-subscribing before the next `message_start` is seeded only by whatever `message_start` its tail still holds, while an already-subscribed client's chip keeps its reading. A **field**, not an appended event like `thinking_tokens` below — the snapshot appends no synthetic `message_start` to `events[]`, and the replay-path one is never retained, so `events[]` holds only genuine ones), `droppedText?` (present **once** on a fork's first snapshot — server consumes it, so a later re-subscribe omits it — ⇒ client prefills the composer). When a thinking block is still streaming, a trailing **seq-less** `system/thinking_tokens` (`data:{estimated_tokens}`) is appended to `events[]` so a client joining mid-thinking shows the current count immediately (the coalesced ring slot already carries the partial thinking text); absent once the block closes — a closed redacted block instead carries its count on `thinking_redacted.estimatedTokens` (see the `thinking_tokens` entry below). No `event`, `segment` or `reset_snapshot` frame for the instance precedes the snapshot after a `subscribe`; those emitted while it is built follow it, in order (a `status` frame is not held and can precede it)
- `reset_snapshot` — Same shape minus the tail metadata (`events: []`); sent after rewind so subscribers clear DOM first. The history the relaunch replays follows as a pulled `snapshot` after the live `history_replayed`, never as `event` frames. Carries `droppedText` ⇒ the client prefills the composer with the dropped prompt (same inline mechanism as `snapshot`'s fork prefill)
- `event` — `id`, `ev` (monotonic `_seq` for idempotent merge). The history a resume, respawn, rewind or prune replays from the jsonl is **not** sent as `event` frames: it is in the ring (pull-only — `Instance._emitUi`'s `pullOnly`), and a client gets it from `snapshot` plus `lineage-events`; only the ctx-seed `message_start` and `system/history_replayed` that follow it go out live. A rotation init is preceded by a seq-less `segment_seam` `event` when its seam is above the ring floor (see `segment_seam` below)
- `segment` — `id`, `currentSegmentId` — sent **immediately before every forwarded outer `system/init` `event`** (the spawn's, and every rotation's, whatever the trim position), and before the divider `event` when one is drawn: the backing segment the instance runs under from here on. The client's authoritative "current" for rewind/fork — it never infers it from a divider
- `status` — `id`, `status` (`spawning|idle|turn|exited|crashed`), `sessionId`, `mode`, `model`, `backend` (moves with a cross-backend model switch; `startController`'s `status` listener in `web/src/app/controller.ts` copies it onto the instance entry), `autoApprovePlan`, `playbookEnforcement`, `modelSwitch` (`{from, to, fromBackend, toBackend}` for the whole of a restart model switch, else `null` — the two backends are equal for a same-backend switch; `model` already names `to` while it runs, and from the relaunch on `backend` names `toBackend`), `modelSwitchFailure` (`{from, to, fromBackend, toBackend, error}` after a failed one, cleared at the next turn start or switch, else `null`), `interrupting` (transient — `true` while a soft interrupt is **armed** on this turn and waiting for its boundary; auto-clears on exit from `turn`. `interrupt({force:true})` never sets it). Does **not** carry `displayStatus`/`activeAgentTasks`/`backgroundJobs`/`waitingOnJob` (see below) — those ride the accompanying `instances` broadcast + REST refetch instead
- `ack` — `reqId`, `ok`, `error?`
- `resume_notices` — Hint to re-fetch `GET /api/resume-notices` (no payload); broadcast to every client on each change to the held notices — one stored by a gated restore, dropped by its session's turn, or taken by Continue / Dismiss
- `hello` — sent on connect
- `error` — `message` (server-side parse rejection; not tied to a `reqId`)
- `instances` / `projects` — Hints to re-fetch (no payload); broadcast on every instance create/remove/status flip — `projects` covers the case where a CLI just flushed a session jsonl. `instances` alone also broadcasts on every playbook bind or move (the gate's `playbook_changed` manager event, fired after the event-log `call` row carrying `bind`/`move` folds), so a worker's `playbook`/`stage` label refreshes without a status flip to ride along on, and on every turn-marks change (`turnEndSeq` / `viewedSeq`, the `turn_marks` manager event) — never a `status` flip, so no `projects` hint. `projects` also goes out once per committed change to a project record, the workspace registry or a worktree record, from REST and MCP alike: the write primitives in `src/projects.ts` / `src/worktrees.ts` mark it through `src/projectsChanged.ts`, an operation of several writes (a create, an adopt, a workspace assignment, rename or removal, the project-delete cascade) sends one, a refusal or no-op that wrote nothing sends none, and a refusal after a write landed (a project delete that dropped a clean worktree before a dirty one refused it) sends one. cc writing a project's `CONVENTIONS.md` sends one too (the listing reports its selection): one per edit, and one per regeneration sweep however many projects it rewrote

Every server → client frame is declared once in the `ServerFrame` union (`shared/wsFrames.ts`, discriminated on `t`); `src/wsHub.ts` builds each frame against its member and `startController`'s listeners (`web/src/app/controller.ts`) read them through the typed `bus` (`shared/ws.ts`). A new `snapshot` field is that declaration plus its producer and consumer; no test enumerates its keys.
